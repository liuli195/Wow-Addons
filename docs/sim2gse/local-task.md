# 本地任务入口

当前三步界面与命令入口共用真实计算程序，默认自动执行搜索与离线导出，不再进行最终五节奏复测。累计十分钟包含初始化、编译和搜索内比较，不预留三分钟复测窗口。这个入口读取单角色并先运行固定引擎的自由选招基准，再依据整批执行计数和原生动作标记取得可按动作，生成离线序列，经固定 GSE（按键序列插件）源码编译核对后，将同一动作块交给受控引擎评估。

页面的“诊断日志总开关”默认关闭。关闭时不保存额外详细过程、动作轨迹、诊断报告和性能统计，也不为记录额外跑模拟；位置修复所需反馈、去重缓存、取消后继续数据和最终结果不受影响。内部任务配置 `diagnostic_logging`（诊断日志总开关）必须显式为真，细分记录设置才生效。

职业、专精和职责交给原生引擎判断，坦克与治疗也沿用伤害优化目标。导出编号取原生角色身份；种族别名由引擎解析，原文保留。受控模拟保留原生战前准备，施法、引导、蓄力及派生效果使用原生调度；不再固定邪恶专精起手。基准的装备组代理逐项记录实际使用后再转换，不因其后台标记而遗漏饰品。

基准中由原生增益明确标为同一基础按钮的替换形态合并到一个动作块，由原生就绪状态决定实际执行哪一形态。当前已验证狂暴战士的怒击替换关系；这不是完整的游戏按键兼容证明，未实例化为增益的形态被动及游戏内蓄力操作仍需后续实际验收。

## 三步界面

在仓库根目录启动，然后用浏览器打开终端显示的本机地址：

```powershell
.venv/Scripts/python.exe scripts/dev/sim2gse/interface.py
```

默认地址为 `http://127.0.0.1:8780/`；端口被占用时使用 `--port 0` 自动选择空闲端口。粘贴角色导出文本并点击“开始运行”，页面显示真实阶段、已完成批次和累计用时；结果就绪后才显示复制区。修改输入或重新开始会清空旧结果，短暂断连会继续等待同一任务。

界面仅绑定本机地址，角色和必要报告保存到 `.local/sim2gse/ui-tasks/`，可通过 `--output-root '中文 空格目录'` 指定位置。新搜索结果注明未进行最终独立复测；历史结果仍按其原复测状态展示。游戏内导入仍未验收。停止服务使用终端的 Ctrl+C（中断快捷键）；重新启动服务后，未完成任务可按下方内部命令恢复，页面提供诊断日志总开关，不增加取消或恢复按钮。

## 单个文件入口

在仓库根目录运行，输出必须是尚不存在的新目录：

```powershell
.venv/Scripts/python.exe scripts/dev/sim2gse/task.py '角色文件.simc' --output '.local/sim2gse/新任务'
```

产品代码位于 `projects/sim2gse/`，命令入口与界面共用 `run_task`（执行任务）。先安装市场中的 `data-store`（数据存储）插件，让代理从实际技能入口执行 `python <skill>/scripts/project_binding.py connect --project <仓库>`；再为当前 `.venv` 安装 `projects/sim2gse/requirements.txt`。所有工具与独立命令共用仓库内 `.local/skills/data-store`，不再依赖用户级旧技能联接。升级或切来源后由代理从新入口运行随包 `update`（更新连接）命令，核对旧来源并重启已运行工具；正常读写在同一进程中加载一次，不逐次定位。核心独立更新后，需失效 `.build-and-verify/cache/` 中 `id` 为 `verify.sim2gse` 的可重建缓存，再运行固定基线快速验证并确认该项实际执行；本仓库的缓存不会自动感知外部技能源码变化。

全部任务的持久结果共用本仓库根目录 `data/`，排除于 Git。`runs`、`candidates`、`batches`、`traces` 是稳定逻辑表，数据以 Parquet 内部 Zstd 保存，直接通过安装技能的 DuckDB 查询接口读取。普通原生报告保留有类型嵌套数据，详细轨迹仅随诊断开关保存。

任务目录保留冻结输入、进度与取消/恢复检查点；`result.json` 只保存数据中心任务身份和状态，不再保存完整结果或根目录 `candidate.txt`。`read_task`（读取任务）从中心还原页面结果与候选；需要搜索记录或原生报告时分别使用 `include_search_records=True`、`include_reports=True`。原生 JSON 是运行交换文件，成功入库后清理。结果不标为最终独立复测通过，失败不会覆盖旧任务。战斗日志对比工具的 `--simulation` 可传任务目录，直接读取中心报告；也保留外部 SimC JSON 输入。

## 取消与恢复

同一任务模块提供 `start_task`（启动）、`cancel_task`（取消）、`resume_task`（恢复）和 `read_task`（读取）入口，供后续界面共用。取消立即停止派发并清理所属进程树，完整批次保存在结果中心，SQLite（本地数据库）保留恢复状态与批次身份。任务正在运行时拒绝第二个执行者恢复。

```powershell
.venv/Scripts/python.exe scripts/dev/sim2gse/task.py --resume --output '.local/sim2gse/已有任务'
```

恢复沿用原有配置、随机数、已完成候选和累计预算；版本或输入变化须新建任务。搜索中取消后继续搜索，不进行最终复测。预算耗尽不能重置耗时或自动延长。详细预算与缓存见[运行契约](runtime-contract.md)。

## 当前准备方式

复用仓库 `.venv`（解释器环境）。唯一新增依赖为项目要求文件中的固定 CBOR（紧凑对象编码）库；已有环境本次只新增该库，没有升级其他依赖。

```powershell
.venv/Scripts/python.exe -m pip install --only-binary=:all: -r projects/sim2gse/requirements.txt
build-and-verify build --project .
build-and-verify verify --project .
```

构建使用 `compatibility/lock.json`（兼容锁）中固定的上游提交、源码树、补丁顺序和构建参数。准备入口从 SimulationCraft（战斗模拟器）官方 Git（版本管理）仓库检出固定提交并核对源码树身份，再在 `.tools/sim2gse/product/` 独立准备原版和受控版；不调用或修改配装器引擎。无网络或编译工具时明确失败。

每次构建记录真实程序散列；任务开始前核验构建状态、程序和补丁身份。引擎使用任务目录内固定的相对文件名，从而支持用户输入和任务目录中的中文及空格。程序关闭联网，角色不会自动上传。

## 验证边界

- 原生试验开关完全由输入配置决定：`allow_experimental_specializations=1`（开启）或 `=0`（关闭）按原生要求放在角色声明前；未提供则使用原生默认值。基准和受控批次使用同一原始文本，产品不注入开关、不自动重试、不自行分类试验支持；原生拒绝、崩溃及报告错误会终止任务并保留日志。此前自动试验模式的验收属于历史行为。
- 原生自动生成队友时，以姓名和职业唯一定位输入角色，只控制该角色；队友沿用原生行动列表。优化使用原生团队伤害，报告同时保留个人伤害。单角色继续使用个人伤害。
- 导出按钮使用原生动作的法术数据编号，运行时渠道编号仍保留观察；没有原生行动列表来源的派生效果不另造按键。

- `native_reference`（原生参考）使用同条件自由选招；`search_result`（搜索成绩）报告选中序列的每秒伤害、有效样本和相对参考的比例。`final.scenarios`（最终复测情景）为空，状态是未请求；`locked_candidate_key`（锁定编号）与 `selected_candidate_key`（选用编号）对应同一搜索结果，不进行复测回退。自由选招参考不是保证能达到的数学上限。
- 报告逐项比较编译动作块与原生实际解析块，按战斗编号、原始输入编号、步进和动作签名双向核对派发与执行计数；施法完成可以晚于派发，战斗末未完成施法单独核对。原生派生事件另行记录，不当作额外按键；未就绪动作按输入推进。
- 日常入口自动选择动作和搜索。前两票的单次回归显式使用 `mode="single"`（单次模式），其 `program`（动作块）和 `phase_ms`（起始相位毫秒）仅用于诊断；单次模式不代表完成优化。
- 当前真实角色候选通过本机 CBOR 往返和固定上游导入后的编译核对；客户端接口使用明确的边界替身。
- 编码采用游戏 12.1 实测向量确认的无封装 Deflate（压缩格式）及 CBOR（紧凑对象编码）字节字符串，表的字符串键同样按字节串处理。`{1,"test"}` 的客户端输出为 `a2J0KUktLgEA`，已逐字节匹配；完整候选的游戏导入与按键仍需验收。
- 能力清单来自本次基准执行过的玩家动作，依据引擎原生归属、后台和被动等标记筛选；不维护人工辅助技能排除表。基准未使用的其他能力不阻断任务。原生实际执行的战前主动动作按原顺序导出为 `[nocombat]`（非战斗条件）步骤，并逐场核对受控引擎的战前轨迹；战斗中选入但无法表达或执行的动作仍明确失败。范围是本次基准策略，不是职业技能全集。
- 基准引擎仅增加观测报告补丁，导出原生已有的整批累计执行次数与动作属性；没有改变原生选招或伤害模型。样例轨迹只用于起点顺序参考，不冒充完整批次。
- 不安装游戏插件，不写游戏目录，也不发送游戏按键。

自动检查使用人工构造的角色样例，覆盖输入保真、注入拒绝、动作块一致性、单技能、不可用步骤、队列覆盖、双主动物品顺序、重置与重放，以及引导饰品和超长宏的拒绝。浏览器回归包含基准未使用的种族及辅助天赋不阻断生成。本机真实角色的单次链由 `tests/sim2gse/manual_native_task.py` 验证，默认完整优化由 `tests/sim2gse/manual_search_task.py` 验证；该检查依赖未提交的用户样本，不能视为远端已运行。

## 2026-09-13：地面落点与输入间隔

用户确认地面技能统一在角色脚下释放，不再额外点选地面。导出按官方客户端 `SpellTargetRestrictions.flags` 的目的地位（64）生成 `[@player]` 宏；普通单位目标技能及已经由天赋提供目标位置的技能保持原类型。法术查询最终导出的编号，主动饰品查询原生使用效果的法术编号；单动作和同块动作使用同一路径，不维护职业技能白名单。

目标数据为本机正式服 **12.1.0.69814**，由固定 SimC（模拟引擎）提交自带的 CASC（游戏存储）提取器与 DB2（游戏数据表）解析器读取。`compatibility/spell-target-masks.json` 保存默认难度的原始非零掩码、原始文件散列和提取器提交，兼容锁核验快照散列。模拟数值数据仍固定为 **12.1.0.69587**；两个版本分别记录，不能宣称数值模型已升级。运行时不读取游戏目录。

页面可调整模拟按键间隔，默认 **300 毫秒**，允许 50 至 2000 毫秒整数。标准、波动、慢速、暂停和相位偏移情景均从该参数派生；配置进入任务和缓存身份。设置只影响模拟，不会替玩家按键，也不要求手动输入严格恒定。

角色脚下释放不代表远程目标必定被命中。当前模拟对照仍要求目标处于技能影响范围内；游戏中站位不满足时不能用模拟伤害作通过标准。完整地面落地与伤害表现等待用户复测。

# 全部搜索优化与规格对照（2026-10-06）

本表只列已实施项目。第一阶段已进入正式规格；后续项目在用户确认补齐版门禁二后也已纳入正式规格并校验通过。未采用的数据库迁移、历史预取、四层或五层筛选等研究方案不列为已实施。五项搜索提速原先只写入实施需求，本次按用户要求补齐其可观察行为。

| 轮次 | 已实施内容 | 规格覆盖位置 |
| --- | --- | --- |
| 第一阶段 | 同一任务直接复用已核验的小成绩，不重复读取、登记或增加样本 | 用户流程：复用已核验成绩 |
| 第一阶段 | 已知记录按逻辑表和键读取，不扫描无关历史 | 数据存储：已知逻辑键读取 |
| 第一阶段 | 一次读多个记录，可直接选择字段并保留类型 | 数据存储：多键及字段读取 |
| 第一阶段 | 减少通用查询准备开销，内部选择适合的读取配置；只记配置、每次读当前数据 | 数据存储：透明读取优化及数据新鲜性；具体方法见既有实施需求 |
| 第一阶段 | 区分缺失、明确损坏和暂时不可读；保留成功引用 | 两仓现有存储故障及缓存保护要求 |
| 第二阶段 | 每12份保存一组，正常结束、取消及预算停止保存尾组 | 用户流程预览：有界分组保存 |
| 第二阶段 | 状态有变化才保存对应部分，减少历史整份重写 | 用户流程预览：只保存变化状态 |
| 第二阶段 | 强停重算未保存组，发布中断可恢复；并发不产生重复记录 | 用户流程预览：只恢复可靠保存结果 |
| 第二阶段 | 组内直接筛选目标记录及字段，调用方仍不依赖路径或文件名 | 数据存储预览：组内字段及匹配记录筛选 |
| 搜索全流程 | 程序结束及时返回，取消和超时继续有效 | 评估预览：减少冗余搜索工作，第1场景 |
| 搜索全流程 | 同层最多两个单线程候选同时计算，按原顺序使用，整层结束后筛选 | 评估预览：减少冗余搜索工作，第2场景 |
| 搜索全流程 | 完整导出检查一次启动完成，所有检查保留 | 评估预览：减少冗余搜索工作，第3场景 |
| 搜索全流程 | 已指定报告目标时只生成一份完整交换报告，原默认调用保留 | 评估预览：减少冗余搜索工作，第4场景 |
| 搜索全流程 | 晋级判断和保存摘要复用同一次比较结果 | 评估预览：减少冗余搜索工作，第5场景 |
| 上限优化 | 默认累计32、128、256，明确指定512仍可用；独立晋级复核保留 | 评估预览：按需要追加评估并复核晋级 |

所有轮次共同保留：通用逻辑表查询，不绑定业务文件名；600秒累计预算、五轮完整无改善停止、取消和恢复、真实样本计数、完整报告及类型、评分与独立晋级复核、诊断开关及完整导出检查。降低上限会改变搜索路径，不能将其完整用时收益当作严格同工作量提速，也不能承诺所有职业质量无损。实际游戏验收未运行。

正式规格：魔兽仓库`myspec/specs/sim2gse-user-workflow/spec.md`与`myspec/specs/sim2gse-sequence-evaluation/spec.md`；数据存储仓库`myspec/specs/data-store/spec.md`。表中“预览”标注指本次审查时的位置，对应内容现已应用到上述正式规格。两仓远端交付按确认后的流程继续。

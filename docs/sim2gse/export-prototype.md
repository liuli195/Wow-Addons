# 最小序列的数据格式与编译约定

对应[验证最小序列的导入与编译契约](../../myspec/changes/sim2gse-wayfinder/issues/07-export-prototype.md)。日期：2026-09-12。临时原型，不是正式导出器或伤害优化结果。

## “契约”的含义

这里是生成器与 GSE（按键序列插件）之间的数据格式和解释规则。例如，生成器表达两个步骤“脓疮打击、天灾打击”，导入解码及编译后应仍是两个步骤，不能顺序颠倒、合并或丢失。一个块里的两件饰品加一个技能，应保持同块及命令顺序。这些规则不保证每条命令在游戏里都能成功施放。

本票先确定结构和编译约定；实际按键失败、公共冷却和队列属于后续执行模型。安装及真实导入按用户决议等候选模拟结果产生后进行。

## 原型与复现

- [Python（编程语言）入口](../../scripts/dev/sim2gse/prototype-export.py)：创建固定样本、编码和本地压缩往返，调用上游核对，输出证据及可查看步骤的单文件演示。
- [Lua（脚本语言）入口](../../scripts/dev/sim2gse/prototype-export.lua)：使用上游测试替身、CBOR（紧凑对象编码）解码器，以及未经修改的导入、校验和编译实现。
- 从仓库根执行：`.venv/Scripts/python.exe scripts/dev/sim2gse/prototype-export.py`。复用已有解释器及固定源码缓存，不安装依赖，不启动游戏，不运行战斗。
- 输出在 `.local/sim2gse/export-prototype/`：`evidence.json`、每例的 `.cbor`、`.trace.txt`、`.candidate.txt` 以及 `walkthrough.html`。候选字符串明确未经过客户端验证；演示只浏览实际编译结果，不模拟游戏执行。

固定上游仍为 `3.3.32 / f225d4c947d168c63451ef7c567d7063c38cc239`，Lua 解释器为已有 5.1.5。本次复核原有五份来源散列，并补取同一提交的上游测试辅助文件；所有使用缓存的源码散列记入证据。

## 已核对的规则与结果

| 项目 | 实际结果及约定 |
| --- | --- |
| 单序列外壳 | 二元数组“序列名、序列对象”经上游导入分支解析到预期名称、职业及内容。 |
| 集合外壳 | `type=COLLECTION`（集合类型），`payload.Sequences`（序列载荷）按序列名作为键保存原始对象；同样到达预期导入存储边界。 |
| 对象内容 | 使用 `MetaData`（元数据）、`Default=1`（默认版本）及 `Versions[1].Actions`（首个版本的动作列表）。样本专精为 252，版本数值为 3332。 |
| 数字键与数组 | CBOR 数组或整数键映射解码后是 Lua 数字索引。带数字子项和 `Type`（块类型）的循环不能全部转成字符串键；本轮用循环样本核对。 |
| 基础动作 | 两个技能编号 `85948`、`55090` 的顺序保持；重复技能未去重。 |
| 同块多命令 | `/use 13`、`/use 14`、`/cast 脓疮打击` 保持在一个宏文本步骤内；反向饰品顺序也保持。只是结构样例，当前角色的两件被动饰品不会因此变成主动物品。 |
| 中文 | 中文帮助文字经编码与上游解码保持一致；样本中文技能名通过显式提供的法术接口测试数据核对，不证明真实客户端本地化已通过。 |
| 校验字段 | 使用上游 `ComputeSequenceChecksum`（计算校验值）写入元数据，上游校验通过；改动动作后的校验失败。校验依赖项目编号与资料片编号，本轮提供正式服 1／至暗之夜 11 的测试数据，仍须客户端确认。 |
| 宏长度 | 原型保守限制单块宏文本不超过 255 个 UTF-8（字符编码）字节，超限样例拒绝。此为原型限制，不宣称已复现上游专用计长函数；也不是整个导入字符串的长度限制。 |

六种样本分别为一个技能、两步顺序、重复技能、同块多命令、反向饰品顺序、带整数键的顺序循环；每种覆盖两类外壳，共 **12 个样本**。八个已知 CBOR 编码向量通过，随后由上游独立解码器与预期 Lua 对象逐键比较，避免只做自编码自解码。

主要依据：[上游导入入口](https://github.com/TimothyLuke/GSE-Advanced-Macro-Compiler/blob/f225d4c947d168c63451ef7c567d7063c38cc239/GSE_Utils/Utils.lua#L434)、[上游模板编译](https://github.com/TimothyLuke/GSE-Advanced-Macro-Compiler/blob/f225d4c947d168c63451ef7c567d7063c38cc239/GSE/API/Storage.lua#L2457)、[校验实现](https://github.com/TimothyLuke/GSE-Advanced-Macro-Compiler/blob/f225d4c947d168c63451ef7c567d7063c38cc239/GSE/API/Checksum.lua#L191)、[上游离线解码器](https://github.com/TimothyLuke/GSE-Advanced-Macro-Compiler/blob/f225d4c947d168c63451ef7c567d7063c38cc239/spec/cbor.lua)、[CBOR 标准](https://www.rfc-editor.org/rfc/rfc8949.html)。

## 必须保留的验证边界

1. **真实客户端编码尚未验证。** 固定 GSE 使用客户端 `C_EncodingUtil`（编码接口）完成序列化、压缩及文本编码。离线原型暂用标准 CBOR、带 zlib（压缩库）封装的压缩及标准 Base64（二进制转文本编码）构造候选；zlib 封装是待验证假设。没有调用真实客户端编码接口，也没有用本地替身冒充它。[上游编码调用](https://github.com/TimothyLuke/GSE-Advanced-Macro-Compiler/blob/f225d4c947d168c63451ef7c567d7063c38cc239/GSE/API/Serialisation.lua#L6)
2. **前缀容忍未验证。** 上游解码从第六个字符切片，包含最后一个 `!`；本地严格解码按完整前缀后开始。尚不知真实客户端是否容忍该字符，不能以本地解码成功证明该上游字符串路径通过。本轮实际测试的是解码后的表进入上游 `ImportSerialisedSequence`（导入入口）分支。
3. **客户端边界使用测试替身。** 中文法术信息、专精所属职业、资料片编号与消息／存储边界均显式替代；`PerformMergeAction`（合并存储入口）被截获并核对，没有写入插件数据。校验算法本身执行原代码，异或运算用仅服务于该校验的 Lua 5.1 算术替身。没有伪造游戏导入或法术可用性证据。
4. **初始位置与重置只有源码依据。** 沿用[既有研究](gse-research.md)；演示的“下一步”和“回到开头”只浏览捕获结果，不能作为 GSE 点击推进、跨战斗重置或队列的实测。
5. 本轮未核对任意外部输入、加密打包外壳、高级动作块或完整 T14—T16（导出相关测试）矩阵。原型 CBOR 编码只覆盖自建样本使用的类型，正式实现应选择成熟编码库。

离线对象、导入分支及编译顺序已有可运行证据；真实字符串导入及客户端行为继续标记未验证。用户于 2026-09-12 确认本票按此范围结项，进入执行模型票；尚未生成推荐伤害序列。

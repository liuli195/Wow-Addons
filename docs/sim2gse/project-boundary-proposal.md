# 项目目录与上游补丁维护边界

日期：2026-09-12。对应[确认项目目录与上游补丁维护边界](../../myspec/changes/sim2gse-wayfinder/issues/04-project-boundary.md)。用户已要求建立统一项目目录，将序列优化器与配装器一并放入；本轮已建立项目入口并迁移配装器，清单、补丁、构建脚本和新增检查仍按后续任务逐步实现。

## 项目归属与边界

在当前仓库的 `projects/`（项目目录）下统一放置 `sim2gse/`（序列优化器）和 `gear-planner/`（配装器）。序列优化器沿用本票已展示的固定上游提交加可审查补丁方案；两个项目各自维护源码，复用仓库公共环境与交付入口。

**公共目录不等于共用引擎。** 两个项目可以复用编译工具、解释器、验证入口和只读官方资料；可修改的引擎源码副本、补丁、构建中间文件及最终程序必须按项目隔离。不得通过同一路径、目录链接或运行时回退，让两个项目使用同一个会被覆盖的引擎。

| 位置 | 职责 |
| --- | --- |
| `projects/sim2gse/` | 本项目源码、自动测试和必要的依赖声明；目前只有项目说明，不预建全部模块。 |
| `projects/gear-planner/` | 由原配装器目录整体迁入的源码、启动入口、样本与现有运行数据。 |
| `projects/sim2gse/native/patches/` | 后续按应用顺序维护自己的引擎差异文件，纳入版本管理。 |
| `projects/sim2gse/compatibility/lock.json` | 后续本项目唯一的兼容清单：上游完整提交、补丁顺序及散列、序列插件研究版本、构建选项等；具体有效值按后续票据取得的证据填写。游戏与公共工具版本引用现有 `scripts/dev/versions.json`（公共版本记录），不手抄第二份。 |
| `scripts/dev/sim2gse/` | 本项目必要的准备、构建和验证脚本；调用上游标准工具。 |
| `docs/sim2gse/` | 研究、维护、验收与使用说明，遵循仓库文档集中存放约定。 |
| `.tools/sim2gse/` | 固定版本的独立上游检出、补丁工作副本和可执行程序；原版与修改版分目录。已有研究缓存保留原位。 |
| `.tools/gear-planner-*` | 配装器已有的原版及专用改版引擎和资料，只由配装器维护；“保留原地”指不移动、不覆盖它们，不赋予序列优化器修改权。 |
| `.local/sim2gse/` | 构建中间文件、角色输入、候选结果、报告和临时打包产物，默认仅本地保存。 |
| 仓库根 `.venv/` | 复用现有 Python（编程语言）解释器环境；新增依赖按实际需要锁定，不升级或替换无关依赖。 |

计划书第 19.1 节是建议结构；本建议把其中的开发脚本、项目说明和运行数据分别归入仓库既有位置。依赖确有冲突时再单独提出解决方案，不现在增设多套环境。构建时把已解析的版本、工具链、补丁身份和程序散列写入本次运行清单；它是证据快照，不是第二份手工维护的版本来源。

## 官方资料支持的维护方式

1. SimulationCraft（战斗模拟器）的维护者构建说明提供 CMake（构建工具）入口，并明确关闭 `BUILD_GUI`（构建图形界面）后可以只构建命令行程序。首版沿用这条路径。该说明含旧环境示例，具体编译器和选项仍以最终固定提交的构建文件为准；本地既有 `b845947` 研究源码也可读到该选项，但它不代替最终构建提交。[维护者构建说明](https://github.com/simulationcraft/simc/wiki/HowToBuild)
2. CMake（构建工具）官方文档推荐源码与构建目录分离，因此中间产物放到 `.local/sim2gse/`；维护者现有构建系统继续负责引擎编译，本项目只作薄层调用。[官方目录说明](https://cmake.org/cmake/help/latest/manual/cmake.1.html#generate-a-project-buildsystem)
3. Git（版本管理）原生支持补丁可应用性检查；正式构建时在正确上游提交的独立工作副本中按顺序检查并应用补丁。若某一步不匹配，停止该次准备，不采用忽略冲突或部分应用来继续构建。[官方补丁说明](https://git-scm.com/docs/git-apply)

据此，建议首版只维护固定引用和小补丁集。整套上游源码不纳入本仓库提交，也不另建需要同步发布的长期分支仓库；以后补丁规模或协作方式确实变化时再评估。这个选择是本项目的维护建议，并非上游要求所有使用者如此组织。

正式补丁工作副本须能准确识别自己的上游提交，不能直接在现有归档展开目录上构建并把外层仓库身份当成引擎版本。研究中核实的 `c1935b9` 原版程序与 `b845947` 源码虽有相同的引擎目录证据，仍不是同一完整构建输入；正式原版对照与修改版要以同一个完整上游提交、数据、工具链和构建选项为基础。[已完成的引擎研究](engine-research.md)

这里的“原版对照与修改版”是序列优化器内部的两份独立程序，不是让序列优化器与配装器共用程序。序列优化器从官方固定源码单独准备原版对照，再在自己的工作副本应用按键控制等本项目补丁，单独构建、记录版本和验证。配装器现有补丁不自动带入；若以后确需复用某项修复，须核对适用性并显式纳入序列优化器自己的补丁记录。既有读取配装器原版程序的研究证据不构成新项目的运行依赖。

配装器当前不只有一份引擎：服务分别引用通用程序、神圣专用程序和织雾属性修复程序。神圣程序包含入口放行修改，织雾程序包含入口放行及主属性修复；它们不能概括成一份“未修改的公共引擎”。[当前服务配置](../../projects/gear-planner/server.py)、[已有改版说明](../gear-planner/mistweaver-minimal-fix.md)

本票不决定禁用引擎联网支持、不选编译器安装方式，也不重新运行现有模拟结果。这些操作不影响当前目录与补丁维护决策；资料能够确认的工具功能不再逐项自测。

## 允许修改与必须保留的范围

- 后续实施主要修改本项目源码、补丁、测试、文档和专用开发脚本。引擎差异限定为已确认的输入控制、必要调度接入、能力识别与诊断；复用原有职业、装备和伤害模型。新发现的职业模型缺口先作为明确问题处理，不能默默重写。
- 配装器整体移至 `projects/gear-planner/`，样本和运行数据随目录保留，现有研究脚本更新路径引用。其通用引擎、`.tools/gear-planner-holy/`（神圣改版）、`.tools/gear-planner-mistweaver/`（织雾改版），以及相应源码、补丁和构建产物均属配装器，序列优化器不得覆盖。自有插件、素材和第三方副本继续保留原位。[服务入口](../../projects/gear-planner/server.py)、[探测入口](../../scripts/dev/gear-planner-research/probe-simc.py)
- 公共文件只在后续接入需要时作增量修改：根项目说明、`.build-and-verify/config.json`（构建与验证配置）、`scripts/dev/check.py`（检查入口）；公共版本清单及现有远端工作流只在新增工具或构建步骤确有需求时修改。既有检查保留。
- 游戏目录、账号配置、已保存角色原文与既有报告不进入修改范围。安装讨论仍留到已有离线候选结果与可导入产物后的真实导入阶段。

## 开发、验证与交付的接入

| 时点 | 沿用入口与必要增量 |
| --- | --- |
| 后续正式开发 | 读取当前 dev-flow（开发流程）技能，按已确认票据在 `codex/`（功能分支前缀）分支实施。 |
| 日常本机验证 | 继续使用 `build-and-verify verify --project .`（统一快速验证命令）；有真实代码后增加本项目的输入、导出和执行模型检查，检查随相关实现加入。 |
| 引擎开始修改时 | 通过统一构建入口调用上游构建系统；增加固定源码／补丁身份检查、必要行为回归及关闭扩展后的原版对照。只通过编译不能宣称执行模型正确。 |
| 文档与触发范围 | 当前 `docs/**` 会选中文档检查，但 `scripts/dev/check.py` 第 79 行只读根说明及 `docs/` 直接子文件；嵌套研究文档实际未读入。`myspec/**` 也不在现有触发范围。正式接入时补齐实际读取范围及匹配的 `paths`（触发范围）、`inputs`（缓存输入），并覆盖新项目与专用开发脚本。 |
| 远端交付 | 沿用 PR Flow（拉取请求流程）和既有远端工作流。现工作流只调用完整验证，尚无本项目引擎构建与依赖准备；新增步骤接入同一套脚本及版本来源，不能把已有绿色状态称为新引擎已验收。 |
| 运行包 | 按原计划后续票据准备受测程序、来源与许可材料；本票不授权推送、合并、发布或游戏写入。 |

当前状态依据：[统一检查配置](../../.build-and-verify/config.json)、[文档检查实现](../../scripts/dev/check.py)、[公共版本记录](../../scripts/dev/versions.json)、[远端验证工作流](../../.github/workflows/verify.yml)、[拉取请求配置](../../.pr-flow/config.yaml)。这些现有文件本轮均未修改。

## 本轮落地范围

用户对目录方案的具体修订是：建立统一项目文件夹，将两个项目放入其中。本轮依此迁移配装器、建立序列优化器入口并修正引用；配装器从新路径恢复到原本机地址，浏览器存储来源与保存键保持不变。迁移和检查记录位于 `.local/sim2gse/project-directory-move/`。本票的其他维护方式沿用已展示建议，后续仍按地图顺序，不因此开始下一项或发布。

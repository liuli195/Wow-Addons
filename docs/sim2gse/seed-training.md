# 人工启动的起点整理

先人工清洗材料，登记到现有数据中心。入口不会自动解释复杂宏，也不会访问网络或安装到游戏。待筛选和已入选是同一中心中的逻辑记录。

## 登记

清洗件是一个对象，包含label（名称）、class_name（职业）、spec（专精）、source（来源）、original（原件文本）、instructions（使用说明）、semantic（语义状态）、changes（清洗说明列表）、family（结构家族）、core（核心分组片段）和program（搜索程序）。semantic使用preserved（语义保留）、rewritten（明确改写）或unsupported（当前不可表达）。不可表达材料同样登记原件和原因，程序必须为空列表，不参与训练；通过list --state unsupported（查看不可表达材料）读取。

示例：

```json
{
  "label": "示例",
  "class_name": "deathknight",
  "spec": "unholy",
  "source": "作者页面及版本",
  "original": "原件文本或完整记录",
  "instructions": "连续普通按键",
  "semantic": "rewritten",
  "changes": ["明确记录删除或替换"],
  "family": "人工指定的结构家族",
  "core": [["putrefy"], ["death_coil"]],
  "program": [["outbreak"], ["putrefy"], ["death_coil"]]
}
```

从目标工作树执行，`--project`指向已经接入数据存储、拥有现有data（数据中心）目录的主项目，不会新建数据中心或用户技能链接：

```powershell
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" register "清洗件.json"
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" run
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" list --state selected --targets 1
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" list --state processed --targets 5
```

默认依次处理1和5目标；`--targets 1`可以只处理单体。默认模板来自锁定引擎配套邪恶角色。完整模板供真实模拟使用，身份解析副本不参与伤害模拟。实际沿用项目原生参数，包括关闭消耗品；模板、引擎、规则和实际参数均进入处理身份，不与外部默认报告成绩混排。

每个候选独立搜索最多5个完整轮次、每轮最多16候选、600秒上限，缓存不能导致额外轮次。之后以三个固定独立随机条件复测，成绩代表只在可信提升时替换；不同家族可保留复测过的初始结构，最多4个新增代表。日志起手不自动认定为循环，清洗者需确认核心与回绕含义。

普通搜索在任务初始化时读取一次对应职业、专精、目标数和引擎版本的已入选记录，将符合当前角色动作映射及导出规则的最多4条候选追加在原有4个起点之后；非法动作、重复起点及超出宏文本限制的候选会跳过。此快照写入任务检查点，搜索运行中不会刷新；恢复已有检查点时沿用原快照。候选在真正评分时由原搜索编译流程编译，不另起一次预检查编译。

普通搜索开始时立即登记活动，不等待起点训练。训练开始时若已有普通搜索正在运行就退出；训练期间若普通搜索启动，训练通过同一任务取消状态停止自己正在运行的原生进程，并保持旧入选库不变。训练对每个候选分别应用600秒搜索上限，不把整批候选累计成一个600秒总上限；参考模拟、五轮搜索和复测都响应同一取消信号。批量运行1和5目标时，两个目标共用同一次训练活动登记。

没有新材料时不重复搜索。发布失败时旧库保持，已保存处理结果可重新发布；条件改变时重新评估。处理失败返回非零退出码，用processed（已处理记录）查看原因。暂时不可读的存储不会被当成空库。

日常执行只输出简短状态，不生成报告。运行目录只保留现有任务检查点和必要临时文件，业务材料、成绩及起点快照通过共享数据中心保存。ABC和全量材料需分别完成验收，不将开发冒烟当作游戏验收。

2026-10-08的ABC标准模板验收：三条在1和5目标都完成五轮；两套快照各4条，真实正常搜索均读取到原4条加新增4条。优化后的六条均不再保留登记核心，因此最佳成果归历史搜索，初始结构代表另外保留。重复训练未新增模拟。循环轨迹检查覆盖前两次回绕及后期施放，不能代表原作者复杂宏或游戏实测。

同4起点的三组匹配对照含准备和归档：冷缓存总耗时中位26.344→26.391秒，热缓存40.640→37.313秒，原生批次数及命中数对应一致，未见明显回退。新增4起点首次评分另测约增加1.198秒；候选总配额相同时不能把后续投入变化说成入口提速。

待筛选库是可反复使用的来源库，已处理材料仍保留；list --state pending（查看来源库）不等于本轮未处理队列。实际执行按条件和处理记录跳过已完成项。完整五轮的初始、最终程序都会用于行为去重，新程序仍正常处理。全量材料与反馈验收见[筛选记录](seed-material-review.md)。

2026-10-09补充：正常搜索的连续完整无改善门槛取初始化后实际有效路径数，原起点和新增代表均计入；重复、非法或评分失败的输入不计入。任何确认改善全局最佳的轮次清零共用计数，起点初始化评分不计搜索轮次。结果search.no_improvement_round_limit（实际停止轮数）及保存后查询返回实际值；config.no_improvement_rounds（原无改善参数）仅保留给训练兼容，不代表正常搜索当前门槛。

一条路径无法产生新候选时标记并跳过，其他路径继续；独立下一路径位置保存到任务中，取消恢复继续原轮转。所有路径都无候选才按space_stalled（候选空间停滞）结束。门槛在初始化后固定，不因跳过而缩小；其他预算及候选上限保持，所以公平机会仍受这些提前停止条件约束。人工预训练依旧最多五个完整轮次；既有起点可用于新任务重新评分，旧规则任务不能原地恢复。下次人工训练由于规则身份变化会重新处理，不在正常搜索中触发。

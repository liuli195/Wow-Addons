# 人工启动的起点整理

先人工清洗材料，登记到现有数据中心。入口不会自动解释复杂宏，也不会访问网络或安装到游戏。待筛选和已入选是同一中心中的逻辑记录。


## 统一来源与增量准备

run和prepare（准备）启动时，将适用的历史最佳程序按history:<run_id>（历史运行身份）自动登记到同一来源库。历史新增、程序修订及明确失效会更新来源；重复扫描不写入，临时读取失败直接报错，不伪装成删除。历史原程序和成绩仍保留，原角色成绩不直接参加本批排名。

已完成历史有一致候选引用和可恢复程序即可进入统一整理；旧搜索只有一个样本、零分或缺少分数不剔除程序。来源资格与成绩复用分别核验，当前训练仍做初始/最终各三批128轮独立复测；已有可靠完整路径按原身份核验复用。

旧清洗件格式继续可用。需要修订或停用人工来源时，可在清洗件增加source_id（明确稳定来源身份），后续使用同一身份再次register；active: false（停用）只移出未来输入，不自动撤回已有代表。不能通过标题或网址猜测更新关系。仅名称、来源描述、家族和核心变化不会使可靠训练成绩失效；使用说明等影响用法的字段保守重新核对准备。

prepare使用与run相同的整理、合法性、归一化和编译管道，不启动优化或独立复测，用户也不必先手动prepare：

```powershell
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" prepare --targets 1
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" list --state prepared --config-key "prepare返回的config_key"
```

派生prepared（准备快照）仍在现有数据中心。角色、场景、引擎、审核爆发和明确准备语义版本决定缓存范围；并发数不影响它。无变化不重复共用参考、整理或输入编译，新来源和修订只处理受影响项。明确损坏或未知缓存版本重建，临时存储失败不缩小队列。完整快照原子写入后才开始训练，失败不会使用半快照。

准备快照记录全部来源、非法或停用原因、逐项改写、行为分组及稳定训练表示。明确限定材料时，本批实际表示与编号只取自所选活动来源；相同行为的不同程序树不能冒充该起点的完整路径。context.frozen_queue（本批冻结队列）保留实际派发输入，全库来源准备缓存仍共用。行为相同但程序树不同的来源保留各自原件和核心；停用原代表来源不会随机换掉仍合法的训练表示。processed（已处理）中的comparison.sources（来源关系）逐来源记录初始和最终程序是否保留其核心，原统计门槛和最多四个入选代表不变。

命令返回preparation（准备统计），区分来源数、原程序唯一数、当前唯一起点、完整路径、待补完整路径、实际派发、恢复及失败。只复用同实际初始表示的完整独立路径；A的最终赢家等于B起点不能免训B，旧动态免训会补入待训，dynamic_skips（动态跳过数）为0。覆盖政策单独记入身份清单，不清空其他可靠成果。无活动合法输入不会清空旧入选库。

## 登记

清洗件是一个对象，包含label（名称）、class_name（职业）、spec（专精）、source（来源）、original（原件文本）、instructions（使用说明）、semantic（语义状态）、changes（清洗说明列表）、family（结构家族）、core（核心分组片段）和program（搜索程序）。semantic使用preserved（语义保留）、rewritten（明确改写）或unsupported（当前不可表达）。不可表达材料同样登记原件和原因，程序必须为空列表，不参与训练；通过list --state unsupported（查看不可表达材料）读取。

示例：

```json
{
  "label": "示例",
  "class_name": "deathknight",
  "spec": "unholy",
  "source": "作者页面及版本",
  "original": "原件文本或完整记录",
  "instructions": "连续普通按键",
  "semantic": "rewritten",
  "changes": ["明确记录删除或替换"],
  "family": "人工指定的结构家族",
  "core": [["putrefy"], ["death_coil"]],
  "program": [["outbreak"], ["putrefy"], ["death_coil"]]
}
```

从目标工作树执行，`--project`指向已经接入数据存储、拥有现有data（数据中心）目录的主项目，不会新建数据中心或用户技能链接：

```powershell
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" register "清洗件.json"
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" check
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" run
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" list --state selected --targets 1
.venv/Scripts/python.exe projects/sim2gse/seed_training.py --project "D:\My Project\Wow Addons" list --state processed --targets 5
```

专项验收可在`run`命令重复传入`--candidate-id <已登记材料编号>`，只处理这些明确材料，避免全量训练。默认仍读取全部待处理材料及历史起点。错误、不可表达或角色不匹配的编号在真实计算前拒绝；每件600秒预算、连续两轮无改善及三种子128轮独立复测不变。新复测批次保存引擎、条件及程序身份摘要，升级核验只读摘要即可核对来源。

并发配置位于执行工作树的`.local/sim2gse/config.toml`（内部配置文件）。默认2条训练×每条2个评分；外层范围1至3，内层范围1至16，乘积不得超过16。非法或超限在任何计算前拒绝：

```toml
[simulation]
target_count = 1
enable_omnium_talents = true

[training]
max_trainings = 2
max_processes = 2
```

训练启动时读取一次，不在运行中热更新。`run --max-trainings 3 --max-processes 2`（3条训练×每条2个评分）可覆盖文件；`--max-trainings 1 --max-processes 16`允许单路径16个评分槽。CLI覆盖后共同验证乘积。普通搜索上限仍为2，目标场景仍顺序执行，每个引擎单线程。同候选搜索与复测不重叠；排队等待不扣600秒，进入搜索后的编译、保存等待及争用仍计原墙钟。每完成一条并可靠保存后补派下一条，最终按冻结顺序比较。

训练成绩的语义身份保留完整模板、双引擎、模拟选项、种子、样本、评分与停止规则，排除并发数和源码原字节摘要。完整输入及其摘要保存在原批次的`identity.json`（身份清单）；源码摘要用于出处，实际执行配置、开始阶段、已用秒数及请求计数分别保留。仅调整并发可复用完整成果及未完成搜索的可靠进度。时间截止仍可能使不同并发完成的候选范围不同；相同工作量性能对照须使用隔离数据项目及运行目录，固定角色、候选、样本和随机条件，不能把多算候选当成提速。

训练、解析／映射／编译或爆发适配的实际语义改变须递增`TRAINING_VERSION`（训练规则版本），搜索、统计和候选行为分别递增既有`SEARCH_ALGORITHM`、`STATS_VERSION`、`BEHAVIOR_IDENTITY_VERSION`。不能靠未递增版本让真实算法变化继续复用成绩；普通任务严格恢复身份不改。

旧be350c90批次必须先从原源码、原模板、原配置和双引擎重建完整条件输入，摘要与原`condition.txt`（条件文件）、全部相关检查点和处理／入选记录一致，才能调用训练专用`adopt_legacy_condition`（导入旧条件凭据）。导入复用现有数据中心写锁，仅补身份清单，原条件、目录、请求键及业务记录不变。凭据须含`condition_input`（完整旧输入）、`source_commit`（完整固定提交）及`semantic_versions`（旧源码真实语义版本）；未知来源、缺键、未经审核的源码差异及不一致一律拒绝。本票三个变动模块只允许固定基线的LF／CRLF（换行形式）摘要。另仅对未改的`gse_import.py`、`macro_interpreter.py`和`runtime.py`，导入时可明确传`source_root`（原源码仓库根）：导入器在现有写锁内只读原文件，要求原字节摘要等于完整旧输入、统一换行后内容摘要等于固定be350文件版本，才保存绑定原输入与基线的摘要结论。恢复和升级核验再核对结论及当前规范化内容；不保存源码副本，不接受调用者自报验证结论，其余规则仍严格匹配。该证明信任受控导入器及本机账本，未提供针对任意恶意改写账本的认证机制。不得由新源码的当前并发配置伪造旧输入；本机真实绑定及新提交验证须单独完成。

已收敛搜索不重搜，也不重新结算原搜索预算；复测沿用TaskStore、成功批次与报告意图，精确核验条件、程序、种子、样本和完整报告，只补初始/最终各三批中的缺口。完整结果先保存在所属TaskStore再交协调父级；汇总或最终发布失败可恢复保存，不重算可靠路径。

默认依次处理1和5目标；`--targets 1`可以只处理单体。默认模板从当前受检构建定位，不读取历史产品目录。完整模板供真实模拟使用，身份解析副本不参与伤害模拟。模板、引擎、语义规则和评分／搜索参数均进入处理身份，不与外部默认报告成绩混排。

先运行check（只读检查），它核对文件、引擎身份与本专精的审核定义，不启动模拟、不替代实际引擎核验。run（运行）和list（查询）默认使用独立爆发模式。爆发宏按专精固定，不按角色天赋或装备调整；训练、页面正式模拟和独立复测都由受控引擎跳过明确未学的技能、被动饰品和空槽，保留完整宏及按键位置。冷却、资源限制仍由引擎判断；未知或无法模拟的动作报错。普通循环仍排除完整爆发宏的内容。需要历史无爆发模式时，对run、check或list显式加`--legacy`（历史模式）；只有该模式保留关闭消耗品的历史规则。`--template`（角色文件）明确指定外部模板，完整内容保存并纳入本次条件。

本次入口修改不等于全库新版训练完成。小规模真实训练到页面的验收独立运行，不进入每次仓库测试；之后需要整库新版成果时再分批处理原材料。

独立爆发训练会从旧登记件和历史成果派生普通循环，按当前固定爆发定义的实际排除范围删除动作，不修改原来源。普通动作块删空，顺序Loop（循环）保持重复次数及剩余块顺序，空体Loop才删除；CastSequence（施法序列）保持原成员顺序与reset（重置），全部成员删除则移除节点，只有一个成员时明确拒绝，不改成普通动作块。没有普通动作或仍含未知动作时明确拒绝。processed（处理记录）的initial_program（初始程序）是派生件；comparison.adaptation（适配说明）保存原程序、删除位置与动作及初始结构核心是否保留。失去核心的派生件只按既有普通历史成果参与入选，原登记家族和核心不变。正常搜索与最终导出仍拒绝残留爆发动作；实际适配语义版本变化后新旧条件分开，旧结果不删除。

每个候选独立搜索，连续两个完整轮次没有确认改善才停止；有确认改善就清零，因此可以超过五轮。每轮最多16候选、每个候选600秒搜索上限和候选总上限保持。无法产生新合法候选也正常结束；预算、候选上限或取消提前结束不算训练收敛，不更新入选库。之后以三个固定独立随机条件复测，成绩代表只在可信提升时替换；不同家族可保留复测过的初始结构，最多4个新增代表。日志起手不自动认定为循环，清洗者需确认核心与回绕含义。

普通搜索在任务初始化时读取一次对应职业、专精、目标数和引擎版本的已入选记录，将符合当前角色动作映射及导出规则的最多4条候选追加在原有4个起点之后；非法动作、重复起点及超出宏文本限制的候选会跳过。此快照写入任务检查点，搜索运行中不会刷新；恢复已有检查点时沿用原快照。候选在真正评分时由原搜索编译流程编译，不另起一次预检查编译。

普通搜索开始时立即登记活动，不等待起点训练。训练开始时若已有普通搜索正在运行就退出；训练期间若普通搜索启动，训练通过同一取消信号停止后补派和全部所属worker的原生进程；保存可靠成果，等待全部所属worker/进程退出后才释放活动锁，并保持旧入选库不变。训练对每个候选分别应用600秒搜索上限，不把整批候选累计成一个600秒总上限；参考模拟、候选搜索和复测都响应同一取消信号。批量运行1和5目标时，两个目标共用同一次训练活动登记。

同批TaskStore共用一个可重入锁协调共享缓存初始化与短事务，报告沿用原发布锁；不持这些锁等待原生计算或异步结果。同请求同时未命中允许少量重复计算，请求数、缓存命中和实际原生启动分别记录；新路径包含搜索与复测，旧可靠记录保留原账本，不冒称已经补录旧复测计数。轨迹按run与请求独立保存，缓存命中保留原轨迹来源引用，不伪造新轨迹；已有可靠报告成绩冲突明确失败，不静默覆盖。

没有新材料时不重复搜索。发布失败时旧库保持，已保存处理结果可重新发布；条件改变时重新评估。处理失败返回非零退出码，用processed（已处理记录）查看原因。暂时不可读的存储不会被当成空库。

日常执行只输出简短状态，不生成报告。运行目录只保留现有任务检查点、完整身份／执行清单和必要临时文件，业务材料、成绩及起点快照通过共享数据中心保存。ABC和全量材料需分别完成验收，不将开发冒烟当作游戏验收。

旧固定五轮规则下，2026-10-08的ABC标准模板验收：三条在1和5目标都完成五轮；两套快照各4条，真实正常搜索均读取到原4条加新增4条。优化后的六条均不再保留登记核心，因此最佳成果归历史搜索，初始结构代表另外保留。重复训练未新增模拟。循环轨迹检查覆盖前两次回绕及后期施放，不能代表原作者复杂宏或游戏实测。

同4起点的三组匹配对照含准备和归档：冷缓存总耗时中位26.344→26.391秒，热缓存40.640→37.313秒，原生批次数及命中数对应一致，未见明显回退。新增4起点首次评分另测约增加1.198秒；候选总配额相同时不能把后续投入变化说成入口提速。

待筛选库是可反复使用的来源库，已处理材料仍保留；list --state pending（查看来源库）不等于本轮未处理队列。实际执行按条件和处理记录跳过已完成项。当前条件下只由可靠完成搜索及六批复测的实际初始表示免重训；最终程序仍参与入选及评分缓存，不替别的起点免训。全量材料与反馈验收见[筛选记录](seed-material-review.md)。

2026-10-09补充：正常搜索的连续完整无改善门槛取初始化后实际有效路径数，原起点和新增代表均计入；重复、非法或评分失败的输入不计入。任何确认改善全局最佳的轮次清零共用计数，起点初始化评分不计搜索轮次。结果search.no_improvement_round_limit（实际停止轮数）及保存后查询返回实际值；config.no_improvement_rounds（原无改善参数）用于训练的两轮门槛，不代表正常搜索当前门槛。

一条路径无法产生新候选时标记并跳过，其他路径继续；独立下一路径位置保存到任务中，取消恢复继续原轮转。所有路径都无候选才按space_stalled（候选空间停滞）结束。门槛在初始化后固定，不因跳过而缩小；其他预算及候选上限保持，所以公平机会仍受这些提前停止条件约束。人工预训练改为每个候选连续两个完整轮次无改善停止；既有起点可用于新任务重新评分，旧规则任务不能原地恢复。下次人工训练由于规则身份变化会重新处理，不在正常搜索中触发。

预训练规则已升级为seed-training-v2（第二版训练规则）。旧五轮处理记录保留原条件，不作为新规则完成证据；下次人工启动训练会按新条件重新处理。正常搜索不会自动重训。此前82份材料的全量成绩仍属于旧五轮规则。

不足16候选的一轮不会增加无改善次数；若该轮确认改善全局最佳，仍清零。正常搜索与预训练共用此判断。

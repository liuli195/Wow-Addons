# 输入控制与饰品执行原型：真实引擎验证结果

对应[任务 8](../../myspec/changes/sim2gse-wayfinder/issues/08-execution-prototype.md)。2026-09-12。**已证明可以在独立 SimC（战斗模拟引擎）内以每 300 毫秒一次输入驱动固定序列，保留原生施放、宠物、装备与伤害计算。** 本次不是界面演示，也不是单独计算技能伤害的替身。

**这证明接入方式可运行，不证明已经准确复现真实客户端，也不证明序列已经优化。任务 8 已按用户确认的原生被动边界结项，下一顺序事项为搜索契约。** 真实输入边沿、排队策略和继承的上游模型限制见文末；本次结项未修改引擎或重新运行搜索。

## 本轮结论与测量

用户原始邪恶死亡骑士装备与天赋保持，单目标、固定 180 秒、单线程、固定随机种子 `20260912`，战斗药水及额外消耗品关闭。每组请求 100 次模拟，上游报告保留 99 个统计样本；原版和改版采用相同规则。

| 运行方式 | 平均每秒伤害 | 结论 |
| --- | ---: | --- |
| 独立原版自由选招 | 79,337.48 | 本次重新构建后的原生对照。 |
| 改版关闭控制器 | 79,337.48 | 完整角色报告逐字段相等，不只比较伤害数值。 |
| 300 毫秒固定研究序列 | 59,465.16 | 原生引擎实际结果；没有执行搜索，不是推荐序列或可达到伤害的上限。 |
| 同序列开启详细轨迹 | 59,465.16 | 开关日志及三次重复运行的完整角色报告一致。 |

固定研究序列为 12 个块、9 种原生主动动作，明确包含开始自动攻击；战前只允许召唤常驻宠物和记录属性快照。具体样例写在[运行检查入口](../../scripts/dev/sim2gse/prototype-engine-check.py)，是本票的研究输入，不是产品技能白名单。正式产品仍须自动生成角色能力清单。

100 次带轨迹运行共记录 **60,000 次输入、14,878 次原生主动执行、10,466 次入队、1,771 次覆盖**；最终执行复查拒绝为 **0**。计数包含上游统计前的首轮，不能直接当作 99 个统计样本的均值。技能替换由原生职业逻辑处理，报告中出现法术 `458128` 的实际执行；研究输入没有把它另列为独立按钮。常驻食尸鬼的原生子动作有实际伤害。

下列时间各取三次进程运行的中位数，含进程启动、模拟和原生报告输出，不含检查脚本之后的解析与断言；三种模式动作量不同，不能据此断言控制器让引擎更快。

| 每组 100 次、每次 180 秒 | 中位耗时 | 请求模拟次数／秒 |
| --- | ---: | ---: |
| 原版 | 0.659 秒 | 151.83 |
| 固定序列 | 0.567 秒 | 176.24 |
| 固定序列与完整轨迹 | 0.667 秒 | 149.96 |

## 如何保证确实测到了引擎

- 两份源码均从散列校验通过的官方 `b845947a34429874433d8e9362326894650dd20a` 归档单独展开到 `.tools/sim2gse/execution-prototype/`。原版和受控版分目录、分程序，没有复制配装器的修改或复用其二进制文件。
- 核对 563 份引擎及构建输入文件：原版无差异；受控版仅修改玩家状态、玩家调度和动作执行三份源码。原生职业、装备、数据表与伤害公式没有改动。差异保存为[可审查补丁](../../scripts/dev/sim2gse/prototype-controller.patch)。
- 本机未发现 CMake（构建工具），本轮采用同一固定源码附带的 Make（构建工具）入口和已有 GCC（编译器）15.2.0，不安装环境。两个版本使用相同参数，关闭联网，输入只读本地数据；此为本地原型构建，不是最终发行选型。
- 按键事件取当前块后推进一次；动作经原生可用性、目标和冷却检查，再进入原生前台或非公共冷却执行路径。详细轨迹分别记录输入、拒绝、排队、覆盖、调度及真正进入原生执行函数的时点，同时记录冷却、符文能量和生命值。
- 原生普通扫描、公共冷却期间扫描、施法期间扫描和施法预选均受控制标志约束；意外进入选招入口会明确报错。测试保留了不应自动执行的默认动作作为检查条件。战前直接执行另设明确边界和日志，避免绕开上述检查。
- 运行前检查最近一次构建成功状态、补丁散列、程序散列。构建失败时拒绝测旧程序；检查开始先将总结果标为进行中，全部断言通过才写通过。

## 决定性样例与结果

本轮完整检查共 25 次引擎进程运行：2 次原版回归、9 个执行样例、9 次性能与重复性运行、5 个拒绝用例。完整检查最终通过。

| 检查 | 实际证据 |
| --- | --- |
| 单技能循环 | 30 秒内恰好 100 次输入，每次相距 300 毫秒；15 次执行，不能把输入数当施放数。 |
| 三步序列中间技能不可用 | 第二次输入在 300 毫秒失败，没有同次自动补放第三技能；第三次输入在 600 毫秒才尝试第三步。 |
| 公共冷却期间连按 | 输入继续推进；窗口外拒绝，窗口内保留候选，到期经原生检查执行。 |
| 新候选覆盖旧候选 | 三技能样例有 8 次覆盖；被覆盖输入的旧候选没有随后再次施放。 |
| 不可用输入保留旧候选 | 6,600 毫秒入队，6,900 毫秒的新动作不可用，旧候选在 6,924 毫秒执行。此为实验采用的策略，客户端尚未确认。 |
| 关闭排队窗口 | 没有入队事件，技能等到之后的有效输入才尝试。 |
| 单主动饰品加技能 | 同刻先执行饰品，再执行技能，整个块只消耗一次输入。 |
| 双主动饰品 | 13→14 和 14→13 两个顺序均测试；首件执行、次件被原生共享冷却拒绝，随后确实能使用第二件；相邻使用至少间隔 20 秒。 |
| 冷却期间触发急速 | 900 毫秒已有技能入队时使用急速饰品；当前公共冷却仍在 1,162 毫秒结束，下次缩短。固定源码中的中途重算调用已注释，不宣称测过中途重排。 |
| 大招自身冷却排队 | 同时等待公共冷却和技能冷却；轨迹证明有自身冷却尚未结束时的入队，实际调度均未早于技能冷却结束。 |
| 明确拒绝 | 越界步骤、被动饰品被当主动动作、带选招条件的动作、同块两个公共冷却技能、引导型饰品均非零退出，核对具体错误信息。 |

双主动饰品用例单独建立装备编号 `270175` 与 `250225` 的测试角色副本，引导拒绝用例使用 `270168`。它们只验证原生饰品执行路径，不作为用户角色成绩。用户原始文件及固定研究序列的装备均未替换。

## 验证中实际发现并处理的问题

1. 职业默认动作初始化会替换自建列表。改为显式提供研究列表及不应被扫描的默认列表，再核对原生初始化后动作数，防止被动或无效动作被删除后步骤索引错位。
2. Windows（操作系统）增量构建中，反斜杠目标名与生成的依赖目标不一致，误走缺少包含路径的隐式编译规则。统一使用上游支持的正斜杠路径变量并明确构建目标，随后重新构建。加入构建成功及散列检查，先前旧程序的试跑不作为最终证据。
3. 选招条件表达式在原型检查时尚未编译，检查表达式指针不能拦住 `if=0`（恒假条件）。改查已解析的原始条件字段，拒绝用例通过。
4. 初版只按公共冷却安排候选，大招自身冷却尚未完成时出现 20 次最终拒绝。改为同时等待两类冷却；重跑后最终拒绝为 0。修正后固定序列从 59,897.36 变为 **59,465.16**，以修正后结果为准，不能选择较高的旧数值。
5. 初始两技能样例先耗尽符文，不能覆盖队列替换；改为包含符文能量技能的三技能样例，实际触发并检查覆盖。宠物伤害证据也按原生报告的召唤技能子动作读取，不能把单独宠物分组里的辅助动作当作全部宠物伤害。

| 原生路径 | 对控制器的约束 |
| --- | --- |
| 玩家就绪事件与普通选招 | 就绪事件会取消已有排队，随后普通选招可能扫描默认列表；不能直接沿用后仅替换一个技能名称。 |

## 结项边界与后续验收

当前实验采用 400 毫秒最大排队窗口、不可用输入不清空旧候选、单一公共冷却候选；还同时遵守原生动作自身的可用性门槛。这些是待游戏对照的模型选择，不能由本模型的自测证明真实游戏也如此。计时输入代表有效点击，原型未在战斗引擎内复现原始按下／松开投递、暂停、跨战斗重置、网络延迟和抖动。施法／引导动作与同块多个公共冷却动作明确不支持，不能据此交付这些能力。

三个被动模型问题的本轮处置：

| 问题 | 当前证据与限制 |
| --- | --- |
| 核心火焰符文 | 原生报告仍提示伤害／治疗目标分流未经验证，固定序列中确实触发，不能当成不影响伤害。模型及警告均保留，未修改假设。 |
| 自我修复符文 | 固定序列全部输入轨迹的生命值均为 100%；这不能证明通用模型已实现，也不能用采样排除所有瞬时联动。尚未完成机制覆盖证明。 |
| 武器附魔 6241 | 保留原始附魔；源码阈值比较与文本疑点尚未用独立实验解释。当前固定输入没有灵界打击，但这不等于所有治疗触发及联动都已排除。 |

用户在结项时明确：这些被动效果由原生引擎自然处理。本项目保持原始装备、天赋、附魔和固定上游实现，不另行修复或重写上述机制。这三项统一处置为继承的上游模型限制，保留原有警告和证据，不加入按键动作，不阻塞固定模型下的搜索实验，也不声称已证明无影响或已修复。我们负责控制器的接入与回归；上游模型准确性审计不再是本票关闭前提。

原生模型文件未改动不等于所有运行行为都已证明正确，故仍保留控制器关闭回归、原生执行轨迹与隐藏扫描检查作为项目自身责任。将来若定位到新增控制器破坏被动事件的证据，必须修复项目回归，不能以“沿用原生”忽略。

正式实施测试交接：T04—T09（输入、失败与队列、饰品）已有上述决定性用例；T10（施法限制）目前只有拒绝分支；T11（关闭回归）与 T12（隐藏扫描）有运行证据；T13（技能替换）已有当前角色分支证据。T15（导出后编译与模拟一致）尚未接通同一产物的完整链路，T16（重置与起始相位）尚未完成战斗引擎与真实客户端对照。完整矩阵与真实游戏验收均不能标记全部通过。

# 游戏实测反馈方案

调研日期：2026-09-13。只读核对本机 GSE（序列插件）3.3.33-a 源码及战斗日志服务官方文档；尚未验证用户本次序列的游戏导入或执行。

## 结论

首轮同时收集 GSE 调试导出和游戏原生高级战斗日志，无需安装新插件。调试记录回答序列尝试了什么，战斗日志回答实际发生了什么。伤害统计截图不能替代原始记录。

## 本机源码证据

游戏插件根目录：`D:/Program Files/World of Warcraft/_retail_/Interface/AddOns/`。

- `GSE/GSE.toc:6`：安装版本为 3.3.33-a。
- `GSE_Utils/Utils.lua:2158`：`/gse debug` 打开调试窗口。
- `GSE_Utils/Events.lua:14`、`:139`：追踪时间、步骤、动作块、序列及版本、技能与法术书匹配、可用性、资源可用性、公共冷却和当前读条。可施放判断不是成功施法回执，资源字段也不是完整数值时间线。
- `GSE_Utils/Events.lua` 的 `TraceSequence`：导出时间使用 `GetServerTime()`，为秒级；不足以精确还原模拟默认的 300 毫秒输入间隔。当前施法查询对游戏保密值有回退处理，不能将空值或缺失行解释为确实没有施法。
- `GSE/API/Storage.lua:2212`：序列点击追踪调用入口。每个追踪动作不能直接等同于动作块内每条命令的成功执行。
- `GSE_Utils/Events.lua:330`、`:335` 和 `GSE_GUI/DebugWindow.lua:1647`：另有成功施法事件驱动的界面标记，但通过最近匹配行关联，找不到匹配还可回退到八秒内的行；导出的旧格式没有独立成功事件字段。因此不能将界面成功标记当作逐按键严格对应证据。GUI 内存有 `createdAt = GetTime()`，当前导出不包含这个高精度时间。
- `GSE_GUI/DebugWindow.lua:4858`、`:4882`：Enable（启用）、Pause（暂停）控制记录；`:4986` 打开导出窗口，`:4947` 提示按 Ctrl+C 复制。`:1999` 导出内存中的调试行，先导出，再重载或退出游戏。

## 收集步骤

1. 在相同装备、天赋条件下重新导出 SIMC（模拟输入），保存从游戏实际使用版本导出的 GSE 字符串，记录本地任务编号。这样可核对导入、编辑或版本选择造成的差异。
2. 游戏设置搜索“高级战斗日志”，启用后输入 `/combatlog`，确认聊天提示为开始记录。此命令是切换状态，避免重复输入反而关闭。
3. 输入 `/gse debug`，清空旧记录，点击 Enable（启用）；若按钮显示 Disable（禁用），表示已启用。正常手动触发目标序列，先试打约 30 秒检查采集，再做完整 180 秒单目标测试。
4. 记录木桩名称/等级、目标数、起止时间、按键方式与标称间隔、延迟、是否移动或手动插入技能、增益和消耗品；初始冷却与资源状态也需说明。不要为了匹配模拟假装手动输入严格等于 300 毫秒。
5. 停止输入后暂停 GSE 调试，点击 Export（导出），按 Ctrl+C 保存原文。另存实际使用序列，不只提供截图。
6. 用 `/combatlog` 停止战斗日志，确认停止提示。日志可能延迟落盘；等候更新，必要时正常退出游戏后读取。日志位于 `D:/Program Files/World of Warcraft/_retail_/Logs/`，按本次修改时间定位 `WoWCombatLog*.txt`，实际文件名以客户端为准。
7. 反馈两份记录和上述测试条件；同机可以直接提供文件路径供只读分析，不必上传公共网站。没有数据时先检查是否启用及写入延迟，不先安装新插件。

原生记录命令也可在仓库同版本界面源码核对：`.tools/wow-ui-source/Interface/AddOns/Blizzard_ChatFrameBase/Shared/SlashCommands.lua:857`；高级日志设置在 `Blizzard_SettingsDefinitions_Shared/Network.lua:17`。

## 对照范围与边界

先检查实际序列版本、动作块和循环顺序，再按成功施法的技能标识、次数、间隔、宠物及派生伤害对照受控序列模拟；最后在相同时间窗口和目标条件下比较总伤害、每秒伤害和技能占比。不要把派生伤害事件重新当作主动按键。

当前模拟默认单目标、固定 180 秒、无自动团队增益及指定消耗品，默认输入间隔 300 毫秒。证据：`projects/sim2gse/engine.py:15`、`projects/sim2gse/sequence.py:63`。实际任务报告优先于默认值。游戏木桩与模拟敌人的等级、护甲和生命阶段可能不同；环境不一致时伤害比例不能证明实现有误。

这两份记录足以做首轮结构、施法频率和伤害差异诊断，但不能保证逐次精确重放所有按键或判定每次未施放原因。秒级 GSE 时间戳无法还原亚秒间隔；战斗日志也不是完整的物理按键及失败尝试记录。若首轮确实需要逐按键时间匹配，再研究最小的高精度输入采集手段，不提前开发或安装采集插件。

随机触发、暴击、延迟与初始状态会导致单次伤害波动，不能要求实测与某一随机样本逐事件相等。先对齐条件并检查结构；需要伤害结论时再做多次同条件测试。

## 官方服务资料

- [Warcraft Logs（战斗日志分析服务）入门](https://www.archon.gg/wow/articles/help/getting-started)：高级日志、`/combatlog` 开关、原始日志目录、木桩日志延迟写入；采集由游戏完成，插件仅能辅助自动开关。
- [Archon（日志服务客户端）官方常见问题](https://www.archon.gg/wow/articles/help/archon-app-help-and-faq)：当前魔兽战斗日志可能在战斗结束数分钟后才写入。网站上传工具是可选分析途径，不是本地采集的前置条件。

这些资料证明采集途径；本次完整日志、调试输出的实际完整性仍需用户试打后检查。

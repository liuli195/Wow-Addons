# 第二阶段保存优化整体验收

最终选择：完整报告每12份保存一组，同时只保存变化的任务字段和归档记录。两项合用在本次整轮实测中最快。

## 同等工作量的整轮结果

四组均完成752次请求、586次实际模拟、166次本轮复用、46988个样本、331次候选编译和662次编译程序启动。逐请求成绩、样本与方差、候选选择、最终成绩和导出文本一致。

| 方案 | 总用时 | 比原版少用 | 减少比例 |
| --- | ---: | ---: | ---: |
| 原版，复用历史实测 | 601.15秒 | — | — |
| 只做报告分组保存 | 401.33秒 | 199.83秒 | 33.24% |
| 只做任务状态保存优化 | 511.84秒 | 89.31秒 | 14.86% |
| 两项合用 | 395.30秒 | 205.85秒 | 34.24% |

报告分组本身已将状态保存次数从2039次降到174次。状态优化在此基础上再省6.03秒，因此两项单独收益不能相加。

预算、输入、随机条件、诊断设置及样本规则保持原值；测量脚本只在达到历史工作清单时停止，不增加请求、不缩减样本，也不改变生产停止规则。新版正常运行仍使用原600秒预算。

历史整轮直接使用公开任务程序；新版三组通过页面请求入口包装同一个任务程序。历史源码、存储代码、引擎身份和285个起始数据文件均已核对一致。历史及新版整轮各一轮，未强制清空系统缓存；这是本次工作量的实测比较，不是所有环境的固定收益承诺。

## 相同页面请求入口的三轮交替对照

另用同一段81次模拟、8167个样本、36次候选编译、72次编译程序启动的工作，四组各跑三轮并交替顺序。每轮成绩、样本、方差、候选、导出及起始数据核对通过。

| 方案 | 三轮用时，秒 | 中间值，秒 |
| --- | --- | ---: |
| 原版 | 74.48、74.19、74.22 | 74.22 |
| 只做报告分组 | 60.75、60.71、60.83 | 60.75 |
| 只做状态优化 | 73.12、73.06、72.97 | 73.06 |
| 两项合用 | 61.15、60.83、60.90 | 60.90 |

小工作量下组合比分组单独多约0.15秒；在较大整轮中，组合少6.03秒。最终选择依据整轮结果。

## 读取、字段与故障恢复

同一批新生成、开启完整诊断的报告，按相同查询条件读取。完整十二份读取各一轮，其余每组取三轮中间值；结果清理放在计时之外。这个数据量与第一阶段早先的报告样本不同，不能直接横比当时的绝对时间。

| 读取方式 | 原版，秒 | 组合，秒 |
| --- | ---: | ---: |
| 单份完整报告 | 0.113 | 0.137 |
| 单份指定字段 | 1.053 | 0.767 |
| 十二份完整报告 | 34.199 | 25.647 |

单份完整报告增加约25毫秒，其他已测方式更快；深层嵌套字段查询仍较慢。两边1263个末端数据字段及类型一致。另逐字段比较十二份完整报告，游戏数据一致；只有每次运行自然不同的时间戳和四个实际运行耗时字段变化，字段本身仍保留。

同一页面任务入口已覆盖完整组、尾组、正常取消、预算停止、保存失败、旧格式恢复、保存后未登记、坏组恢复、不同任务目录并发、位置清单丢失或截短，以及多组部分提交后强停。已保存结果不重复生成逻辑记录；未保存成绩不能成为恢复时的有效赢家。强停允许重算未保存组，正常停止保存尾组。

最终代码本机统一验证通过：320项测试、102项附加检查，以及文档和测试登记检查。存储技能本机检查通过，含13项存储检查和真实安装入口冒烟。两位独立审查使用用户指定模型及高思考强度，修复后无阻塞。没有进行实际游戏客户端验收。

# 领域文档

工程技能在调查代码库时，应按以下规则使用本仓库的领域文档。文档集中在 `docs/`。

## 调查前阅读

- `docs/CONTEXT.md`（领域词汇表）
- `myspec/specs/` 中与当前工作相关的规格
- 涉及装备规划器时，同时读取现有[装备规划器领域术语](../gear-planner/CONTEXT.md)

规格代替架构决策记录（ADR）：正式规格保存在 `myspec/specs/`，是存在过的规格；决策、取舍与已否决的候选做法一并记在其中，本仓库不另设 `docs/adr/`。

如果这些文件不存在，直接继续，不要报告缺失，也不要预先建议创建。只有在领域术语或规格确实得到确认后，才创建领域文档。

## 文件结构

本仓库采用 single-context（单上下文）布局，文档集中在 `docs/`：

```text
/
├── addons/
├── docs/
│   └── CONTEXT.md
├── myspec/
│   ├── specs/
│   └── changes/
├── projects/
├── scripts/
└── tests/
```

## 使用词汇表中的术语

当输出需要命名领域概念时，例如问题标题、重构建议、假设或测试名称，应使用 `CONTEXT.md` 中定义的术语，不要改用词汇表明确排除的同义词。

如果所需概念尚未出现在词汇表中，应先确认是否正在创造仓库并未使用的新术语；若确实存在缺口，则交由 `/domain-modeling` 处理。

## 标明规格冲突

如果输出与现有规格冲突，必须明确指出，不得静默覆盖。

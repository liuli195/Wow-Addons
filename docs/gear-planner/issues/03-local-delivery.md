## 问题

在确认数据来源、许可和计算依赖后，选择能本地运行的最小网站结构、启动方式、数据更新方式与缓存边界；是否允许使用时联网获取未缓存装备？将网站放在本仓库哪个独立目录，如何复用验证入口且不干扰现有插件？

浏览器保存、文件导入导出、无账号与不要求公网部署已经确认，不重复询问。不能将“本地运行”擅自解释为“完全离线”或“允许使用外部服务”。

## 讨论记录

2026-09-08：用户授权开展本事项，主代理领取。按路线规划、决策问答和领域建模技能核对现有环境，提出本地启动、数据获取和更新方案；用户尚未作出的选择不写作已确认。本轮只形成规划决议，不实施网站或安装依赖。

第一轮用户明确选择：首次下载所需程序和公共数据，日常用缓存，缺失中文名称或公共物品资料自动联网补充；角色导出和配装留在本机。使用仓库内双击启动脚本打开浏览器，不制作独立安装包。

第二轮用户明确选择：启动检查新版，由用户点击后更新；已有方案统一使用新版，重算前提示。用户没有选择逐方案保留旧引擎版本或升级时强制另存。

## 结论

2026-09-08：四项用户决策完成，本事项关闭。以下为据此确定的最小本地方案；仅记录规划，不实施网站、安装依赖或启动常驻服务。

### 本地运行

- 网站位于仓库根目录 `gear-planner/`；文档继续在 `docs/gear-planner/`，启动与数据更新脚本位于 `scripts/dev/`。提供仓库内双击入口，启动本地服务并打开浏览器；不制作安装包，不设开机自启。
- 浏览器页面通过轻量本地服务调用原版模拟器。优先复用已核实的仓库 Python 3.12.10 与标准库、原生网页能力；当前没有需要复用的现成网站项目，不先添加大型框架、数据库或独立网页构建链。
- 服务只监听本机回环地址，使用固定访问地址与端口，保持浏览器保存空间稳定。端口占用时明确报错，不静默切换地址；提供明确关闭服务的方式。具体端口在实施时检查占用后固定，无需用户选择端口号码。
- 角色与配装留在本机。服务校验来源、请求大小及字段，仅构造受控的模拟器输入，限制计算时间，不把导出文本作为可控制文件、命令或网络来源的任意配置执行。

### 数据获取与缓存

- 首次下载经核实的计算程序和公共数据；日常优先使用本机缓存。缺失中文名或公共物品资料可自动联网补充，仅查询必要的公共物品信息，不上传角色导出或整份配装。
- 工具及版本化属性数据位于 `.tools/gear-planner/`，公共名称缓存、临时工作文件和诊断位于 `.local/gear-planner/`。浏览器保存多个方案，文件导入导出用于备份与转移，沿用已有决定；不把临时诊断当方案主存储。
- 计算程序、装备属性数据、构建和热修复组成一个已核对的计算版本；名称资料可独立补全。自动补充物品属性必须匹配当前计算版本，无法匹配时保留输入并显示缺失，不混入其他版本的值。研究缓存不自动视为正式分发资源。

### 更新与已有方案

- 启动时非阻塞检查更新，发现新版后提示，由用户点击更新。没有网络时仍可使用完整缓存；首次缺少必要程序或数据时明确说明尚未准备完成。
- 更新仅限已支持的 12.1 第二赛季。新组合先完整下载、核对来源及内容校验、检查程序与数据版本并运行基线检查；热修复造成合理数值变化时需要解释和更新验收基准，不简单沿用旧数值断言。失败不切换，继续使用最后可用组合。
- 所有方案统一使用当前已启用的新版计算，不为每份方案维护可执行的旧引擎。记录计算版本用于追踪，不代表方案锁定旧版本。
- 切换新版后，重算前提示哪些方案或结果受影响，保留装备配置本身。尚未重算的旧结果明确标注为旧版结果；重算成功后更新结果及版本信息，失败保留原配置并显示原因，不把部分结果覆盖为完整新结果。版本变化不是强制另存新方案的理由。

### 后续实施与验收衔接

- 接入仓库现有构建与验证入口；新增规划器检查按目录选择，不干扰插件检查。当前文档检查仅覆盖顶层文档，需要补充规划器文档与功能检查，不能借现有检查通过宣称网站通过。
- 中文缺失、特殊物品变体、计算精度与重算失败的展示和支持标准，继续在[准确性验收与不完整数据的支持边界](04-accuracy-contract.md)中明确；本事项不提前替代该讨论或原型验收。

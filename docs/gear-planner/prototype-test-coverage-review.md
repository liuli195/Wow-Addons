# 原型测试覆盖审查

日期：2026-09-09。范围：当前 `.local/gear-planner-prototype/index.html`、`server.py`、25 个现存检查脚本及已确认需求。审查不修改产品实现、不修改浏览器方案、不启动正式开发；新增隔离缺陷复现脚本与本报告。

## 结论

没有完整覆盖。现有检查偏向鲜血样本下的后端计算、编辑规则与目录元数据；页面状态流转、持久化异常、真实浏览器操作及全量变体覆盖不足。原型交互获用户认可，不等于测试验收完成。

本次逐一运行 25 个脚本，23 通过、2 失败，合计约 105 秒。[逐脚本日志](../../.local/gear-planner-prototype/coverage-review-run.json)。这是脚本通过数量，不是功能覆盖率、分支覆盖率或游戏准确率；当前没有可据以量化这些覆盖率的采集结果。

仓库标准验证执行 `build-and-verify verify --project .`，仅选择文档检查，通过的是 6 份文档的编码、围栏与示例。配置没有接入原型脚本，不能将该通过结果当作原型功能门禁。

## 优先发现

### 高：普通保存失败仍覆盖内存中的已保存方案

`index.html` 的普通保存处理器先替换或追加 `builds`，再尝试写入本地存储；写入失败后只提示，没有恢复内存记录。故本次页面会把未落盘配置当作已保存记录使用，与刷新后的状态不一致。另存为的失败保护不能证明普通保存安全。

通过提取当前真实处理器、隔离模拟存储失败已复现；没有修改用户实际存储。复现见 [隔离探针](../../.local/gear-planner-prototype/audit-coverage-probes.js)。应补普通保存的新增、覆盖、失败后重选、刷新恢复检查。

### 高：护甲边界错误没有被现有计算检查拦住

当前 `fmt` 零位格式化将 3347.586 显示为 3348，而游戏已实测 3347；当前差异计算也使用原生小数相减。隔离探针验证的是页面真实格式化函数。已有后端检查多关注属性原值，对页面护甲与比较没有边界断言。正式任务已记录修复，但当前尚未修复。

### 高：两个全量相关脚本已经过期

- `check-catalog.py`：本次遍历 350 项，322 项未满足其断言；脚本仍假设替换后为 334 或制作 331 等默认高装等，而当前要求保持原装备等级。例如实际保留 311 却期望 334。部分项还会触发后来新增的装等确认要求。因此不能把 322 解读为 322 件装备错误；也不能把旧的目录通过报告当作当前有效保障。
- `check-levels.py`：在替换“守毒者的骇人兜帽”时因 311 不可用、需确认 308 而退出；尚未完成后续全量遍历。应按当前合法替换规则构造输入，然后覆盖所有目录产品与合法装等，而非删除失败断言。

### 中：部分通过测试未执行当前实现

- `check-build-names.js` 自行复制名称函数，并检查已取消的自动“副本”命名行为。
- `check-delete.js` 自行复制旧删除处理器，未覆盖当前删除最后一份方案后清空状态的分支。
- `check-empty.js` 自行复制旧清空逻辑，还含已删除的演示及耗时元素。
- `check-summary.js` 自行复制摘要函数；修改当前页面摘要不一定让它失败。
- `check-sets.py` 校验已有 `set-effects-check-results.json` 报告，而非从当前缓存到当前页面重新验证全专精套装显示。

这些脚本本次均通过，但不足以证明当前对应功能正确。应优先调用真实实现，避免维护两份业务逻辑。`check-save-as.js` 与 `check-stat-filter.js` 已采用提取实际处理器/函数的方式，但仍使用局部替身，不是完整浏览器流程。

### 中：缺少可重复的浏览器完整流程和异步异常检查

当前脚本没有从真实页面完成“导入 → 替换 → 修改 → 保存 → 重载 → 对比 → 导出 → 文件再导入”的自动化闭环。历史浏览器手工检查可作辅助证据，但本次没有重新执行全部历史交互，也未确认导出文件落盘后再导入一致性。

缺少网络中断、计算超时、请求乱序、连续导入/切换、对比请求过期、原装备合并迟到响应、关闭/取消对话框后状态保留的系统检查。存在请求序号代码不等于其行为已经测试。服务端请求来源、令牌、大小限制有实现，但现有脚本主要直接调用函数，缺少真实 HTTP（网络请求）边界回归。

## 正式开发前的处理建议

1. 先修复普通保存失败和护甲显示/比较，并让当前实现的回归检查拦住这两个问题。
2. 更新两份过期目录/装等脚本，替换四份复制旧逻辑的检查，套装从当前数据验证；不以放宽断言换取通过。
3. 补一条隔离浏览器完整闭环，加入最后方案删除、取消、文件往返、请求迟到和保存失败等关键分支；不使用用户真实方案作为可写测试数据。
4. 把这些检查接入正式项目的统一验证入口。完整属性拆分、全角色适配、数据更新、性能与跨角色真实游戏核验作为正式开发验收项继续追踪。

本次只完成覆盖审查与缺陷复现，不声称上述修复或补测已完成。

## 修复与补测（2026-09-09，按用户授权实施）

以下为审查后的变更，前文审查结果保留为历史证据。

- 普通保存先构造新记录并写入成功，再更新内存、当前方案及保存状态。新增/覆盖保存失败均保留原已保存记录；当前编辑仍可导出。局部真实处理器测试及独立浏览器存储故障注入均已覆盖。
- 新增角色面板数值转换，仅护甲使用当前游戏样本支持的截断；保留计算结果原始小数，比较采用双方转换后的面板值之差。验证三个真实样本、空值、差值 +102 及非护甲属性不被截断。此范围不证明全职业护甲规则。
- 删除名称、删除、空状态及装备摘要测试中的旧业务逻辑副本，改为提取当前页面实现执行；自动副本命名的废弃测试移除，最后方案删除清空的当前分支已覆盖。
- 目录测试按当前保留装等规则核对，并在不兼容时验证明确的替代等级；合法装等测试处理相同确认流程，保留全部 471 件成品选项检查、107 个原生计算变体样本。套装测试改为读取当前服务的 65 件套装成品效果，核对所有记录中的 40 个专精，不再把历史检查报告当数据来源。
- 实际浏览器测试采用全新、用后关闭的临时浏览器上下文，不读写用户浏览器配置。验证真实导入、替换、合法装等、宝石和附魔变更、保存、另存为同名拒绝及取消、刷新重载、比较、下载落盘再导入一致性、删除取消和最后方案清空、保存失败后重选旧记录，以及不匹配筛选项置灰仍可点。
- 浏览器测试发现启动初始化尚未完成就能点击导入，导致令牌未就绪；已让导入入口在初始化完成后启用。该流程随浏览器测试回归。
- 对当前真实异步函数注入乱序响应，验证计算、比较、原装备合并均忽略迟到结果，编辑请求失败保留先前结果。真实请求错误边界、全量超时情况仍不能由这些局部替身全部替代。

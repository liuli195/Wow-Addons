# 准星 HUD 圆弧四边毛刺调查

调查日期：2026-10-03；整理日期：2026-10-04。范围为血条、能量条和凝固之血条的图片轮廓、缩放采样与移动填充切口。本文件保留当时的观测，不把历史测试参数当成当前实现。

## 最终结论

10倍导出保留了原图细节，但不能单独保证游戏缩放后的边缘平滑。图片静态轮廓与游戏实时产生的填充切口是两类问题，应分别检查。采用完整逐级缩小贴图后，用户的同屏对照反馈更好；随后选择统一柔和遮罩，并将遮罩渐隐宽度减半。用户于2026-10-04确认当时部署版本的游戏验收通过。

没有取得游戏内部采样器的抓帧证据，不能把全部毛刺归为一个已证明的唯一原因，也不能宣称所有分辨率或图形后端均已验收。

## 两类边缘为什么要分开

1. **图片四周轮廓**：游戏把高分辨率图片画到较小区域时，一个屏幕像素可能覆盖许多原图像素。提前平均生成的小尺寸图片有助于稳定显示细边缘。仅有2的幂尺寸或请求平滑过滤，不能证明文件内已经保存完整缩小图层。
2. **移动填充切口**：血条、能量条、职业资源使用旋转遮罩；凝固之血使用游戏原生圆弧进度条。切口是显示时产生的，静态图片平滑并不保证切口同样平滑。两种绘制方式的柔化参数不能直接当作同一单位比较。

早期原生圆弧柔化值约0.00275，接口说明只描述“数值越大过渡越缓”，没有给出与屏幕像素的精确换算。因此把该值解释成固定设计单位，是候选估算，不是暴雪官方定义。

## 来源与证据边界

- [Microsoft纹理过滤说明](https://learn.microsoft.com/en-us/windows/win32/direct3d9/texture-filtering)：支持缩小时预先平均和过滤的通用原理，不能单独证明魔兽当前加载器的行为。
- 仓库固定的暴雪12.1界面资料：`SimpleTextureBaseAPIDocumentation.lua` 的 `SetTexture`（设置贴图）接受过滤模式，`SetRadialProgressBarFeather`（设置圆弧移动切口柔化）描述过渡强弱；`Blizzard_MapCanvasDetailLayer.lua` 使用 `TRILINEAR`（相邻缩小图层之间的平滑过滤）。固定版本见[版本清单](../../scripts/dev/versions.json)。这证明公开接口和地图调用方式，不证明外部PNG图片自动生成缩小层。
- [BLP格式维护者说明](https://skarndev.github.io/wowlib/python/blp/)：BLP2（魔兽贴图格式第二版）支持多个缩小图层及独立透明度保存。
- [Pillow图片库的BLP实现](https://github.com/python-pillow/Pillow/blob/main/src/PIL/BlpImagePlugin.py)：当时本机直接保存路线只有基本层，不能用“保存成功”代替完整图层检查；当时试制文件还存在独立透明度回读不一致问题，未作为正式成品采用。该记录不代表所有未来版本的图片库都存在相同限制。

没有找到一手证据足以断言魔兽加载外部PNG图片时一定没有缩小层，也没有证据证明“2的幂尺寸加平滑模式”必定自动生成缩小层。

## 最后采用的处理

保留设计原图和10倍PNG（透明图片格式）导出；按原加工方式生成2的幂成品，正式图片保存完整缩小链，主体与配套材质统一请求平滑采样。血条、能量条、职业资源共用半宽渐隐遮罩；凝固之血仍由原生圆弧进度条绘制，不称两种切口完全相同。

详细比较见[缩放方案研究](crosshair-hud-texture-sampling-comparison.md)，生产入口见[素材生产说明](../../assets/CrosshairHUDMedia/README.md)，分日期验收及最终状态见[实施与验收记录](../../myspec/changes/crosshair-blood-dk-features/validation.md)。刚补的原生绑定自动恢复小修复尚未重新部署，不能由用户对此前部署版本的验收反推该修复已实机通过。

# 仓库素材生产流程

## 使用范围

本流程默认用于准星HUD及以后新增的白色可染色界面素材：主体、背景、填充、阴影、遮罩、刻度。
颜色和透明度由插件配置控制；图片只保存白色与透明度。
彩色照片、图标及其他插件已有素材不直接套用本流程，不为统一格式改掉它们。

## 原图从哪里来

当前主体和阴影读取已确认Figma原稿的10倍PNG导出；遮罩、刻度由脚本生成，
居中填充由主体原像素平移生成。不读取归档中的旧SVG（矢量图片）：
旧血条、能量条SVG线宽仍为6，与当前7.8不一致。

新的SVG可以作为将来的生产来源候选，但须先核对几何、阴影和转换效果。
SVG能按目标尺寸重新生成像素，少一次图片缩放；不保证一定比高分辨率PNG好。
无论来源选哪种，游戏成品仍须经过本流程的完整缩小层、文件检查和实机验收。

## 固定流程

1. 保留设计原稿；准星素材沿用10倍导出，背景透明，不裁掉内容和阴影。
2. 在`assets/CrosshairHUDMedia/manifest.json`登记文件、显示尺寸、内容尺寸和圆心偏移。
   预览单位和设计单位按现有换算核对；不得把10倍导出与成品密度混为一谈。
3. 用现有加工脚本生成白色透明PNG（用于核对的图片）。对称补透明边到2的幂，保留原图形和位置。
4. 用现有构建入口生成BLP2（游戏材质文件）。原始层透明度保持不变；每层平滑减半，
   宽高分别减半，直到1×1。512×256等矩形也必须生成完整层级。
5. 游戏使用BLP成品和TRILINEAR（在相邻尺寸层之间平滑取样）。主体、背景、填充、
   阴影、遮罩和刻度都遵循这个标准；像素对齐、角度、线宽和位置不由素材构建擅自调整。
6. 文件检查通过后部署测试；游戏验收通过才算完成。

## 准星素材的标准设置

| 项目 | 标准 |
|---|---|
|设计原图|保留10倍透明导出，不覆盖原定稿|
|加工密度|读取清单中的`exportScale`，目前每设计单位8像素|
|画布|宽高分别为2的幂；方形或矩形按现有摆放清单|
|游戏格式|BLP2，颜色表模式1，独立8位透明度，格式提示8|
|缩小层|完整保存到1×1；使用现有Pillow（图片处理工具）的BOX（区域平均缩小）|
|颜色|可见像素保持纯白，不把透明度乘进颜色，不做彩色量化|
|原始层|与PNG核对图透明度逐像素一致|
|保存方式|PNG核对图保留；游戏读取同名BLP|
|版本管理|BLP与其他图片一样采用Git LFS（大文件保存方式）|

BLP保存适配器为`scripts/media/white_blp.py`，只负责白色模板的标准文件布局。
缩小算法复用已有图片工具，不引入新的缩放算法或额外转换软件。
依据：[BLP格式实现](https://skarndev.github.io/wowlib/python/blp/)、
[逐级缩小原理](https://learn.microsoft.com/en-us/windows/uwp/graphics-concepts/texture-filtering-with-mipmaps)。

## 操作入口

重导或新增原图时先加工，再构建、检查；只是从现有核对图重建游戏成品时不必重复加工：

```powershell
.venv/Scripts/python.exe scripts/media/prepare_crosshair_media.py
.venv/Scripts/python.exe scripts/media/build_crosshair_media.py
.venv/Scripts/python.exe scripts/media/verify_crosshair_media.py
```

这些脚本已接入仓库原有构建与验证配置，日常遵循仓库统一入口。
本轮按用户要求暂时单独运行，不调用统一入口。生成测试已加入准星检查项。

新增主体在清单登记后自动生成对应BLP；有特殊居中填充或遮罩的素材，还须在构建脚本
登记生成规则。同步游戏的尺寸、偏移与加载名称，由摆放测试检查两边一致。
新素材必须加入同一份清单和检查，不能只把一张图片复制进游戏目录。

## 自动检查必须覆盖

- 原图倍率和尺寸、加工后的画布、白色模板、透明度、轮廓和摆放。
- 游戏文件格式编号；缺失、多余、损坏或截断的缩小层。
- 原始层与PNG一致，每一级的尺寸、白色和透明度符合生成规则。
- 矩形素材的完整缩小层、错误格式拒绝，以及插件真实加载名称与摆放。

这些检查不能替代游戏实际显示。仅“本机能读回”不算游戏兼容通过。

## 游戏验收与回退

同一对照页检查1080p、1440p、4K；准星0.5、1、2倍；完整图和10%、50%、100%填充。
检查内侧、外侧、两端、短进度末端、阴影接缝、颜色与透明度。
不同分辨率未测试时记录未测试，不写“全部兼容”。

部署前保存本次会覆盖的游戏文件及校验摘要；不改游戏存档。新增或替换材质后完全退出游戏再进入，
避免旧图片缓存影响判断。失败时按备份恢复插件文件和加载方式；源图、PNG核对图都保留。
构建先在暂存目录完成所有生成和文件检查，原图错误时不会先清空现有成品。

## 不能写成结论的说法

- “2的幂＋平滑参数就保证没有毛刺”：还必须存在正确的缩小层，并检查实际游戏效果。
- “HUD调到2倍就是放大原图”：取决于图片实际占用的屏幕像素。
- “暴雪官方公布非2的幂绝对无法使用缩小层”：本轮未找到该官方说明。
- “17号完整图通过，所以所有填充端头都通过”：端头还受到遮罩或原生裁切影响。

2026-10-03：用户认可17号完整缩小层观感，并授权接入生产流程。
当前标准已实现；所有正式组件及其他分辨率的游戏验收仍需逐项记录。

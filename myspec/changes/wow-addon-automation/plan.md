# 魔兽插件调试与测试效率提升 实施计划（落地方案）

本文件是[自动化测试与调试配套方案研究](../../../docs/wow-addon-automation-research.md)的落点：把研究结论按**投入产出比**排成可施工的顺序。研究本身是案头核查（2026-09-17），**未安装、未实测任何候选工具**——因此本计划里每一项都标了"确定性"与"前置验证"，不要把研究结论当成已验证的事实。

- 覆盖范围：`MYUI_CrosshairHUD`、`Sim2GSEProbe`、仓库级调试基建
- 目标客户端：实际安装为 **12.1.0.69814**；仓库锁定值 69587 已过期（见第 7 节）
- 不在范围内：游戏内全自动闭环——研究已确认它在合规前提下不存在，本计划不尝试

**流程说明**：按[本地任务跟踪约定](../../../docs/agents/issue-tracker.md)，一项变更应包含 `spec.md`（需求）与 `issues/NN-<slug>.md`（票据）。本文件先只产出**方案**；待用户授权实施时，再据此拆出需求与票据，按开发流程逐票施工。

---

## 1. 排序总览

排序依据不是"哪项能力最强"，而是 **(确定性 × 收益) ÷ 投入**。确定性低的大项目一律靠后。

| 序号 | 项目 | 投入 | 收益 | 确定性 | 谁做 |
| --- | --- | --- | --- | --- | --- |
| **P1** | SavedVariables 读取器 | 小 | **大**（地基） | 高 | 代理 |
| **P2** | 安装 BugGrabber（报错自动落盘） | **≈0** | 中 | 高 | 用户授权部署 |
| **P3** | 聊天捕获插件（自研，落盘 print／`/dump`／报错） | 小 | **大** | 高 | 代理 |
| **P4** | 受限上下文强制复现流程 | 小 | 中高 | 中（需实测） | 代理出步骤，用户执行 |
| **P5** | 探针自动起停 与 `/chh` 报告落盘 | 中 | 中 | 高 | 代理 |
| **P6** | 控件几何断言试点（模拟器） | **大** | 中（但不可替代） | **低** | 代理，**须先过 G2** |

**P1 与 P3 是核心**：它们把"用户贴给代理"变成"代理自己读"。P1 是一切的地基——没有它，后面落盘的数据也没人读。

## 2. 各项详解

### P1 · SavedVariables 读取器

**目标**：代理能直接读取游戏落盘的保存变量，不再需要用户手动找文件、复制、粘贴。

**现状**：仓库里**没有任何**读取 SavedVariables 的代码（全仓检索只在 `projects/sim2gse/README.md` 命中，那里写的是人工拷贝步骤）。而 `Sim2GSEProbe` 已经在 `/reload` 时落盘了——**闭环缺的只是读取端**。

**改动**：

| 文件 | 内容 |
| --- | --- |
| `scripts/dev/read_savedvars.py` | 定位 `_retail_/WTF/Account/<账号>/SavedVariables/<插件>.lua`，用 `.tools/lua-5.1.5/src/lua.exe` 把文件当 Lua 加载、序列化为 JSON。**只读，绝不写入游戏目录** |
| `tests/dev/test_read_savedvars.py` | 喂手工构造的样例文件，断言解析结果（纯离线） |
| `.build-and-verify/config.json` | 登记为一条本机验收——它依赖本机游戏路径，**不进 CI** |

**为什么用 `lua.exe` 而不是正则**：仓库已有可用的 Lua 5.1 解释器（`.tools/lua-5.1.5/src/lua.exe`，本机实测 `-v` 正常）。已知的唯一同类工具用正则近似，作者自述 "we don't have a real Lua parser here, so we approximate"。用真解释器解析是严格更优的做法。

**验收**：喂入样例文件得到预期 JSON；喂入缺字段／畸形文件时报错而非静默返回空。

**风险**：低。不触碰游戏文件，不依赖外部工具。

---

### P2 · 安装 BugGrabber

**目标**：报错自动落盘，配合 P1 形成"出错 → 用户按一次 `/reload` → 代理读文件"。

**现状**：开发流程文档推荐了 BugGrabber 与 BugSack，但**游戏目录里一个都没装**（已核实，只有 `DialogueUI` 与 `EllesmereUIChat`）。

**改动**：把 BugGrabber 装入 `_retail_/Interface/AddOns/`。**BugSack 可选**（它只是给人看的界面）。

**收益边界（必须说清）**：BugGrabber 只抓**显式报错**。准星 HUD 的五个实机失败里，四个是静默错误、一个被自己的 `pcall` 吞掉——**它一个都抓不到**。它是兜底网，不是主力诊断。

**前置（G3）**：需确认其 `.toc` 支持接口号 120100。装上后故意制造一个报错，确认能被记录并落盘。

**流程**：部署到游戏目录需按[协作指南](../../../docs/wow-addon-development-guide.md)单独授权，不进入常规验证。

---

### P3 · 聊天捕获插件（自研）

**目标**：用户在游戏里敲的 `/run print(...)`、`/dump` 等临时探针输出自动落盘——**这是目前最高频、最痛的摩擦**。

**为什么自研**：研究确认**没有现成插件做这件事**。

- `/chatlog` 抓不到：它捕获 `CHAT_MSG_*` 事件，而 `print()`（`Blizzard_PrintHandler.lua:66-72`）与 `/dump`（`ChatFrameSetup.lua:21-23`）都是**绕过事件直接调 `DEFAULT_CHAT_FRAME:AddMessage`** 的旁路调用，`AddMessage`（`ChatFrame.lua:35-41`）是终点 sink。
- DevTool（`brittyazel/DevTool`）已归档，`.toc` 只到 `120000`，不支持 12.1，且无导出能力。
- BugSack 只收报错，其 "chat" 选项是**输出提醒**不是捕获。

**做法**：暴雪留了四个**官方扩展点**（源码确认，且暴雪自己在用），不需要任何 hook 技巧：

| 钩子 | 拦截范围 | 出处 |
| --- | --- | --- |
| `setprinthandler(fn)` | 全部 `print` | `Blizzard_PrintHandler.lua:74-80`（暴雪自用于 `GlueParent.lua:902`） |
| `DevTools_AddMessageHandler(fn)` | 全部 `/dump` 输出（多播列表） | `Dump.lua:81-83` |
| `DEFAULT_CHAT_FRAME.addMessageObserver` | 一切进默认聊天框的消息 | `ChatFrame.lua:38-40`（TTS 在用） |
| `AddLuaErrorHandler(fn)` | Lua 报错 | `Blizzard_ScriptErrors.lua:66` |

**三个必须处理的坑**：

1. `setprinthandler` 与 `addMessageObserver` 是**单槽位**——必须链式转发给原处理函数，否则会破坏暴雪自己的 GlueParent 与 TTS。
2. 必须设**环形缓冲上限**，否则 SavedVariables 会被日志撑爆。
3. **`/etrace` 与 `/fstack` 收不到**——它们的输出只进自己的 UI 窗口，没有重定向钩子。替代做法是用 `/run` 探针注册事件后 `print`，那些 `print` 能被捕获。

**验收**：敲 `/run print("x")`、`/dump GetBuildInfo()`、故意报错各一次 → `/reload` → 代理能从落盘文件里读回三条。

**风险**：链式转发写错会破坏暴雪原生功能——必须有回归测试覆盖"转发到原处理函数"这条。

### P4 · 受限上下文强制复现流程

**目标**：把"只能在副本／PvP 里偶然撞上受限上下文"变成"随时可复现"。

**为什么值得**：准星 HUD 五个实机失败里最贵的两个（①血弧符能弧在受限上下文是秘密值；⑤秘密令牌不能当表键）根因都是受限上下文，而**离线工具原理上验不了**（模拟器用宽松桩）。这是唯一能压缩这类成本的官方手段。

**做法**：12.0 起客户端提供 6 个 `addon*RestrictionsForced` CVar 可手动强制受限上下文（重启不保存），配套 `C_Secrets` / `C_RestrictedActions`。产出一份"如何进入受限上下文并观察"的步骤文档。

**前置**：需实测确认 12.1 上的实际行为（研究阶段只读了源码，未实测）。

**边界**：它减少的是**撞见缺陷的等待时间**，仍由人工执行，不把验收变成自动。

---

### P5 · 探针自动起停 与 `/chh` 报告落盘

**目标**：用户的游戏内操作从"敲若干命令"降到"按一次 `/reload`"。

**现状与改动**：

| 插件 | 现状 | 改成 |
| --- | --- | --- |
| `addons/Sim2GSEProbe/Core.lua` | 需敲 `/s2gprobe start`、`mark`、`stop` | 进战斗自动 `start`、离开战斗自动 `stop`；斜杠命令**保留**作手动覆盖 |
| `addons/MYUI_CrosshairHUD/Core.lua` | `/chh` 的 `Report()` 只打印到聊天框 | 同一份数据**同时写进** `MYUI_CrosshairHUDDB` |

**前置**：必须先定探针以哪一版为底（见第 7 节）——`Core.lua` 绕不开这个选择。

**流程**：按开发流程走 TDD，并为两项改动登记进 `.build-and-verify/config.json`（否则 `tests/dev/test_inventory.py` 会拦截）。

**边界**：秘密值不能存进 SavedVariables（无法序列化），因此诊断记录只能是"类型／是否取到"，不能是数值。现有代码已经这样处理（`SafeScalar` 返回 `"unavailable"`），不冲突。

---

### P6 · 控件几何断言试点（模拟器）

**目标**：补上唯一**无替代品**的一层——"控件到底落在哪"（x/y/宽/高，±1 像素）。

**为什么排最后**：投入大（须自建 12.1 镜像）、确定性低（前提未验证）、且**不能替代实机验收**。

**已知限制**：

- 已发布产物停在 12.0.x 线，**没有 12.1 标签**；源码默认构建已是 12.1/120100，但须自建并推送镜像，`@master` 走不通。
- **没有像素比对**——全仓无 golden image，截图是有损 WebP，且镜像里不支持 `screenshot`。外观类问题验不了。
- **秘密值是宽松桩**，跑绿不能证明受限上下文正确。
- 不加载 SavedVariables。
- 采用度接近零：真正 `uses:` 它的只有作者自己的示例仓库。

**前置（G2，硬门槛）**：准星 HUD 硬依赖 `EllesmereUI` 与 `MYUI`。**这两个能否在模拟器中加载成功未经验证。不通过就停止本项**，不要先投入自建镜像。

**验收标准**：能加载真实插件、能验证一个实际行为、**故意改错后测试会失败**。三条不齐不算接入。

## 3. 候选池（本版不做，条件成熟再议）

| 项目 | 为什么暂缓 |
| --- | --- |
| 性能预算检查（离线统计控件 API 调用次数对照预算） | 收益真实但低于 P1–P5；能抓"误加每帧轮询"，不能证明真实渲染开销 |
| 接口检索 MCP（`wow_api_mcp` 已对齐 12.1） | 减少"接口名／参数写错"，属预防性收益；现有 LuaLS 已覆盖大部分 |
| wowless 离线解释器 | 作者自称 pre-alpha，且**进程出错也返回 0**，不能当门禁 |
| Mechanic 诊断平台 | 队列执行后**不清空**，每次登录／重载重复触发 → **会污染采集数据**；且 alpha、本地服务无认证无沙箱 |
| 打包发布（BigWigs Packager） | 需要公开发布时才接入，与调试效率无关 |

## 4. 负向清单：明确不做

| 不做 | 原因 |
| --- | --- |
| 合成输入自动重载（`SendKeys` 类） | EULA bots 条款明文禁止，CN 版措辞更严，**无意图豁免**。公开案例中无因此被封的记录，但检测边界不公开——不构成安全依据 |
| 像素比对／截图回归 | 整个魔兽生态空白，模拟器也不支持 |
| 捕获 `/etrace`、`/fstack` | 输出只进自己的窗口，无重定向钩子（用 `print` 式探针替代） |
| 实时落盘 | 沙箱唯一持久化出口是 SavedVariables，无受支持的中途 flush |
| DevTool | 已归档，`.toc` 停在 120000，不支持 12.1 |
| WoWUnit | 无开源许可证，清单停在 120001，不支持 12.1 |
| 用离线结果冒充实机验收 | 沿用仓库既有的三层证据分层：离线自测通过 ≠ 原型可行 ≠ 实机验收通过 |

## 5. 前置验证清单（gate）

这些是**做之前必须先拿到答案**的问题。每项成本都很低，但会改变后续决策。

| 编号 | 验证内容 | 影响 | 成本 |
| --- | --- | --- | --- |
| **G1** | 游戏内执行 `/run C_Timer.After(2, function() ReloadUI() end)` | 若重载成功 → 沙箱内定时重载可行；若报 `ADDON_ACTION_BLOCKED` → 该方向永久关闭。**不影响 P1–P5** | 一行命令 |
| **G2** | `EllesmereUI` 与 `MYUI` 能否在 wow-ui-sim 中加载 | **P6 的硬门槛**，不通过则 P6 直接取消 | 需先自建镜像，故应先做一次最小探测 |
| **G3** | BugGrabber 的 `.toc` 是否支持 120100、能否正常落盘 | P2 的前提 | 装上试一次 |
| **G4** | `C_Log.LogMessage` 写到哪；`C_ChatInfo.SendAddonMessageLogged` 是否进聊天日志且实时增长 | 若任一实时落盘成立，**可省掉 `/reload`**，P1 的价值进一步放大 | 三条 `/run` 命令 |

## 6. 与现有流程的衔接

- **测试**：P1、P3、P5 都按 TDD 走（先写会失败的测试）。P1、P3 的解析与转发逻辑天然可离线测；P5 沿用 `tests/addons/<插件名>/` 的"Python 驱动本机 Lua 5.1"既有做法。
- **登记**：任何新增检查必须进入 `.build-and-verify/config.json`，否则 `tests/dev/test_inventory.py` 会拦截。依赖本机游戏路径的（P1 的端到端读取）作为**本机验收**，不进 CI。
- **部署**：P2、P5 涉及写入游戏目录，需单独授权，不进入常规验证与拉取请求自动工作流。
- **证据分层**：每项完成后分别报告"离线测试通过""本机可读""实机可用"，不得互相冒充。

## 8. 一句话总结

**核心只有两件事**：P1 让我读得到，P3 让东西进得来。做完这两件，你的调试循环从"敲命令 → 看聊天框 → 复制 → 粘贴"变成"进游戏 → 按一次 `/reload` → 我直接读"。其余各项都是在这条主干上加值，或明确划定不做的边界。

# MYui 解锁位置重载保持

Triage（分拣）: ready-for-agent

## Problem Statement

玩家在 EUI（EllesmereUI）解锁模式里移动准星 HUD 后，退出解锁时看到的位置与重载界面后的位置不一致。实机记录显示，同一次操作中重载前实际锚点为 `111.111 / -72.222`，MYui 保存的位置为 `88.611 / -44.533`，重载后实际锚点变为 `111.111 / -55.556`。位置恢复链使用了与 EUI 解锁结束位置不同的坐标语义。

## Solution

让 MYui 在 EUI 解锁模式保存和恢复位置时使用同一套坐标契约，使玩家退出解锁时看到的位置在重载后保持不变。修复只纠正现有实现，不改变正式规格、不增加位置控件，也不引入诊断插件。

## User Stories

1. 作为使用 MYui 准星 HUD 的玩家，我希望在 EUI 解锁模式移动 HUD 后重载界面仍保持原位，从而不必反复重新定位。
2. 作为使用非默认 HUD 缩放的玩家，我希望位置保存不受 HUD 尺寸缩放错误影响，从而在任意允许缩放下保持稳定。

## Implementation Decisions

- 复用 EUI 解锁元素现有的保存、加载和应用位置接口。
- 以重载前后根框坐标一致作为位置契约，不以 EUI 输入框显示值代替实际框体位置。
- 仅修正位置换算链；不增加日志、独立探针、延时重贴或第二套位置存储。
- 保留像素吸附；像素吸附不得造成可累积漂移。

## Testing Decisions

- 最高层级测试接缝是现有解锁元素完整装配测试：使用真实模块注册出的解锁回调，模拟保存、退出解锁和新会话恢复。
- 回归样例使用已确认的非默认缩放和非零位置，断言重载前后 HUD 在 UIParent（界面根框）坐标中的位置一致。
- 测试预期来自用户实机观察到的持久化行为要求，不复制生产换算公式生成期望值。

## Out of Scope

- 不修改正式规格。
- 不修改 EUI 源码。
- 不制作日志系统或独立探针插件。
- 不调整 HUD 外观、尺寸范围、可见性或其他设置。

## Further Notes

用户已完成定量实机复现。修复后的最终游戏验收仍需在相同缩放和位置场景下确认。

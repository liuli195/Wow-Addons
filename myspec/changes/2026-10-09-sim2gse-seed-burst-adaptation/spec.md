# 旧起点的独立爆发适配

## Problem Statement

独立爆发训练在普通循环的角色动作映射之前直接读取旧登记件和历史成果。实际批次101条候选中58条因固定爆发动作在普通动作池中被排除而在模拟前拒绝，不能继续利用其普通循环部分。

## Solution

原来源不变，仅在独立爆发训练入口派生去除当前固定爆发动作的普通循环候选，然后沿用现有训练、行为去重、缓存、独立复测和入选流程。

## User Stories

1. 用户可重用含固定爆发动作的旧材料和同专精历史成果，并查明原程序与本次删除差异。
2. 用户能看到普通循环顺序、重复次数、剩余控制结构和重置规则保持；没有普通动作或无法忠实表达的材料明确拒绝。
3. 用户不会因适配而丢失原来源、旧成绩或已有入选库，未知动作仍明确报错。

## Implementation Decisions

- 仅在独立爆发训练的候选预处理处适配；普通搜索、导入检查、固定爆发内容及原生跳过语义不变。
- 复用实际审核爆发块生成的排除策略及动作身份匹配，不写两技能黑名单。
- 普通动作块和顺序循环内移除排除动作，空动作块删除；循环重复次数与剩余块顺序保持，整个循环空体时删除该循环。
- 施法序列保持成员顺序和原重置定义；删除后两个或以上成员沿用现有表达，零成员删除，单成员明确拒绝，不能改成普通动作块或伪造重复成员。
- 没有可执行普通动作时明确拒绝；未知动作或无效控制结构沿用既有校验错误，不能静默放行。
- 原登记件及历史记录不写回；候选编号关联原来源。训练处理记录保存派生初始程序，并在已有比较JSON字段中保存原程序及删除位置/动作，不扩表结构。
- 复用现有精确核心检查记录派生初始程序的核心保留；丢失核心的初始程序沿用既有普通历史成果分类参与入选，原来源家族与核心不变。
- 引擎、标准角色、每候选600秒预算、连续两个完整无改善轮次及独立复测/入选条件不变。规则指纹变化隔离新旧处理条件，不删除原结果。
- 正式规格当前要求训练材料含爆发动作整条拒绝；交付门禁须调整该条训练特例，普通搜索/最终导出仍拒绝残留爆发动作。

## Testing Decisions

- 接缝为现有人工训练公开入口run及查询list；复用现有测试设施，先红后绿。
- 最小核心覆盖：来源/历史派生、全固定定义排除、剩余普通块/循环/施法序列语义、空结果和未知动作、来源保留、条件去重。
- 云端内存适配和既有解析检查如实标注，不冒充Windows受控引擎验收；有Windows依赖的既有统一快速验证后续安排，不干扰正在运行的五目标训练。

## Out of Scope

不修改原材料、删除旧成绩、重构存储或添加框架；不修改本机运行中训练；不重训全库；不推送或合并主干，不正式发布。

### 3.2 字节完整性

`-text` + **干净克隆验证**足以防止原始字节被换行转换破坏。

```gitattributes
scripts/dev/wow-addon-test/**  -text
.agents/skills/wow-addon-test/**  -text
```

**两个真身目录都要覆盖**（不只工具目录）——技能的逐字节比较也参与安装器的覆盖保护。

**两种摘要必须区分**：

| 摘要用途 | 实现 | 要求 |
| --- | --- | --- |
| 工具完整性清单 | `core.py`：对 `read_bytes()` 的**原始字节**计算 | 保留原始文件字节；**不重算清单掩盖导入变化** |
| 运行报告的生产源码 / 适配器摘要 | 先按 `utf-8-sig` **读文本**再编码计算 | 这是**实际加载文本**的摘要，**不能默认等于工作树原始字节摘要**——换行或编码标记可能在读取过程中已被处理 |

**修正一处表述**：不是"行尾转换必然导致重复安装报错"，而是
**源与目标因换行处理不同而内容不一致时才会触发覆盖保护**；两份文件被一致转换时不必然冲突。

摘要文件集合**排除运行产物与生成的指针**（`tool-location.json`、报告），避免正常生成被误报为"多出文件"。

### 3.3 运行报告的落盘与归档（本轮新增）

`tests/verify.py` **硬编码**写 `ROOT/reports/selftest.json`，且交付目录**自带**该文件；
而工具自带的 `.gitignore` **只忽略 `reports/local-*`**，**不忽略 `reports/selftest.json`**。

后果：若把报告目录按原样纳入跟踪，**每跑一次自测都会改写受跟踪文件**；而且历史报告容易被
误当成"本次结果"。仅设置工作目录、只调用外层入口、或**把报告排除出摘要集合，都不能解决**——
**排除摘要 ≠ 排除版本跟踪**。

| 约定 | 最小处理 |
| --- | --- |
| 工具内部落盘 | 允许原自测写进工具自己的 `reports/`，**不修改工具核心代码** |
| 版本管理 | **导入时不跟踪该运行报告目录并精确忽略** |
| 统一归档 | 仓库入口把**本次**自测结果保存到 `.local/tests/wow-addon-test/`，**保留真实退出状态** |
| 验收 | **连跑两次后受跟踪文件不变**；失败时也有本次诊断结果；**不把历史报告误当本次结果** |

### 3.4 授权依据：**公开发布前的未关闭检查**

保留声明、不擅自重新授权是**必要措施，不是授权依据**。"公开可见"不等于"已获复制、修改、分发授权"。

### 4.2 硬约束：**仓库准备不得调用原安装器**

读交付的工具源码 `install_skill()` 后确认：它先检查已有目标内容是否不同，然后**无论内容是否相同都执行
`shutil.copytree(...)`**——"内容相同"只通过检查，**不会跳过复制**。因此若把技能真身迁入 `.agents/`
再回链，然后照常运行原安装器，**源与目标会指向同一目录**，底层复制报同文件错误。

**因此确定的流程**：

| 阶段 | 动作 |
| --- | --- |
| 提交布局 | 技能实体仅在 `.agents/skills/wow-addon-test/` |
| 仓库准备 | 生成本地指针；创建 Claude 侧连接；**创建工具原技能目录的回链** |
| 忽略规则 | 精确忽略上述两个连接路径与 `tool-location.json` |
| 本仓库重复准备 | 校验现有真源与连接，更新**已确认归属**的生成状态；**不调用原安装器把真源复制到自身** |
| 兼容性测试 | **保留**原安装器向**独立临时项目**安装的测试，以及 `init` 测试 |

**回链不能省略**：`init()` 仍从**工具原技能路径**读取适配器模板；工具自测也调用 `init()` 与
`install_skill()`。所以 **CI 必须先准备连接，再运行完整自测**。

### 4.3 链接形式

- 本机**开发者模式关闭** → `mklink` 需管理员；**`mklink /J`（目录联接）不需要**。
- `core.symlinks=true`，但索引内**无任何符号链接**；CI 与本机环境不同，还原行为不一致 → **链接不进版本库**。
- **待实测**：两端代理是否真的跟随目录连接加载技能（**不假设**，需从两个链接入口实际运行）。

| 3 | **后端身份要另行保存**：`run` 报告元数据**只有**插件名、源码摘要、适配器摘要（已读源码确认），**不含后端字段** → 由仓库入口在**同一固定环境**下保存后端信息并与该次报告关联，**不得断言 run 报告自身含此字段** |
| 4 | **测试清单盲区**：`tests/dev/test_inventory.py` 只扫根 `tests/`；`scripts/dev/wow-addon-test/tests/` 下的工具自测漏登记不会被发现 → 必须**显式入口与登记断言**；适配器 `.lua` 辅助文件也要登记调用者 |

### 5.3 预算口径

工具**完整验证实测约 10 秒**（未含 MYUI 对照与缺陷注入）。仓库 60 秒是**本机完整验证预算**，
CI 的 90 分钟是**作业超时**，两者不能与单次示例耗时混为一谈。**每项超时与全仓预算分别设置**，
并在实施后重新实测完整验证。

### 5.4 触发路径的既有行为

CI 的 "Classify changes" 用轻量正则跳过纯文档改动；工具与适配器**不在**该名单内 →
一改即触发完整构建与验证，这是**期望行为**。

## 8. 三类资源：**本次必须全部覆盖**

### 8.0 本次目标（用户已定）

**用本工具把 MYUI 的死亡骑士职业全部测通**——死亡骑士三专精 × 三个组件（生命、主资源、职业资源），
**包括需要做转换投影的生命与主资源部分**。因此第 8.1/8.2 节列出的缺口**不是"登记为差异"的出口，
而是必须解决的工作项**。

### 8.0.1 本次保留现有读数通路，但不宣称它是唯一可能

**约束（本次）**：保留现有引擎曲线求值通路，**不为满足测试输出契约，强迫生产代码对秘密读数
做算术或新增可读比例**。测试侧从**实际观测结果**归一化，不要求插件额外计算比例。

**不宣称**"任何合法实现都只能输出角度"——**已核实接口文档否证该说法**：

| 依据 | 内容 |
| --- | --- |
| `.tools/wow-ui-source/.../UnitDocumentation.lua` | `UnitHealthPercent` / `UnitPowerPercent` 的 Returns 写明：**未传曲线时返回浮点百分比**；传曲线时返回曲线求值结果 |
| 秘密值相关标记 | **两者都有，但标记不同**：`UnitHealthPercent` 标 `SecretReturns = true` 与 `SecretWhenCurveSecret = true`；`UnitPowerPercent` 标 `SecretWhenUnitPowerRestricted = true` 与 `SecretWhenCurveSecret = true`（**没有 `SecretReturns`**）。**返回百分比不代表结果必然可读**；结果受秘密值限制时，**不得对其进行算术** |

**所以准确表述是**：受限上下文里生命与符能是秘密值、**不能做算术**（这是设计约束，有实机缺陷为证）；
但"只能拿到角度"是**当前实现选择**（`Core.lua` 传曲线交引擎求值），**不是接口的普遍限制**。
本次**不重构生产代码**，也不把当前选择误写成唯一可能的实现。

### 8.0.2 那么生命与主资源怎么"测通"

工具比较器**无投影能力**（8.1 已核实），契约又要求原生的 `value`/`maximum` 字段；
而插件手里**只有角度**。可行的路径是：

**必须区分两条曲线路径**（混同会同时破坏可检出性与独立性）：

| 环节 | 正确做法 |
| --- | --- |
| **宿主接口模拟** | 实现曲线创建、设置类型、添加端点与求值行为，且**必须使用生产代码实际传入的曲线与端点求值**——否则注入到生产曲线的错误**根本传不到观测结果**，测试会失明 |
| **观测生产输出** | 取生产代码**实际保存或传给显示层的角度**，**不得直接返回输入比例** |
| **独立比较依据** | 用仓库侧**按已确认设计固定**的映射；**不得在运行时从被测曲线、`MaskAngle()` 或 `ArcCurvePoints()` 反推逆映射** |

**"不得复用插件曲线"只限定在期望生成与逆向判定环节，不扩展到宿主模拟环节。**

**缺陷注入是必要验收，不是唯一充分判据**：同一错误曲线正逆两用确实可能抵消映射错误
（`θ = C错误(f)`，`C错误⁻¹(θ) = f`），但**这只能推出可能漏检曲线映射类缺陷，不是所有错误都会"永远通过"**。

**验收口径**：

1. 正常版本**通过**；
2. 分别在**生命**与**主资源**链路注入**确实影响已选检查点的非等价曲线错误**，测试**必须在预期组件、
   预期检查点产生可解释的结果差异**；
3. 恢复后**重新通过**；
4. **不得**把语法错误、缺依赖、超时或运行中断当作"曲线缺陷已被正确检出"的证据。

独立判据、真实生产路径、完整执行检查，以及第 7 节已有的事件与符文缺陷测试，**仍须全部保留**——
一个变异被检出**不能替代**这些检查。

### 8.1 已核实的契约事实（G6 部分关闭）

| 问题 | 源码依据 | 状态 |
| --- | --- | --- |
| 能否添加局部宿主接口替身 | 契约明确允许有依据的局部依赖与接口替身 | **允许**，具体替身仍需验证 |
| 能否做明确的单位适配 | 契约允许字段重命名、索引整理与明确单位适配 | **允许**，但不能借此重写业务计算 |
| 原生比较器是否支持任意输出投影 | `compare()` 仅按组件取字段后**递归比较**，**无投影配置或回调** | **不支持** |
| 比例能否冒充原始值与上限 | 契约要求相应的原始逻辑字段 | **不能**；缺失字段不能靠伪造上限补齐 |

**仓库已有直接证据**：`tests/addons/MYUI_CrosshairHUD/test_core_readings.py` 已实现线性曲线与
`UnitHealthPercent`/`UnitPowerPercent` 的离线替身。

**结论**：三类资源**原则上可做离线逻辑验证**，局部宿主替身**有契约依据**；
但**现有生产输出与工具标准输出之间仍有观测契约缺口**——需要仓库侧明确比较方案，
**不能把比例转换当作原生 `run` 已支持的能力**。

### 8.2 符文的两个具体缺口

| 缺口 | 证据 | 后果 |
| --- | --- | --- |
| 观测结果**没有 `start`/`duration`** | 生产代码保存比例、状态与剩余时间，公开读数只返回 `index`/`frac`/`state` | 工具的冷却字段**不能仅靠重命名得到**；**不能从输入补填**后宣称验证了插件 |
| 读取接口**没有经过显示排序** | `Core.GetReadings()` 按原索引返回；排序在 `BuildState()` 内执行 | 只测读取接口**无法验证装配后的槽位顺序** |

**排序的边界（本轮修正）**：工具契约**明确关闭视觉排序**，参考驱动**按符文原始索引采样**、
不执行显示排序。因此**不能要求现有基线承担它已明确排除的排序验证**。
- 生产排序逻辑继续由**仓库既有回归**覆盖（`tests/addons/MYUI_CrosshairHUD/test_logic.py` 中已有相关断言）；
- 若要验证**生产装配后的槽位顺序**，应**单列该测试**，且**不宣称现有原生资源基线已覆盖**。

### 8.3 G4 不能凭单个自测名关闭

`unconfigured_api_input_fails` 通过，**不能证明"所有缺失接口都会显式失败"**：生产代码存在缺接口
直接返回、以及经 `pcall` 捕获错误的路径。**必须在真实 MYUI 接入中验证**：缺接口或缺输入不会被
解释成**合法空状态**，也不会**沿用旧状态后仍判通过**。

## 12. 一句话总结

**本次目标**：**用这个工具把 MYUI 的死亡骑士全部测通**——三专精 × 三组件，
**含需要转换投影的生命与主资源**（用户已定，见 8.4 的完成口径）。

**四件事已定**：工具进版本库、技能真身只在 `.agents/skills/` 且两端连接、CI 跑真实工具、
不做其他职业。Lua 后端用仓库**已有的 5.1.5**，远端**零新增依赖**。

**三件必须先解决**：**行尾属性**（两个真身目录都要，否则首次克隆完整性就挂）、
**授权依据**（保留声明不等于获授权，公开传播前的未关闭检查）、
**生命与主资源的双边投影比较方案**——比较器无投影能力（8.1），当前实现经引擎曲线求值只观测到角度（8.0.1），
故：**宿主替身必须用生产传入的曲线求值**（否则注入的曲线错误传不到观测），
而**期望与逆映射必须由仓库侧独立固定**（复用被测曲线会漏检曲线映射类缺陷），
验收按 8.0.2 的四条口径执行。

**两条硬约束**：技能真身迁走后，**仓库准备不得调用原安装器**——它无条件 `copytree`，会让源与目标撞在一起；
自测**硬编码**写工具自己的 `reports/selftest.json`，该目录**必须不跟踪**，否则每跑一次自测就改写受跟踪文件。

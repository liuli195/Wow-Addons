# 04: 数据检查规则、时序口径与清理字段

**What to build:** 工具新增**第一条数据检查规则**，把**没有判别力**的用例修到有判别力；
把**取值时刻**口径定死；把**清理适用性**做成报告里的正式字段。
目的：**不再有"看起来通过、其实什么都没测"的用例**。

**Blocked by:** 02（自包含技能布局与双代理冒烟）

**Status:** done

- [ ] 规则实现两条断言：**前后可区分**（本次要验证的资源量必须能与上一检查点区分，**无关组件的变化不能代替**）、
      **类型可区分**（类型切换时，**同一份切换后输入**中新旧类型比例必须可区分，**不跨时刻**）
- [ ] **"可区分"经正式投影与容差判定**，不是"原始数值不相等"
- [ ] **只约束已确认的三类用例**的目标检查点，不推广到所有带切换的步骤
- [ ] 三类用例数据修到通过；**两个小回归**成立：前后量改回相同必失败、新旧类型比例改回相同必失败
- [ ] 数据与基线**经生成器重生成**并核对差异；**正常测试命令不自动重生成期望**；原有有效场景与回归保留
- [ ] **取值时刻口径**写入规格并实现：区分模拟器漏跑计时器 / 需要等待的合法延迟 / 连续变化资源的周期刷新；
      **不笼统写"允许 1%"**；保留"不得在每个检查点强制刷新生产代码"
- [ ] **清理检查**在报告中给出「已适用 / 不适用」**两个字段**；**"不适用"不计为"通过"**；
      即使适配器失败或超时，**运行器自身的释放仍必须执行**
- [ ] 报告输出参数化（不再写死内部路径、不再改动受跟踪资产）
- [ ] 工具自带自检与示例回归**全部通过**

## 完成证据

规则库第一条；无判别力 258→0；维护入口拒绝带缺口写入；清理两字段；报告输出参数化。提交 e0749e3。

**复审后订正（提交 5296d15 起）**

- **前后可区分原先打包了三个组件**：生命随便变一点就能把"主资源根本没变"掩盖过去——正是规格禁止的"无关组件变化代替"。而且打包成元组后 `diff()` 只做整体相等比较，连浮点容差都用不上。已改成只比**本次要验证的那个量**（主资源比例），并补了第三条反面回归"无关组件不能代替"（旧口径下实测不触发）。
- **时序驱动顺序是反的**：原先先装这一步的输入、再推进时间，于是两个检查点之间到期的计时器会读到"未来"的输入。已改为先按上一检查点推进、再装输入；原来的自检只比对源码字符串，已换成**真跑一次的行为探针**（旧顺序实测读到 900，新顺序读到 500）。
- **写死的 2% 容差已移除**：改为按该次充能时长折算（一次轮询占多少），不再笼统写比例。
- 维护入口原先只重算数据三项摘要，改一次运行时就对不上；已改为重算清单列出的每一个文件。
- **容差统一**：数据规则用 1e-8、正式比较用 1e-6，两边对"可区分"的判断不一致。已统一到工具的正式口径（1e-8，实测 72 通过不受影响），并加检查防止再次漂移。

# 04: 数据检查规则、时序口径与清理字段

**What to build:** 工具新增**第一条数据检查规则**，把**没有判别力**的用例修到有判别力；
把**取值时刻**口径定死；把**清理适用性**做成报告里的正式字段。
目的：**不再有"看起来通过、其实什么都没测"的用例**。

**Blocked by:** 02（自包含技能布局与双代理冒烟）

**Status:** ready-for-agent

- [ ] 规则实现两条断言：**前后可区分**（本次要验证的资源量必须能与上一检查点区分，**无关组件的变化不能代替**）、
      **类型可区分**（类型切换时，**同一份切换后输入**中新旧类型比例必须可区分，**不跨时刻**）
- [ ] **"可区分"经正式投影与容差判定**，不是"原始数值不相等"
- [ ] **只约束已确认的三类用例**的目标检查点，不推广到所有带切换的步骤
- [ ] 三类用例数据修到通过；**两个小回归**成立：前后量改回相同必失败、新旧类型比例改回相同必失败
- [ ] 数据与基线**经生成器重生成**并核对差异；**正常测试命令不自动重生成期望**；原有有效场景与回归保留
- [ ] **取值时刻口径**写入规格并实现：区分模拟器漏跑计时器 / 需要等待的合法延迟 / 连续变化资源的周期刷新；
      **不笼统写"允许 1%"**；保留"不得在每个检查点强制刷新生产代码"
- [ ] **清理检查**在报告中给出「已适用 / 不适用」**两个字段**；**"不适用"不计为"通过"**；
      即使适配器失败或超时，**运行器自身的释放仍必须执行**
- [ ] 报告输出参数化（不再写死内部路径、不再改动受跟踪资产）
- [ ] 工具自带自检与示例回归**全部通过**

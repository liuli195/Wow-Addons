**复审后订正（提交 5296d15 起）**

- **判定原本不在工具里**：技能公开入口 `run` 报的是"78 个差异、0 通过"，真正的判定落在仓库侧辅助程序——等于工具没在用。已给工具加**项目投影**这条接缝（`wowtest.json` 的 `projection`），工具自己产出正式判定；声明了却坏掉时显式失败，不静默退回通用比较。
- **"已知差异"原先不看产品期望**：只在偏离原生时才核对，于是插件退回原生表现（断线被填满、类型跟随被报告值）反而被当成"与原生一致"放行。已改为**先核对产品期望、再看是否偏离原生**。
- 补齐原先没真正比较的目标字段：主资源类型缺失不再静默跳过；就绪／空转的符文比例不再不比；符文索引必须正好 1..N。
- 缺陷注入原先**直接改受跟踪的生产文件**，且各次运行共用同一输出路径、互相覆盖。已改为在**临时项目副本**里注入，并补了事件／计时器路径的注入。
- **实测的不可观测项**（写进投影的"未参与比较"，不是推测）：摘掉 `UNIT_HEALTH` 订阅后 78 个用例差异仍为 0——0.1 秒轮询会兜住一切事件更新，检查点间隔不小于一次轮询。所以本工具能证明"读数算得对"，**不能**证明"事件订阅写对了"。

# 02: 自包含技能布局与双代理冒烟

**What to build:** 工具成为**一个自包含技能**——仓库内装好即可被两个代理发现并使用，
不需要定位指针、安装器或回链；数据以压缩形式随技能分发且**只有工具消费**；
面向代理的输出走**统一有界出口**。

**Blocked by:** 01（契约与来源核对）

**Status:** done

- [ ] 技能真身位于仓库技能目录，另一代理侧为**目录连接**；**无**定位指针、**无**安装器、**无**工具原位置回链
- [ ] 技能目录组织符合共享规范：入口 / 参考文档 / 脚本 / 其余载荷
- [ ] 入口文档**不出现数据文件路径**；路径以**相对技能根**表述
- [ ] 数据以压缩形式存放，工具内部解码；**正常运行前不要求代理手工解压**
- [ ] 面向代理的输出走统一出口并受限额：总字节上限、差异预览条数上限、**保留真实退出状态、完整计数与"详情已截断"标记**
- [ ] **截断的是展示，不是实际执行的用例数**
- [ ] **G2**：两代理各自的发现与定位冒烟通过，并**报告实际加载来源路径**（含目录连接是否被跟随）
- [ ] 布局重排后工具自带自检**仍全部通过**
- [ ] 技能内部自检**在根目录显式登记调用入口**，不复制两套实现

## 完成证据

技能真身 .agents/skills/ + Claude 侧连接；压缩载荷（12MB→429KB）；打包不变量经反证。提交 2cdab8b、fe71475。

**复审后订正（提交 5296d15 起）**

- 自检项数：**37**（原记 32，此后又加了数据规则、压缩资产时间戳、时序行为探针等项）。
- 输出限额：原实现**裁剪一次不保证字节数**——字典键数不受条数限制约束，100 个字段 × 512 字符约 52 KB，超出 16 KB 预算。已改为逐级收紧到真的装下，并补上"字段多""宽嵌套""预览条数""失败信息上限"四条边界用例。
- 会超预算的命令原先**没有取回完整结果的路**（catalog 把 40 个专精截到 10 个就没了）。已补 `--output`。
- 措辞订正：本条验收条件里的"无安装器"指的是**不需要**安装器（技能自包含、原地可用），不是"不许存在"。`install-skill` 把整份技能复制到**另一个项目的**技能目录，供后续复用；已补测试证明它只往目标项目里写、且副本能独立跑。

**仍未验证**：Codex 侧的实际加载与完整任务冒烟——上次因用量上限阻塞，之后没有补做。技能在 `.agents/skills/` 里布局正确，但"Codex 真的能发现并执行它"没有实测证据。

# Sim2GSE 接入最小数据存储技能

## Problem Statement

旧数据工具已经彻底移除。普通模拟和搜索的现有结果需要进入新的统一结果中心，并继续支持当前结果查看、缓存复用和取消后恢复，不能旁路复制一份后仍依赖永久 JSON（数据交换格式）报告。

## Solution

消费 my-agent-skills（个人技能仓库）2026-10-05-data-store 变更定义的 write/query（写入/查询）契约。本文只定义 Sim2GSE（角色级按键序列优化器）的适配，不复制或扩充通用存储契约。

## User Stories

1. 作为使用者，我希望日常模拟和搜索照常运行，已经生成的普通结果自动保存并能统一查询。
2. 作为使用者，我希望正常结果完整保留，包括伤害分布和伤害来源，不只有最终均值。
3. 作为使用者，我希望详细动作轨迹只在明确开启记录时保留，不为存储补跑模拟。
4. 作为使用者，我希望同条件缓存命中及取消后继续仍正确，不重复计算完成批次或重置预算。
5. 作为使用者，我希望网页查看、复制导出和现有结果消费者都从同一真实结果读取。

## Implementation Decisions

- 新的持久结果只使用核心技能的 Parquet（列式文件）内部 Zstd（压缩算法）；SimC（战斗模拟器）原生 JSON 仅作运行交换。现有 TaskStore（任务状态保存）、检查点、锁和共享缓存继续负责运行状态，不把这些机制重新做成数据中心。其结果载荷按需改为中心身份与必要恢复状态，不能在 SQLite（任务状态数据库）的 JSON 字段中另藏一份完整结果；“机制不变”不代表物理载荷逐字不变。
- 结果中心使用唯一、明确配置的项目级数据根目录，默认是 Wow-Addons 仓库根目录下的 data；所有模拟任务与搜索任务共用，不放进每次任务或各自 output-root（输出目录）的 data 子目录。根目录由单个适配入口解析和传入，业务调用者不散落物理文件路径；生成数据须排除于 Git（版本管理）和技能分发。运行技能的位置只在该适配入口配置一次，不能固定指向开发源码仓库。
- Sim2GSE 适配层定义推荐稳定逻辑表：runs（任务与冻结上下文）、candidates（候选与导出）、batches（批次请求、成绩及有类型原生报告）、traces（明确请求的逐事件轨迹）；这些是消费端数据集契约，不写死在通用技能。普通伤害分布、玩家/宠物伤害明细保持可直接查询的数值与嵌套列；不另存不透明原始报告副本。后续训练等调用者可直接使用 DuckDB 原生游标按有限行数分批查询，不要求把全部历史记录装入内存，也不在本次增加训练功能。
- runs 保存实际已产生的身份、状态、阶段、冻结输入、引擎与配置、已用时间及最终/取消结果。candidates 保存实际候选身份、程序与导出文本。batches 保存实际请求身份、种子、样本请求量、已完成样本、DPS（每秒伤害）、方差及原生报告。traces 仅保存实际已有且获准持久化的事件；不存在的字段不额外制造。
- 批次成功后即时写入中心，再由现有 TaskStore 登记可复用成功；任务结果收尾时写入，调用同一通用 write 操作。必要批量写入不变成缓冲平台或定时任务。
- 必要适配覆盖任务结果读取、搜索批次读取与缓存校验、网页候选复制和基准结果消费者。改变的是物理数据取用，搜索算法、原生引擎、预算、排名、缓存命中条件与恢复计数语义不变。
- 原缓存基于 native.json（原生报告）原始字节的 SHA256（内容摘要）无法在移除永久 JSON 后逐字保留。新表示必须继续拒绝身份不符、必要字段缺失、成绩不符或损坏的 Parquet 数据，保留现有请求和完整性检查目的；不保留原 JSON 字节副本，也不增加写后哈希回读；不保证识别人为重写合法 Parquet 后对可选统计字段的逻辑篡改。此必要存储适配须在门禁一明确展示。
- 详细轨迹沿用现有诊断总开关及细分开关；算法临时需要的轨迹使用后清理。保持当前模拟次数，不为记录、查询或验证持久化再跑一次模拟。
- 所有旧数据已删除，不实现旧格式兼容、历史迁移或规则变更后强行续跑。

## Testing Decisions

- 最高公开接缝为现有网页任务入口及其实际 task（任务）入口：普通模拟/搜索产生结果，页面读取与复制、查询、取消/恢复和缓存复用使用同一持久数据。
- 云端存储核心与集成快速检查复用现有低成本测试接缝；必须覆盖原生嵌套字段保真、DPS 分布、伤害来源、诊断关闭无持久轨迹、无额外模拟、损坏数据不作为成功缓存、取消/恢复不重复计数。
- 所有新测试放仓库统一测试目录并纳入现有 build-and-verify（构建与验证），不增加验证框架。
- 全部代码在云端开发，经 Git（版本管理）传递后，仅 Windows（视窗系统）专属验证使用已授权本机现有环境和两个已就绪引擎，执行现有 60 秒快速检查及必要原生冒烟；不改引擎、不增加本机完整验证。远端 CI（持续集成）仍走仓库原有完整检查。
- 分别报告云端、本机快速/原生、远端及实际游戏验收；本次不声称游戏内验收通过。

## Out of Scope

通用技能契约之外的新功能；旧工具、数据或规格复活；归档、预览、恢复、迁移、容量、定时清理、额外诊断；搜索算法、原生引擎、检查点/缓存机制改造；新本机兼容层；历史数据兼容；额外模拟；与此适配无关的界面重做。

## What to build（要做出什么）

设置页的「常规」分区里多出可见性这一项，排在总开关右边；总开关关掉时它整格置灰、点不动。

- 可见性作为常规清单的**第 2 项**：启用准星HUD → 可见性 → HUD缩放 → 图层。
- 排布**沿用清单原有的自适应规则**（每行两项、奇数时末行右边留空），不为它做任何特殊处理——它就是清单里的普通一项。
- 能力集（caps）：不做鼠标悬停；「队伍」与「团队」互斥；启用御空术判定。
- 总开关关掉 → 可见性那一格**置灰、点不动**，让「谁是主」一眼可见。
- 配置存储以**取值函数**形式交出，不缓存表对象（配置加载会替换整个表）。

## Acceptance criteria（验收条件）

- [ ] 可见性行出现在常规清单第 2 位，紧随总开关
- [ ] 排版走清单的自适应规则，没有为它新增特殊分支
- [ ] 能力集含「不做鼠标悬停」「队伍与团队互斥」，并启用御空术判定
- [ ] 总开关关掉时该格置灰不可点；打开时恢复可点
- [ ] 控件工厂可用时调建页 → 可见性行被建出
- [ ] 控件工厂不可用时调建页 → 仍返回数字高度，不报错（离屏安全）
- [ ] 配置默认值显式为「总是」
- [ ] 交给 EUI 的是取值函数而非缓存表
- [ ] 离线检查通过

## Comments（讨论）

**完成证据**（提交 `9dbde26`，修复见审查修复提交）：红灯为「可见性应紧挨总开关（第 2 项），实得「HUD 缩放」」，实现后转绿。固定基线完整验证 `status: passed`。

**票面修正（经独立审查指出）：**

- 验收项原文「排版走清单的自适应规则，**没有为它新增特殊分支**」措辞不严。实现里确实新增了 `kind == "visibility"` 这一格类型与一个挂载函数。**准确的说法是「排版没有为它新增特殊分支」**——它和别的格子一样只占半格、由清单的自适应规则排布；新增的是**格子类型**，不是排版分支。
- **「第 2 位」原先只断言了清单的数据序**，证不了建出来的行真的把它放在总开关右边。**已补强**：夹具现在记录每个槽位落在第几行哪一侧，并断言可见性挂在第一行右槽。

**格子类型白名单的扩展**：既有测试 `test_config_plan.py` 里有一条「常规格子只能是开关／下拉／滑块」的守卫，其注释写明该规则「实机里来回漂过五次」才被守住。本次**有意**把它扩为封闭集合并加入 `visibility`，在守护处当处写明了日期与理由。经审查确认该扩展**未被静默吞掉**，但指出**记录层级偏低（规格里没记）**——本仓库用规格代替架构决策记录，故已在规格实施决策 14 补记。

## Problem Statement（问题）

我是玩死亡骑士的魔兽玩家，屏幕正中装着自己设计的准星 HUD（血弧、符能弧、六个符文格）。

**问题是它永远在那儿。** 打本时它是我的仪表盘；可出了本——跑图、做任务、在主城挂机——它照样杵在屏幕正中。它占的地方不大，但那是我**视线的中心**，一直亮着就是一直在抢注意力。

我要的是：**该出现的时候出现，不该出现的时候别烦我。** 具体想要这些：

- 只在战斗中出现，脱战就消失
- 只在团队副本里出现，野外做任务时不显示
- 御空术飞行时藏起来（飞行时我不看符文）
- 单人时显示、进队就藏（或反过来）

**而其中有一样我明确不要：鼠标悬停才显示。** 准星在屏幕正中，那正是我按住右键转视角最常经过的地方。要是那片区域被 HUD 吃掉鼠标，我转视角转到一半就不动了——那比不看 HUD 糟糕得多。

同时我有两条底线：

- **升级完不能变样。** 我现在的准星一直在，升级之后它必须还在，不能因为我没去动新设置就消失了。
- **别给我两个都能关的开关。** 现在设置页里已经有一个总开关了，再冒出一个「从不」跟它抢同一个意思，我会不知道该按哪个。

## Solution（方案）

给准星 HUD 接上 **EllesmereUI 自带的可见性系统**，而不是自己发明一套条件判断。

好处是**条件、选项界面、多选语义、全部／任一组合、显示／隐藏否决这些全部由 EUI 提供**——EUI 自己的动作条、资源条、冷却管理、单位框架用的就是这一套。我只要把 HUD 接上去。

在设置页的「常规」分区里，可见性作为**一个新的配置项**出现，紧挨总开关：

```
── 常规 ──
[启用准星HUD] [可见性 ▾]
[HUD缩放]    [图层 ▾  ]
```

条件直接用 EUI 的：从不、总是、战斗中、脱战、御空术、非御空术、团队、队伍、单人，以及「全部满足／任一满足」的匹配模式和显示／隐藏两条通道。

**这一版刻意不做鼠标悬停**，下拉框里不会出现这一项。

## User Stories（用户故事）

**条件本身**

1. 作为死亡骑士玩家，我想让准星 HUD 只在战斗中显示，这样脱战后屏幕中心就干净了
2. 作为死亡骑士玩家，我想让准星 HUD 只在脱战时显示，这样战斗时屏幕中心不被自己的 HUD 挡住
3. 作为死亡骑士玩家，我想让准星 HUD 只在团队副本里显示，这样野外做任务时不受打扰
4. 作为死亡骑士玩家，我想让准星 HUD 只在队伍里显示，这样组队内容时才看它
5. 作为死亡骑士玩家，我想让准星 HUD 只在单人时显示，这样进本后让位给团队框架
6. 作为死亡骑士玩家，我想在御空术飞行时把准星 HUD 藏起来，因为飞行时我不看符文
7. 作为死亡骑士玩家，我想在非御空术时显示准星 HUD
8. 作为死亡骑士玩家，我想让准星 HUD 永远显示，这样它和我升级前一模一样
9. 作为死亡骑士玩家，我想让准星 HUD 从不显示，这样我可以临时关掉它而不动总开关

**条件的组合**

10. 作为死亡骑士玩家，我想同时勾选多个条件，让它们在「同一类之间满足一个即可、不同类之间必须都满足」的规则下组合
11. 作为死亡骑士玩家，我想在「全部满足」和「任一满足」之间切换，决定多条件是取交集还是取并集
12. 作为死亡骑士玩家，我想单独指定「隐藏条件」，这样某些情况可以否决掉别的条件已经通过的显示
13. 作为死亡骑士玩家，我想在改动条件后**立刻**看到效果，不需要重载界面

**与总开关的关系**

14. 作为死亡骑士玩家，我想保留现有的总开关，并让它继续是「一关全关」的那一个
15. 作为死亡骑士玩家，我想在总开关关掉时看到可见性那一项**变灰、点不动**，这样我一眼就知道现在是谁说了算，不用去猜哪个开关优先级高
16. 作为死亡骑士玩家，我想让总开关和可见性都关着时都不会留下拖动框——被关掉的东西不该冒出一个能拖的空框

**解锁模式**

17. 作为死亡骑士玩家，我想在解锁模式下**条件判定为隐藏时仍然能拖到准星 HUD**，这样我把条件设成「仅战斗中」之后，还能在主城里调它的位置
18. 作为死亡骑士玩家，我想在解锁模式下**总开关关着或选了「从不」时不出现拖动框**，因为那种情况下这个元素本就不该存在

**演示模式**

19. 作为死亡骑士玩家，我想在演示模式下**无视可见性条件**照常看到 HUD，这样我调颜色、透明度时不必先去满足条件

**升级与容错**

20. 作为现有用户，我想在升级后行为**完全不变**（准星照常在），直到我自己去动可见性设置
21. 作为现有用户，我想在设置页里**一开始就看到「总是」**，而不是一个空白的下拉框让我犹豫要不要动它
22. 作为用户，我想在 EllesmereUI 改版导致接口对不上时**仍然能看到准星**（只是条件失效），而不是准星无声无息消失、连改回来的地方都没有
23. 作为用户，我想在切换 EUI 配置档案时**本插件的配置纹丝不动**

**范围之外但需要知道的**

24. 作为用户，我想知道本插件**不支持按专精分别设可见性**——这是配置独立存放的直接后果

## Implementation Decisions（实施决策）

### 复用边界

1. **接入 EllesmereUI 的共享可见性系统，不自建。** 条件定义、选项界面、多选语义、全部／任一、显示／隐藏否决、事件判定全部归 EUI。本插件只做两件事：把自己的配置存储交给 EUI，接收判定结果并显示或隐藏。
2. **不用鼠标悬停，设 `caps.noMouseover`，且不注册悬停目标。** EUI 的共享悬停服务是每 0.15 秒一次的轮询，它在光标进入时会对注册对象调用 `EnableMouse(true)`——那会让屏幕正中那片区域吃掉鼠标，**直接违反既有规格「HUD 不得启用鼠标交互、点击必须穿透」**。曾考虑过改规格（否决：破坏已有验收）与注册纯表代理对象绕过（否决：复杂度该等真有需求时再付）。
3. **能力集（caps）取 `partyIncludesRaid = false` 与 `luaDragonriding = true`。** 前者让「队伍」与「团队」互斥，后者启用 Lua 侧的御空术判定。

### 作用范围

4. **整条 HUD 一条条件，不按元素分别设置。** EUI 的模型本就是「一个框体显示或不显示」，其求值器接的是「一份配置加一个键名」。按元素做会让配置面变成「四元素乘 N 模式」，且一旦将来要做悬停，「光标压在血弧上算不算命中」将无解。元素的取舍继续归**元素开关**。

### 模块与出口

5. **新增独立模块 `Visibility`，加载顺序排在 Config 之后、Core 之前。** 理由：EUI 一旦改版，需要翻的只有这一个文件。
6. **对外只暴露一个布尔问答（「现在该不该显示」）。** EUI 的求值结果是四值协议（真／假／悬停／空），其中「悬停」是真值字符串——任何写成「如果是真」的调用方都会在悬停模式下静默判错。本模块把这套协议压成一个布尔，调用方永远不需要看见它。
7. **整个 HUD 只有一处回答「该不该显示」。** 现在有两个地方在问同一个问题（渲染侧要不要画、解锁元素侧要不要给拖动框），而且答案抄的是同一句总开关判断。**必须让两处都问同一个出口**——否则两处一旦不一致，症状就是「屏幕上看不见 HUD，正中却留着一个能拖的空框」，这正是既有验收条款针对的坑。
8. **配置存储必须以「取值函数」而非缓存表的形式交给 EUI。** 配置加载会替换整个表对象，缓存引用的人会从此读写一张废表。

### 总开关

9. **保留总开关，并让可见性那一项在总开关关掉时置灰。** 曾考虑去掉总开关、让「从不」接管——**否决**：EUI 的可见性清单是写死的，只支持过滤「鼠标悬停」一项，**没有任何受支持的途径能移除「从不」**；硬改全局清单会同时改变 EUI 所有模块的行为。于是选择让层级显式化：总开关是主，可见性在它关掉时置灰不可点。

### 解锁模式

10. **总开关关、或可见性为「从不」→ 不出现拖动框**（这属于「这东西不该存在」）；**其他条件判定为隐藏 → 绕过，照常可拖**（这属于「现在不满足条件」，但它是活的，编辑时应当可调）。后者避免「把条件设成仅战斗中就再也拖不到这个框」的死锁。

### 降级

11. **认不出来就显示。** EUI 改版、接口改名、返回值不符合预期时，一律按「显示」处理。理由：降级发生时配置页上那一行很可能同时失效，用户没有任何自救手段；显示至少还能用——「功能失效」和「东西没了」在用户眼里是两码事。
12. **交互状态判定用 EUI 自己的缓存值，不用游戏的 `InCombatLockdown`。** 两套谓词混用会让 EUI 的判定与本插件触发的重算在锁定期窗口里对同一状态给出不同答案。

### 配置

13. **默认值显式写入「总是」。** 升级前后行为完全一致；显式写还能让设置页那行一开始就正确显示「总是」，而不是留一个看似「没设置过」的空白。
14. **设置页位置：常规清单第 2 位**（启用准星HUD → 可见性 → HUD缩放 → 图层）。清单是自适应排版（每行两个、奇数时末行右边留空），可见性作为清单里的普通一项参与排版，不需要特殊处理。紧挨总开关是为了让置灰关系一眼可见。
15. **演示模式绕过可见性。** 与它现在绕过总开关的做法一致——演示模式存在的意义就是「条件不满足时也能看」。
16. **不支持按专精分别设可见性。** EUI 的专精覆盖只认它自己档案里注册过的表，而本插件的配置是独立存放的（已定决策），EUI 会主动清除写进去的覆盖值。这是独立存放的直接代价，接受。

### 工程约束

17. **不新建全局变量。** 导出走插件自己的命名空间表，否则静态检查会失败。
18. **新增的测试文件必须登记进统一验证入口**，否则仓库的清单检查会失败。

## Testing Decisions（测试决策）

**什么是好测试**：只断言**外部可观察的行为**，不断言实现细节。一个内部函数测得再全，也可能整条线根本没接上；所以断言点要选在玩家真实用到的那道缝上。

**唯一接缝：装配入口（最高层级）**

按清单顺序零参数加载全部模块 → 装入一个**带可见性运行时的假 EllesmereUI**（判定结果可翻转）→ 触发登录事件 → 翻转判定 → 断言两个外部可观察结果：

1. **渲染侧**：准星框体的显示状态
2. **解锁元素侧**：交给 EUI 的那个元素报告的「是否隐藏」

**这两个必须由同一次翻转同时驱动**——它们由两条不同代码路径从同一个判断算出，任何单点测试都够不到「两处一致」这个跨子系统不变量，而它正是本项目已经踩过并被写成验收条款的坑。

**同一条接缝上的其他断言**：

- **接线覆盖**：只测内部判断函数的话，即使它从没被接上也照样全绿；打在这条接缝上天然覆盖「有没有接上」。
- **降级**：把假 EUI 上的可见性接口**全部撤掉**再走一遍，断言仍然显示且不报错。
- **设置页**：登录后取出交给 EUI 的模块表，在「控件工厂可用」时调一次建页并断言可见性行被建出；「控件工厂不可用」时断言仍返回数字高度。

**既有先例**：解锁元素契约测试已经在登录后断言过交给 EUI 的那个元素，是同一条现成接缝；公共核心的侧边栏测试有现成的「捕获并触发登录事件」写法可照抄。

**需要的脚手架改动（唯一一处）**：现有解锁元素测试里，框体的显示函数是个空实现，不记录状态。要改成记录，否则「屏幕上有没有」无从断言。

**边界——必须写明**：这一层验的是**本插件调用的形状**，不是 EUI 的行为。假 EUI 是照 EUI 源码抄的**契约夹具**，夹具抄错了会导致测试全绿而实机静默失败。**离线通过不等于实机通过，两者不得互相冒充**——真实条件行为另立实机验收项。

## Out of Scope（范围外）

- **鼠标悬停显示**（本版刻意不做，理由见实施决策第 2 条）
- **按元素分别设可见性条件**（见第 4 条）
- **按专精分别设可见性**（见第 16 条）
- **跟随 EUI 配置档案存放**（已定决策，本次不复议）
- **实机验收本身**——离线测试不能替代游戏内人工确认，实机项在实施阶段另行安排
- **改动元素开关、颜色、缩放、图层等既有能力**

## Further Notes（补充说明）

**接口核实**：本规格涉及的全部 EllesmereUI 接口，均已对着本机安装的 9.1.8 版实测确认存在：
求值入口（返回真／假／悬停／空，空表示回落到旧标量逻辑）、更新器注册（**多播**，追加进表，不会顶掉 EUI 自家模块）、悬停目标注册、悬停意愿查询、请求重算、共享交互状态读取、模式判定、以及配置行构建入口。

**一处必须小心的语义**：求值返回「空」的**含义是「继续走旧标量逻辑」，不是「显示」**。实现时若把空当成显示，会跳过整条兜底链。

**加载时机是安全的**：可见性运行时在常驻加载的核心插件里；而配置行构建入口位于**按需加载**的选项插件中——但那一行本来就只在建设置页时才创建，两者不冲突。

**已知风险**：本插件调用的是 EUI 的**内部**接口，不是它承诺给第三方的契约。本项目已有先例——EUI 改版导致三张表改名，所有访问点都补了判空守卫，且**失效表现是静默的**。这正是实施决策第 5 条（独立模块）与第 11 条（认不出来就显示）要对付的东西。

**交叉核验的收获**：本规格成稿前经过四轮独立核验，抓出并修正了六处错误，其中一处是核验方自己的误判导致方案被改坏。**低层 API 的名称、参数个数、字段归属是错误高发区，高层设计反而稳定**——这条经验值得沿用到实施阶段。

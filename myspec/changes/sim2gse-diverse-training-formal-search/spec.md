# 差异化训练成果与当前角色正式搜索

**Status:** ready-for-agent（需求与票据划分已确认；门禁一已确认）
**Flow:** Full
**Implementation authorization:** 用户已明确批准门禁一；本机 GPT-6-A medium 实施、GPT-6-A high 每票独立审查，详见 gate-preparation.md。云端本次仅传递需求文档。

## Problem Statement
训练目前会丢弃已经完成评价的可用起点；单纯追求相同的算法又掩盖了训练保留多路线与正式寻找最高每秒伤害这两个不同目标。参数在不同阶段必须独立生效，下游不能继续固定截断数量或在恢复时读取新配置。

## 领域术语

- 候选：一条可执行程序；精确去重与行为相似是两件事。
- 档案：本次任务全程成功评价候选的记录，不是另一支种群。
- 代表：高质量范围内行为不同的候选；冠军是同阶段质量最高者。
- 训练快照：完整发布的一组程序及其生产时的验证依据；正式搜索重新评分。
- 种群：当前参与演化的固定容量候选集合。
- 行为覆盖：关键玩家增益在战斗时间内生效的比例，不是测试覆盖率。
- 完整代：计划内后代均取得处理结果并统一完成生存决策的代际边界。

## Solution
训练让各条有效父代路线每代获得一次繁殖机会，通过后代与相近父代的竞争维持固定规模；正式让后代与抽样范围内相近候选竞争，以正常每秒伤害选择答案。两者共享可靠评价与恢复能力，但不共用可变配置。
训练在高质量候选范围内保留冠军并选择行为不同的代表，只进行正常条件的独立复测，发布全部合格代表；正式读取这些程序后按当前角色重新评价，不继承训练成绩。

## User Stories
1. 作为训练用户，我希望全部合法且精确不同的材料成为起点，不因粗分截断或被复制凑数。
2. 作为训练用户，我希望每条父代每代都获得一次繁殖机会，而不是只有平均参与机会。
3. 作为训练用户，我希望两个合法孩子按与父母整体最相似的配对竞争，仅更好者替换父代。
4. 作为训练用户，我希望只有一个孩子合法时由它挑战较相似父本，另一个父本保持；两个均非法时保留父代。
5. 作为训练用户，我希望奇数末位正常进行单亲变化，不被复制为另一名父代。
6. 作为训练用户，我希望从全程成功评价的档案选代表，而不是只看最后一代。
7. 作为训练用户，我希望预筛人数自动等于终评上限的两倍，并受实际候选人数约束。
8. 作为训练用户，我希望粗评冠军必占一席，剩余席位优先覆盖不同表现；我接受部分相近高分候选未进入终评的取舍。
9. 作为训练用户，我希望只做正常条件复测，不再为稳定代表计算四种扰动；默认三批、每批请求128，实际有效样本另记。
10. 作为训练用户，我希望最大发布人数跟随训练终评上限，最低发布数独立配置且默认4。
11. 作为训练用户，我希望全部冻结入围者评价完成后才发布；不足门槛、取消或失败时旧快照保持，不临时补人。
12. 作为正式搜索用户，我希望适用训练快照里的实际成果都被读取，不固定截断八条，也不按今日训练配置裁剪旧快照。
13. 作为正式搜索用户，我希望起点经过当前角色适配、精确去重及成功初评后形成真实种群，不保证凑成十三条。
14. 作为正式搜索用户，我希望竞争范围按真实初始人数的66%向上取整，人数和窗口随任务冻结。
15. 作为正式搜索用户，我希望正式终评数量、概率、采样、参考、停滞、并发和行为权重与训练分别配置，不相互串线。
16. 作为正式搜索用户，我希望按正常成绩选最终答案，不为了训练多样性而改用正式多样性入围。
17. 作为用户，我希望行为统计区分原生执行次数与按键尝试、伤害命中；精确程序身份不能被统计相似度取代。
18. 作为用户，我希望零值有可靠依据，缺失、未知格式或身份歧义明确报告，不伪造覆盖、不退回程序结构比较。
19. 作为用户，我希望取消和恢复保留冻结父代、候选顺序、种子及评价计划，只补可靠凭据缺失部分；半代不记完成。
20. 作为用户，我希望复测恢复不重选名单，发布失败可补发布，正式已完成场景不被重跑。
21. 作为用户，我希望旧完整成果和报告继续按其原契约验真；不兼容未完成任务明确拒绝混接新算法。
22. 作为用户，我希望所有新正式任务只从原生起点、适用训练快照与一个适用历史正式冠军取来源，不再额外扫描旧独立训练冠军。
23. 作为用户，我希望预算由实际场景、批数、请求数和候选数计算，缓存命中与真实新增模拟分别记录，不把终评节省比例冒称整体节省。
24. 作为用户，我希望页面开始、继续、读取结果与现有训练命令仍是实际入口，不必学习新的框架或数据中心。

## Implementation Decisions
- 训练与正式采用不同的生存竞争方式，但共用已存在的评价、档案、缓存和完整代恢复能力。
- 训练预筛倍数为二，冠军保留一席是规则；训练终评上限贯穿最大成果数量，正式终评上限独立。
- 当前原生来源类型不变，实际人数由有效来源决定；所有新正式任务只消费一个历史正式冠军。旧成果可读不等于沿用旧任务来源政策。
- 同分时保留父代；相似度和匹配平局按稳定候选身份及原槽位次序确定，不引入新可调参数。
- 正式窗口内无放回抽样，后续孩子面对当前已更新种群；完整代后统一提交。
- 参数只在入口按支持范围解析，计算条件随任务冻结；运行中不自动调参。
- 场景时长、合法性上限与旧版本身份沿现受检契约；不为灵活性放开所有约束。
- 一期相似指标使用动作原生执行频率和有明确玩家身份、适用性及报告证据的关键增益覆盖。持续伤害不纳入相似指标，但照常模拟、计入总伤害与每秒伤害，并保留原有相关正确性验证；不新增事件采集。
- 只有受检完整报告、适用对象注册和序列化规则共同证明的省略才解释为零；未知格式、宠物与玩家身份歧义不视为零。关键增益名单随角色及适用规则固定，不按某个候选是否触发增益临时改变。
- 行为差异由固定参考总执行频率归一化的频率差异与关键增益覆盖平均绝对差组成；两者初始各占一半。适用关键增益名单整体为空时整个比较环境只用频率；不得按单个候选缺项静默退化。

## Testing Decisions
- 最高用户入口：正式页面的开始、继续和结果读取；训练的现有运行命令及公开训练入口。
- 推荐从这些入口验证可观察的参数隔离、成果数量、来源数量、失败和恢复结果；内部演化规则复用现有真实优化器与内存状态测试，不宣称它证明磁盘可靠性或原生报告格式。
- 参数接线使用小型合成数据：训练人数8改10，预筛16改20，发布最多10；正式终评仍8；真实种群9、10、13、15对应窗口6、7、9、10。
- 保留少量现有页面/命令/持久化接线证据；替换旧整代覆盖、稳定代表及五场景的新任务断言，旧成果只读校验继续保留。
- 实际报告字段证据单独核验；不得以合成字段替代现有报告能力证明。
- 最高测试接缝及三票划分已由用户确认；本次仅完成需求发布与复读，尚未运行实现验证或模拟。

## Out of Scope
运行中自动调参；新策略注册框架；额外候选旁路；复制凑人数；通用时序特征；新的事件采集；改变爆发计划或战斗时长；扩大受支持专精范围；实机效果保证；自动合并、发布及主干直接推送。

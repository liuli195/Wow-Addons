# 03：公开结果、恢复兼容与全链交付验收

**What to build:** 用户通过训练命令和正式页面读取实际成果数量、阶段进度、有效样本、预算和可采取行动的错误原因。

**Blocked by:** 01：训练产生可恢复的差异化成果；02：正式页面消费实际成果并进行局部生存竞争

**Status:** ready-for-agent

**实施授权:** 完整门禁一已获用户当次确认；本机按批准分支、模型、顺序与预算实施。

## Acceptance criteria

- [ ] 用户通过训练命令和正式页面读取实际成果数量、阶段进度、有效样本、预算和可采取行动的错误原因。
- [ ] 预算由实际场景数、候选数、批数和请求迭代数推导；区分计划请求、有效样本、缓存命中与新增模拟，不保留固定五场景、八条或十三条上限。
- [ ] 默认训练终评预算由8×5×3×128降为8×1×3×128，仅该阶段减少80%，不得宣称全部训练减少80%。
- [ ] 旧完整快照和报告按原版本可读可验；旧未完成任务不混接新算法或配置，错误说明恢复限制及安全新建方式。
- [ ] 从真实公开入口验证失败不覆盖旧发布、缺凭据补缺、发布故障补发布、正式已完成场景不重跑；保持合理小规模接线与持久化验证，不扩建低收益故障矩阵。
- [ ] 规格、用户说明和预算展示统一到已批准策略；删除被替代的新任务稳定冠军、扰动链、固定发布数量和多余来源逻辑，同时保留旧完整证据阅读能力。
- [ ] 完成仓库要求的适用检查并记录命令、结果及未覆盖边界；不把替身测试宣称原生或游戏实测，不运行新模拟、无限训练或未经批准的安装。
- [ ] 每票独立审查问题已处理，全链公开结果可复核；交付保持功能分支，不自动合并、正式发布或推送主干。

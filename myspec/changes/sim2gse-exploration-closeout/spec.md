# Sim2GSE 探索分支收尾

Status（状态）：ready-for-agent；本机文档检查及独立审查已通过，外部交付等待门禁二。

## 问题

已放弃的多样性探索仍停留在功能分支，部分记录保留旧阶段描述，三份暂停实验材料尚未纳入版本管理。用户要求先保留现有逻辑完成交付，再另开新变更讨论简单列表。

## 交付行为

1. 保持原有遗传算法及独立爆发行为，保留正式数据和历史证据。
2. 同步已确认主干更新，交付撤回结论和恢复记录，明确历史阶段与当前状态。
3. 三份暂停的循环次数实验材料原位、原文字节纳入版本管理；本收尾记录说明暂停状态优先于材料中的旧待实施描述，不将票据标成已完成。
4. 通过统一验证及独立审查后展示交付门禁；获准后创建拉取请求、检查、合并、同步主干并非强制删除已合并功能分支，保留本工作树。

## 决策

仅一个端到端收尾票据，主代理串行实施，全部完成后独立审查。使用完整开发流程，因为涉及同步与外部交付，但不增加产品设计或重做已结束实验。已有会话已确认保留现状、原文纳管、仅文档收尾及新方向另开分支，无未决产品需求。

领域仍使用按键动作块、可按动作、尝试频率等已有词汇；本次不新增领域概念或正式规格。压力场景：旧票据写可实施不代表恢复授权；旧记录写待恢复不否定后文已经恢复；主干文档更新不应被旧分支覆盖；检查未匹配或跳过不能记成通过。

## 验证

目标是仓库交付记录，不改变游戏产品入口。公开检查入口为已安装的统一构建验证程序，固定基线执行差异验证，要求通过且检查清单非空；差异证明产品代码、正式规格和暂停材料字节未变。独立审查覆盖最终基线后的差异与本需求。

同步失败或冲突不强制重置；只在批准范围内解决，涉及产品逻辑则停止。验证或远端检查失败保留证据，不降低检查。合并前工作区须干净，正式数据不参与清理。

## 范围外

一键一技能改造、变异交叉修正、恢复旧局部搜索、训练、模拟实验、游戏验收、正式成果读写、整仓清理和依赖升级。不得提前应用正式规格或提前合并删除分支。

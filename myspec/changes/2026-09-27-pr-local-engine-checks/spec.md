# PR 与本机的引擎检查范围

## Problem Statement

PR（拉取请求）仍准备并构建 SimulationCraft（战斗模拟器）引擎，再运行依赖引擎的 Sim2GSE 测试，远端检查耗时很长。仓库现有完整验证同时承担本机与 PR 两种场景，尚未使用新版 Build and Verify（构建与验证）的场景选择能力。

## Solution

在现有统一检查配置中，将引擎构建及 `verify.sim2gse` 标记为仅本机运行。CI（持续集成）显式使用 PR 场景，使这些检查在 PR 中被排除，保留其他现有检查，并停止远端专为引擎进行的准备、编译和缓存。本机不带 PR 参数时，继续执行原有构建目标和全部 37 项完整验证。依赖私人资料的手工验收继续按原入口单独运行，不加入统一配置。

## User Stories

1. 作为开发者，我希望 PR 不再编译引擎，以缩短等待时间。
2. 作为开发者，我希望引擎相关的自动测试只在本机运行，同时本机完整验证仍覆盖它们。
3. 作为审查者，我希望 PR 继续运行不依赖引擎的插件、素材、文档、开发工具和装备规划器检查。
4. 作为维护者，我希望检查范围由统一配置决定，且输出明确列出 PR 排除的检查。
5. 作为维护者，我希望 CI 不再下载引擎源码、安装编译工具或保存引擎构建缓存。

## Implementation Decisions

- 复用现有 Build and Verify 的检查项 `pr` 布尔字段及调用参数 `--pr`，不另建检查列表或过滤器。
- 引擎构建和单组 Sim2GSE 测试属于本机；不依赖引擎的 Sim2GSEProbe 插件检查继续属于 PR。
- `verify.sim2gse` 是一整个测试组，包含部分不直接调用引擎的用例；本次按用户确认的现有检查粒度整组归本机，不另拆新检查项。
- CI 的完整与固定基线验证均进入 PR 场景；本机入口不传 `--pr`。
- 远端准备保留仍被 PR 检查需要的工具、依赖和资料；移除仅服务于引擎的准备工作。
- 将旧规格中“CI 执行全部本机检查”的约束更新为“CI 执行全部 PR 可执行检查”，并同步仓库操作说明。

## Testing Decisions

- 通过现有统一命令分别检查本机和 PR 场景的 `checked`（已检查）与 `excluded-by-pr`（被 PR 排除）输出。
- 本机完整验证必须实际运行原有 37 项检查；PR 完整验证必须实际运行其余检查，不因无引擎产物失败。
- 核对 CI 入口确实传入 `--pr`，且不再执行引擎专用准备；远端 PR 实际状态检查作为最终证据。

## Out of Scope

- 将依赖私人角色或研究数据的手工验收加入统一配置。
- 改写引擎或其测试内容、削减本机完整验证覆盖。
- 保证 GitHub PR 全流程在 60 秒内完成；实际耗时须单独测量。

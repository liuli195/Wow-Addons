# Sim2GSE 搜索顺序循环与空点击

## Problem Statement

自动搜索目前只生成普通动作块。第三方 GSE 的 Loop（循环）和 Pause（暂停）虽能导入模拟，却不能由搜索生成、评价、选择和导出。

## Solution

让自动搜索生成含最小 `Sequential Loop + Repeat Count`（顺序循环及重复次数）和 `WaitClicks(n)`（等待 n 次空点击）的候选。导出后用锁定 GSE 编译器确定逐次按键计划，同一计划进入原生受控模拟。搜索内部只使用一种暂停表达；Clicks/MS/GCD 的写法在 GSE 边界处理。

## User Stories

1. 作为使用者，我希望搜索实际尝试和评价顺序循环候选，比较循环对结果的影响。
2. 作为使用者，我希望搜索实际尝试和评价空点击候选，比较暂停对结果的影响。
3. 作为使用者，我希望所选候选能导入 GSE，并且编译点击顺序与模拟顺序一致。
4. 作为使用者，我希望不同按键间隔下空点击占用正确的输入时刻。
5. 作为使用者，我希望原有普通动作候选和搜索的预算、选优、复测规则继续有效。

## Implementation Decisions

- 只扩展候选空间及必要的导出和编译适配，不改评分、统计比较、选优、预算或复测算法。
- `Repeat Count` 指整个 Loop 的重复次数，不是独立定期 `Repeat` 块；只开放 Sequential（顺序）循环及已有可模拟动作。
- 搜索内部只用 `WaitClicks(n)` 表示暂停。GSE `Pause{Clicks=1}` 会展开为零步，不得当作一次空点击；候选只能采用能忠实导出的非零等待值。
- 保留候选身份、来源位置、4096 步上限、锁定 GSE 编译核对和原生评价。超限或不一致候选在原生评价前拒绝。
- 现有正式规格禁止高级结构进入搜索，必须在正式规格更新时明确解除本票这两种结构的禁令；其他导入结构仍隔离。
- 对照官方 GSE 3.3.34 与仓库锁定 3.3.32 的相关语义，不升级全部导入协议。

## Testing Decisions

- 最高层公开接缝为页面“开始运行”所调用的 `/api/tasks` 自动搜索入口；核对实际搜索档案、所选候选、导出文本、上游编译计划和原生动作块。导入模式测试不能代替搜索验收。
- 确定性测试覆盖候选确实生成和评价、循环顺序/次数、空点击数、不同按键间隔、来源路径、超限拒绝。点击预期独立取自官方 GSE 源码和测试。
- 回归原有普通动作候选、缓存恢复、预算、复测和导入路径；真实游戏验收单独报告。

## Out of Scope

不新增 Priority/ReversePriority/Random Loop、独立定期 Repeat、复杂宏解释器、`/castsequence`、预训练或新的评分/选优算法。搜索不产生等价的多种 GSE Pause 写法；不重构已有 MS/GCD 导入行为。

# 搜索 Loop 与空点击的实施设计

## 架构结论

自动搜索目前以动作块列表保存候选；`program_key()` 对候选整体取摘要，`candidate()` 经 `select()`、`from_action_blocks()`、`compile_program()` 导出。`program.py` 已有共享的 Loop、Pause 与逐点击节点，但搜索适配器和 `codec.export()` 只接受普通 Action。导入端能模拟这些结构，不能证明搜索会生成它们。

保留现有普通动作候选的形状和入口。搜索候选仅增两种结构化条目：顺序 Loop（子动作块与重复次数）和 `WaitClicks(n)`（n 个空点击）。候选生成及变异可以产生这些条目；键、任务恢复和比较仍使用原有通用候选摘要及预算规则。`WaitClicks` 是搜索语义，导出边界才转换为 GSE `Pause`；本票不产生 `MS` 或 `GCD` 写法。

## 编译与评价路径

1. 搜索候选适配到现有 `Program(adapter="search")`，动作、Loop 和等待节点均带 `source.adapter="search"` 与稳定路径；Loop 的 `Repeat` 是整个子序列的重复次数，不创建独立 `RepeatNode`。
2. 导出边界把同一树编码为 GSE Action、`Loop{StepFunction="Sequential",Repeat=count}`、`Pause{Clicks=n}`。普通动作路径保持原有导出结果；结构化路径使用仓库锁定的 GSE 3.3.32 编译器及现有源码散列锁，读取其真实逐点击结果。Loop/等待的来源计划与实际步骤逐项核对，超过 4096 次点击或无法映射时先拒绝。
3. 只把核对后的一个 `CompiledProgram` 连同导出文本交给既有 `sequence.compiled_program()` 与 `evaluate()`；空点击对应空动作块，沿用既有 `input_interval_ms` 生成输入时刻。不能在原生评价中再次解释 Loop 或 Pause。
4. 保持现有评分、胜者判断、预算、复测和缓存验证逻辑；候选键包含控制结构及参数，批次请求继续包含核对后的编译计划。结构化候选在原生评价前完成导出合法性检查。

## 两张纵向票据

**01 顺序循环：** 从普通种子可到达含连续动作与重复次数的候选；公开 `/api/tasks` 自动搜索入口证明其被编译、评价和导出。独立预期取自 GSE 官方 3.3.32 与 3.3.34 源码及循环测试，断言展开顺序、次数、精确来源和超限拒绝；普通候选继续通过。

**02 空点击：** 在票 01 的结构化路径上增加 `WaitClicks(n)` 生成与调整。GSE `Pause{Clicks=1}` 展开为零步，故搜索只产生可忠实导出的非零等待值；不同 n 的候选身份不同。公开入口断言导出后的空点击数、来源和 300/600 毫秒等不同按键间隔所占的输入槽位，核对原生实际动作块。

每票先在同一公开入口写出可观察红灯，再做最小修改并转绿；逐票提交后以固定提交范围独立审查。导入端的既有 MS/GCD 行为和正式 `myspec/specs/` 暂不修改。正式规格中的“高级结构不得进入搜索”与本需求冲突，实施验证完成后在规格交付阶段只针对这两种结构提出修订。

## 已知风险

- 现有搜索 `select()` 不接受空动作块，不能直接把 `WaitClicks` 当普通块塞入。边界须保留空点击与来源，再由核对后的编译计划喂给原生模拟。
- GSE 官方未给 Loop.Repeat 设置 128 上限，而本地导入适配器有额外限制。本票只生成很小的重复次数并沿用 4096 点击硬上限，不借机扩展第三方导入协议。
- 真实客户端验收与离线 GSE 编译、原生模拟分开报告；本次本机通过不等于游戏内通过。

# 搜索预算与诊断记录减负

Triage（分拣）: ready-for-agent

## Problem Statement（问题）

用户希望在固定角色、装备、场景和按键节奏下，利用累计十分钟找到伤害更高的序列。最终五节奏复测及失败后回退不再符合目标；默认运行不应承担仅为事后分析而产生的记录和额外模拟成本。

## Solution（方案）

实施用户确认的五项：详细记录默认关闭、轻量进度更新、合并重复完整状态保存、保留位置修复必需数据但关闭额外诊断、删除最终复测。新增统一名称“诊断日志总开关”，默认关闭并优先于各诊断细分开关。

## User Stories（用户需求）

1. 用户关闭诊断日志总开关时，不保存详细过程、动作轨迹、诊断报告和性能统计。
2. 用户关闭总开关时，不仅为了收集记录额外运行模拟。
3. 用户仍能使用位置修复；算法必需轨迹仅用于计算，保留需要的反馈，不长期保存详细轨迹。
4. 用户仍能避免重复模拟，正常取消和继续，且不会重复计数或重置预算。
5. 用户能看到轻量进度和最终结果，不需要每半秒将完整历史写入磁盘。
6. 用户的十分钟预算不再预留三分钟最终复测；初始化、编译、搜索和搜索内比较仍计入累计预算。
7. 用户直接得到搜索选中的最好序列，不因其他按键节奏的最终复测回退到初始序列。
8. 用户显式打开总开关后，才允许细分设置启用额外记录。

## Implementation Decisions（实施约定）

- 保留现有局部修改、伤害选优、合法性检查和去重机制；不开启可执行性拦截，不增加跨节奏稳定性评分。
- 区分算法反馈、结果复用与恢复必需数据、额外诊断记录。主开关只支配第三类，不影响第一、二类。
- 轻量更新仍须保留累计耗时和停止状态；必要的批次预约、成功结果与搜索决策必须可靠保存。不能用减少保存次数换取恢复丢结果或免费预算。
- 总开关关闭时，细分诊断配置不能绕过总开关；不得产生仅服务于诊断的模拟作业。
- 算法所需模拟可临时产生输入和轨迹文件，但计算结束后不将详细轨迹作为诊断历史保存。成功缓存保留核验所需原生报告。
- 删除强制最终复测、三分钟预留及复测失败回退。预算不足或用户取消时只利用已经完整评分且可导出的结果，不将半份报告计为成功。
- 改后代码不原地续跑条件不同的旧任务；保留旧文件，按已有条件核验拒绝混用，不自动迁移历史实验。
- 报告搜索成绩、样本和自由选招参考，不声称独立复测通过或真实游戏验收通过。

## Testing Decisions（验证约定）

- 最高公开入口为页面创建任务接口；通过它和现有任务运行、取消、继续及读取入口验证，不只测内部函数。页面参数与结果说明同步更新，旧结果仍可读取。
- 先写失败测试，再改实现；覆盖总开关优先级、无额外诊断文件和模拟、位置反馈保留、轻量保存、取消与恢复、预算、无最终复测与回退、最终导出一致性。
- 使用相同候选与随机条件比较记录开关，核对评分、候选选择和导出行为；固定工作量测写入次数、耗时和文件量，不以固定十分钟内开关两侧候选数必然相同作为要求。
- 复用原生引擎做短实测验证真实文件路径和反馈；运行仓库统一相关检查。不重跑五小时全量搜索，不预设伤害改善百分比。

## Out of Scope（不做）

新搜索引擎、新评分体系、新可执行性门槛、删除历史数据、游戏部署、远端推送与合并。

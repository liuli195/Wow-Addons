# 人工起点训练显式四并发

## Problem Statement

人工起点训练的同层候选评分被限制为最多两个单线程引擎。维护者希望在不打断当前五目标训练、不改变评价规则的前提下，明确选择四并发并用相同工作量验证实际收益。

## Solution

训练复用既有内部TOML（配置文件）中的独立训练区域，默认并发2，可直接调整1至16，CLI（命令行）参数可覆盖本次配置；16是现有每轮最多候选数。启动时冻结实际配置，不在运行中热更新。复用现有同层评分执行器，仍按原顺序使用成绩，整层结束后筛选。普通搜索默认及显式可选上限保持2，原模拟配置读取容忍新增训练区域。

训练与成绩身份排除仅改变调度的并发数，使用角色、引擎、程序、随机条件、样本、评分与停止规则及既有语义版本区分。源码摘要继续记录出处，不将日志或调度代码的原字节变化直接当成算法变化。旧批次仅在完整原输入与原条件重建一致、既有来源已明确核验后沿用原条件、目录及请求缓存命名空间；保留旧记录，另记实际配置及执行来源，不伪称新源码原式哈希等于旧值。真正语义变化或不能证明的来源仍拒绝。

## User Stories

1. 作为维护者，我希望人工训练可显式选择4个单线程评分进程，以验证同层评分的收益。
2. 作为现有使用者，我希望省略新参数时仍为2并发，以保留现有默认行为。
3. 作为维护者，我希望非法并发值在计算前被拒绝，以避免不受控资源使用。
4. 作为维护者，我希望乱序完成的候选仍按原顺序使用成绩，以保留评分和筛选规则。
5. 作为维护者，我希望取消、失败和恢复仍保留完整成功批次，以避免丢失结果或重复计算。
6. 作为维护者，我希望只调并发仍复用可靠完成成果，并记录实际执行差异，以免重训并保留出处。
7. 作为维护者，我希望用相同候选、样本和随机条件对照2与4，以区分调度收益和增加工作量。
8. 作为维护者，我希望本机当前五目标训练继续原条件运行，以避免开发干扰现有计算。

## Implementation Decisions

- 使用现有同层候选评分执行器；仅训练路径允许1至现有每轮上限16，普通任务、恢复和双场入口仍校验最多2；不引入新调度器或依赖。
- 复用现有内部配置根和读取能力；训练公开命令、训练公开调用及实际训练配置传递并发值，缺省2，明确命令行值优先。内部配置每次启动读取一次，普通模拟读取忽略训练区域。
- 每个引擎仍使用1个线程；同层结果顺序、整层后筛选、晋级复核和独立复测保持原行为。
- 每候选600秒预算、16候选完整轮次、连续两个完整无改善轮次、候选总上限保持。
- 训练语义身份排除并发数和全部任务规则的原字节摘要，保留现有训练、搜索、统计及候选行为版本；算法实际变化须明确升级相应版本。真实参数或语义改变不得复用成绩；普通任务严格恢复身份不改。
- 在既有批次旁保存必要的完整条件输入、源码出处和实际执行段；旧批原输入须重建且摘要匹配原条件，受核验后沿用原目录及请求键，随机状态、已用预算、已完成批次和旧成果保持。拒绝未知旧来源，不扫描迁移全库。
- 升级核验复用同一身份验证器，分别检查语义兼容、旧命名空间及实际出处，不按当前完整配置重新计算旧哈希误拒合法旧成果。
- 云端沿用当前工作树和固定基线，沿用 `codex/seed-training-parallel-four` 功能分支；不修改本机当前训练工作树。

## Testing Decisions

- 唯一最高层公开接缝为训练命令入口 `seed_training.main`（人工起点训练命令）。从 `run --max-processes 4` 穿透到真实训练配置和同层候选评分。
- 复用现有构造角色、真实独立数据中心测试副本和引擎外部边界；不伪造产品内训练、评分或条件身份实现。
- 先通过该入口取得最小失败检查，再做最小实现，再运行同一检查转绿。验收内部值4/16、默认2、命令行覆盖、非法值、最大同时评分数和原顺序消费；普通任务、恢复及双场显式4仍拒绝，普通模拟区域不受新训练区域影响。
- 复用已有取消、失败、恢复检查；只调并发复用可靠完成成果，受核验旧批保留随机状态、已用预算及成功请求，另记执行段。真实模板、引擎、随机条件、评分或语义版本变化必须拒绝复用；缺失、篡改及未知旧凭据不得通过。
- 同工作量对照使用同一分支、角色、候选顺序、随机条件、样本量和预算，分别取2及4；数据项目和工作目录独立；新规则下2与4的语义条件相同。比较相同完整评分批次数、样本数、成绩与顺序及耗时，失败和取消不记为性能成功。
- 云端只记录实际可执行的检查，不将Linux（云端系统）替身诊断当Windows（目标系统）真实引擎验收。现有命令依赖Windows锁及受检引擎；本机专项验证由隔离分支执行且不得干扰当前训练。
- 正式验证使用现有统一入口、干净提交和固定基线；缺工具、平台不兼容与未运行分别报告，不能以跳过冒充通过。

## Out of Scope

- 跨材料、跨场景调度，独立复测六批并行，新存储、无凭据身份例外、全库迁移、评分或收敛规则修改。
- 普通搜索默认四并发，预算增加，调整引擎线程数，完整材料重训。
- 中断当前本机训练，切换本机运行代码，合并主干、正式发布或修改远端设置。

# 01: TC 服务端请求队列双场对照

Status（状态）: closed; negative comparison result retained
Blocked by（阻塞任务）: None（无）

## What to build

从现有序列评估入口显式选择 TC 服务端施法请求队列策略；保持默认策略及 GSE 步进、SimC 结算不变。用同一最终序列对旧、新两场按键时序分别运行基线与 TC 策略，输出可复核轨迹和事后评分。

## Acceptance criteria

- [x] TC 准入、单槽替换、取消与可执行时取出按固定上游源码和默认 10ms 地图更新间隔建模；窗口外拒绝不改动旧请求，资源和技能自身冷却不在准入时预判。限本次序列不含引导法术的路径；实际服务器更新相位未知。
- [x] 最高层序列评估入口红灯转绿；默认策略、物品顺序、自动攻击和禁用控制模式回归通过。
- [x] 两场各自只传入探针按键时刻，同一最终序列、角色、种子 `20260914`，不传实测状态；模拟输出冻结后才评分。
- [x] 报告两场技能集合差异、成功频率差异率、时序一致／不一致率、相对固定基线变化及首个分叉；负收益也如实报告。
- [x] 保存源码身份、输入、轨迹、构建和验证证据；若实验无法覆盖 TC 的客户端或网络行为，明确限定结论。

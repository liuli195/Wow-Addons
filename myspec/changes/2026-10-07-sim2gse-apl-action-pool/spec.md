# 第四阶段第一步：解耦完整 APL 搜索池与基准起点

Triage（分拣）: ready-for-human
Status（状态）: implemented-awaiting-delivery（实施与验证完成，等待规格与交付确认）

## Problem Statement

当前搜索仅允许原生基准实际执行过的可按动作。默认 APL（动作优先级列表）的单体分支没有使用某个动作，并不证明固定按键序列使用它没有收益。已观察到五目标产物在统一单目标条件下高于单目标产物，而单目标搜索无法生成其中的合法动作。

## Solution

复用固定 SimC 已实例化的完整默认 APL，识别当前角色合法且 GSE 可表达的可按动作作为搜索目录；继续使用本次基准实际执行目录及轨迹作为原有起点依据。用户选择的目标数量仍决定评分条件。

## User Stories

1. 用户从现有页面提交角色搜索时，合法动作不会仅因本次基准未执行而被永久排除。
2. 用户仍获得原有基准派生起点，不因搜索目录扩充而暗中更换起点策略。
3. 用户无需维护全技能书或职业白名单，控制命令、派生效果和当前角色不具备的动作不会作为新增按钮。
4. 新目录中的候选能够通过现有编译、受控评分和导出流程；失败不得被记录为成功。
5. 旧结果保留；引擎或目录契约变化时，旧任务不得以新条件原地恢复。

## Implementation Decisions

- 保留现有模块和公开任务入口，不新建候选池框架或 APL 文本解析器。
- 搜索目录与基准起点目录分别表达；已有按钮规范身份、替换形态及真实装备物品处理继续复用。
- 优先通过仅用于基准引擎的报告补丁提供完整 APL 目录，保留已执行动作统计原义。仅基准源码身份需要变化；统一构建工具可能检查或构建两个模式，不新增构建模式。
- 不按瞬时资源、冷却、目标条件或执行次数筛掉合法可按动作；不将 APL 的条件逻辑搬进 GSE。
- 普通默认序列与四类已有起点继续使用基准目录；变异和候选表达使用完整目录。
- 报告协议缺失或原生可按动作无法支持时明确报告，不能静默回退旧目录并宣称完整。
- 评分、晋级、预算、停止规则、现有算子概率及战前空点击语义保持不变；扩池自然允许候选变化，不承诺固定预算必然提高伤害。

## Testing Decisions

- 最高用户入口为页面自动搜索任务；自动检查复用公开任务入口、现有引擎报告适配及起点黄金样例。
- 固定邪恶角色单目标样例的完整目录须允许合法但未执行的枯萎凋零及 epidemic；原起点保持一致。
- 用确定性候选验证新增动作能够编译、评分和导出，不要求随机搜索必定选中某技能。
- 用最少代表样例覆盖非按钮过滤、未选天赋、替换形态、真实主动饰品及协议不兼容；逻辑检查优先内存内，复用现有测试，不建设新框架。
- 原生基准同条件伤害与轨迹不得因报告扩展改变；受控引擎身份应保持不变，若统一构建产生差异须先查明。
- Windows 按仓库统一入口做本机必要验证，维持六十秒预算；全量检查留在 CI。原生构建与功能模拟按现有独立流程报告，不冒充本机快验耗时。

## Out of Scope

- 人工或历史种子接入、自适应算子、交叉重组、退火、重启及停止条件修改。
- 一键辅助或全技能书枚举、全职业能力平台、额外多场景能力发现模拟。
- 导入序列 nocombat 支持缺口、游戏设置及正式服效果验证。
- 把默认 APL 声称为角色全部合法技能全集。

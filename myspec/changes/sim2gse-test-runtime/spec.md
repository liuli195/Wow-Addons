## Problem Statement

Sim2GSE（角色级按键序列优化器）的 PR（拉取请求）必需检查目前约需 8 分钟。70 项测试中，多项只验证搜索状态、结果发布或职业兼容条件，却重复执行完整的原生基准、搜索、复测或浏览器流程，使真实 SIMC（模拟引擎）工作超出对应断言所需范围。

## Solution

先只简化测试内部：复用现有构造报告、标准库替换工具、临时目录和 SQLite（轻量数据库）接缝，让每项测试仅执行其断言需要的真实层级。保留一个完整浏览器真实任务、一个完整搜索复测，以及全部原生序列和 Windows（操作系统）资源边界检查。业务实现、模拟预算和测试覆盖含义不变。

## User Stories

1. 作为维护者，我希望 PR 必需检查在 Runner（运行机器）启动后三分钟内完成，以便快速获得可靠反馈。
2. 作为维护者，我希望状态机、缓存和结果发布测试使用确定性构造输入，以免无关的真实战斗耗时和机器负载改变结果。
3. 作为维护者，我希望原生序列、进程树、句柄和文件共享行为继续经过真实边界，以免加速测试掩盖集成缺陷。
4. 作为维护者，我希望完整浏览器和完整搜索复测各保留一条最高层贯通路径，以证明用户入口仍连接真实任务。
5. 作为维护者，我希望远端检查报告完整测试数量和实际用时，以便确认加速没有漏测并判断是否达到目标。

## Implementation Decisions

- 不新增生产环境的内存引擎、存储接口或测试专用业务分支。
- 搜索协调测试在模拟结果生产接缝注入构造成绩或事件，继续执行真实选择、恢复、缓存和发布逻辑。
- 缓存散列、SQLite 恢复和原子文件发布继续使用真实临时存储，不伪造成纯内存文件系统。
- 序列测试复用相同角色的基准、能力和候选准备；每项需要原生轨迹的断言仍运行真实受控引擎。
- 职业兼容场景不再重复完整浏览器、断网、搜索、复制和清空流程；它们改走满足各自断言的最高公开 Python（编程语言）入口。
- Windows 进程所有权、进程终止、句柄释放、文件共享冲突及浏览器进程树清理继续使用真实操作系统边界。
- 第一阶段不增加外部 Runner 分片；若远端实测仍超过三分钟，返回需求阶段，使用实测证据决定下一步，而不是预先扩大范围。

## Testing Decisions

- 最高层测试接缝是完整 Browser → Service → Task → SIMC（浏览器、服务、任务到模拟引擎）路径，保留一条真实成功路径和必要的界面错误路径。
- 搜索复测保留一条真实 `run_task`（运行任务）贯通路径；选择、反馈、缓存和恢复分支通过其现有依赖接缝获得确定性输入。
- 原生控制器的排队、施法、饰品顺序、重放和关闭等价性仍通过真实 `sequence.evaluate`（序列评估）验证。
- 完整测试仍应报告 70 项测试和 31 项子测试；若因合理合并或参数化使数量变化，必须逐项证明原断言均被保留，不能只比较总数。
- 本机记录修改前后的相同命令耗时；远端以 PR 必需检查从 Runner 启动到通过不超过 180 秒为目标，不包含平台排队。

## Out of Scope

- 修改 Sim2GSE 产品行为、搜索算法、模拟次数或时间预算。
- 用假引擎替换所有真实 SIMC 契约测试。
- 第一阶段增加 GitHub Actions（自动化流水线）矩阵、付费运行机或自托管运行机。
- 承诺缓存失效后的首次完整编译或 GitHub 平台排队在三分钟内完成。

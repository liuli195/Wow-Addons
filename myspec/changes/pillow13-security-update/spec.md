# 图像依赖安全升级与素材兼容验收

**Status:** ready-for-agent（完整门禁一已确认，实施中；未验收或合并）

## Problem Statement

仓库当前图像依赖版本受到上游已公布安全问题影响。已有升级拉取请求包含修复版本，但落后当前主干；旧检查结果不能证明当前仓库组合通过。新版图片缩放行为可能改变重新生成的像素，仅成功生成文件或通过旧成品检查，不足以说明新输出符合既有素材意图。

## Solution

沿用现有升级拉取请求，将图像依赖从 Pillow 12.3.0 更新为 13.0.0，在当前主干组合上取得真实验证结果。对受缩放变化影响的少量现有素材说明尺寸、透明度和像素差异；外观仍应符合已确认的轮廓、位置和透明意图。不预设所有像素必须完全相同，也不默默接受无法解释的变化。

## User Stories

1. 作为仓库维护者，我希望使用已包含已知安全修复的图像依赖，降低继续使用受影响版本的风险。
2. 作为维护者，我希望升级沿用原有拉取请求，而不是产生重复的升级交付。
3. 作为维护者，我希望看到升级与当前主干组合的实际检查结果，而不是把旧绿灯当作新结果。
4. 作为素材使用者，我希望重新生成的图片仍保持既有尺寸、轮廓、位置和透明意图。
5. 作为维护者，我希望任何图片差异都有明确解释，必要时才查看局部外观并处理退化。
6. 作为准星界面使用者，我希望现有游戏素材格式、完整缩小层和原始透明度约束继续成立。
7. 作为维护者，我希望缺少原图、依赖不可用或检查失败时明确停止，而不是把未运行写成通过。
8. 作为维护者，我希望调查和验证不覆盖设计原图、不批量替换正式成品，也不触碰游戏安装与个人设置。
9. 作为维护者，我希望本次单依赖升级不改变已确认的验证覆盖、性能预算和安全保护。
10. 作为维护者，我希望最终得到可复核的版本、差异和检查证据，合并决定仍单独确认。

## Implementation Decisions

本需求只约定上述可观察结果，不规定内部代码结构。技术范围、公开验证接缝与实施次序另记在唯一票据中。兼容指符合现有素材契约，不等同于无条件的逐像素相同；生成成功不等同于素材验收成功。

## Testing Decisions

从现有公开素材构建和检查入口验证升级后的实际结果；少量同源图片的前后对比作为补充，不替代完整公开入口。检查尺寸、可见轮廓、透明区域和像素差异；差异必须解释，发现可见退化时处理后重验。复用现有准星素材格式、完整缩小层与透明度检查，不增加无关组合矩阵。未运行、失败、被排除和通过分别报告；本地图片检查不能冒充全部游戏分辨率验收。

## Out of Scope

不新增素材、不重做设计、不批量重生成或提交正式图片；不扩展角色按键序列优化器实验、不重编产品引擎、不复制数据中心或整套环境；不调整既有并行配置、六十秒预算和安全保护；不改变游戏运行行为、不部署、不合并或发布、不忽略机器人升级、不关闭安全规则。

## Further Notes

安全事实依据为 [Pillow 官方公告 GHSA-v9pv-5gc8-w2m6](https://github.com/python-pillow/Pillow/security/advisories/GHSA-v9pv-5gc8-w2m6)：受影响版本包括当前 12.3.0，修复版本为 13.0.0。此事实不表示仓库已经遭到利用。本变更不改变现有正式素材规格；正式规格如需增补，只能在最终第二门禁预览并确认后处理。

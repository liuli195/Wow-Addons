# 04：把可模拟的导入序列送入原生 DPS 模拟

Label（标签）: change:task
Triage（分拣）: needs-info
Status（状态）: blocked

## What to build

用户选定导入序列和版本后，当前角色可按动作得到严格映射，逐次按键计划驱动原生受控引擎；不可映射动作在模拟前被拒绝。

## Blocked by

03：按上游语义编译全部 GSE 控制块。实现完成；仍缺一个能严格映射的真实第三方序列作为本票真实 DPS 验收样本。

## Acceptance criteria

- [ ] 可模拟的邪恶死亡骑士样本从真实导入字符串获得 DPS 报告、逐次输入轨迹与条件摘要。
- [x] 空点击占用输入，动作块、来源路径和原生回报保持一致。
- [x] 未知技能、物品、条件、宏命令或环境依赖不进入伤害模拟且有具体诊断。
- [x] 角色原始输入及导入字符串可追溯；现有优化与单次评估行为不变。

## Completion evidence

第二、三、四项由公开导入任务入口与 145 个 Sim2GSE 测试（另含 52 个子检查）验证：固定上游生成的动作/空点击保持输入次数和源路径；未映射技能在服务任务中失败且不产生导入 DPS 字段。任务可能先运行角色参考轮转以取得原生身份和能力清单，但失败导入不会运行受控序列伤害模拟。任务保留 `input.original.simc`、`input.gse`、序列与版本、SHA-256、来源路径及编译场景。旧搜索候选仍走原 codec 适配，公开搜索任务回归通过。

真实 DPS 条件尚未满足。原有 9 条不同真实原串、11 个成员均已检查；追加两位公开 DK 作者的 3 条原串、4 个成员，来源和摘要记录在 `docs/sim2gse/gse-import-corpus.md` 及本机忽略目录 manifest。新增成员分别因未映射的 spell 316239、`[nochanneling]`、`[channeling]` 和无法验证的 `@player` 目标而在受控模拟前被拒绝。原样本阻断也按成员记录于语料文档；未猜测 316239/1247378，没有把 `item 13` 当成空点击，也未修改伤害模型。按有界采样要求停止继续寻找来源。

精确 `/targetenemy [noharm][dead]` 规则能让候选编译继续到后续真实动作，但没有让四个追加成员进入 DPS：它们分别暴露了上述更深层阻断。故本票保持未完成；需要一条真实序列仅使用当前已映射动作和已验证命令，或由需求方另行调整真实 DPS 验收范围。

# Sim2GSE 第三方 GSE 序列导入与模拟

## Problem Statement

2026-09-25 范围修订：本分支验收锁定 GSE 3.3.32 的导入格式、无损结构解析与 GSE 控制语法；WoW 宏命令的完整解释和由宏阻断的 DPS 不属于本分支验收。以下原始目标与历史票据作为过程证据保留，若与本修订冲突，以本修订为准。

Sim2GSE（角色级按键序列优化器）目前只会生成简单动作块，不能把外部作者发布的 GSE（高级按键序列插件）导入字符串作为输入进行 DPS（每秒伤害）模拟。第三方序列可能包含多个版本、嵌套循环、定期重复、暂停、条件块、嵌入序列、变量及宏命令；如果只凭一条样本设计解析器，容易遗漏合法结构，且把未知含义静默略过会产生虚假的成绩。

## Solution

本次剩余工作是用锁定上游导入器逐项复核合法外壳、字段和控制块，补齐发现的格式缺口，保持宏原文可追溯；把已有的有限宏命令处理从 GSE 控制模块剥离，保持现有行为与拒绝原因，不扩充宏语义。将来源、可借鉴部分、许可限制及本次验收矩阵写入仓库文档。

用户在本机界面提供角色资料和一条或一组 GSE 导入字符串，选择目标序列与版本后，系统完整解码并无损解析锁定 GSE 版本支持的全部语法，展示名称、版本、全部原始字段、语法清单及可模拟性。解析成功与可信模拟分别判定：只有在序列已编译成可核对的逐次按键计划，且全部可按动作都能映射到当前角色并可由原生受控引擎表达时，才运行 DPS 模拟；其余情况返回原文位置、具体原因及对 DPS 的影响，不给出虚假的 DPS。

## User Stories

1. 作为本机用户，我希望粘贴第三方 GSE 导入字符串，先检查完整结构；若角色和运行条件足以忠实执行，再发起模拟以比较序列伤害。
2. 作为本机用户，我希望导入集合中多个序列和单序列的全部版本都能列出，并明确选择目标，以免模拟错误版本。
3. 作为本机用户，我希望 Action、Repeat、Loop、Pause、If、Embed 六类块和嵌套结构都被解析并显示，以便知道导入内容是否完整。
4. 作为本机用户，我希望常见的顺序、优先级、反向优先级与随机步进按 GSE 规则处理，以便按键顺序可信。
5. 作为本机用户，我希望定期重复和暂停占用正确的点击次数，以免 DPS 被错误放大。
6. 作为本机用户，我希望 If 条件和 Embed 引用能被保留、验证并在条件明确且依赖齐全时模拟，以免悄悄选错分支或漏掉子序列。
7. 作为本机用户，我希望宏、变量、修饰键和环境依赖不能准确求值时看到清楚的拒绝原因，以免误把估计结果当实机结果。
8. 作为本机用户，我希望同一角色的可按动作按角色能力核对，未知技能、物品或条件不会被静默删除。
9. 作为本机用户，我希望看到源字符串摘要、GSE 版本、目标序列与版本、编译结果和模拟输入条件，以便复核和复现。
10. 作为开发者，我希望多条公开真实导入样本覆盖主要语法及不同作者写法，以便验证解析和上游行为一致。
11. 作为开发者，我希望当前搜索生成的简单序列也走可复用的序列程序与编译边界，以便以后加入 Repeat、Loop、Pause，而本期不改变搜索空间和选择结果。
12. 作为结果使用者，我希望导入失败或不支持的语义在模拟前终止，原始角色输入与导入字符串仍可追溯。
13. 作为开发者，我希望每条已收集第三方原串的每个成员和版本都在最终代码上经过解码、无损结构解析及模拟能力核对，以便发现只在真实作者写法中出现的遗漏；无法执行宏不影响结构解析结论。
14. 作为结果使用者，我希望无法解析或无法忠实模拟的原串列明准确原文、位置、原因和需要补充的条件，以便决定是否接受该限制。

## Implementation Decisions

- 本分支“支持完整 GSE 语法”指对锁定 GSE 3.3.32 可接受的导入外壳、序列与集合对象、六类块及合法字段组合进行无损识别，能通过公开检查入口列出全部成员、版本、字段和原文；GSE 控制展开继续对照锁定上游。解析成功不要求每个宏、游戏内变量、宠物动作或角色技能都能执行，也不要求每条原串有 DPS。
- 集合内普通 `!GSE3!` 编码序列和普通编码的独立 `VARIABLE/MACRO` 对象属于锁定上游可接受的外壳，应纳入结构验收；它们的宏正文仅保留，不执行额外语义。未知未来版本或类型仍明确拒绝。
- 当前有限的宏条件和命令处理可保留，但其解释逻辑须与 GSE 导入、控制展开分开；仅移动现有行为，不新增条件、命令或场景能力。

- 以仓库锁定的客户端版本和固定 GSE 上游版本为兼容目标，先检查当前上游发行版和真实样本的格式差异；如需升级兼容锁，另行记录源版本与哈希。
- “全部语法”以锁定 GSE 3.3.32 上游可导入结构为界，包括六类控制块的全部合法字段、嵌套、步进、成员、版本、变量和宏原文，以及上游支持的普通与受保护导入外壳。不得以“六类块名称能识别”代替无损结构解析；超出锁定版本的输入须给出明确兼容诊断。
- 样本优先收集适用于 12.1 正式服的邪恶死亡骑士公开导入字符串，再用其他职业覆盖语法缺口。记录来源、发布日期、声称适用版本、GSE 版本、散列和语法特征；只存测试所需的允许再分发内容，无法确认授权的原文放在被 Git 忽略的本机样本库，并保留可重取的链接与摘要。
- 导入采用严格的大小、层数、节点数、展开步数和引用环上限；区分无效编码、合法但不支持的版本、可解析但不可模拟、可模拟四种结果。
- 解码与结构解析保留每条原串全部成员和版本的原始字段、原条件表达式、禁用状态、宏文本与来源路径；畸形结构和未知块不得静默转换成空步骤或其他块。统一的序列程序表示动作、空点击、控制节点及来源映射。编译层从程序生成逐次按键计划；搜索的现有简单动作块只作适配，搜索变异和选择策略不加高级语法。
- 使用固定上游 GSE 编译行为作对照，验证控制块展开、版本选择与字节协议；绝不执行第三方 Lua（脚本语言）代码。If 条件、变量、宏和嵌入依赖仅在可确定、可核对的语义下进入模拟；其他情况明确标记为不可模拟。
- 原生受控引擎继续承担伤害计算。逐次按键计划含空点击，来源位置和时序在评估前后核对；不把无法表达的控制语义近似成普通轮转。
- 页面增加独立导入评估入口，保留现有优化入口和默认搜索行为。任务结果分别展示导入状态、编译状态、模拟状态和错误位置。

## Testing Decisions

- 最高层语法验收入口为页面使用的 `POST /api/gse/inspect`：检查锁定上游全部合法外壳、六类块、字段保留、路径与明确失败。以固定上游向量覆盖真实语料缺口，标明合成证据；最终在现有全部 16 个原始文件的每个成员和版本复跑。完整语法结论不由 16 个样本单独推出。
- 宏剥离用现有公开检查和导入任务入口做行为回归：原有可模拟宏仍可模拟，原有不支持宏仍在同一位置拒绝，不以 DPS 成败评价 GSE 语法覆盖。

- 优先从公开任务入口和本机页面接口检查真实用户行为，辅以上游协议与编译的对照检查；测试预期独立于本机解析器的实现。
- 样本矩阵至少覆盖单序列、集合、多版本、六种块、嵌套、不同步进、重复间隔、点击与毫秒暂停、变量与宏命令、嵌入引用、畸形输入和资源限制；一条样本可覆盖多项，但不得以单条样本代替整个矩阵。
- 所有已收集原串按摘要逐成员、逐版本在最终代码上复跑，分别记录解码、无损结构解析及可模拟性；已具备的编译、角色映射和 DPS 证据另列，不要求全部样本完成这些阶段。真实第三方样本与合成语法样例分别统计。
- 每个拒绝结果列明原始语句、成员、版本、块路径或宏行、无法处理的确切原因、对模拟结果的影响及所需角色或运行条件；记录对应代码提交和角色资料摘要。
- 对既有可模拟样本做行为回归，核对导入字段、GSE 上游编译步骤、逐次输入、原生解析动作块和 DPS 报告；对不可模拟样本核对未启动原生受控评估且给出准确原因。这是保留现有行为的检查，不是全部 GSE 语法的 DPS 验收。
- 搜索回归比较固定基线下候选键、导出序列、编译步骤和选择结果；确保本期搜索不产生高级语法。
- 完成聚焦测试、仓库统一验证和独立审查；游戏内验收状态照实标记，不作为本期 GSE 结构解析验收条件。

## Out of Scope

- 不实现完整 WoW 宏解释器，不扩大现有宏条件或命令支持，不以 12.1 邪 DK 原串取得 DPS 作为本分支交付条件。原 08 票保留为后续范围记录，不阻断本次 GSE 语法验收。

- 本期不把 Repeat、Loop、Pause、If 或 Embed 加入搜索生成、变异或选择。
- 不尝试在本机模拟任意第三方 Lua、游戏内实时插件状态、不可观测的修饰键/目标状态或不受控的随机性；这些条件无法确定时拒绝 DPS 模拟。
- 不修改角色伤害模型，不承诺本机模拟等于真实游戏结果。
- 不在未获得第二道交付门禁授权前更新正式规格、提交 PR（拉取请求）、合并或清理分支。

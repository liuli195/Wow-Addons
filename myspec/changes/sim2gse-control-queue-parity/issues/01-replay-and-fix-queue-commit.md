# 01: 真实按键时序独立模拟验收与队列承诺修复

Status（状态）: in-progress
Triage（分拣）: ready-for-agent

## What to build

让同一最终序列分别按旧／新两场探针按键时间独立模拟，保留战前首击状态，修正队列承诺后客户端冷却预测相对原生执行时钟的累积漂移；从最高层序列评估入口返回可复核轨迹。探针在模拟前只提供按键时间，模拟完成后才提供成功技能序列用于评分；其他实测状态不得进入模拟输入。

## Blocked by

None（无，可立即开始）

## Acceptance criteria

- [x] 最高层真实时间戳回放在修复前稳定复现首个 GCD 技能过早执行，以及 `putrefy` 被后续技能错误替换。
- [x] 战前首击产生的 GCD 在开战输入时间线上保留，不再由独立战前执行后清空。
- [x] 轨迹明确记录排队、暂定锁定、确认执行、失败候选恢复和实际执行；已锁定动作不能再被后续输入替换。
- [x] 队列承诺只接收通过原生可用性、资源、冷却和窗口检查的动作，不破坏非 GCD、读条、不可用动作和自身冷却行为。
- [x] 同一候选和固定种子分别按两场真实输入时刻做事后诊断回放，并报告成功次数、技能频率与 LCS（最长公共子序列）时序一致率；该结果不作为新验收值。
- [x] 现有候选结构、序列评估入口、搜索、评分和导出结果保持不变。
- [x] Sim2GSE 针对性测试与仓库规定验证通过；实际游戏验收仍单独报告。
- [ ] 从最高层序列评估入口按同一最终序列、角色资料、种子 `20260914`，分别以旧／新两场各自的探针点击时刻运行 180 秒；三个反馈参数均不传入，保存两场完整的模拟输入、命令与引擎身份、原生报告和轨迹。两场模拟输出冻结后才读取各自探针的成功序列评分，战斗日志不参与模拟。
- [ ] 连续多轮队列承诺不得使客户端冷却预测相对原生可执行时刻累积领先；最高层入口先红后绿，并验证修复只依赖模拟当时已知状态。
- [ ] 按规格中固定的八类技能、别名映射和频率／LCS（最长公共子序列）公式评分；旧、新两场时序不一致率均低于 5%，旧场不得退步；报告成功次数、技能集合及频率差异。事后反馈回放不计入达标。

## Specification coverage

覆盖本变更规格中的真实按键时序独立模拟验收、战前状态保留、队列承诺、轨迹可观察性和搜索层隔离；带实测状态反馈的回放仅保留为诊断能力。

# 01：训练与正式搜索同代评分连续补位

Status（状态）：ready-for-agent；门禁一已确认，实施及定向检查完成，统一验证和独立审查待完成。
Blocked by（阻塞任务）：无前置票据；本次门禁一已确认。

## 交付

在现有内存粗评路径中，空出一个计算位置就补入本代下一个请求；保持配置并发上限、评分前完整编译校验、完整代换代、结果选择及最终保存。训练和正式搜索共同受益，不新增用户设置；最终复测派发仍沿用原实现。

## 验收条件

- [ ] 先写高层行为测试证明第十三个请求无需等前十二个全部结束，旧实现失败后再实施。
- [ ] 已提交未结束请求和完整编译至模拟工作不超过任务配置；不无限排队、不跨代派发。
- [ ] 正常完成时，完整请求身份集合及次数、重复候选位置、成绩、档案内容、随机状态、代数和最终结果一致。
- [ ] 完成顺序变化不改变选拔；实际进度时间如实变化，不要求档案原始插入顺序或耗时一致。
- [ ] 发现致命失败、预算终止或取消后不再补派，收尾本任务已启动工作；保留原失败额度与恢复规则。允许发现失败之前启动数量与旧窗口不同，并记录这一边界。
- [ ] 原有允许剔除的正式粗评失败继续处理；旧磁盘窗口、报告保存和最终复测边界不改变。
- [ ] 通过现有训练、正式搜索高层接缝与统一验证；不另造调度框架或固定测速功能。
- [ ] 在规格限定的一百八十秒、一百二十八评分批和每批三十二次请求范围内进行一次短真实对照，记录等价性和实际吞吐；不足或无收益如实报告，不启动完整训练。
- [ ] 独立审查完成，修复有效发现后整理门禁二；未获交付门禁确认不应用正式规格、不合并。

## Comments（讨论）

用户已同意提速计划。本票仅包含首个切入点；编译锁与缓存等后续优化不一起实施，便于单独判断投入与收益。

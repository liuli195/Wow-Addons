# 位置观察轨迹批次关联修复

**Status:** ready-for-agent

## Problem Statement

开启诊断并完成位置观察时，新轨迹的批次键为空。按稳定逻辑表关联批次的分析会漏匹配这些轨迹；搜索成绩、选优、导出及已保存的位置摘要不受影响。

## Solution

位置观察写轨迹时传入已经生成并用于保存对应批次的批次键，恢复现有结果中心的关联契约。

## User Stories

1. 作为分析使用者，我希望新位置观察轨迹能关联原批次，以取得对应候选及批次用途。
2. 作为搜索使用者，我希望修复保持成绩、选优、导出和诊断开关行为不变。

## Implementation Decisions

- 复用已有可选批次键参数，仅修复一个遗漏参数的调用。
- 不修改数据存储技能、表结构、缓存身份、引擎或工具。
- 不自动补齐或迁移既有空键记录。
- 这是既有结果中心契约的缺陷修复，预期无需正式规格增量。

## Testing Decisions

- 复用最高层级公开任务入口 run_task 及公开稳定表查询，扩充现有双比较位置观察测试，不新增测试接缝。
- 先验证产生了位置观察批次及轨迹，再验证同一任务的新轨迹批次键非空且可关联原批次，避免空结果导致假通过。
- 保存同一检查的红灯、绿灯证据；云端构造边界与 Windows 固定基线快速验证分开报告。
- 全部临时文件只保存在当前仓库内。
- 正式验证发现既有硬退出测试可能在真实任务进程退出前恢复；获用户补充批准后，仅使该测试等待真实任务进程句柄，不改生产锁或验证预算。消除已证实同步缺口，不声称已证明首次锁失败的唯一原因。

## Out of Scope

历史迁移、共享核心或表结构改造、新增模拟、独立测试框架、工具与引擎修改、正式规格扩展。

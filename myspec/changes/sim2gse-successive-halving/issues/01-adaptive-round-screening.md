# 01：同轮明显落后淘汰与按需追加

Status（状态）: ready-for-agent
Blocked by（阻塞任务）: 无；执行前需开发门禁确认。

## 交付行为

用户从现有页面开始优化，同轮先累计32次筛选；仅明确落后者停止，其他候选复用成绩补到128次，再按需要最多512次。保持原赢家与晋级独立复核、预算、取消及恢复正确。

## 验收条件

- 从页面任务接口创建任务，观察真正派发次数和最终导出；能分清时少派发，区间重叠时继续，同分按固定顺序，完成顺序不改变结果。
- 首层及后层决定只用当时已完成的成绩，不读取被淘汰者未来成绩。
- 只剩一个本轮候选不代表击败原赢家；不同样本量的粗筛分数不取代晋级配对复核。
- 挑战路线与全局原赢家时双方按同层成绩比较，必要时给原赢家补齐批次并保存；新规则替换旧全局早停，不叠加淘汰。初始路线起点沿用原行为。
- 方差与原报告均值、样本数一致并通过缓存完整性校验，范围计算合并批次间差异。
- 取消及恢复在各阶段可重复验证，不重复模拟成功批次、不重复预算或样本计数，旧规则恢复明确拒绝。
- 失败或残缺批次不作为有效成绩，预算不足输出已有有效结果并完成清理。
- 保留600秒总预算、两个单线程进程及连续五个完整无改善轮次停止；不改引擎或恢复最终五节奏复测。
- 先通过该入口产生可观察失败检查，再实施，最终同一入口检查通过；统一构建验证与独立审查通过。

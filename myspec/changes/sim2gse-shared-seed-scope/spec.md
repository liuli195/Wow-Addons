# 起点训练与使用统一共享范围

## Problem Statement
起点保存和读取未使用一致英雄范围，后训练模板会覆盖另一个英雄成果，训练冠军又被默认模板限制。

## Solution
复用规则配置三元身份：专精、英雄天赋、目标类型。完整训练凭据保留；每共享范围保留4个入选代表，普通搜索按同范围读取，再适配及评分。另从同范围完整最终成果取1个训练冠军；角色历史冠军保持原严格身份。

## User Stories
1. 用户训练不同英雄和场景后，各组四个代表互不覆盖。
2. 用户更换同组角色或引擎后，程序可适配重评分，旧成绩不冒充新成绩。
3. 用户可追溯全部完成训练，未入选不删除。
4. 旧记录仅在可靠原凭据证明三元身份时归类，不猜、不删。

## Implementation Decisions
复用已有规则configuration_key、训练记录表和公共存储；条件身份仍用于成绩与恢复。具体目标数留在评估条件，不作共享主键。保留原单条件选优和四条上限。训练冠军验证来源自身模板、引擎、检查点、报告；不再要求当前默认模板相同。

## Testing Decisions
经公开prepare/run/list及双场任务验证，不测试新私有帮助函数；使用既有外部引擎边界与隔离中心。覆盖分组、跨角色重评分、四条上限、冠军及未知旧数据拒绝混用。

## Out of Scope
不改选择模型范围、历史冠军身份、搜索数量或正式规格，不新建存储框架，不运行真实训练。

## Further Notes
用户已确认三元范围和4+4+2。云端定向诊断不能代替Windows完整训练；永久目录和正式中心绑定由协调者执行。

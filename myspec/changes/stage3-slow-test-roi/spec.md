# 阶段三：保目标覆盖的慢测试准备与重试分层

## Problem Statement

全仓43组验证的GSE真实组是已观察到的最后完成组。历史最慢十来源用例call为10.18秒，但其中先用双场完整执行建立旧冠军，再用第二次HTTP双场检验十来源与替换；只有第一轮单体冠军被后续断言使用。另一个快照发布用例曾因真实IO额外重试而出现预期3次、实际4次，尚未定位具体系统错误，不能简单放宽次数断言。

## Solution

两张独立小票，串行实施、逐票独审：先减少旧冠军准备中的无独有断言场景，保留目标HTTP双场十来源整链；另把确定性重试次数与真实目录发布分层。现阶段只准备方案，代码须在本Gate1获批后修改。

## User Stories

1. 开发者仍能从HTTP双场入口验证十来源组成、完整自然搜索、正常复测与真实冠军替换。
2. 开发者不为只使用单体冠军的前置条件重复执行无独有断言的群体准备。
3. 开发者能精确验证两次权限失败后第三次成功和两次固定等待，不受真实系统短暂占用污染。
4. 开发者仍能真实发布源码快照、从注入失败恢复、清理临时目录并拒绝变化后的源码。
5. 开发者得到完整43组、原60秒预算下的实测结果，不把删除工作量直接当作净耗时收益。

## Implementation Decisions

- 旧冠军必须由现有公开单体任务入口实际产生；不直接伪造冠军、复测凭据或发布结果。后续十来源HTTP双场运行及全部既有业务断言不变。
- 保留角色、爆发、条件、评分映射和搜索参数。改变的只是第一轮旧冠军准备入口与场景数；不改变生产算法或正常复测规模。
- 快照重试使用现有公开替换函数验证确定性规则，不新增重试器或假文件系统。真实发布保两次注入失败和真实目录替换；等待不再被替换为空操作。
- 两票均不改生产、正式验证配置、并行、预算或普通守卫；只涉及各自一个测试文件。

## Testing Decisions

票01保留第二次POST dual→GET结果，及十来源4/4/1/1、无旧chains、自然停滞、300DPS、来源替换、v2契约、完整代与3批/381样本断言；真实旧冠军需先确认完成且发布成功。票02把原精确3次/2次等待断言移普通，真实目录内容、单pending、成功发布、清理及后续篡改拒绝保留。每票分别定向、普通守卫、inventory与Windows完整43验收。

## Out of Scope

不实施阶段四Lua；不启动默认DPS对照；不把已有benchmark偶发宣称已修；不将第二次十来源双场改成单场；不减少来源/样本/代数、不删故障保护，不创建通用缓存或新测试框架，不合并或发布。

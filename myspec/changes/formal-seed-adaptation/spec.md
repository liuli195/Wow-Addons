# 正式搜索按当前角色适配起点：真实原生报告回归

**Status:** ready-for-agent；本轮最小门禁一已由父协调向用户展示并获批，Astra 独立设计审核通过。

## Problem Statement

已完成的标准训练合法包含种族／天赋技能。当前角色的真实原生目录可将已初始化但资格不可用的技能标为 `native_non_button`，且技能编号为零。消费端只识别 `native_unavailable`，并要求裁剪前映射真实技能编号，导致合法余部被整条拒绝。

## Solution

仅修复当前角色消费起点的通用过滤，兑现已有正式规格 `sim2gse-seed-training/spec.md` 的适配契约。不改训练端策略、不禁止巨魔合法技能、不写死具体技能名或编号。

## User Stories

1. 作为用户，我希望已训练程序中原生确证不可用的技能可移除，而非因报告分类顺序丢掉合法余部。
2. 作为用户，我希望普通块、循环、等待和施法序列保留剩余顺序及重置语义。
3. 作为用户，我希望未知动作、证据不足、原结构超限或非法重置仍明确拒绝，不被裁剪洗白。
4. 作为用户，我希望当前合法同名动作优先保留，冷却、资源和未执行次数不成为删除依据。
5. 作为用户，我希望派生程序重新绑定、按行为去重并使用当前成绩，来源及旧训练成果保持不变。

## Implementation Decisions

- 基于 APL 的玩家技能原生类型、初始化精确真值和不可用精确假值判断；排除设施、物品、未知类型及证据不足，不依赖通用按钮分类状态，不改变通用按钮准入。
- 裁剪前分别核对原结构／重置与已知成员。复用既有 `parse_castsequence(actions=None)`，不伪造技能编号，不建设第二套语法解析框架。裁后重新真实绑定；零成员删除，单成员拒绝，两个及以上保留原表达。
- 沿用当前 canonical（规范化）、去重、评分和冻结消费链，不凑起点数，不沿用旧分数。

## Testing Decisions

- 本轮批准的规则接缝为现有起点消费、共享结构裁剪和真实内存搜索状态机。新增边界矩阵仅在普通内存层；既有双场 HTTP 真实接线代表改用真实报告形状，不新增重链。
- 先红后绿；覆盖多个名称／编号与原生 spell（法术）／attack（攻击）类别，普通块首中尾、循环、等待、施法序列零／一／多成员，以及同名可用、未知、设施、物品和字段缺失。
- 云端定向及普通层验证与 Windows 最终正式验证分开报告。独立 GPT-6-A 审查及 Windows 最终验证由父协调，历史守卫副本不作为最新正式证据。

## Out of Scope

不重训、不改正式 data（数据）或 `myspec/specs/`，不改通用按钮准入，不合并主干、不发布、不操作本机。不复制工具、虚拟环境或数据大目录；只读复用云端已有依赖。

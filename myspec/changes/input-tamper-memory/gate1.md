### 实施接缝与范围

`task._resume_task`先读取 profile 并执行 `_verify_task_inputs`，其后才构造 `search.TaskStore`。普通两场景分别匹配“原始输入副本已变化”和“任务输入副本已变化”，另一份输入和保存散列保持有效；避免通用“输入”错误掩盖错误样例。普通测试通过公开 `task.resume_task`，按 `test_retired_capabilities.py::test_public_resume_refuses_incompatible_frozen_modes_without_rewriting_identity` 先例，替换外部读取、中心可用性、foreground_search及_task_lease上下文；不替换SHA、输入校验或resume调度，不建立文件系统模拟器。两输入和profile使用明确样例，禁止写入由既有普通守卫保障。

真实承接位置：`test_task_records_effective_config_and_rejects_changed_resume` 的配置变更拒绝/状态不变断言之后、最后成功resume之前。整段原物理篡改断言移入，复用已生成任务；`_read_state` 必须位于 TaskStore 禁调用补丁作用域之外。普通输入按文件名明确返回字节，未预期读取应失败，不能全部路径一律返回相同内容；不要只引用别处双场父输入篡改代表，它不覆盖这里的有效输入与SQLite保护。

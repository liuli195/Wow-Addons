# 输入篡改规则内存化（阶段二首个切片）

## Problem Statement

全仓普通规则必须在受守卫的内存环境验证，只有真实集成边界允许外部环境。当前输入篡改前置拒绝用例，为检查散列与 TaskStore 构造顺序，另行生成一份完整任务；相邻集成用例已生成同配置任务。此准备重复，但不能因此删除物理篡改及不写坏已有成果的证明。

## Solution

把公开恢复入口的输入散列拒绝规则移到普通层，以明确内存字节作为外部读取输入，仍执行生产散列校验。全部既有物理篡改断言由相邻真实配置/恢复用例复用已生成任务承接，逐次还原输入后继续其原成功恢复。只改一个测试文件，不改生产接口，不建假数据库、文件系统或检查点框架。

## User Stories

1. 作为开发者，我要原始输入和有效输入被改动时都在打开 TaskStore 前拒绝恢复。
2. 作为开发者，我要普通散列与顺序规则不依赖文件、数据中心或真实锁。
3. 作为开发者，我要真实文件被篡改时，SQLite 逻辑状态及已有成果文件字节均不变化。
4. 作为开发者，我要还原输入后原任务仍能按冻结配置成功恢复。
5. 作为开发者，我要全仓登记、有效断言和60秒预算不变，性能收益由实际完整验证说明。

## Implementation Decisions

- 普通用例保留公开 resume_task 接缝；只替换已有外部读取、中心可用性、前台活动及租约边界。输入内容和保存散列显式提供，生产散列计算与拒绝分支不替换。
- TaskStore 使用禁止调用观察对象；错误原因必须匹配输入拒绝，不能只证明任意异常。没有数据库可打开，不引入模拟数据库。
- 真实用例保留原始输入和有效输入两个物理篡改场景，失败后还原字节；继续验证真实 SQLite 逻辑状态和三个成果文件字节不变。
- 真实断言合到既有配置/恢复任务上，不再独立创建第二任务。这减少独立任务准备次数，不删除篡改类型或状态保护断言；不声称两次独立任务生命周期仍存在。
- 仅测试归属与准备复用变化，生产搜索、引擎、配置及恢复行为不变。

## Testing Decisions

- 最高接缝仍为公开恢复入口，不以直接调用散列私有函数替代其先校验后构造存储的顺序。
- 普通输入替换复用已有退休能力恢复测试模式；真实准备沿用同文件配置恢复用例。
- 原断言逐项承接及验证步骤见 gate1.md。普通层必须在既有守卫下通过；物理篡改、SQLite及文件字节保护仍由 real 集成用例实际执行。
- 云端定向、普通全集及 inventory 检查不替代 Windows 全43组正式验收；缺依赖、失败、未运行分别报告。

## Out of Scope

不改并发、60秒预算、正式验证配置、旧候选计划或其他测试；不做阶段三十来源双场删减，不做阶段四 Lua 内存化，不启动新旧默认 DPS 对照，不推送、合并或发布。本切片不代表全仓阶段二完成。

## Further Notes

- 用户已批准恢复通过配置及进入阶段二；本具体迁移仍待完整 Gate1 展示后确认。
- 普通化与真实准备复用为一张纵向票据；父层一次确认其粒度、接缝、覆盖承接及执行/独审安排。
- 历史独占 real-six 日志该节点 call 3.54秒，不是本改动净收益；全仓恢复后父层回读43组通过58.062秒，不能用单项差直接推端到端节省。

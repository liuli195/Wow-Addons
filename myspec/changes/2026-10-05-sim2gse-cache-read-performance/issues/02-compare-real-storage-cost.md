# 02: 用真实样本确认读取改善与存储选型

**What to build:** 用一次性脚本和真实数据副本验证第一阶段达到可用读取性能，并为是否采用 DuckLake 提供正确性、性能和维护成本证据。

**Blocked by:** 01 搜索复用已核验成绩并保持失败恢复语义。

**Status:** ready-for-agent

- [ ] 对照当前最小修正、DuckLake、原生 DuckDB，明确实际版本及可用平台；不自动迁移或选择后端。
- [ ] 使用现有真实分片及实际命中的键，覆盖点读完整报告、必要字段、有限批量、少量追加与重开回读；不同结构及同键重试不丢字段、不重复样本。
- [ ] 三次小对照记录中位数与最慢值，不据此声称尾部稳定性；分别计初始化、执行、获取、核验、写入、总墙钟与峰值内存。
- [ ] 点读在当前规模以 1 秒以内为目标，必要时使用既有性能分析解释未达标的具体成本。
- [ ] 固定候选/种子结果一致，并报告真实搜索端到端时间及归档成本；不把原生内部统计之和当完整进程时间。
- [ ] 所有样本副本、诊断脚本、扩展测试资源和证据只放当前仓库的既有本地诊断目录体系，不进入技能运行目录或常驻验证套件。
- [ ] 不让 DuckLake 接管现有唯一文件，不改变用户全局安装、配置和生产数据；安装或新位置若超出门禁授权先报告。

## Comments

此票是小型对照及验收，不是数据迁移票；结束后给出 A/B/C 推荐及停止扩大改造的理由。

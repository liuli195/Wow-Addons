# Loop（循环块）新增计数的候选价值筛查

Status（状态）: ready-for-agent；仅需求准备，实施待门禁一确认。

## 问题陈述

用户希望先核实搜索是否缺少有效改法，再逐项用确定性对照实验判断帮助。当前已有循环次数编辑仅提供2、3；需要知道新增1、4对真实父程序是否有局部价值，避免直接扩大训练成本。

## 解决方案

只对两个既有真实父程序各一个已有循环块比较次数1、2、3、4，固定其他输入。对照集合是2、3，扩展集合是1、2、3、4。结论限定于两个父程序，不代表完整遗传算法胜负。

## 用户故事

1. 作为使用者，我希望按结构而非旧伤害挑选父程序，避免挑出有利结果。
2. 作为使用者，我希望单体和范围伤害分别对照，知道各场景结果。
3. 作为使用者，我希望每次只改变一个循环次数，知道结果来自哪项改法。
4. 作为使用者，我希望相同候选与种子只计算一次，避免浪费。
5. 作为使用者，我希望冠军固定后再用全新共同种子复核，避免把筛选优势当真实收益。
6. 作为使用者，我希望平分优先旧集合，避免无收益的新次数被称为赢家。
7. 作为使用者，我希望看到无效、失败、未完成和成本，避免只看最好成绩。
8. 作为使用者，我希望正式成果保持只读，实验不影响已经完成的撤回。

## 决策

- 每场四个唯一候选使用相同筛选种子，各请求32次迭代，只评一次。
- 对照从2、3选冠，扩展从1、2、3、4选冠。精确同分优先旧集合2、3，再按规范身份稳定排序。
- 扩展筛选成绩不低是集合包含关系的必然，不作为成功证据。
- 冠军冻结后使用3个全新共同种子，各请求128次迭代复核；复核后不重新选择次数。
- 同一冠军共享复核结果，差异为0。
- 两场最多20次原生调用、1792请求迭代；有效样本按实际报告记录。
- 总运行12分钟、累计新增128 MB硬停止；清理不重置累计量。预计2～5分钟、20～100 MB，属于估算。

## 验收与测试决策

- 通过真实编译及原生评分入口观察结果，先检查输入冻结和不同次数实际按键展开，再筛选和复核；本机模拟不能替代游戏验收。
- 报告两场候选、选择结果、每批有效样本和伤害、配对差异、重复和无效数量、失败及未完成状态、耗时和累计字节。
- 身份不符立即停止，不静默补算、换样本或重抽种子；预算到达后保留准确状态。
- 不修改正式产品代码，不写回正式成果；过程数据只在仓库指定临时位置保存并清理。
- 无收益或冠军相同均是可接受的完整结果，不强求正向结论。

## 范围外

完整遗传算法性能对比、扩大种群或训练、施法序列结构改动、恢复已撤回策略、正式发布或推送。等待点击块本轮不纳入；登记库存在等待点击块，其真实适用父程序尚未核验，不能宣称全库没有样本。

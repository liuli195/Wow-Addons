# 01：完成两个真实父程序的循环次数候选筛查

**What to build（交付行为）:** 在正式成果保持只读的条件下，输出单体与范围伤害两个父程序的新增循环次数局部价值及完整成本、失败状态。

**Blocked by（阻塞任务）:** 无前置票据；实施依赖门禁一确认。

**Status（状态）:** ready-for-agent

这是一个端到端纵向票据，包含冻结、候选生成、真实评分、留出复核和小型结果交付；拆开会产生不能独立回答用户问题的中间层。

- [ ] 只使用设计中固定父程序、位置和完整评价身份；先验证合法性与实际按键展开差异。
- [ ] 四个唯一次数各一次共同种子32请求筛选；对照选2/3，扩展选1/2/3/4；同分优先旧集合，再按规范身份排序。
- [ ] 冻结冠军后3新共同种子×128请求复核；同冠军复用，差异0；不在复核后重选。
- [ ] 最多20原生调用1792请求，12分钟128 MB累计硬停，逐项记录有效样本、失败、重复、无效和成本。
- [ ] 报告只解释两个父程序的局部价值，不把集合包含带来的筛选优势称为收益或算法胜负。
- [ ] 等待点击块本轮不纳入，不能以“来源库无样本”为理由；其适用性尚未核验。
- [ ] 先通过最小失败检查证明同候选同种子不会重复调用、同分规则正确、留出不能参与选冠、预算停止不继续评分，再实现通过；真实验收走现有编译及原生评分接缝。
- [ ] 不新增可移植但未接统一验证的测试；若需要持久测试，按仓库规则接入统一入口；一次性实验检查保留证据。
- [ ] 不改产品代码、配置、正式数据或引擎，不复制工作树和数据中心；结束清理指定过程目录。
- [ ] 全部完成后经独立只读审查，记录已运行检查、未运行检查及游戏未验收状态。

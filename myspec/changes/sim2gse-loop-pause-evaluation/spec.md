# Sim2GSE 顺序循环与暂停评价

## Problem Statement

现有导入程序虽能解析 GSE 控制块，但搜索来源仍只接受普通动作块；暂停在内部保留多种 GSE 写法。改变按键间隔时，难以保证模拟的是 GSE 真正编译出的按键计划。

## Solution

支持最小 `Sequential Loop`（顺序循环）与循环 `Repeat` 次数；在 GSE 边界把 `Pause`（暂停）的 Clicks/MS/GCD 写法转换成唯一 `WaitClicks(n)`（等待 n 次空点击）。编译计划与原生受控模拟消费同一点击顺序，出现差异时拒绝评价。

## User Stories

1. 作为本机用户，我希望顺序循环的展开顺序和次数与 GSE 编译结果一致，以便评价真实的按键计划。
2. 作为本机用户，我希望暂停占用正确数量的空点击，以便暂停期间不会额外施法。
3. 作为本机用户，我希望切换按键间隔后得到相应暂停步数，并能复查转换依据。
4. 作为开发者，我希望原有简单搜索的候选、导出与选择行为不变。

## Implementation Decisions

- `WaitClicks(n)` 是内部唯一暂停表达，`n` 为非负整数。GSE 表达仅在输入与输出边界转换；展开后逐次空点击交给现有原生受控引擎。
- 本票的 `Repeat` 指循环块的重复次数；不新增独立定期 `Repeat` 块能力。循环只支持 `Sequential` 顺序及已有可模拟动作。
- 保留每次展开点击的来源位置和现有 4096 步上限。继续复用共享程序、上游编译核对与原生评价入口，不另造模拟器。
- 以官方最新发布的 GSE 3.3.34 源码和编译测试作一手对照，核验仓库固定的 3.3.32 在本票语义上是否相同；本票不隐式升级全部导入协议。
- GSE 的暂停换算以实际上游编译规则为准：`Clicks=1` 编译为零步；普通非空 `MS` 在 GSE 3.3.32 与 3.3.34 中按固定 1000 毫秒除以按键间隔并向上取整；`MS=GCD` 使用公共冷却毫秒数除以按键间隔，其非整数结果在 Lua 数值循环中按整数步数向下计数。换算结果不大于 1 时编译为零步。此处记录的是上游实际行为，不把 `MS` 字段的名义值带入核心。

## Testing Decisions

- 最高层公开接缝为 `run_task` 导入评价入口，核对受控模拟最终消费的动作块；下一层为导入编译后的逐次按键计划，断言动作、空点击、来源顺序及原生输入轨迹一致。
- 确定性测试覆盖两动作顺序循环的 1 次与多次重复、循环内暂停、Clicks/MS/GCD、不同按键间隔、临界值及超限拒绝。预期独立取自官方源码与测试，不复制本机实现。
- 比较既有搜索候选、导出与导入评价回归；执行统一完整验证，分别报告失败、跳过和游戏内未验收。

## Out of Scope

不新增 Priority/ReversePriority/Random Loop、复杂宏解释器、`/castsequence`、预训练、搜索算法或候选生成优化。不承诺真实游戏按键节奏与伤害结果。

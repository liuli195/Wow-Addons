# 缩短内存任务的序列编译占锁时间

Status（状态）：ready-for-agent；实施、统一验证和独立审查完成，待门禁二交付确认。

## 问题

序列编译在任务共用锁内完成；不同候选相互等待，进度读取、评分登记及取消状态更新也可能被挡住。上一项已交付的连续补位不能消除这段等待。本次收益尚未测量，历史编译累计时间不等于本次可节省时间。

## 方案

只在训练和正式搜索的内存运行路径中，用短时间登记、锁外原编译、短时间提交结果的方式，减少不同候选和进度读取之间的等待。评分前仍须完成原真实编译校验。

## 用户故事

1. 作为训练使用者，我希望不同候选能够利用已有计算位置进行编译，减少串行等待。
2. 作为正式搜索使用者，我希望同样受益，不必增加设置。
3. 作为查看任务的使用者，我希望某个候选正在编译时，进度仍能读取和更新。
4. 作为重复请求的调用者，我希望同一候选共享成功编译结果，不能重复启动同一份编译。
5. 作为结果使用者，我希望序列编码、步骤、评分请求、成绩、随机状态、代数和最终推荐保持一致。
6. 作为取消或恢复任务的使用者，我希望等待编译的请求能退出，不被遗留占位永久挡住。

## 实施决定

- 保留原编译器、兼容校验、行为核对和编码往返检查；不把编译推迟到最终结果，不用简化语法假设代替真实编译。
- 在短锁内查现有任务内缓存、可信历史编译结果，并按已冻结行为身份登记本次编译占位；真正编译及等待其他编译完成都在任务总锁之外。
- 优先复用标准库的完成结果对象和现有锁；不同候选可沿原工作线程并发，同候选的等待者共享这一轮结果或异常，不新建编译线程池、进程服务或通用管理框架。
- 编译通过后核对实际执行步骤与冻结标准形式，在短锁内登记缓存及必要计数，再让后续评分使用。共享准备字典、计数和诊断不能因移出总锁发生丢计或错配。
- 必须逐一核对编译的所有调用位置。归档阶段只消费已经核验的结果，不能因外层仍持总锁而再次等待或触发重编译，抵消本次优化。
- 在成功、编译拒绝、超时、预算终止、取消和其他异常出口清理占位、通知等待者；等待过程遵守原取消与预算检查，不留下永久等待，也不新增重试或放宽失败额度。
- 编译仍放在评分重试循环之外，编译失败不能被改记为一次评分失败或因此自动重编译。编译启动计数仍来自真实启动回调，编译返回计数保持原“编译函数正常返回”的口径，不偷偷改成“最终形式核对通过”的数量。
- 占位只存在本次运行内存，不进入恢复文件或成果格式；取消和恢复继续遵守现有可靠状态规则。新旧任务兼容性按原软件身份检查处理，不迁移旧任务。
- 编译至模拟合计使用已有请求位置，同时运行不超过任务配置，默认每组五个；不另开五个编译加五个模拟，不跨组借用资源。
- 旧磁盘路径保持原方式。候选缓存准入与复用条件不变；不扩展跨任务缓存，不减少兼容资料内容校验。
- 初始种群、参考、变异与交叉、评分与复测次数、完整代边界、最终保存和输出保持既有规则。

## 测试决定

- 沿现有训练运行入口、正式任务启动与读取入口，以及两者已有共用优化接缝验证；不新增仅供测试的产品调用接口。
- 先用受控编译响应和同步信号证明旧版会阻塞、新版允许另一候选进入编译，并且第一候选尚在编译时可以读取任务进度。明确启用产品内存运行，不能仅因样例用了内存数据库就声称覆盖本次路径。
- 复用已有行为去重用例检查相同候选只编译一次、复用同一成功结果；保留最少必要的异常、取消、校验拒绝和继续运行代表，确保等待者退出、无非法原生评分、无遗留占位。
- 同条件正常对照核对导出文本、实际执行步骤、完整评分请求及次数、成绩、样本、方差、必要反馈、种群、随机状态、代数和最终结果；完成先后和实际耗时允许不同。
- 通过既有统一差异验证和必要真实入口冒烟；保持普通与真实检查分层，不扩展历史大矩阵或提高检查预算。
- 另做一次性短真实对照，使用本次主干基线与改后方式、相同冻结候选和条件。新增性能对照最多一百二十八批，每批三十二次请求，累计一百八十秒，任一额度到达即停止补派并收尾；失败重试也计入额度。既有验证和收尾用时分别报告。
- 对照只衡量当前材料的编译与粗评效率，不设最低提速、不保证有收益、不推断完整训练质量或整体耗时。没有明确收益也如实交付结论，不追加实验。

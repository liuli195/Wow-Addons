# 实施及验证记录

## 实施

内存运行中，短时间占锁查询准备结果和缓存、登记同候选编译占位；原编译及等待在锁外完成，核验后短时间登记结果。复用标准库等待结果对象与原工作线程，不增加编译池。

共享准备字典、编译返回计数和诊断事件按任务锁保护；诊断计时沿原独立锁。真实编译启动仍由原回调统计。原生评分前仍检查实际步骤与标准形式一致。归档只消费已经核验的缓存，不能在持锁状态下补编译或等待。

编译仍在评分重试循环外，失败不改计评分失败、不额外重试。成功、拒绝、取消、预算结束和其他异常均通知等待者并释放占位，成功登记过程也纳入异常保护。旧磁盘运行、缓存准入、编译器、引擎、繁殖、评分和保存结构未改。

## 失败到通过及定向检查

- 训练和正式搜索共用高层优化入口配合真实活动任务读取：受控第一候选编译期间，要求第二候选进入编译且公开进度读取返回运行中。旧版两项均失败，原因是第二候选仍被第一候选挡住；改后两项通过。
- 同候选并发的两个合法不同阶段请求，共享一次编译结果。正常、编译拒绝、取消、预算结束和步骤不符五项检查，通过同步信号确认确有等待者，再释放编译。成功只编译一次；失败等待者均退出、不启动原生评分，且不增加评分失败额度；同条件继续运行成功。
- 保持旧口径：真实启动计数与编译函数正常返回计数分开，步骤核对失败仍计正常返回一次。
- 前述七项及既有正常结果对照两项共九项通过，1.23秒。另一次三个相关模块119项及4子项通过，9.28秒；后者早于预算终止补充，不冒称最终统一验收。
- 新检查使用明确开启产品内存运行的真实临时任务，原生编译和报告响应为受控输入；不能据此声称真实战斗或数据中心保存验收。实际编译和模拟由以下短对照与既有统一真实检查覆盖。

## What to build（要做出什么）

**把整套改动放进真实战斗环境里验一遍** —— 这一票不写功能，只出证据。目标是回答唯一那个真正重要的问题：

> **在一地 AOE 特效里，我到底能不能一眼看清血弧、符能弧、符文格和准星？**

顺带把既有行为的回归扫一遍：缩放、专精切换、进出本、登录恢复、鼠标穿透、框架层级。

## Acceptance criteria（验收条件）

- [ ] 在**有 AOE 特效的战斗场景**里，三条资源与准星**一眼可辨**（附证据）
- [ ] 在**明亮地面**（雪地／沙漠）与**昏暗地面**（洞穴）上同样可辨
- [ ] 阴影浓淡从最重调到 0 的全程，元素本身**始终不受影响**
- [ ] 缩放 0.5–2.0 全程：阴影与条**对齐**，且**不发糊**
- [ ] 切专精、进出本、登录之后阴影**仍在**
- [ ] 阴影层**不吃鼠标**（按住右键转视角不被挡）
- [ ] 框架层级设置对阴影层同样生效（调到窗口之下时阴影不浮上来）
- [ ] 证据**记录在案**（截图或录像，注明场景与设置）

## 备注

- 本机验收**不进统一验证**（仓库规则：本机验收不得进入 PR 统一验证）。
- 视觉判断由**用户**做 —— 工具链的截图通道不可靠，数值断言归自动化，眼睛归人。

## Comments（讨论）

**状态改为 done（2026-09-19）。** 用户在实机逐项验过，全部通过。本票要求的证据是实机
观察本身；本仓库的规则是「数值断言归自动化，眼睛归人」，眼睛这一侧已经判完。

实施期间实机暴露并修掉的主要问题：素材边缘锯齿——根因是贴图边长不是 2 的幂，
拿不到 mipmap（详见 change 规格的「实施后的更正」与 `assets/CrosshairHUDMedia/README.md`）。

**顺带记一条已接受的偏差**（规格用户故事 21「阴影不能溢出到框外」）：三条阴影贴图的
可见内容超出 128 单位的拖动框最多 **3 个设计稿单位**，超出的是不透明度 ≤12% 的尾巴，
可感知的部分在框内。这是设计本身决定的——环半径 54 ＋ 条粗 7.8 ＋ 阴影扩散已大于框的
半宽 64，而把阴影裁到框边会切出硬边。**用户决议：接受该容差**，规格里写明了这条容差，
并由 `verify_crosshair_media.py` 的 `verify_drag_box` 量住（可见部分必须在框内、
整条尾巴溢出不超过 4 个设计稿单位）。

# 02：阴影进入游戏：素材 ＋ 渲染层

Triage（分拣）: ready-for-agent
Status（状态）: ready-for-agent
Assignee（领取者）: 主代理
Parent（来源）: [Crosshair HUD 阴影图层规格](../spec.md)
Blocked by（前置事项）: 01（素材尺寸与摆放表由它定下）

## What to build（要做出什么）

**让设计稿那圈黑色柔化阴影真的出现在游戏里。** 这一票既出素材也出渲染 —— 因为阴影图产不出来就没得渲染，两半拆开谁都不能独立验收。

### 素材侧

- **每个形状配一张自己的阴影图**：准星（含中心点）、血弧、符能弧、六个符文格，共 **9 张**。六个符文格的形状**各不相同**（实测 6 个不同哈希、各自独立摆位），**不能共用**一张。
- **烘焙 C 档配方**（设计稿定稿值）：三层投影 `半径 3 / 不透明度 1.0`、`半径 8 / 不透明度 0.85`、`半径 20 / 不透明度 0.65`，偏移 0、扩张 0。烘焙时把 **alpha 峰值归一化到 255** —— "最重档"就是通道上限，游戏内只能往下调。
- **阴影图必须是白图**，阴影剖面存在 **alpha 通道**里。游戏里的染色是乘法：黑图乘任何颜色还是黑，**阴影颜色就永远调不动**，直接违背需求。白图则默认乘黑得到设计稿的效果，也能乘成任何颜色。
- **alpha 的取得方式**：先关掉节点的效果导出**形状图**，再打开效果导出**合成图**（白形状 ＋ 黑阴影），用形状图当遮罩从合成图里分离出阴影的 alpha，RGB 统一填白。
  > **这条路尚未实测**（Figma 的导出通道当时是卡死的）。形状边缘的抗锯齿**可能**污染分离结果。实测不成立就改走"复制一层做图层模糊"的路 —— **不许硬编一个看起来像的结果交付**。
- 清单新增 9 条。**不需要为阴影图放宽任何既有校验断言**：白图 ＋ 柔化 alpha 经实测能通过现有全部四条（尺寸、有不透明像素、RGB 三通道相等、不透明处纯白），预乘 alpha 那条因白图亮度方差为 0 而自动跳过。

### 渲染侧

- 渲染模块为每个元素**在底图之下**再建一层阴影纹理，子层级**低于**底图。
- **阴影不挂遮罩** —— 设计稿里阴影是包住整条弧的整圈轮廓，与填充比例无关。
- **空转态仍显示阴影** —— 空转的语义仍是不显示填充，但阴影不受影响；空转时恰恰最需要它标出位置。
- 元素状态表新增**阴影色**与**阴影浓淡**；核心构造状态表时填入（**本票先用固定值：纯黑、最重**，可调是下一票的事）。
- 阴影层**不接收鼠标**；随 HUD 一起缩放、一起隐藏、一起换框架层级。
- 阴影层不参与填充换算，因此**不接触受限上下文里的秘密值**。
- 领域词汇表新增「**阴影**」：元素底图之下的黑色柔化层，形状跟随元素轮廓、不随填充比例变化。

## Acceptance criteria（验收条件）

- [ ] 素材校验通过，且**未为此放宽任何既有断言**
- [ ] 9 张阴影图均为白图（RGB 三通道相等且为纯白），阴影剖面在 alpha 通道
- [ ] 进游戏能看到**黑色柔化阴影**包住每条弧、每个符文格与准星
- [ ] **空转的符文格仍有阴影轮廓**
- [ ] 条本身的颜色、填充比例、背景色**完全不受影响**
- [ ] 阴影层**不吃鼠标**（按住右键转视角不被挡）
- [ ] 缩放 HUD 时阴影与条**始终对齐**，且不发糊
- [ ] 切专精、进出本、登录后阴影仍在
- [ ] 不新增构建目标

## 备注

- Figma 导出通道卡死时需先重启 Desktop Bridge 插件（同 01）。
- 设计稿的坐标与素材像素是 **1:1**（设计稿是 2 倍预览，素材是每设计单位 2 像素），所以设计稿上的投影半径可以直接当像素读。

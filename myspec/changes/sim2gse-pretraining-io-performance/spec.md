# 预训练检查点与最终凭据读取的最小性能优化

Status（状态）: in-review（实施与云端构造验证完成，待独立审查和正式交付）

## Problem Statement（问题）

现有预训练在同一检查点内重复比较完整归档，同一小摘要写入任务与共享SQLite（嵌入式数据库）时重复JSON（数据交换格式）编码；最终发布又逐条打开同一报告组，并重复计算冻结manifest（清单）摘要。用户已批准优化前两项，要求复用现有能力、低成本证明等价，不增加低收益架构。第三项只允许先独立离线量化，尚未批准实现。

## Solution（方案）

仅消除上述重复计算：检查点一次可靠提交足够时不再重复全量比较；同次双写复用一次编码；最终凭据按已知组逐组读取，冻结清单摘要在本次选择中只计算一次。全部完整报告、120条现场凭据的身份与统计核验、十二份分组、取消尾组、错误恢复及旧四条保护继续有效。

## User Stories（用户故事）

1. 作为训练使用者，我希望同等输入和工作量少做重复保存计算，而不改变训练、评分或停止结果。
2. 作为恢复使用者，我希望重开后读回完整一致状态，已可靠保存的批次不因取消或存储故障重复模拟。
3. 作为成果使用者，我希望全部入围凭据仍逐一完整核验，缺失、重复、损坏或暂时不可读时不冒险发布新四条。
4. 作为运行使用者，我希望完整报告最多按一组处理，不因批量读取把十组大报告同时留在内存。
5. 作为维护者，我希望复用已有事务、批量读取及构造验证入口，不新增缓存、异步或性能平台。
6. 作为决策者，我希望看到同等产物、次数、前后耗时及小型峰值测量，不把嵌套统计全部当作可节省时间。

## Implementation Decisions（实施决定）

- 两张独立纵向票据并行实施；它们没有真实依赖，分别独占检查点模块及其专属测试、最终选择模块及其专属测试。共享Git（版本管理）操作与最终集成验证仅由父任务串行执行。
- 检查点保留末组既有事务、发布意图、成功摘要、进度及计数提交顺序。原始摘要的位置回填须在末组安全状态持久化前完成，不能直接删除仍负责保存后置变更的最后一次保存。
- 仅在本次刷新已可靠提交完整状态，且随后没有未保存摘要改变状态时，消除同次重复全量比较。空刷新、仅未保存摘要及混合分支保留必要保存；失败回滚及同对象重试不依赖永久脏标记。
- 同一摘要写入本地与共享SQLite时复用局部编码结果，保留各位置原有成功状态和用途条件，不改表、格式或事务框架。
- 最终选择仅保留小摘要的按组关系；逐组复用现有read_many（多键读取），读完、核验后立即释放，禁止跨组缓存完整报告。缺少组位置时沿用现有位置查询与旧逻辑键，不扩大全中心扫描。
- 目标批次须唯一、完整；仍对每条凭据执行原有请求摘要、条件、候选、用途、种子、迭代、成绩及完整报告统计核验，仍核验四条最终程序行为。不能靠字典覆盖吞掉重复记录。
- 清单摘要仅在一次最终选择调用内复用。评分请求摘要、完整报告核验及必要SQLite小摘要读取次数不因此减少。
- 逐组读取使Python（编程语言）侧完整报告对象从原单条读取增加至一组最多十二份，必须记录小型峰值；不得宣称内存零增加或一次读取120份。

## Testing Decisions（测试决定与预算）

- 最高真实用户入口沿用既有训练CLI（命令行界面）的run及同工作区再次run恢复；检查点的公开模块接缝沿用TaskStore.checkpoint/save。复用真实隔离数据中心，不mock（替换）整个算法、存储或发布，不新增生产测试接口。
- 云端复用既有`.local/ga-pretraining-03/constructed-only-pytest.py`及其原生进程禁止边界，只运行最小受影响构造子集；不运行原生引擎、编译、长真实模拟或整套重训练。
- 第一票复用局部检查点结构变化、字段删除、事务失败回滚及同对象重试，补最小新报告位置回填重开、空／混合检查点和末组失败保护。第二票复用公开四条发布、取消尾组、原条件恢复、发布失败保留旧四条及仅修复缺组的代表，并补重复目标拒绝和读取次数断言。
- 取消／恢复及发布故障优先选现有参数的一条有判别力代表，不扩成完整交叉矩阵。共同链及最终受影响子集由父任务集成后串行运行，不让两个实施者重复消耗同一验证预算。
- 修改前先记录固定构造输入的before（优化前），修改后对相同产物与工作量做after（优化后）；分项重放最多三组短配对，不为每次配对重跑完整训练。若缺少可安全重放的输入，明确报告未测，不增加长模拟或新测试平台。
- 同等性核对包括四条内容与顺序、程序、五场景分数／样本／方差、冻结身份、可靠批次、重开状态、尾组和发布意图恢复；诊断统计应反映真实工作减少，业务计数不变。
- 确定性指标：适用检查点完整归档比较两次降为一次；双写摘要编码两次降为一次；最终报告访问从凭据数R降为已知组数G（现场120→10）；本次最终选择的清单摘要124→1。全部120次完整核验及必要摘要读取保留，混合分支不强求一次比较。
- 分别记录检查点、最终选择及构造入口耗时，另记Python分配峰值和进程RSS（驻留内存）峰值。报告测试仪器与平台局限，不以固定秒数或比例作易抖动测试断言，不把Python测量当成DuckDB（查询引擎）全部原生内存。
- 不改既有60秒正式验证预算、不放宽断言、不改变测试收集或CI（持续集成）归属；云端构造结果不冒称本机完整、真实性能或游戏验收。

## Out of Scope（范围外）

异步保存、新缓存或持久化框架、跨组完整报告缓存、引擎及编译、GA（遗传算法）、评分、反馈、早停、配置／样本／种子、长期完整报告副本、正式规格改写、主干合并或发布均不包含。第三项实现不包含；仅可在已确认对象与已有数据范围内独立离线量化，不据量化结果自行扩大产品修改。

# Repository Data Adoption

**Status:** ready-for-agent

## Problem Statement

用户已经批准全仓数据治理方案：以仓库根统一管理，原地保留目录；先压缩和清理，再商量长期容量、额外余量和保留策略。现有入口拒绝根内目录联接，所有生产写入又要求长期策略全部设置；现有产品任务尚未接入数据管理。不能通过虚构临时无限容量、跳过磁盘准入或只在界面外套一层命令解决这些问题。

## Solution

复用既有数据管理入口和产品任务生命周期，让普通根盘点如实报告但不遍历已识别目录链接；长期政策可以未设置，实际写入载荷、元数据峰值、并发承诺和所在卷空间仍必须核验。产品的新任务与恢复任务使用同一受管生命周期，保持原输出路径，成功后分批登记封口普通产物，SQLite 使用一致性映像；未完成状态保持可恢复和受保护。

本变更只交付最小代码支持及合成验收，不执行真实历史登记、压缩、迁移、隔离或永久删除，不写用户机器配置，不安装定时任务。

## User Stories

1. 作为仓库维护者，我希望仓库根可以包含两个 Agent 的目录联接，让完整盘点不因技能发现入口而失败。
2. 作为维护者，我希望看到跳过链接的路径和数量，避免把链接目标重复计入或把未观察的数据冒充已盘点。
3. 作为维护者，我希望显式对象、受管工作区和删除操作继续拒绝链接，避免放宽普通盘点影响数据边界。
4. 作为维护者，我希望清理前不被迫决定长期容量和额外余量，同时每次实际写入仍不能超卖可用空间。
5. 作为维护者，我希望未指定保留期和维护频率不会阻止已经批准的按需操作，也不会因此启用自动清理。
6. 作为维护者，我希望元数据和日志的必需空间由实际操作计算，不把未设置的额外余量偷偷当成零安全预算。
7. 作为产品使用者，我希望现有界面和命令行的新任务沿用原输出路径，并在任何任务文件写入前完成受管准入。
8. 作为产品使用者，我希望未提供必要管理配置或本次任务预留时明确失败，不静默退回游离目录。
9. 作为产品使用者，我希望取消、失败和进程中断保留数据与可核实的恢复状态，不因过期心跳就丢失保护。
10. 作为产品使用者，我希望大型任务的普通产物按既有边界分批登记，不因超过一千项而伪报完成或把全部目录长期留在管理外。
11. 作为维护者，我希望任务数据库和共享缓存作为可变来源管理，一致性映像包含 WAL 中已提交的数据，而不是只散列主文件。
12. 作为维护者，我希望现有数据技能保持自包含，产品适配复用同一实现，不增加第二套索引、归档程序或删除框架。

## Implementation Decisions

- 管理根是普通文件目录范围；目录链接的目标不属于这次遍历的字节合计。普通文件、代码、工具和未知文件均计入该范围，动作仍只作用于具体对象。
- 普通根盘点与严格对象校验具有不同用途。只为普通根遍历启用已识别目录链接报告；显式路径、产物、运行工作区和破坏性动作沿用严格验证。未知重解析类型继续拒绝。
- 长期业务上限、额外维护余量、额外元数据余量、保留期和维护频率允许未设置。未设置不产生虚构数值，也不消除实际物理准入。
- 每个增长及必要维护写入必须覆盖自身的载荷、元数据、WAL、日志和既有并发承诺。复用现有峰值估算；不能把额外余量未设置简单解释为没有元数据成本。
- 分包大小和使用租约时的时长由对应动作要求，不再让不相关的长期政策阻止按需动作。生产启用和根身份绑定仍是独立必要条件。
- 只有受管生产已显式启用时，产品入口才使用同一个受管任务生命周期接口，覆盖新任务与恢复任务；复用现有任务载荷预留字段与协议，保持已有输出目录和请求身份。管理禁用或尚未接入的既有运行方式保持原有行为，不给所有 CLI/UI 用户突然增加必填参数。
- 当前搜索配置不能可靠推出产物字节上界，因此不发明默认任务预留。仅在受管生产已启用时，未提供所需任务预留才拒绝写入；该任务参数不同于暂缓决定的长期总容量。
- 任务预留不是操作系统硬配额。原生子进程可能直接增长文件；超出预留时必须停止后续受管增长、拒绝封口并保留现场，不声称能阻止所有瞬时越界。
- 界面在准入前不创建任务目录或保存粘贴输入；原有页面不增加管理按钮，配置从启动入口传入公共任务入口。
- 普通产物分批登记；可变 SQLite 来源和一致性映像身份分开。父目录共享缓存不能按每个原生批次复制整库。只有终态登记和所需映像核验成功后才能核销本次未来承诺。
- 运行预留表示未来写入承诺，不等于引用可清理证明。全部产物登记及所需一致性映像校验完成后可核销；缓存引用未知或有界扫描截断仍保留全根未知引用保护，公开报告依赖不完整，不能据此迁移或永久清理。此语义在最终规格差异中明确展示。
- 取消、失败或中断不冒充已封口；恢复需核实原所有者死亡或 PID 复用并绑定新持有者，不能仅按时间释放保护。

## Testing Decisions

- 数据管理的最高公开测试接缝为实际命令行入口；现有真实子进程测试和同入口内存调用均可复用。验证外部 JSON、退出码、文件存在/原始字节和公开状态，不以内部索引查询替代行为验收。
- 产品的最高测试接缝为现有任务命令行和实际界面任务提交接口，两者进入同一新建/恢复生命周期。底层模拟器等外部进程可使用已有合成适配，Windows 实际入口另由本机验收。
- 票一验证：含已识别目录链接的完整和增量盘点；显式链接对象仍拒绝；长期政策未设可进入获准操作；实际空间、元数据峰值和并发承诺不足仍拒绝；初始化失败不遗留根标记或索引。
- 票二验证：准入先于界面输入及任务目录写入；保持原输出路径；缺配置、缺任务预留、重复/越界路径和空间不足不开始任务；取消、中断与恢复验证持有者身份和预留。
- 票三验证：大任务通过复用有界分批登记完成；使用最小真实跨批样例并单独核验数量边界，不强制再次造一千个真实文件。SQLite 映像包含已提交 WAL、排除未提交事务；中断重试幂等，失败不能提前解除保护或伪报封口。
- 每票遵循同一入口红灯到绿灯；正式本机验证使用固定基线 fast，CI 执行现有 PR 场景完整检查。不得新增本机 full 门槛或用 Linux 诊断冒充 Windows 原生验收。

## Out of Scope

- 真实历史数据操作和不可恢复永久删除。
- 操作系统级磁盘硬配额、透明按需解压、跨任意外部根自动接管、通用目录排除框架、新数据库或后台服务。
- 批量解除未知或持久引用、改变旧缓存业务含义、增加诊断数据、修改搜索算法或模拟预算。
- 预先决定长期容量、额外余量、保留期或开启定时任务。

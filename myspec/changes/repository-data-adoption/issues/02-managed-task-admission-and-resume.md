# 02: 原路径任务准入与恢复

**What to build:** 使用者从现有命令行或界面启动新任务、恢复未完成任务时，进入同一个受管生命周期，保持原输出目录；任何任务文件写入之前完成配置、路径、任务预留和实际空间检查，取消或中断后保留可核实的恢复状态。

**Blocked by:** 01: 仓库根盘点与真实空间准入。

**Status:** ready-for-agent

- [x] 公共新建/恢复任务接口复用一个管理接口，界面和命令行不各自实现一套协议。
- [x] 仅受管生产已显式启用时要求管理配置与本任务预留，沿用已有预留协议；缺失时拒绝受管写入，不静默回退。管理禁用的既有 CLI/UI 保持原有行为。
- [x] 准入绑定原输出路径但不提前制造会被产品拒绝的已存在任务目录；重复请求、身份和令牌受核验。
- [x] 界面的目录创建与粘贴输入保存均在准入之后；页面不增加管理按钮。
- [x] 活动任务及共享可变来源保持保护；恢复必须核实持有者身份，心跳过期不能单独判死。
- [x] 公开任务 CLI 与界面提交接口验证原路径成功、无配置/预留、路径冲突、并发不足和取消/恢复；前置失败无新增任务文件。
- [x] 明确任务预留不等于操作系统硬配额；超出时保留现场并拒绝封口，不伪称已限制瞬时写入。

## Comments

- 门禁一已确认；原路径准入、共享 CLI/HTTP 接入、取消恢复与禁用兼容已实施，正式规格未改。
- 同入口红绿：CLI 缺预留由未识别参数转为明确拒绝；原路径任务由无管理状态转为同根运行登记；HTTP 由启动先建目录转为准入前零任务文件；取消后恢复由缺运行身份失败转为保留同一 run ID 和原预留。原始输出位于 `.local/repository-data-adoption/ticket02-*-red.txt` 与 `ticket02-green.txt`。
- 云端合成验收：`pytest -q tests/sim2gse/test_data_management.py tests/sim2gse-data/test_lifecycle.py`，29 passed、7 subtests，16.79s。含禁用策略旧行为、标记根漏配置、实际空间不足、原持有者仍活动拒绝与真实子进程退出后续领。Windows 互斥锁在云端仅用 OS 边界适配；原生 Windows 统一留到三票后的 fast 验收。
- 该票只建立准入与可恢复状态；终态产物登记依赖下一票完成后才能宣称完整生产接入。

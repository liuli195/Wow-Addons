# 原生替换故障完整恢复

## Problem Statement
页面真实搜索在原生替换形态执行成功后误报派发与执行不一致，父任务失败时仍显示场景运行中。

## Solution
保留原按钮完整签名和原生实际动作，凭本次实际派发及原生共享队列真实替换转交归因。页面终态如实显示失败或未完成，既有成果和检查点保留。

## User Stories
1. 用户通过原页面入口搜索时，原生替换形态正常参加评分与导出一致性核验。
2. 用户使用施法序列时，真实替换成功推进原成员，中断不推进，派生效果不清除待确认状态。
3. 用户查看失败或中断的任务时，页面不再显示停止的场景仍运行。
4. 用户切换修复后版本时，旧任务保留并通过原资料新建任务，不混用构建身份或自动重训。

## Implementation Decisions
复用固定上游死亡骑士共享队列替换入口，记录每次来源输入的真实转交链。只有实际派发的原动作能够授权关联；关联冲突拒绝覆盖，重复终结继续由一致性门禁拒绝。执行、受影响中断、失败反馈与施法序列推进使用同一关系；轨迹实际动作保持原生名称，签名保持派发命令。直接执行内部替换仍属于原调度事件，不额外发送终结事件。受控引擎身份更新；基准身份预期不变。

## Testing Decisions
沿用公开原生evaluate及页面GET任务入口；必要最小回归覆盖完整签名、替换执行/中断、派生不充当终结、重复终结及终态场景显示。真实原请求在本机同冻结输入下红绿复验，Windows引擎通过现有构建入口生成，不用构造报告冒称原生通过。

## Out of Scope
不改变上游版本、技能数值、爆发、训练规则、旧数据、合并主干、发布或本机开发。

# 01：完整报告按12份分组保存并可靠恢复

**What to build（交付行为）:** 用户启动真实搜索后，完整报告每12份保存一组，正常结束、取消及预算停止保存尾组。强停恢复只重新计算未保存结果；已保存结果仍按完整身份核验及稳定逻辑表查询，调用方不用处理文件路径或配置读取策略。

**Blocked by（阻塞任务）:** 无。

**Status（状态）:** ready-for-agent

- [ ] 从现有页面任务请求入口写出并运行分组尚不存在的失败检查，再实现并用同入口确认通过。
- [ ] 完整组12份、尾组1至11份正确保存，实际数值、完整字段及逻辑类型保留，内存缓冲有界。
- [ ] 未保存成绩与持久化成功分离，归档、待处理候选及赢家恢复不能使用缺少完整报告的摘要。
- [ ] 正常取消、预算停止、正常结束先保存尾组；保存失败明确报告，保留此前成功组和累计预算。
- [ ] 强停及发布后未登记的中断窗口可恢复，已发布完整组可核验复用，无重复逻辑记录或错误完成标记。
- [ ] 分组单报告读取由查询引擎筛选，保留旧单键完整组、批量、字段和通用查询能力；不引入业务硬编码、文件路径参数或额外持久数据库。
- [ ] 旧单报告历史和旧任务可读取恢复；重复使用不新增独立样本；诊断、编译、成绩及导出规则不变。
- [ ] 优化1单独对照包含登记、尾组及查询开销，记录真实工作量和实际收益；不套用原保存重放99秒作整轮承诺。

## Comments（讨论）

用户已选择优化1与12份分组，并接受未保存组强停后重算；开发动作等待门禁一。本票包含完整用户流程，不拆为只有存储或只有查询的半成品任务。

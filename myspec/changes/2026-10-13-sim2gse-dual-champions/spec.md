# 正式搜索4加4加2双冠军

**Status:** accepted-awaiting-pr-delivery（两票开发、独立审查及官方无缓存验收已通过；门禁二已批准、正式规格已应用，待PR交付）

## Problem Statement

正式搜索只消费四类原生起点和至多四个训练代表，不能保证覆盖全部已完成训练中最终复测均值最高的程序，也不能可靠继承当前角色的正式搜索最佳程序。训练代表的家族筛选不等于训练冠军，标准模板旧分也不等于当前角色成绩。

## Solution

保留4类原生和4个既有训练库起点，独立追加1个训练冠军和1个正式冠军。两个目标场景分别选取并冻结冠军，按行为去重，最多10条真实有效路径。正式冠军先按当前条件核验和评分建立保留基线，继续变异；其余起点照既有可信晋级规则挑战。可靠保存本次正式结果后才能发布正式冠军，恢复可幂等补发布，陈旧任务不能覆盖新冠军。

## User Stories

1. 作为用户，我希望单目标与AOE（群体目标）的训练冠军分别产生，不混用不同目标下的最高分。
2. 作为用户，我希望所有同条件已完成训练的最终程序都能参选，而非仅从四个家族代表中选第一。
3. 作为用户，我希望最终三次独立复测平均DPS（每秒伤害）最高者成为训练冠军，不取单次最高分。
4. 作为用户，我希望初始程序及初始成绩不参选，最终未改结构仍凭最终成绩参选。
5. 作为用户，我希望最终程序未保留来源核心也可凭有效最终成绩胜出，不被家族名额误排除。
6. 作为用户，我希望缺少最终复测或条件不符的记录被明确排除，不混入其他模板、引擎或节奏的高分。
7. 作为用户，我希望冠军原程序和模板分可追溯，适配到当前角色后的程序与新分另行保存。
8. 作为用户，我希望训练冠军不适用时明确缺席，不把第二名静默冒称第一名。
9. 作为用户，我希望两个冠军都不挤占原4加4的名额，也不为凑10条复制或补选。
10. 作为用户，我希望等价程序只建立一条路径，但保留两种冠军和其他原始来源。
11. 作为用户，我希望当前角色和专精、完整条件对应的正式冠军被优先保留并继续变异，不因初始化顺序丢掉保底结果。
12. 作为用户，我希望打平、未完成挑战或未证明改善时保留原冠军，仅经既有可信比较胜出才接替。
13. 作为用户，我希望恢复使用任务开始时冻结的两个冠军，不因训练库后来变化改变当前任务。
14. 作为用户，我希望读写故障与没有冠军明确区分，已保存的可靠成果不丢失。
15. 作为用户，我希望结果先保存、冠军后发布；发布失败可补写，不重新计算已经完成的批次。
16. 作为用户，我希望同时启动的旧任务不会把另一任务刚更新的正式冠军覆盖。
17. 作为用户，我希望旧正式历史仅按有界且明确的范围接入并重新评分，不在每次搜索全表扫描，也不声称未迁移的数据已迁移。
18. 作为用户，我希望这次功能不重训、不改变训练并发、原四条代表或训练身份，不增加计算预算。

## Implementation Decisions

- 训练冠军是同一已核验标准角色模板、职业专精、引擎、目标数、模拟选项、训练/统计/行为版本、复测种子与样本规则、按键节奏及爆发内容下，全部completed（已完成）记录的最终program（程序）与scores（成绩）均值最大者。稳定程序身份及候选身份处理完全同分。
- 只读现有seed_processed（已处理训练记录），不依赖本批活动来源、当前指定材料或seed_selected（入选代表）名额。初始程序与成绩绝不加入排名；core_retained=false（未保留来源核心）不构成排除条件；不额外要求最终显著战胜初始。
- 复用标准模板只读检查、完整条件输入、语义条件及identity（身份凭据）核验。按记录实际任务位置定位证据，不假定训练只使用默认工作目录。最终成绩必须有三项有限有效值，对应三份完整retest-final（最终复测）的程序、条件、种子、128次样本规则及报告。
- 不为查询调用准备、训练或复测入口；不写训练记录、入选库和训练冠军排行，不新增双写。明确坏记录可排除并说明，临时存储故障必须显式报告，不能当空库。
- 独立冻结training_champion_snapshot（训练冠军快照）：来源种类、训练条件、模板/引擎身份、候选、final阶段、原最终程序、三份旧分/均值、证据引用；当前角色适配及行为身份另存。冠军适配复用现有严格静态资格、合法性、导出及行为去重规则。最高者不能适配时该来源缺席，不改选第二名。
- 正式冠军条件沿用完整正式条件并显式绑定冻结角色资料与专精；不同角色、目标、装备、天赋、节奏、引擎、评分或爆发条件隔离。只复用程序，当前评分仍按原成功批次核验规则；不跨条件继承旧分。
- 在既有共享数据中心保存小型正式冠军记录，使用既有点读与原子写入；记录条件、版本、程序/行为身份、正式来源任务/候选、成绩/样本摘要与批次引用，不复制完整报告。
- 逻辑来源是4加4加2；正式冠军优先核验/评分为保留基线并先轮转，其余来源维持相对顺序，所有路径均可变异。等价合并保留全部来源，实际路径数决定无改善门槛，最多10；不增加预算、每轮候选数、样本或并发。
- 正式赢家必须先可靠保存完整候选、报告、晋级证据与导出核验，然后在短锁内重读冠军版本并发布。只有继承版本仍当前且赢家经过有效晋级链才替换；无改善或同程序不反复改写来源。并发冲突保留本次结果并明确未接班，不启动后台仲裁。
- 发布意图与状态随任务保存；崩溃或写入失败后的补发布位于完成/预算耗尽等恢复早退之前。幂等重试不重复模拟、不重置预算；取消仅允许可靠完整且已有合格证据的赢家发布，部分挑战不能发布。
- 旧历史接入单独限定明确正式来源范围，支持有界一次性核验和重新评分；不得每次搜索扫描历史。没有可证来源或尚未执行接入时如实标记未接入；本次不访问或迁移用户真实数据。常规初始化点读正式冠军。
- 入口限定正式任务，训练共用优化器默认行为不变。不为正式起点递增公共SEARCH_ALGORITHM（搜索算法版本）或训练语义版本。旧式迁入凭据涉及源码摘要兼容，必须专项核验；不静默放宽旧凭据，若受阻明确报告。
- 恢复继续严格核验任务条件与规则摘要；改版前旧普通任务不绕过严格身份原地续跑，旧结果仍可读。
- 不在实施阶段修改正式规格；正式规格预览、完整差异及应用只在门禁二进行。

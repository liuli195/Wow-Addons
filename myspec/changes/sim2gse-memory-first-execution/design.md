## 共用改动边界

- 深化 `projects/sim2gse/search.py` 的现有 TaskStore（任务存取对象）：取得已核验成绩、登记成绩、保存恢复点、发布最终证据。训练和正式搜索共用，不各造缓存。
- `population_training.py` 与 `formal_search.py` 保留现有演化规则；只替换成绩生命周期和恢复保存调用。全程归档仍参与前八排名，不能机械删成当前种群。
- `sequence.py`、`engine.py`、`runtime.py`：使用受控内存通道送入资料、读取结果与错误；保留超时、取消、进程归属、句柄限制。现有原生输入已支持标准输入，完整报告输出仍按文件名写，必须增加受控输出能力。
- 原生粗评增加轻量返回，身份、装备、版本、目标、有效样本、分数、方差、技能统计及必要位置反馈仍严格核验；最终复测输出完整报告。修改版本和构建锁，避免混用旧程序。
- `codec.py` 与现有脚本包装层增加字节输入，继续复用原导入编译器及校验响应，不另写编译器。
- `interface.py`、`task.py`、`dual_task.py`、`search_timeline.py`：运行状态及曲线由内存提供；最终保存曲线与记录。启动、暂停、取消、恢复与结束都覆盖父子任务。
- `result_store.py`：新格式证据使用任务自有不可变分组，读取按明确引用定位。旧位置目录与旧数据保持兼容；不能直接删旧全局锁，旧扫描器会把未登记文件视为异常。
- 复用现有增量状态字段、批量压缩写入和逻辑表能力，减少连接与重复转换；不得因固定外层结构而丢弃内部可选字段。先对独立分组并行准备与写入，再短锁检查版本并切换成果。
- `seed_training.py` 与 `task.py` 的成果版本读取同时支持旧、新身份；新旧证据不可混用。

## 已决策的设计树

范围 → 两条链都改；保存 → 少量恢复加最终保存；性能 → 减少次数与提高单次效率同时做。
算法 → 保留；内存 → 有界、无自动落盘；恢复 → 完整边界、允许重算；证据 → 粗评轻量、最终完整。
并发 → 独立文件并行，同一成果短锁；兼容 → 新版本直引、旧版本只读；失败 → 不切换当前成果。
上述来自会话的已确认目标；600秒安全边界、同工作树新分支、串行逐票审查及公开测试入口作为本次门禁一推荐一起确认，不再重复询问已决定目标。

边界场景：一代超过600秒时等待完整代；最终准备失败时上一版仍有效；保存成功而响应丢失时重试可辨认已完成；恢复后不能重置失败额度或丢失历史最佳。将这些场景写入规格和票据，是本轮实际使用带文档追问、术语建模的产物；依仓库领域约定不另建术语库或决定记录目录。

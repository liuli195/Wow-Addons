## 问题与目标

现有训练逐个保存候选、频繁保存完整报告，并反复检查旧报告和更新公共位置记录。模拟、序列编译、进度与曲线也会生成过程文件。只降低报告保存频率不能解决整个问题。

两个目标同时成立：训练与正式搜索的中间计算在有界内存中完成，只允许少量恢复保存及最终结果保存；同等规模整批任务的保存相关累计耗时争取低于60秒，必须通过实测验收，不能预先宣称达标。

## 术语与范围

- 中间计算：从冻结输入到最终复测结束之间的候选生成、编译、模拟、评分、诊断、去重和进度更新。
- 轻量成绩：经过身份与样本核验的分数、方差、技能统计和当前策略所需的位置反馈；不是未经核验的缓存分数。
- 恢复点：可恢复到最近完整边界的最小一致状态；不承诺恢复每一步。
- 最终证据：支持既有最终复测、选择、后续读取与重新评分的完整报告及来源身份。
- 发布完成：必要证据已保存并读回核验，最后才让新成果替换当前成果；后台仍有必要写入时不能算完成。

## 可观察行为

1. 用户从现有训练命令启动训练，随后从现有页面启动单目标及多目标正式搜索，最终获得可读取、复制的推荐序列；不增加第二套操作入口。
2. 常规计算阶段不写候选、粗评完整报告、模拟输入输出临时文件、编译临时文件、进度文件或曲线文件。现有可执行程序与资料可读取；页面进度从运行中的内存状态读取。
3. 粗评直接产生轻量成绩；最终复测保留完整证据。不能仍生成完整大报告再丢弃并声称消除了其开销。
4. 使用现有同一份配置承载必要的新运行策略，不另建配置系统。既有评分、样本数、繁殖概率、停机规则、复杂语法开关和最终选择规则保持一致。
5. 默认恢复安排：初始化完成、进入最终复测，以及距离上次恢复保存约600秒后的下一个完整代边界。重合边界合并；主动暂停在安全边界保存。不把600秒说成最多损失600秒。
6. 恢复保存包含种群、待处理状态、随机状态、停滞计数、全程前八及核验摘要、必要历史身份和反馈、失败及重生额度。历史信息只能在证明不影响当前算法后裁减。恢复点后的未保存计算允许按冻结条件重新执行。
7. 内存使用有明确上限，大报告核验并提取后及时释放；不得通过数据库临时文件或自动溢写兜底。容量不足时清楚报错并保留最近恢复点，不能无限增长或静默改变评分。
8. 不同任务的最终证据可并行准备与保存；共享锁只保护同一成果的短时切换。并发冲突、写入失败、报告损坏或响应丢失不得损坏上一版成果，也不得冒报成功。
9. 所有入围前八的既有最终复测证据保留，之后按原规则选四；正式搜索也保留原有最终证据要求。不能为了速度缩减复测。
10. 新成果使用独立版本身份和直接证据引用；旧成果继续按旧格式核验和读取，不迁移、不重写旧训练材料。

## 验收与失败路径

- 训练命令与页面正式搜索是最高层验收入口；内部替身测试只作补充。覆盖训练发布、页面消费训练起点、按当前角色重新评分、最终结果读取与复制。
- 同冻结条件及随机种子核对评分、有效样本、方差、技能统计和编译行为；覆盖取消、超时、输出超限、子进程清理及双路输出不互相阻塞。
- 覆盖完整代恢复、未完成代重算、随机状态延续、历史最佳不丢失、失败额度不重置、最终证据缺失/损坏、并发发布和失败重试。
- 用系统级文件记录观察实际进程及子进程写入；只在脚本层拦截写文件不能证明无过程写盘。恢复与最终保存窗口、验收观察器自身写入分别标记。
- 用旧批次同等规模的9739条评分记录及480份最终复测证据，在隔离目录验证保存规模；另作模拟引擎升级要求的小材料完整自然结束训练及页面重新评分，不重复整套四组85起点训练，也不做收益对比实验。
- 保存耗时包括原生为保存生成报告、解析、转换、压缩、等待锁、文件与数据库写入、恢复点、最终读回及收尾。互相包含的阶段不得重复相加；跨组累计耗时与实际并发时间分别报告。不得把费用挪到模拟耗时或后台隐藏。
- 一分钟未达标或系统写入证据不足时如实报告，不能将验收条件改小后宣称完成。

## 不在范围

不扩展种群、不调整搜索质量策略、不做三组收益实验、不提供每一步恢复、不建立通用队列或新数据库框架、不改游戏部署、不宣称实际游戏伤害已验收。

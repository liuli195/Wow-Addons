# 游戏导入与整体验收

Status（状态）: open
Triage（分拣）: ready-for-human
Assignee（领取者）: unassigned

## Parent

[开发需求](../spec.md)

## What to build

在已有真实离线候选与导入文本的前提下，与用户完成目标客户端的手动导入和关键按键行为对照，修复已定位的项目差异，并交付可运行三步流程的整体验收记录。

## Blocked by

[三步界面接入真实计算](04-three-step-interface.md)

## Acceptance criteria

- [ ] 先核对真实候选和导入文本已就绪，再讨论目标游戏版本、按键序列插件安装或配置；不提前安装。
- [ ] 用户从第四票真实界面复制文本，实际导入目标插件并核对角色、专精、动作块与绑定，记录准确版本。
- [ ] 对实际失败步进、队列、同块物品、替换与重置进行关键对照；代理不伪造用户观察，不自动按键或写游戏配置。
- [ ] 当前角色双被动饰品不能证明主动饰品实机行为；要标为主动饰品实机通过，须取得实际装备主动物品的客户端样本，否则明确保留对应待验收状态。
- [ ] 发现项目输入控制或编码差异时定位并修复，重新运行受影响的离线验证和必要搜索复测；不顺带重写上游被动模型。
- [ ] 汇总 T01—T22 的实际证据和整体完成定义，本机、游戏与尚未执行的远端／环境检查分别记录，跳过不算通过。
- [ ] 交付真实可运行三步流程、准确启动说明和结果位置；无显著改善仍可如实交付，未取得实机证据不得宣称完整验收。
- [ ] 不要求制作运行包、安装器或公开发布；任何后续远端交付按独立授权处理。

## Testing Decisions

最高入口是第四票真实界面生成文本后，由用户在目标游戏手动导入和按键；覆盖 T04—T10、T13—T16 的客户端对照和 T22 整体操作，其余测试引用前四票本次受检身份。出现差异时以同一输入重放定位，不用自测替身替代游戏观察。

## Specification coverage

`Sim2GSE distinguishes local and game validation`；导出一致性与本地运行的最终外部验收。任务需要用户参与，不能由代理代答。

## Completion evidence

待记录真实目标版本、用户观察、导入产物与模拟身份、差异处置及最终状态；当前未实施、未取得游戏验收。

# Sim2GSE Implementation Change

Status（状态）: open
Triage（分拣）: ready-for-agent

## Problem Statement

用户需要把真实邪恶死亡骑士角色导出自动转成经过模拟与复测的按键序列。目前已有研究、固定输入原型和获用户验收的三步界面，但没有真实输入到搜索再到导出的完整产品。旧规划说明不能冒充符合 MySpec（自有规格）格式的正式行为规格。

## Solution

按已经确认的五个纵向任务串行完成：角色到最小导出、同一序列的原生模拟、搜索复测及恢复、三步界面接真实流程、目标游戏导入验收。日常用户只需粘贴字符串、开始并查看进度、在结果就绪后复制文本。最终要求是可运行的三步界面，不要求安装包、便携包或公开发布。

本文件采用 to-spec（转为开发需求）的模板，是开发变更入口；正式行为要求另按 MySpec 能力格式管理，不将算法、计划或待办混入正式规格。见下方规格候选及任务映射。

## User Stories

1. 作为用户，我希望粘贴真实角色导出即可开始，以免维护技能和饰品清单。
2. 作为用户，我希望当前装备和天赋保持原样，以便结果确实适合我的角色。
3. 作为用户，我希望主动技能与主动饰品自动参与，以免遗漏可按动作。
4. 作为用户，我希望被动效果自然由引擎处理，以免出现额外的人工配置。
5. 作为用户，我希望模拟与导出的按键顺序一致，以便复制的文本对应受测候选。
6. 作为用户，我希望进度反映实际计算，以便知道当前是否仍在运行。
7. 作为用户，我希望结果就绪才出现复制区，以免误用旧结果或未完成的文本。
8. 作为用户，我希望十分钟内停止计算并预留复测时间，以免无限等待。
9. 作为用户，我希望取消后保留完整进度，以便按原有预算继续。
10. 作为用户，我希望无显著改善或验证未完成被如实告知，以免把噪声当收益。
11. 作为用户，我希望角色资料留在本机，以免被自动上传。
12. 作为用户，我希望先取得离线结果再讨论游戏导入，以免提前安装无用组件。
13. 作为用户，我希望界面简洁可运行，以免为首版等待额外打包与发布工程。

## Implementation Decisions

- 12.1 正式服的固定适配版本、邪恶死亡骑士、静止单目标、每场一百八十秒、名义三百毫秒输入，首版药剂关闭；沿用已确认自动识别与原生被动边界。
- 使用独立受控引擎与原生伤害模型，保留配装器的源码和运行环境；已有固定研究代码仅作为复用依据，不能把硬编码样例变成产品清单。
- 统一动作的多起点局部搜索、分批加测、独立复测和精确缓存沿用已确认契约；时间、并发及恢复遵守运行契约。它们属于实现决策，不写成正式行为规格里的算法待办。
- 提供一个本地任务运行入口贯穿解析、导出、执行、搜索和结果读取；三步界面调用同一入口，不另建一套演示业务。该正式入口尚待实现，现有页面仅用于交互参照。
- 同一份动作块程序同时交给编码编译与受控模拟；当前导出原型和执行原型分别使用硬编码对象及手工索引串，正式实现必须连接它们，而不是维护两套独立序列。
- 最终技术外壳不由网页原型自动决定；保持已确认三步交互和本地运行目标，采用当前项目约定下最小可运行实现，不额外建设桌面框架、服务器或打包系统。
- 文档准备不改主规格。候选留在本地规格工作区，完成实现、验证与审查后，按开发流程的规格交付阶段重新生成并核对正式差异。

## Testing Decisions

- 最高产品入口是用户提交角色、开始任务和复制结果的同一真实操作链路；当前不存在完整实现，不能使用原型计时器或伪造字符串替代验收。
- 前三票通过拟建的同一本地任务公开入口驱动实际解析、编码器和独立引擎；第四票将同一入口接入三步交互，再从实际界面重复相同成功与失败断言。首票须明确该入口的可运行调用方式，后续不得换成各自孤立的测试脚本。
- 每票先建立对应入口的最小失败检查，再完成实现并复跑转绿；研究脚本作为底层回归证据补充，不能作为唯一产品验收。
- T01—T22 逐项分配到任务；中文空格路径通过真实读写验证，游戏行为由用户实际手动导入和按键观察，不以离线替身冒充。
- 取消、损坏报告、版本变化、最终样本隔离及无改善路径均需保留可复跑证据；实际游戏之前不请求安装。

## Out of Scope

打包与安装器、公开发布、自动更新、账户或云端服务；多目标、其他专精、首版药剂、逐动作设置；重写被动伤害机制；改动配装器；自动按键、游戏目录写入或读取游戏进程。打包不再是第四或第五票的前置门槛。

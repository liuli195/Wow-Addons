## 当前范围与决定树

用户已明确替代旧来源首批方案：六步全部属于本次，训练和正式搜索统一考虑。旧三票及“来源省够便不做其余”的安排不再有效。仍沿原变更目录保存，当前范围由新版需求和门禁定义。

- 目标：当前真实规模整批同时内存2048兆字节，性能、功能及质量不退化；不能只计主程序或只验训练。
- 范围：来源→准备与初始种群→共用运行→编译模拟报告→检查点恢复→最终复测保存读取，另设整链验收票。先后顺序不代表后续可不做。
- 保真：原并行、起点、随机计划、评分、历史、语法能力、诊断、恢复及证据保持。
- 数据：固定内容引用与小清单，旧数据完整读取，开发先隔离；正式激活与兼容回退在门禁二确认。
- 限制：有损选项另行讨论，不能自行降并行/裁历史；不重写引擎。新目标未达就报告未完成，不用来源收益代替整链完成。
- 待本门禁确认的工程选择：完整分支名、七票串行与每票审查、公开验收接缝、短/完整对照及磁盘预算、同条件临时停止线和正式激活时点。

这是需求访谈与领域建模的本轮复核结果。沿已有来源、原件、修订、准备快照、完整代等术语，六步是流程范围，不新建另一套领域词典。

## 2026-11-11整链返工：历史保存分片

真实3513条历史的小对照确认：整批交给存储转换使进程峰值约1.16吉字节；每片512条约0.33吉字节，完整摘要相同，耗时接近。采用现有公开存储写入及已知键批量读取，不改存储技能、评分、并行或历史内容。历史超过512条时，将原一个完整分片改为多个有类型的分片；每片最多512条，不承诺单条任意大记录也能满足固定内存上限。

完整证据契约仍为版本3，新增可选历史布局archive_format=2及archive_groups清单，archive_group保留为首片位置；没有该布局标识的旧单片资料继续按旧规则读取。未知布局、清单缺失/重复或首片不符明确失败，不降级成只读首片。新布局不承诺旧代码可读取，旧代码会因数量/摘要不符拒绝，旧资料不迁移、不覆盖。

所有片写成并完整读回、校验原全历史摘要后才向任务状态发布新位置。中断或响应丢失时保留成功片，重试完整验真后复用；已有片损坏或内容冲突不能静默覆盖。读取通过公开read_keys（已知键批量读取）取得明确列出的片，在既有内存排序区恢复原顺序，逐条校验全部字段，调用方只保留指定字段。两条链共用此路径；仍需分别验证产品入口，不把短对照当全链通过。

## 恢复点并行争用补修

训练和正式搜索继续共用TaskStore检查点。保存期间的长输入不重复逐条转成JSON：仅在本次持锁快照内复用规范编码的固定片段，每条请求的候选字段仍独立编码，拼成原来同一完整SHA256校验值。固定片段编码总量最多1兆字节，超过后沿原完整计算；不缓存校验结论，不跨保存、任务或角色复用。公共请求及恢复格式不变，恢复读取仍独立执行原完整请求校验。

共享判断区分JSON中不同的类型和值，包括布尔、整数、小数及正负零；只有类型和值都安全等价的公共输入才复用。同种子但内容不同的输入不混用，输入变动时仍在写临时文件前拒绝原校验键。新快照给原ordinal字段建立普通索引，避免完整核验和恢复读取建立临时排序结构；旧无索引快照照常读取，原256兆字节页数上限与封存/读回/同步/原子替换顺序保留。

独立统计锁原型虽降低转换计时内的等待，但把结果交接一起计入后没有吞吐收益，因此未采用。报告重复解码原型也未在并行实测中表现出明确收益，未修改校验规则。不能以局部等待移位或短回放替代整轮性能验收。

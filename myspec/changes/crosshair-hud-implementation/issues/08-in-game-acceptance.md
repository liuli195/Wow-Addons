## What to build（要做出什么）

在真实客户端里把 16 条验收清单逐条走一遍，**各层证据分别记录**。

三层证据不得互相冒充：**离线自测通过 ≠ 原型可行 ≠ 实机验收通过**。本票只产出第三层的结论。

清单（前 13 条为用户确认，后 3 条为设计审查补出的覆盖空白）：

1. 血弧、符能弧、6 个符文格都按真实数值正确填充，方向对
2. 花掉 1 个符文 → 该格整格变背景色，再按比例长回来
3. 一次花掉 4 个以上符文 → 多出来的显示为整格背景色（不是 1%），且不报错
4. 总开关 + 4 个子开关都生效；总开关关掉时子开关置灰不可点
5. 缩放滑块两端（0.5 与 2.0）都正常：不糊、不跑位
6. 图层：打开暴雪设置窗口、打开任意下拉菜单 → HUD 都在其下方
7. 默认在屏幕正中；进 EUI 解锁模式 → 出现拖动框、能拖、退出解锁后位置保持
8. 切专精、死亡复活、过图 → 不报错、数值恢复正常
9. EUI 侧边栏 `MYUI` 分组下出现 `CrosshairHUD` 一行，页面能打开；电源按钮能真的禁用它
10. 改几条配置后重载界面，设置仍然保留
11. 打开 EUI 的全局搜索并输入关键字 → 不报错
12. 禁用 EllesmereUI → 本插件也不加载（硬依赖生效）
13. 性能轻度观察：战斗中体感流畅；用插件耗时分析器看平均耗时与尖峰无异常
14. 解锁拖动框的尺寸与位置正确
15. 改界面缩放后 HUD 不偏移、不发糊
16. 主开关关掉后屏幕中心不残留可拖动的空框

## Comments（讨论）

### 2026-09-16 第 1 轮（外观）：两条失败，均已修复并复验通过

**失败 ①：血弧与符能弧默认都是空的。** 现象：两条弧只有背景色，没有任何填充；进战斗后符能弧也不涨。诊断探针（`/chh`）显示 `UnitHealth`／`UnitPower` 的 `issecretvalue=true` 且 `可取数=false`——**受限上下文里它们是秘密值，连加法都做不了**。

初版策略（检测到秘密值就丢弃、保留上一次的值）本身就是错的：秘密值正是合法的显示输入，丢弃等于在副本与 PvP 里把两条弧打死。改为按 EllesmereUI 的同一套做法——把「比例 → 角度」这条**仿射**映射做成 `Enum.LuaCurveType.Linear` 曲线交给 `UnitHealthPercent`／`UnitPowerPercent` 引擎端求值，结果**原样**喂给 `mask:SetRotation`（`Rotation` 是 `Enum.SecretAspect` 之一）。渲染契约随之从「填充比例」改成「旋转角」，全程插件不读那个值。

**失败 ②：符能弧的填充方向反了。** 现象：从上方那端往下长。设计意图是两条弧都从靠近 6 点钟那端向上长——左弧顺时针、右弧逆时针（镜像）。反向的正确做法是把遮罩整体再转 180°，而不是翻转比例。

**失败 ③（自查）：假数据驱动的方向与真实行为相反。** 它原本血量从空涨、符能只掉不涨，拿它检查外观会得出与失败 ① 相同的错误结论。已改成满血起掉、空起涨。

**复验**：血弧满血、两条弧方向正确、符能随战斗上涨——用户实机确认。

**清单进度**：第 1 条的血弧与符能弧部分**通过**；符文格部分待下一轮。

### 2026-09-16 第 2 轮（EUI 配置页）：失败 ④，已修复待复验

**失败 ④：点行右边的电源按钮禁用本插件后，侧边栏里 `MYUI` 分组下的那一行整个消失，再也点不回来。** EUI 自家的模块只是置灰，仍能点回来。

根因：EUI 的侧边栏行只认 `EllesmereUI._addonInfoByFolder`，而条目是**谁加载谁写**。本插件被禁用后重载时不再加载，自己写不回去。EUI 自家模块没这问题——它的名册是写死在核心里的静态清单（`ADDON_ROSTER`），模块没加载也照样在册；行在渲染时按 `info.alwaysLoaded or IsAddOnLoaded(info.folder)` **实时**算出启用与否。只要行在册，禁用后自动置灰、电源按钮自动变回"启用"，**不需要插件做任何事**。

修法：把系列名册搬进公共核心 `MYUI`（新增 `Series.lua`）。核心不会被电源按钮禁用，行因此一直在册；功能插件只保留页面与解锁元素的登记——它被禁用时点开那一行没有页面，与 EUI 自家被禁用的模块行为一致。回归测试锁住"**只加载核心、功能插件完全没加载时，那一行也必须在册**"，并顺带锁住两条踩过的坑：不许设 `alwaysLoaded`（那是"不提供电源按钮"的意思，不是"行常驻"），重复注入必须幂等。

**顺带修正一处早先的误解**：往 `_syncExempt` 里加目录名只影响同步图标，与行是否留存无关；当初设它的理由写错了（保留它是对的，理由换成"本插件配置独立于 EUI 档案，没有可同步的数据"）。

**清单进度**：第 4、9、10、11 条待复验。

### 2026-09-16 第 3 轮（解锁模式）：配置页的位置控件多余，已按 EUI 原生做法改正

**用户发现（设计问题，非缺陷）**：配置页里自建的「位置」下拉 + X/Y 滑块是多余的。EUI 解锁模式的齿轮（元素选项）面板里本来就有 X/Y 输入，和拖动框同处一个会话；正确做法是用它，而不是在配置页里另开一套。

连带查出**两个真缺陷**：

1. **齿轮面板里没有 X/Y**。根因：EUI 把宽度／高度／**X/Y 位置**几行全都放在 `if canResize and elem then` 块里，而本元素当初为了绕开尺寸匹配的缩放缺陷设了 `noResize = true`——把 X/Y 一起藏掉了。这是"绕开问题的同时把功能也绕没了"：现在的做法是启用尺寸并给出正确语义（宽度／高度即整体缩放，`linkedDimensions` 保持等比），再用官方给的 `matchUnavailable` 关掉尺寸匹配。
2. **齿轮里没有「元素选项」跳转**。EUI 只在 `_ELEMENT_SETTINGS_MAP[key]` 存在时才画出那一项；现在写入了 `{ module = "MYUI_CrosshairHUD", page = "Crosshair HUD", highlightText = "HUD 缩放" }`——这条是 EUI 明确给第三方留的口子（延迟体重建该表时会合并回先前注册的条目）。

**同时修正的还有**：缩放的取值范围收进 `Config.SCALE_MIN/MAX` 一处，配置页滑块与齿轮的宽度／高度共用（两条入口改的是同一个值，不许各存一份）。

**回归测试**：新增 `test_unlock_contract.py`，锁住"不许设 `noResize`"（它会连 X/Y 一起藏掉，而配置页那边已经不自建位置控件了，两头都没有就改不了位置）、`getSize` 永远返回数字、以及跳转的页面名必须是本模块声明过的页面。

**规格已同步**：配置页项数 19 → 18，位置改由解锁模式齿轮承担。

**清单进度**：第 7、14、16 条（解锁拖动那一组）待复验，第 4、9、10、11 条待复验。

### 2026-09-16 第 4 轮（配置格式）：透明度合并／拆分，职业色无效

**失败 ⑤：选了职业配色但毫无变化。** 根因：EUI 的颜色缓存**以类名令牌为键**，而 `UnitClass` 在受限上下文里交回的是**秘密令牌**——秘密值不能当表键，查表直接抛错，被我们自己的 pcall 吞掉后静默回落到自定义色。EUI 源码里给这种情况留了原话：退回 `C_ClassColor.GetClassColor(secretToken)`，"right class, but Blizzard's default shade instead of the user's"。

修法是把取值链补齐成三级：EUI 缓存 → `C_ClassColor` → 老牌全局色表；全都不可用时回落到自定义色，**绝不允许是 nil 或黑**。第一级保留是有价值的（能反映用户在 EUI 里改过的职业色），第二级保证拿得到。颜色通道本身也可能是秘密值，所以校验一律用 `type`，不许对通道做真值判断，取值后原样交给 `SetVertexColor`。

**用户指出的格式问题（非缺陷）**：填充色与背景色各自和透明度压在一行（EUI 的 `ColorPicker` 开 `hasAlpha` 就是这个形态，整行算一项配置）；原先只有一个「透明度」改的是整条，填充与背景分不开。已拆成 `fillAlpha`／`bgAlpha` 两个值。顺带：**取色器回调里不再把来源切回自定义**——取消回调也走 `setValue`，"打开又取消"会把职业配色悄悄改掉。

**回归测试**：新增 `test_config_color.py`，逐级断言取值链（含"EUI 缓存抛错时必须退回 `C_ClassColor`"这条实机 bug）、秘密通道必须原封转交、两个 alpha 在渲染层各自到位、以及"全都不可用时必须回落到自定义色"。把取值链还原成出 bug 时的样子，测试会以"实得 0.851（自定义色）"失败。

**清单进度**：第 4 条（子开关与总开关）待复验；其余同前。

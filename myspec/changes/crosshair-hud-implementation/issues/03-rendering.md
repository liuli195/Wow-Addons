## What to build（要做出什么）

屏幕中心出现一个正确的准星 HUD，用假数据驱动就能看到三条资源按比例填充。

- **容器与帧层级**（归本票）：按设计稿坐标系摆放，圆心居中，整体等比缩放。
- **两条弧 + 6 个符文格 + 准星**：用旋转半平面遮罩实现角度填充，遮罩中心对准圆心，过渡宽度就是切线抗锯齿的来源。摆放时设计稿 y 偏移取负。
- **显示状态表接口**：渲染侧不读配置、不读游戏数据，只接受一张按元素组织的状态表（状态、比例、填充色、背景色、透明度、显隐）。**空转态要求完全隐藏填充纹理，不是把比例设成 0。**
- **一个临时驱动器**喂假数据（循环变化的填充比例），让本票能独立验证。**驱动器在票据 04 被真实读数取代。**

本票**不做**：事件与轮询、配置、EUI 挂载。

## 验收条件

- [x] 屏幕中心出现准星 HUD，两条弧与 6 个符文格的形状与设计稿一致
- [x] 填充比例随时间变化，切线是过圆心的径向线、边缘平滑无锯齿
- [x] 符文格的部分填充在 12° 的小格子上可辨识
- [x] 缩放值变化时整体等比缩放，不跑位
- [x] 渲染侧不引用任何配置项或游戏读数接口

## Comments（讨论）

### 2026-09-16 完成，本票关闭

**产出**：`Elements.lua` —— 容器与帧层级、8 个遮罩（两条弧 + 6 个符文格）、准星；接口是**显示状态表**而不是"按比例更新"。

两处按计划落实的关键约定：

- **空转态完全隐藏填充纹理**，不是把比例设成 0（状态表显式携带 `state`）。
- 渲染侧**不引用任何配置项或游戏读数接口**——颜色与比例全部由 Core 整表下发。

**关于"假数据驱动"**：`/chh demo` 用假数据循环驱动全部元素，本票据此可独立验证；票据 04 之后默认走真实读数。

**实机验收项**（外观、切线平滑度、缩放不跑位）**并入票据 08 的统一实机清单**，不在本票单独走一遍。

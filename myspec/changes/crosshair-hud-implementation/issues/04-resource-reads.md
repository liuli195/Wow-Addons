## What to build（要做出什么）

三条资源跟随真实游戏数值，替换掉票据 03 的临时驱动器。

- **血量与符能**：事件驱动，比例钳位；**四个读数接口都可能返回秘密值**（血量那个可能无条件返回），取到不可读值时跳过本次更新、保留上一次的值。
- **符文**：约 10Hz 轮询（**不能用纯事件驱动**——回复速度变化不保证触发事件，会导致进度条在增益期间走偏）。**判定顺序必须是：先判就绪 → 再判返回是否为空 → 最后才做除法。**
- **动态重排**：就绪的符文聚到一端。注意 6 张符文格纹理各自是环上不同角度的弧段、**位置固定不可互换**——重排改变的是"每个槽位显示哪个符文的状态"，不是换纹理。
- 结构性事件：切专精、天赋改动（去抖合并）、登录（延迟重读）、死亡复活、区域切换。
- **不注册符文类型事件**（正式服没有符文类型区分）。

## 验收条件

- [ ] 血弧与符能弧跟随真实数值，方向正确且互相镜像（验收 1）
- [ ] 6 个符文格各自显示自己的充能比例（验收 1）
- [ ] 花掉 1 个符文 → 该格整格变背景色，再按比例长回来（验收 2）
- [ ] 一次花掉 4 个以上符文 → 多出来的显示为整格背景色（不是 1%），且不报错（验收 3）
- [ ] 就绪的符文聚在一起（验收 6 的动态重排部分）
- [ ] 切专精、死亡复活、进出副本不报错、数值恢复正常（验收 8）
- [x] **秘密值降级由离线测试覆盖**（见下）

## Comments（讨论）

### 2026-09-16 完成，本票关闭

**产出**：`Core.lua` 的读数与事件、`tests/addons/MYUI_CrosshairHUD/test_core_readings.py`。

**秘密值降级由离线测试覆盖**（本票的硬要求，从票据 02 移入）：取到不可读值时**跳过本次更新、保留上一次的值**。测试用两种哨兵——不可读对象与**数值型秘密值**——并覆盖"检测函数本身抛错"这一路。

**过程中查出并修掉两个真实缺陷**：

1. **检测函数失效时原本 fail open**（当成"不是秘密值"照用）→ 改为 **fail closed**（无法确定就当作不可读）。秘密值一旦流进算术不会被察觉，所以宁可少读一次。
2. **检测函数原本在模块加载时捕获**（`rawget` 存进局部），行为耦合加载顺序。改为**调用时查**——这也正是那条测试原先失败的根因。

**测试的第一次负向验证骗过了自己**：关掉秘密值检测后测试仍通过，因为 `ReadNumber` 里"能否做加法"那道兜底把 table 哨兵顺手拦下了。但真实魔兽的秘密值是**数值型**，做算术不报错、只会传播秘密——那道兜底拦不住。补上数值型哨兵后，三条注入错误全部被拦住。

**实机验收项**（三条资源跟随真实数值、符文三态、切专精/死亡/过图）**并入票据 08**。

### 2026-09-16 从票据 02 移入一项验收

票据 02 原文要求"秘密值降级**与**空转降级"都由离线测试覆盖，但秘密值降级住在 `Core`（需要 `issecretvalue`，是魔兽接口），只能在写 `Core` 的这一票落地。为测试而把它塞进 `Logic` 会多造一层抽象，与"小插件不要搞重"相悖，因此改由本票承担。

**本条是硬要求**，原因是它在实机**无法按需触发**——用户无法在游戏里让血量接口返回秘密值，16 条人工清单一条都盖不到它。而仓库的测试 harness 今天就能造：`tests/addons/Sim2GSEProbe/test_probe.py:26` 已示范哨兵值写法（`function issecretvalue(value) return value == secret end`）。

要断言的行为：**取到不可读值时跳过本次更新、保留上一次的值**，绝不让秘密值参与比较或算术。另需覆盖**四个接口的标注差异**——`UnitHealth` 是 `SecretReturns`（可能无条件返回），另三个是"受限时才可能"。

> **实机验收项不在本票勾选。** 本票只勾离线可判的项；外观、交互与集成那部分在[票据 08](08-in-game-acceptance.md)的统一实机清单里验证，勾选状态在那张票上更新。

# 参考引导的父子代繁殖：实施需求草案

状态：布丁最终审核及限定复核通过；2026-11-09用户显式确认门禁一，要求新独立工作区，已进入实施。四票串行主代理开发、每票独立审查，生产训练和完整搜索仍不在本轮范围。

本文记录从用户开始讨论“第二步：变异与交叉优化”至今的决定。完整决策沿革见同目录 `discussion-record.md`（讨论记录）。后续研究结论须更新本文，不能只留在聊天中；被替代的方案保留沿革但不能混入当前要求。

具体可实施契约、公开测试入口和四张纵向票据见同目录 `design.md`（门禁设计）及 `issues/`（任务票据）。本轮将剩余工程细节列成门禁整套推荐，不再把已放弃的成功率公式当作待决事项。

## Problem Statement（问题说明）

当前变异、反馈修复和操作执行混在同一条路径中，用户难以了解实际改了什么、为什么改、哪些位置或技能无法修改，以及有效修改、重复、评分复用和最终收益之间的关系。新增的目标变异必须具体使用同场景参考的成功频率与先后关系，不能把现有失败位置反馈冒称为已经实现。

仅减少无效操作、补日志不满足本需求。方案必须从原始训练种群贯通到正式搜索和最终推荐导出；以真实代码、记录和低成本验证说明现状、缺口和最小改法。

## Solution（解决方向）

1. 复用当前数据表示、基础操作、DEAP（遗传算法框架）、评分、可靠保存与恢复，不建立第二套搜索平台，不修改安装的框架包。
2. 分开基础操作、随机选择、参考目标选择：基础操作只管合法条件和执行；随机变异随机选择操作、位置与所需技能；目标变异根据成功频率和短时序差异提出操作及位置。
3. 目标变异、随机变异、交叉是三个平级且独立的触发步骤，取消外层总变异门。固定顺序为“目标变异→随机变异→交叉”，三个概率分别在0至1内，不要求合计为1。
4. 目标步骤与随机步骤按每条子代抽取，交叉按每对抽取。一个正常繁殖轮中，一条子代最多各尝试一次目标变异、随机变异和交叉；非法重生沿现有有界规则处理。
5. 参考提供方向，原伤害评分决定保留与排名。相似度不取代伤害评分，不承诺参考为理论最优，也不禁止超越参考。
6. 训练每组使用自己的模板、英雄天赋及具体目标数参考；正式搜索重新使用当前用户角色与场景的参考。单目标使用一目标参考，五目标使用五目标参考，不把所有多目标当成同一种条件。

## User Stories（用户可观察要求）

1. 用户能够区分交叉触发概率、随机变异触发概率和目标变异触发概率，不存在未说明的外层80%或旧50%反馈门。
2. 用户在相应诊断开启时能够区分配置触发次数与实际有效修改次数；关闭时明确未采集，不伪造0。抽中不保证必然改变内容，训练不因此新增完整过程日志。
3. 用户能够将同一基础操作用于随机及目标路径；禁用语法不会被任一路径重新引入。
4. 用户能够知道目标建议依据是频率、短时序还是两者共同支持，并看到实际操作和源位置。
5. 用户能够在同场景下比较真实成功施法频率，而非列表出现次数、按键次数或排队次数。
6. 用户能够对“列表中完全缺失”“已有但使用不足”“使用过多”分别得到可解释的候选建议。
7. 已有技能成功频率不足时，在“增加该技能一处”和“移动该技能现有一处”两种合法操作间随机选择，不再划分2.1／2.2，不按成功率数值选择操作。用户已确认这一规则，尚未授权开发。
8. 用户能够观察实际成功技能的相邻先后关系；比较不跨战斗、独立爆发或其他不可比边界拼接。
9. 普通循环的基础按钮、替换形态、爆发、战前、宠物和派生效果归属可靠；派生伤害不冒充额外成功按键。
10. 每次目标变异只应用一个基础操作。多项证据可以共同支持一条修改，但不能未经说明连续执行多个目标修改。
11. 目标步骤没有可执行建议时明确跳过，后续随机步骤仍只按自身概率触发，不暗中强制补随机。
12. 参考身份不匹配、模拟错误、存储错误与单次无建议明确区分；错误不能伪装成无建议。
13. 原始训练材料仍经现有准入、角色适配、爆发排除和去重。合法候选不能仅因不像参考被永久排除；来源原件不改。
14. 训练父本、每代子代、反馈与随机状态按组隔离；一个组不能使用另一英雄、模板、角色或目标数的反馈。
15. 训练继续按完整代、既有粗评和五场景复测规则发布四个合格且不同行为的代表；不足四条不凑数，不覆盖旧成果。
16. 正式搜索仍消费原四类起点、适用训练成果和历史冠军等全部合法来源，经过当前条件下适配、去重和重新评分。
17. 训练成果进入正式搜索时仅传递可核验程序及出处，不把训练模板参考或旧分数当成当前角色的目标和成绩。
18. 单目标、五目标正式任务各绑定自己的当前角色参考，沿既有评分、自然停止和正常复测后推荐冠军。
19. 最终导出的GSE（高级按键序列插件）序列与受测程序一致；独立爆发沿冻结定义单独处理，普通候选不能借爆发名义绕过限制。
20. 合法重复可以保留种群名额，但同一完整评价复用可靠成功结果；复用不能增加独立样本数，不要求所有子代都不同。
21. 父本被复制后才修改；一个子代的修改不会原地改变父本或其他子代。
22. 三个修改步骤之间不新增逐步择优评分；最终子代沿用原评分，父本必要反馈另计。不把研究期间的增位／移位对照接成每代必跑的生产步骤，上一轮独立探测建议保留历史，不列为当前默认推荐。
23. 没有全部完成的一代不能计入完整代数、无改善计数或发布结果。
24. 中断后按原冻结策略、参考、随机状态、待处理子代和已耗重试次数恢复，不重新抽一代或热换参数。
25. 新旧策略的成果及恢复身份可区分；旧完整成果保留只读，不把旧未完成任务悄悄切到新策略续跑。
26. 日志只记录必要且有界的证据，观测开关不改变随机选择、候选、评分或业务结果；默认关闭详细诊断不应删除目标策略真正必需的数据。

## Implementation Decisions（实施约定与待决边界）

### 已确认的结构与顺序

- 共用增加、删除、替换、交换、移动以及现有合法片段交叉能力；保留四项复杂语法的现有配置控制，不删除复杂编辑代码。
- 三个平级触发步骤，执行顺序为目标、随机、交叉。保持框架包不变，只调整项目自身的调度；尽量复用框架的操作注册、复制及分数管理。
- 一份输入对应一份可靠位置反馈。发生修改后，旧源位置反馈不能直接冒充新程序反馈；场景参考仍可有效。目标在最前面，优先复用选中父本的反馈。
- 不以目标无建议为由强制补随机。此前的“自动回随机”建议已被本约定替代。
- 用户已确认80%目标、30%随机、30%交叉作为可配置初值，以及新任务明确退役旧总变异参数；不代表伤害最优。80/60/60与80/20/20只保留历史备选，不是本轮默认或待运行对照。

### 频率规则草案

频率指同场景每有效分钟的真实成功次数，不是源列表重复次数。

1. 技能缺失：参考使用而列表没有；有容量时提出插入，满容量时优先考虑替换一个使用偏多位置。
2. 已有技能不足：
   - 不再细分原因，随机选择增加一处或移动已有一处；两种都可执行时等机会抽取，只剩一种合法操作时选择该种，均不可执行时跳过。
   - 插入受容量限制，移动必须实际改变内容；不暗中改为替换、交换或删除，也不因成功率高低改变选择概率。
   - 这是候选生成规则，不保证实际成功频率一定提高，仍由最终伤害评分判断。
3. 技能使用过多：优先把一处替换为使用不足技能；没有合适替换时可提出删除一处。

这些都是生成候选的软建议。参考不使用某技能不能成为永久封锁；首版按同口径频率正负差提少量建议，相等不改，不新增未经验证的硬容差或样本量阈值。保留实际样本数及有效时长，小样本风险由原评分与复测控制，不把建议当成游戏定律。

### 已确认：频率不足时随机增加或移动

用户2026-11-09已决定放弃成功率数值选择，不再区分2.1／2.2，采用简单随机增加／移动。旧分类、成功率办法及独立对照保留在讨论记录中作为历史，不作为实施待办或默认步骤。

**当前规则已确认，开发尚未授权。**

1. 同条件成功频率发现不足，选定关注技能；不能只因成功率低就处理一个成功频率已经达标的技能。
2. 对选定技能，在增加一处、移动已有一处两种合法改法中等机会随机抽取。技能由参考缺口确定，位置继续结合当前反馈、短时序及合法性选择；不依据成功率高低选择操作，不新增这一内部选择的配置项。
3. 一次目标步骤只做一个操作，随后按已定独立门执行随机变异、交叉；最终子代沿用原粗评、榜单和复测。不为这一项另开原版／增位版／移位版评分，不新增“先对照获胜才繁殖”步骤。
4. 非法、没有变化、没有可靠目标建议分别记录。已确认禁止的强制随机回退、父子择优、额外名额均不加入。

**历史备选：成功率优先选择，用户已明确放弃。以下仅解释验证背景，不属于当前要求。**

- 此处把用户口述“示范成功率”按其分子分母解释为“施放成功率”：同一技能真实成功次数／有效尝试次数，不是参考模拟自己的成功率。
- 对当前普通循环每个基础按钮分别计算，重复位置先归并，同输入排队、失败后成功不能重复计数；零尝试为未知，不记为0%，并排除暖场、爆发、战前、宠物和派生事件。
- 当时各技能成功率排序，“中位数库的平均值”存在歧义，研究比较中间一半均值、直接中位数和全体技能均值。因整个办法已放弃，不再需要确认公式或开发此统计。
- 原备选是在成功频率不足时，按成功率相对中心值优先增加或移动；用户已放弃其硬分支、软偏向及后续专门验证计划。
- 低成功率也可能来自冷却、资源、状态限制或过密尝试；高成功率也不排除时序改善空间。增加一处会改变整轮长度及后续时刻，移动也会影响资源竞争，因此两种编辑不是互斥根因的纯修复器。
- 在同一归并口径下，成功频率＝尝试频率×成功率。因此成功不足可能同时通过增加尝试或提高成功率改善。例如每分钟尝试10次成功6次、参考8次，可考虑多尝试，也可将原10次的成功率提高至80%；60%并不能证明只缺尝试。按当前成功率反推所需尝试仅是成功率保持不变时的估算，不是因果判断。

**本轮验证与推荐边界。**

公开测试角色、单目标、三种父本、两个固定种子，每批4请求、扣暖场后3场。复用现有编译与原生评分，共18个新评分批次、72请求，约2.859秒；未训练、未正式搜索。按已有参考四个基础按钮统计找到3个不足案例，各提前冻结一个增位和一个移位，不按伤害挑位置。中位数与中间一半均值在这四技能样例相同，3次均未选中两版平均伤害较高者；全体技能均值选中1次。

这只否定当前硬判断足够可靠，不证明成功率引导普遍无效或方案甲生产收益更高。原生自由参考保留爆发而小例未接独立爆发链路，故不是完整生产条件对齐验收；只有一个公开角色、少数编辑、两种子，比较用两版观察成绩算等机会选择的期望，没有运行两套遗传搜索，也没有独立赢家复测。

用户现已确认简单办法：不足技能随机增加或移动，最终走原评分；成功率备选不再保留为开发或研究待办。不加入独立对照，也不每次同时评两版后取最好。

### 短时序规则草案

第一版比较相邻普通成功技能关系，采用候选自身反馈定位源列表。具体整数比值、严格比较条件、三类先后及并列规则见设计第2节判定表；没有有界甲→丙→乙见证时，只称衔接不足，不宣称已定位阻隔原因。

1. 顺序反向：参考常见甲后乙，候选常见乙后甲；提出交换或移动。
2. 连续重复不合参考：候选过多甲后甲，而参考通常穿插其他技能；提出移动、交换，优先保留技能数量。
3. 应衔接却被隔开：参考常见甲后乙，候选常被其他成功技能隔开；提出移动已有乙或移开中间项。

“相邻成功”不等于物理时间很短。记录实际间隔用于核验，第一版不增加固定毫秒衔接硬规则，也不承诺逐秒重放动态参考。模糊同刻顺序、不可定位项不猜测；战斗、爆发边界不得被过滤后拼成虚假相邻关系。

### 目标内部建议选择：尚待最终确认的推荐

- 合法性和数据身份先行；频率、时序平级，不要求频率完全匹配才处理时序。
- 各维度先给少量最明确可执行建议，相同操作与位置的建议去重并合并依据；一次选一条，不为同一问题重复投票。
- 仅一个维度有建议时使用它；双方建议不同时，第一版给两个维度同等选择机会。该选择规则是助手推荐，尚非收益验证结论。
- 规则按问题分类，不限制“频率只能增删”“时序只能移动”。频率不足也可能需要移动；缺少衔接且频率不足时，也可能共同支持插入。

### 原四条诊断规则的最终处理方向

- 用户明确要求抛开旧四条边界，分别定义频率、时序规则；可靠数据可复用，不原样叠加旧规则。
- 失败位置、未尝试技能、低成功率数据作为证据，不各自自动决定改法。
- 原“资源溢出后按相邻事件猜消费者并插入”已在上一功能中停用，不恢复。
- 取消仅凭“尝试超过两次、成功率低于5%”自动删除的旧推断。资源溢出第一版保留观察，不单凭它插入。

### 参考与成果身份

- 当前原始参考动作轨迹仅是有限场次/长度记录，不能当作100或128场完整成功统计。排队失败过滤也不能普遍证明其余记录均真正成功。
- 原始执行次数可能含暖场，不能直接除以伤害有效样本。需核对真实执行挂点、有效战斗分母、基础按钮映射，优先复用可靠统计，必要时补有界小摘要。
- 参考及候选摘要应包含可核验的成功频率、相邻成功对、有效样本和时间分母；候选另有按键来源与源位置。既有日志关闭不应丢弃这些业务必需摘要。
- 自由参考与受控候选分别接入真实执行路径，共用统计口径而非假设现有受控通知覆盖两者。自由参考显式绑定普通按钮目录／爆发排除集合，仍自由选招；受控按冻结来源与爆发窗口断段，即使爆发全失败也不拼接两端。跨窗口延迟执行按原输入归属，不能连接当前段。
- 暖场资格沿原有效评分生命周期，单请求仍有一有效样本，不能一律删除编号0。成功为0但有效时长非0与摘要缺失严格区分。完整有效战斗时间包含爆发耗时，具体口径见设计。
- 冻结角色、装备天赋、英雄、具体目标数、引擎、模拟条件、按法、语法及独立爆发身份。训练和正式参考分开绑定。
- 任务身份新增三个概率、执行顺序、目标策略与摘要版本、参考身份；恢复不热更新。评分缓存继续按完整评价条件核验，不为本需求重构跨任务缓存平台。

### 繁殖、失败与成本约定

- 保持现有竞争选择、固定容量完整换代和历史领先榜，不新增父子合并择优或“变差退回父本”。允许相同父本重复被选，奇数末条只跳过交叉。
- 非法子代沿原初次失败后最多10次额外重生；模拟及反馈沿原原候选原条件一次重试。正式搜索现有明确评分异常的保留槽位策略与训练失败策略分别保留，不能互相套用。
- 每步先排除明确不可执行的操作，最终仍做完整合法性及导出上限检查。不要求每次变化，不无限重抽，不复制补齐不同候选。
- 同程序同条件反馈复用，不逐建议模拟。目标、随机、交叉之间不各跑伤害评分，最终统一评分。新增必要诊断探测的预算及接入办法如被推荐，必须明确列作设计变化，不隐瞒额外成本。
- 必需业务摘要／恢复待办始终保存；纯诊断的触发、变化、非法、重复、评分复用等沿原采集开关，关闭时标未采集。双父本、切点与全过程输入输出只接正式搜索原观测范围，训练仍基础日志／曲线；不能将全部最终收益归功于目标步骤。

### 本轮复核补齐的具体边界

- 基础操作先筛合法集合，再随机选择操作与位置；增加／替换再选技能。交换选内容不同的位置，插入计算普通程序、固定战前前缀及最终编译共同限制，不只检查普通列表是否小于128项。
- 当前简单路径五类随机操作最初各占五分之一；随机移动保留连续一至四项及原可执行约束，目标移动固定该技能源结构一处。共用编辑不等于同一选择范围；复杂结构不展开后改某个运行副本，无法可靠绑定时不提该目标建议，原复杂随机能力保留。
- 当前交叉先保留同切点整尾交换；首项可由变异改变，不是搜索不可达。保留小空间编辑覆盖检查；目标交叉、任意中段交换、复杂循环编辑扩展留作另项，不混入最小改动。
- 正式观测开启时区分记录创建、候选处理、原生实际启动、完成、复用及种群去向，关联双父本、切点、来源和无变化原因；训练仅在原基础采集边界内报告必要摘要，关闭诊断标未采集。名额和不同行为数仍可从业务状态核验，重复评分复用不算新增探索。
- 框架继续复用操作注册、复制、失效分数管理及已有保存链路。原调度固定先交叉后变异，不能靠改参数得到用户指定顺序；项目调度调整不等于修改框架包。早期“直接保留原调度，只加内层目标比例”的建议已被三个独立门及新顺序替代。
- 三个概率仍放现有共用配置文件，训练、正式各自取值并冻结；门禁推荐初值目标0.8、随机0.3、交叉0.3，非已证实最优。新任务显式提供旧总变异参数明确报退役，历史完整成果仍按旧凭据只读；页面、运行参数、文件、默认的既有优先级保持。完整字段与错误契约见设计，不保留隐形外层门。
- 参考准备、必要反馈、粗评与复测共用现有组内并发名额，不额外开一批引擎。正式搜索与训练的调度优先关系及既有并发限制保持；保存恢复包含反馈准备状态和实际重试消耗。

## Testing Decisions（验证要求）

1. 四票最高公开入口分别绑定现有单程序任务与训练准备、训练公开入口、正式任务公开入口、页面服务器与双场启动／恢复。从这些入口做失败检查、转绿和最终冒烟，覆盖材料到四代表、当前角色一／五目标参考、推荐及导出；不只测试内部选择器。
2. 先做小型确定性逻辑检查：每项基础操作、首尾与容量、三个独立门、执行顺序、目标无建议跳过、重复评分复用、位置反馈失效、两场参考隔离及恢复。
3. 手工事件检查同一输入排队/失败/后来成功的最终归并、暖场/爆发/派生排除、频率相同顺序不同、时序相同次数不足等情形。
4. 保留现有失败重试、非法重生、完整代、取消恢复、随机路径重放及观测开关不影响结果的检查。
5. 先证明逻辑与端到端链路正确，再在明确授权、固定预算和独立复测下做原生口径及比例收益对照。本机定向测试、纯逻辑样例、原生模拟与游戏验收分别报告。
6. 任何新增禁止语法、反馈错位、参考混用、原地改父本、无界额外计算、观测改变业务、失败覆盖旧成果或恢复换参数，都须阻止交付。
7. 频率不足分支覆盖：两种合法操作的随机选择、只有增加可行、只有移动可行、均不可行、容量上限、重复位置移动无变化、相同输入下改变成功率统计不影响操作选择，以及不新增独立评分。成功率中心值与2.1／2.2分类不再要求实现。
8. 新增关键反例：爆发全部失败仍断段、跨窗口延迟成功、排队后成功一次、替换转发、单请求／暖场、零成功非零时长；同一行为不同源结构重绑位置；反馈途中、目标后／随机前、随机后／交叉前、非法重生和整代未提交的恢复。旧参数即使显式为0或false也报退役，不先用真值忽略。

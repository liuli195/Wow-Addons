# 04：双场页面配置、恢复与最终导出闭环

**What to build（交付行为）:** 用户在现有页面设置三个独立概率，启动当前角色单目标与五目标任务，观察实际状态、恢复未完成任务，并分别取得两条普通推荐及独立爆发导出。

**Blocked by（阻塞任务）:** 03：训练成果与全部起点贯通正式推荐导出。

**Status（状态）:** completed

## 验收条件

- [x] 页面显示三项概率及固定顺序，明确各自独立、合计可超过100%；不残留旧总变异字段或隐形转换，不展示研究用成功率中心配置。
- [x] 页面选择、文件和直接入口优先级一致；双场父任务与两个子任务冻结同一概率策略，但分别绑定真实目标数及各自参考。
- [x] 沿现有页面服务器请求及双场公开启动／恢复入口完成失败检查→通过，不绕开页面只测参数函数。
- [x] 单／五目标推荐分别经正常复测并导出，独立爆发按可信冻结定义单独处理；导出与受测程序一致，四语法关闭效果保持。
- [x] 一场失败、取消、恢复和旧成果读取状态真实；恢复不把新配置写进旧任务，不重新抽代，不展示旧分数为当前成功。
- [x] 观测开关不改变业务，必要业务摘要仍在；正式原观测范围开启时能解释变化、重复及复用，关闭为未采集。训练基础日志边界不扩大，不新增整套日志平台。
- [x] 四票必要回归纳入现有统一检查，固定基线差异验证在干净提交树通过且实际检查非空；各入口成功及风险路径冒烟完成。

## 公开测试接缝与范围

现有页面服务器和网页请求测试、双场启动／恢复以及真实导出检查。自动夹具覆盖整条链，必要有界原生核验按设计上限；不启动生产训练、完整搜索、最佳比例比较或游戏验收。

## 验收条件

- [ ] 同一真实成功收集方式覆盖自由参考与受控候选，每有效战斗统计基础按钮次数、相邻对、前项分母和完整有效时长，不以有限样例轨迹代替。
- [ ] 排除暖场、战前、宠物、派生和独立爆发计数；基础／替换形态正确归并；爆发与战斗边界断开相邻，分母不扣爆发时间。
- [ ] 在已有报告／可信批次记录保存版本化摘要及完整条件身份；缺失、损坏、身份不符明确失败，不填零；真实全零统计与缺失区分。
- [ ] 诊断开关不改变摘要、战斗行为、随机状态和伤害；不为摘要调用额外可执行条件检查或追加模拟。
- [ ] 从单程序任务及训练准备的公开入口完成失败检查→修复→通过；新摘要可重读，旧完整成果仍按原凭据只读。
- [ ] 必要原生口径验证遵守设计上限，不将模拟验证冒称游戏验收或伤害提升。
- [ ] 自由参考与受控分别有真实执行收集路径；参考显式传普通按钮目录／爆发排除集合，保持自由选招，不套受控窗口。不能以受控执行前通知冒称通用成功挂点。
- [ ] 覆盖排队后成功仅一次、替换转发、爆发全失败仍断段、跨窗口延迟执行归原输入、单请求仍一有效样本、暖场资格及零成功非零时长。
- [ ] 每票结束回归当前仍公开的正式入口；引擎身份改变使旧未完成任务不兼容时明确拒绝，不误伤历史完整成果。整个变更12调用／每批4请求／累计45秒含失败重试，不按票重置。

# 数据中心限定读取与消费端修复

Status: implementation-in-progress

## Problem Statement

页面、双场搜索与训练已经知道任务或批次身份，却仍通过通用查询注册整个共享中心，造成无关数据读取、内存压力与故障扩大。原训练分组核验与历史六列筛选已在固定基线完成，本变更保留其回归，继续修复已知身份仍扩大读取的问题。存储错误经任务包装后也可能被页面误判为计算或角色错误。

## Solution

复用现有数据中心、逻辑键、报告位置清单及任务检查点，先限定需要的表，再优先按已知存储组和逻辑键读取必要字段。父任务已核验的爆发身份贯通子任务，子任务仍核对当前定义。旧公共接口在启动计算前明确报错。分组复测与旧单条复测均能通过同一只读核验入口定位。

## User Stories

1. 作为页面用户，我希望摘要读取只访问所需记录和字段，以免查看进度读取完整历史报告
2. 作为页面用户，我希望详情使用任务已经保存的批次位置，以免查询无关中心数据
3. 作为双场搜索用户，我希望两个场景复用同一冻结爆发身份，同时拒绝已变化定义
4. 作为训练用户，我希望历史整理只读取当前职业专精的必要字段，并批读已知候选键
5. 作为训练用户，我希望多材料选择只读取一次已有登记快照，并保持错误编号拒绝规则
6. 作为升级用户，我希望核验能读取真实分组复测，同时兼容旧单条报告，且仍严格验真条件、程序与样本
7. 作为用户，我希望数据存储不可读在页面显示为可行动的存储故障，不被误报为角色或引擎错误
8. 作为维护者，我希望消费启动核对公共接口能力，并明确区分隔离开发验证与正式安装接入

## Implementation Decisions

- 公共通用查询要求必需非空的逻辑表范围；单键、多键、字段投影与过滤接口沿用原契约
- 消费适配器加载时检查公共 API（应用接口）版本恰为 2，并检查多键读取能力；不修改已安装发行号来伪称发布
- 已知批次优先使用任务只读检查点的存储组；无法从检查点定位时使用现有报告位置清单或既有单键格式，不因缺失而自动全表扫描
- 报告位置对象复用已核验清单增量，不删除首次完整性核验、写入锁、原子发布或恢复机制
- 首次未知爆发身份只查询爆发定义表；父子与同次训练准备传递已核验的冻结身份，实际开始仍点读并验证当前记录
- 历史整理在限定任务表中用 SQL（结构化查询语言）按职业专精过滤并投影必要字段，候选按已知键批读
- 复测核验复用任务保存的分组定位和字段过滤；旧单条没有组凭据时仍按原键点读
- 基准源码快照显式绑定原项目共享中心，不建立第二套生产中心
- 消费票 01 与 02 由同一实施者串行完成；训练已合入当前主干，已完成的分组 postcheck、历史六列 SQL 筛选与连接释放修复保留，不重复开发

## Testing Decisions

- 接缝沿用已连接项目消费入口、任务运行与结果读取、双场启动、训练命令行准备与查询，以及只读升级核验
- 每个票据先通过最高可用公开入口保留最小红灯，再最小修改并重跑同一入口取得绿灯
- 使用真实隔离 Parquet（列式文件）与小组数据，加入无关损坏表证明已知读取不扩大范围
- 原生模拟与编译复用既有测试边界；不真实训练、不访问私人角色或生产中心
- 分组复测至少一项真实存储样本，不能以按业务键返回字典的替身掩盖存储寻址错误
- 云端 Linux（操作系统）兼容诊断不代表 Windows（操作系统）、真实引擎、实际游戏或正式技能安装验收

## Out of Scope

不更改引擎、评分、训练收敛、动作规则、600秒搜索预算或旧数据；不新增存储系统、静态检查器、历史全量复核或缺少证据的完成凭据扩验。正式发布、合并、部署、本机诊断及真实训练另行授权。此前被拒绝上传的训练旧测试不夹带提交或上传。

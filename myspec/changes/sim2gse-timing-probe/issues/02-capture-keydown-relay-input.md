# 02: 采集 GSE 安全执行消息

**What to build:** 使用 GSE 安全绑定时，探针从每次安全动作提交发出的 GSE 消息记录完整提交，让保存结果包含序列、提交步骤和动作，而不只记录原生施法事件。

**Blocked by:** 01/采集真实 GSE 输入与施法时机（已完成）。

**Status:** closed

- [x] 离线公开接缝复现 GSE 安全执行消息，并能在修复前得到零点击的失败结果。
- [x] 修复后同一消息按点击序号只记录一次完整点击，并正确还原序列回绕前的提交步骤。
- [x] 受限值安全降级、合法布尔值和乱序旧消息处理继续通过。
- [x] 12.1 正式服确认安全动作提交会增加点击记录，并完成五段队列实验采集。

## Completion evidence

- 红灯：真实中继路径断言失败，提示 `keydown relay has no observable completion hook`。
- 绿灯：同一公开接缝测试通过，记录一条完整提交；受限值安全降级保持通过。
- 固定基线快速验证状态为 `passed`，检查插件语言、静态规则、清单、运行测试、文档和测试登记。
- 0.1.1 的中继点击后回调在正式服仍产生零点击；该失败证明按钮点击脚本不是可靠采集入口。
- 0.1.2 改用安全执行后的按钮更新方法，正式服仍为零点击；该失败证明安全执行不会可靠触发普通 Lua（脚本语言）更新钩子。
- 0.1.3 直接从全局 `GSE` 订阅消息，但本机 GSE 3.3.33-a 的全局对象只是兼容代理，不含消息接口和已编译序列；正式服状态明确显示消息未连接。
- 0.1.4 改为从 GSE 共用的 AceEvent（事件总线）订阅消息，并只在点击序号连续时以相邻消息的下一位置还原步骤，不再依赖 GSE 私有命名空间；12.1 正式服确认消息已连接、动作提交会增加点击记录，随后完成五段队列实验采集。
- 实机验收只证明带动作的安全提交消息可采集；暂停或当前步骤没有动作时 GSE 不发送该消息，因此不在本票据的可观察范围内。
- 0.1.5 修复合法布尔值 `false` 被写成“不可读取”的问题，拒绝重复和倒退的旧点击序号，并补充多序列交错回归覆盖。

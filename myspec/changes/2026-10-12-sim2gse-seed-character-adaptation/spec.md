# 按当前角色适配已训练起点

**Status:** gate2-approved-spec-applied-pr-in-progress（门禁二已获批、正式规格已应用；PR交付进行中）

## Problem Statement

已训练起点来自标准角色，但新网页任务使用用户的实际角色。标准巨魔萨莱因角色的五目标入选库有四条程序，其中两条含当前高岭牛头人角色没有的狂暴或灵魂收割；当前加载过程因一个不支持动作丢弃整条程序，合法的普通循环也无法进入搜索。

## Solution

新任务读取既有入选快照时派生适合当前角色的程序，只移除原生报告明确证明因种族、天赋或等级而永久不可用的可按动作。保留其余按键动作块与控制结构，重新进行当前角色合法性检查、行为去重和评分。原训练来源、程序与成绩保持，不重新训练。

## User Stories

1. 作为网页用户，我希望标准角色训练出来的合法普通循环能用于自己的角色，从而不因一个没有学会的动作丢失整个起点。
2. 作为高岭牛头人用户，我希望含狂暴与自动攻击的按键动作块移除狂暴并保留自动攻击，从而保留其可执行部分。
3. 作为没有灵魂收割的用户，我希望仅含灵魂收割的按键动作块删除，从而不加入永远不能执行的步骤。
4. 作为网页用户，我希望冷却中、资源不足或暂时不能成功的动作保留，从而不把正常战斗失败条件当成角色缺失能力。
5. 作为网页用户，我希望未知动作或不支持的语法明确说明无法采用的原因，从而不会得到静默漏动作的程序。
6. 作为网页用户，我希望其余动作、动作块和循环的顺序及重复次数保留，从而理解适配后程序实际会尝试什么。
7. 作为网页用户，我希望空点击保留其次数，从而不因技能裁剪改变既有等待定义。
8. 作为网页用户，我希望施法序列的成员顺序和重置规则保留，从而不把施法序列偷偷改为普通按键动作块。
9. 作为网页用户，我希望没有剩余可执行动作或无法忠实表达的程序独立跳过并记录原因，从而其余合法起点仍可搜索。
10. 作为网页用户，我希望适配后按实际行为去重，从而相同程序不会冒充不同搜索路线或虚增停止门槛。
11. 作为网页用户，我希望新程序使用当前角色与当前场景重新评分，从而不会把标准角色的旧成绩当成当前成绩。
12. 作为用户，我希望可通过既有任务读取入口核查原起点、派生程序、删除位置和原因，从而追溯适配发生了什么。
13. 作为用户，我希望每个任务只读取一次小型入选快照并在恢复时继续使用冻结结果，从而库的后续变化不会混入进行中的任务。
14. 作为用户，我希望原始来源、已完成训练成绩和已有入选库保持，从而本次修复不要求重新训练已完成的路径。

## Implementation Decisions

- 适配只发生在新普通搜索任务的入选起点加载阶段；网页默认双场流程通过既有任务入口使用它。单次显式程序、导入、原生引擎、固定爆发定义和通用动作选择规则不改变。
- 只使用本任务当前原生 APL（动作优先级列表）目录已经实例化的动作证据：动作已初始化且静态资格不可用，才能列入可删除集合。当前动作池中已有的同名可用按钮优先保留。缺字段、未初始化、未知名字、仅未执行以及饰品不可用说明不能替代这项证明。
- 静态资格依据是角色等级、种族和天赋，不使用冷却、资源、执行次数或瞬时成功条件推断。动作身份沿用既有名称和原生映射，不建立手写技能黑名单。
- 将已有训练适配中的纯结构裁剪提取为共享的小接口；训练入口仍只计算原来的固定爆发排除策略并调用该接口，不加入当前角色缺技能的新策略。只读原程序，返回派生程序与逐项删除位置。
- 普通按键动作块移除明确排除动作，空块删除；顺序循环保持重复次数及剩余块顺序，整个循环空体时删除。原无效次数、超长或无效块不因裁剪被洗成合法结构。
- 空点击等待节点保留并沿用既有次数校验；只有空点击而没有可执行动作的结果仍拒绝。
- 施法序列裁剪前先以当前原生已知动作证据核验原成员与重置定义，再移除明确排除成员。零成员删除，两个及以上成员保持原表达；单成员仍由既有最少成员规则拒绝，不能转为普通动作、复制成员或伪造重置。未知成员、无效原结构或重置不因删除被掩盖。
- 派生后以真正的当前角色动作池重新规范化、检查固定爆发排除、按行为身份去重并进行现有导出预检。只把通过后的派生程序加入原四类起点之后，仍最多追加四条；数量以真实合法、去重且成功评分的路线为准，不承诺八条。
- 未知或无法映射的入选起点沿用现有候选级拒绝，记录原因并继续其他候选；不能删掉未知动作后采用剩余部分，也不能掩盖整个快照的读取故障。
- 任务检查点同时冻结实际起点和适配决定。决定记录原候选身份、原程序、派生程序、删除位置与原因、采用／重复／拒绝结果和成功时的行为身份；复用既有任务 JSON（数据交换格式）摘要保存，由既有公开任务读取入口返回。不扩充逻辑表，不新增页面控件或日志框架。
- 原来源、训练处理记录、入选快照和旧成绩不写回。当前搜索仍按既有评分、预算、样本、并发、路线轮转和停止规则运行，不启动训练或独立训练复测。
- 共享裁剪提取应保持训练行为逐项一致，因此不仅因源码移动递增训练、搜索、统计或行为语义版本。训练源码摘要仍保留出处；可靠完成成果沿用现有严格语义身份核验。
- 新普通任务的源码规则摘要会改变。旧普通任务及旧训练子任务的原地续跑继续按既有严格摘要检查拒绝，旧结果可读且不被改写；不增加迁移或兼容绕过。新代码创建的任务在同条件恢复时继续沿用冻结程序、成绩与预算。
- 正式规格只在完成实施、验证及限定审查后的第二门禁准备预览和应用，不在实施阶段修改正式规格。

## Testing Decisions

- 目标产品是网页默认双场搜索。最高层级真实用户入口为页面的开始运行请求：POST /api/tasks，mode 为 dual；经原生产任务执行到 GET /api/tasks/{id} 的场次结果。红灯、绿灯和最终冒烟使用同一入口，不能只以私有辅助函数测试代替。
- 复用已有内存结果中心、快速评分边界和 HTTP（超文本传输协议）服务检查设施；合成角色与原生目录证据不包含用户私人数据。云端替身接线证据如实标为接线与纯逻辑检查，不冒称 Windows（操作系统）受控引擎或真实游戏验收。
- 主要成功检查：五目标快照含狂暴与自动攻击同块、灵魂收割单独块；确认派生程序进入当前角色评分，四类原起点顺序保持，适配后重复只保留一条，旧 score（成绩）不成为当前分数，原来源与旧成绩逐项不变。
- 结构与拒绝检查：普通块、顺序循环次数及顺序、空循环、空点击等待、施法序列剩零／一／多成员及原重置；未知动作、缺原生证据、未初始化、当前可用同名动作、无效原结构、无效重置、仅空点击和导出不支持均保留明确原因。
- 永久不可用的判断检查覆盖精确布尔字段，不把冷却、资源不足或未执行计数当删除依据。既有通用动作选择、导入和显式程序仍严格拒绝当前角色不支持的动作。
- 冻结与恢复检查：入选快照只读一次；初始化中断后用原快照，完成初始化后的恢复不重新适配；新库变化不影响当前任务；规则变化按既有恢复入口拒绝并保留历史；快照读取失败明确失败而不是空库。
- 共享裁剪的训练回归沿用现有训练公开入口，确认固定爆发排除、单成员拒绝、来源关系、独立复测和完成成果复用行为不变；无需实际重训全库。
- 正式差异验证使用同一干净工作树和固定基线，通过统一快速验证入口；只有 status 为 passed（通过）且 checked（已检查）非空才接受。当前 Linux（操作系统）环境缺少仓库配置的 Windows 解释器及受控引擎，不能将定向检查或远端 PR（拉取请求）排除范围作为该层通过证据。该环境阻塞须在正式验证阶段解决或明确停留，不自动切到本机。

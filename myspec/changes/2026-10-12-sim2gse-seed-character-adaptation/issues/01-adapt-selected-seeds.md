# 01：新网页任务按当前角色适配已训练起点

**What to build:** 用户从网页默认双场入口启动新任务时，已训练的入选程序只移除当前原生静态资格明确证明永久不可用的动作，保留其他结构，经当前角色合法性、导出预检和行为去重后进入当前角色评分。通过既有公开任务读取入口可核查原候选、派生程序、删除位置和原因。原训练来源和成绩保持，不重新训练。

**Blocked by:** None（无其他票据，可以在开发门禁一确认后开始）。

**Status:** ready-for-agent

## Acceptance criteria

- [x] 从网页 POST /api/tasks 的默认 dual（双场）流程建立可观察红灯，再以同一入口证明绿灯和最终冒烟；五目标场景使用适配后的训练起点。
- [x] 狂暴与自动攻击同一按键动作块只删除狂暴；灵魂收割单独块删除；当前可用动作及冷却／资源不足动作保持。
- [x] 删除集合只来自当前原生 APL（动作优先级列表）来源中精确的已初始化且静态不可用证据；不以未执行、缺字段、未初始化或饰品说明代替证明，不维护手写技能黑名单。同名当前可用按钮优先保留。
- [x] 普通块和顺序循环裁剪后顺序、循环次数及其他节点保持；空块与空循环删除，WaitClicks（空点击等待）保留；原结构错误不因删除被掩盖。
- [x] CastSequence（施法序列）裁剪前验证原成员及重置定义；零成员删除，多个成员保持顺序及重置；单成员、未知成员或无效原定义明确候选级拒绝，不转换成普通动作或伪造成员。
- [x] 派生程序仍经真实当前角色规范化、固定爆发排除、导出预检和行为去重；原四类起点顺序保持，最多追加四条，不保证八个不同起点，不虚增搜索停止门槛。
- [x] 未知名字或不支持语法不静默裁掉；候选独立跳过并保存明确原因。没有可执行动作或仅空点击的结果同样拒绝；快照读取异常仍使任务明确失败。
- [x] 当前角色评分使用派生程序，旧训练分数不成为当前成绩；原来源、训练处理记录、入选快照、程序及旧成绩逐项不变，无训练或训练复测调用。
- [x] 任务检查点冻结起点与适配记录，既有公开任务读取可返回候选身份、原／派生程序、删除位置／动作／原因、采用／重复／拒绝结果及成功行为身份；不扩表、不新增页面控件。
- [x] 同一任务只读取一次入选小快照；取消及同条件恢复保持冻结程序、成绩和预算，不因入选库后来变化重新适配或补入起点。
- [x] 原源码规则摘要变化继续阻止旧任务原地续跑并保留历史，不放宽身份核验；新代码同条件恢复继续成功。训练共享裁剪行为不变，可靠完成训练按既有语义身份复用，不仅因源码移动重训或递增语义版本。
- [x] 现有通用动作选择、显式程序、导入、固定爆发、预算、样本、并发和评分规则保持；共享裁剪提取的既有训练入口回归通过。
- [ ] 完成针对本票的独立只读审查且无阻塞项；正式差异验证使用同一干净工作树和固定基线，通过统一快速入口且 checked（已检查）非空。Linux（操作系统）定向接线、Windows（操作系统）原生和远端检查分别报告，缺失层不伪称通过。
- [x] 实施与审查修复均不改正式规格；正式规格候选及准确 PR（拉取请求）交付动作在第二门禁展示后再获批执行。

## Testing seam

目标产品是网页默认双场搜索；最高真实用户入口为 POST /api/tasks，mode 为 dual（双场），沿生产任务链执行至 GET /api/tasks/{id} 的五目标结果。原因追溯通过既有公开任务读取入口；页面不新增显示控件。复用已有合成角色、内存结果中心、快速评分边界和 HTTP（超文本传输协议）接线设施，保持真实原生模拟验收单独报告。

## Implementation notes

只有一个纵向切片，不按共享函数、存储或页面分层拆票。优先复用既有纯结构裁剪及任务 JSON（数据交换格式）摘要，不引入新框架、逻辑表或兼容迁移。先最小可观察失败检查，再最小修改，重跑同一检查与受影响回归。共享 Git（版本管理）操作只由主代理串行执行。

## Known blocker

当前云端 Linux 环境没有统一配置所需的 Windows 解释器和受控原生引擎产物。开发门禁可决定开始云端实施，正式验证阶段仍须停在该前置问题，不能以 PR（拉取请求）排除项或替身结果代替；不自动切到用户本机、不更改统一检查配置。

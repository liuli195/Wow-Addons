# Crosshair HUD 实施计划（方案计划）

本文件是[实施地图](spec.md)的终点产物：把八张已关闭票据的结论整理成一份可施工的方案。**不含任何待填位**——每一条技术结论都能追溯到对应票据。

- 目标客户端：12.1.0 / build 69587 / Interface 120100
- 插件清单：公共核心 `MYUI` + 功能插件 `MYUI_CrosshairHUD`
- 首版职业范围：**仅死亡骑士**

| 阶段 | 内容 | 完成标志 |

## 2. 插件结构

### 2.1 公共核心 `MYUI`

```
addons/MYUI/
  MYUI.toc                       组根：## Category: MYUI，**不带** ## Group
  Media/CrosshairHUD/*.png       10 个成品纹理（已就位，见第 7 节）
```

- **无依赖、无 SavedVariables、无 Lua 代码**。它目前只持有素材；将来若第二个功能需要共享代码或素材，再往里加。
- **不进 EUI 侧边栏**——它不是用户可见的功能。
- `MYUI.toc` 的 `## Notes` 里必须写明用途（例如"准星 HUD 的共享素材，请勿单独禁用"）：用户在插件列表里取消勾选 `MYUI` 会让**全部 10 张纹理静默失效**（纹理路径 404 不报错）。
- **这是仓库 `addons/` 目录下第一个纯素材插件**。仓库既有先例是"单目录自带 `Media/`"（`EUI_FacetedPortrait`）；素材单独成插件的先例在仓库外（`SharedMedia_MyMedia`）。两条后果必须记住：**禁用即失效**，且**它在拿到 Lua 代码之前无法通过 `check.py toc`**（该检查要求目录里至少有一个 `.lua`，见 §9.2）。
- 按[协作指南](../../../docs/wow-addon-development-guide.md)的要求，**插件代码与共享素材要分别列入部署范围**——`MYUI` 属于后者。

### 2.2 功能插件 `MYUI_CrosshairHUD`

```
addons/MYUI_CrosshairHUD/
  MYUI_CrosshairHUD.toc
  Logic.lua        纯计算，不碰任何魔兽接口（见 3.1）
  Elements.lua     渲染：弧、符文格、准星
  Config.lua       配置数据模型与 EUI 配置页
  Core.lua         装配：事件、轮询、应用、EUI 挂载注入
```

`.toc` 元数据：

```
## Interface: 120100
## Title: |cff7fafcbMYUI|r Crosshair HUD
## Notes: 屏幕中心准星 HUD：血量、符能与死亡骑士符文。
## Category: MYUI
## Group: MYUI
## Author: MYUI
## Version: 0.1.0
## Dependencies: EllesmereUI, MYUI
## SavedVariables: MYUI_CrosshairHUDDB

Logic.lua
Elements.lua
Config.lua
Core.lua
```

**`## Group` 是"看起来像一个系列"的关键，不能漏。** EUI 的做法是：主插件**不带** `## Group`，20 个兄弟插件全部写 `## Group: EllesmereUI`，于是插件列表里归成一组、可以折叠展开；再配 `## Category` 与带品牌色的 `## Title` 前缀。少了这个字段，用户会在插件列表和插件管理器里看到**两个毫不相干的插件**，而不是一个系列——这正是首次部署时踩到的坑。本项目的对应写法：公共核心 `MYUI` 作为组根（不带 `## Group`），功能插件写 `## Group: MYUI`。品牌色取设计稿符能弧的蓝 `|cff7fafcb`。

**发布口径（将来上传插件网站时用，属方案的"范围外"）**：**一个项目，发布包里装多个文件夹。** 核对 EUI 的做法——21 个文件夹里**只有主插件** `EllesmereUI` 带 `## X-Curse-Project-ID` / `## X-Wago-ID`，20 个兄弟插件一个都没有。所以：

- 平台项目 ID **只写核心插件 `MYUI.toc`**，功能插件**不写**（两个都写可能被打包工具当成两个项目）。
- 发布包同时包含两个文件夹——由**打包工具**决定，不在插件代码里（EUI 的安装目录里没有任何打包配置，配置在源码仓库侧）。
- 玩家下这一个包、解压，两个文件夹一起进 `AddOns`。

**加载清单不是可选的**：`scripts/dev/check.py` 对空清单直接 `raise`「加载清单为空」（`:33-34`），对每个列出的文件还要求存在且不越界（`:37`）。**清单里的文件顺序就是依赖方向唯一的落地手段**（`Logic → Elements → Config → Core`），`Logic.lua` 必须排第一。

- **硬依赖**（用户决议）：EUI 缺失则本插件不加载，**不做任何兜底**。
- **SavedVariables 由本插件自己持有**（用户于[配置存储方式复议](issues/08-config-storage-reconsideration.md)改为独立存储），不写入 `EllesmereUIDB`。

## 3. 模块划分

### 3.1 `Logic.lua`：纯计算

**加载时不得触碰任何魔兽接口**（这是它可被仓库 Lua 5.1 测试环境加载的唯一前提，也是这条文件边界存在的唯一理由——拆的是"纯计算"与"魔兽接口"的边界，不按功能拆）。

**导出机制必须照仓库惯例**：仓库的测试以 `assert(loadfile(源文件))()` **零参数**加载被测文件（`tests/addons/Sim2GSEProbe/test_probe.py:81`），因此**不能**用暴雪惯用的 `local addonName, ns = ...` 传私有表。导出只能是 `_G.<表名>` 形式——这也正是仓库两个插件一律写 `_G.X` 的原因（`.luacheckrc` 的 `read_globals` 只有 6 个名字，新建全局会触发 W111 让检查失败）。

只导出三组纯函数，外加**全部几何常量**：

| 组 | 职责 |
| --- | --- |
| 弧线填充换算 | `MaskAngle(start, span, f) → 弧度`；它同时编码遮罩镜像方向与 WoW 的逆时针弧度约定 |
| 符文充能计算 | 形参可空（`start`／`duration` 可能为 `nil`）；返回 `比例, 状态`。**`state` 是唯一权威**，空转时 `remaining` 返回 `nil` 而非 `math.huge`，避免 `inf` 流进排序键或显示逻辑 |
| 符文排序 | 状态数组 → 槽位顺序。**三个排序键缺一不可**：就绪在前 → 充能中按剩余升序 → **`runeIndex` 决胜**。丢了第三个键，同剩余时间的符文在 `table.sort`（非稳定）下会每轮 100ms 换位、槽位抖动——而任何单帧断言都测不出来 |
| 几何常量 | §4.1 的起始角与跨度表作为**纯数据**放在这里，`Elements` 引用；否则测试得硬编码第二份副本 |

**唯一会被拉回魔兽接口的是秘密值检测**（`issecretvalue`，以及"跳过本次更新、保留上一次值"的有状态策略）——它必须留在 `Core.lua`。仓库已有现成写法可照：`addons/Sim2GSEProbe/Core.lua:31-58` 的 `SafeScalar`／`SafeCall`。

### 3.2 `Elements.lua`：渲染

持有全部纹理对象与遮罩，**不读配置、不读游戏数据**。

**接口是一张「显示状态表」，不是"按给定比例更新"**：每个元素的状态为 `{state, fill, fillColor, bgColor, alpha, visible}`，由 `Core` 从"配置 + 游戏读数"算好后整表下发。

- "按比例更新"这个接口**承载不了**配置规格要求的填充色／背景色／透明度／启用四类属性。若让 `Elements` 自己去读配置，页面与渲染就被绑在一起了——这正是两条边界各自该守的东西被混掉。
- 状态表必须显式携带 `state`（`ready`／`recharging`／`empty`）：**空转态要求完全隐藏填充纹理，不是把比例设成 0**。`Core` 不得越过这张表去直接操作 `Elements` 内部的纹理。
- 附带收益：状态表是**纯数据**，可以在离线测试里断言，把符文排序与降级结果从"只能实机看"拉回可测层。

### 3.3 `Config.lua`：配置

数据模型、默认值、读写；以及 EUI 配置页面的构建函数（交给 `Core.lua` 注册）。

### 3.4 `Core.lua`：装配

事件注册、符文轮询、把游戏数值换算成比例后驱动 `Elements`、把配置变化应用到 `Elements`、以及 EUI 侧边栏与页面的挂载注入。

**依赖方向**：`Core → {Config, Elements}`，`Elements → Logic`，`Config → Logic`（共享常量与默认值）。**`Logic` 是唯一叶子**，`Config` 与 `Elements` 互不知晓。

> 早先写的 `Core → Config → Elements → Logic` 是**错的**：`Config` 根本不需要知道 `Elements`（配置变更的**应用**在 `Core`）。照错误声明去实现，会诱导 `Config` 去调 `Elements` 的更新函数，把页面与渲染内部绑死。

**落地手段是 `.toc` 的文件顺序**（见 §2.2）：`Logic → Elements → Config → Core`。

## 4. 渲染契约

### 4.1 设计稿坐标系

素材共用 256×256 坐标系，圆心 `(128,128)`、半径 54、线宽 6。角度为**从正东顺时针、y 向下**。

| 元素 | 起始角 | 跨度 |
| --- | --- | --- |
| 血弧 | 99° | 102° |
| 符能弧 | 339° | 102° |
| 符文格 1–6 | 219° + (i−1)×18° | 12° |

魔兽的 y 轴向上，因此摆放时 **WoW 的 y 偏移 = 设计稿 y 偏移取负**。

### 4.2 填充换算（已数值验证）

设某条弧起始角 `a`、跨度 `span`、填充比例 `f ∈ [0,1]`：

```
遮罩旋转角 θ = -(a + span·f) - 90        （度，逆时针为正）
```

**验证**：对 8 条弧（两条主弧 + 6 个符文格）× 101 个填充值 × 399 个弧上采样点逐一比对"该点是否应被填充"与"公式给出的可见性"，**零错误**；唯一分歧出现在切线本身，外观上无影响。验证脚本见[弧线渲染实机原型](issues/02-arc-fill-prototype.md)的讨论记录。

> 备选的 Cooldown 扫掠方案**已否决**：其切线是几何扇形硬边、没有抗锯齿，实机观感明显劣于遮罩方案（用户实机判定）。

### 4.3 遮罩

- 一张 **256×256** 的半平面图（128 设计稿单位见方、2 像素/单位），**左半不透明、右半透明、中线 2 像素线性过渡**。
- 每个元素一个遮罩实例，`SetAllPoints` 于该 HUD 的容器框（容器即 128 设计稿单位见方、圆心居中），按 4.2 的公式设置旋转。
- 过渡宽度就是切线的抗锯齿来源，2 像素为实机基线。
- **遮罩方向与 4.2 的公式是一对**：镜像翻转会让所有填充方向整体反向。校验脚本断言方向。

### 4.4 尺寸与缩放

- **默认缩放 1.0**（用户实机在 1.0 / 1.5 / 2.0 三档中选定）。
- 滑块范围 **0.5 – 2.0**，步进 0.05。
- 实现方式：**父框 `SetScale`**，整体等比；子元素全部按设计稿单位 × 缩放值摆放，不逐元素参与缩放运算。
- **必须注册 `UI_SCALE_CHANGED`**：EUI 自己就会调 `UIParent:SetScale`（`EllesmereUI.lua:2164`、`EllesmereUI_Startup.lua:31,37`），而仓库先例 `addons/EUI_FacetedPortrait/Core.lua:304` 正是注册了这个事件。界面缩放变化时需重新对齐与像素吸附，否则 HUD 会偏移或发糊——而这恰好是验收第 5 条要判的"两端不糊、不跑位"。
- **关于"零损失"的准确表述**：上限 = 素材密度 ÷ **有效**界面缩放。素材为 2 像素/设计稿单位；界面缩放拉满 1.0 时上限为 2.0，与滑块上限一致；用户 4K 显示器的默认界面缩放下上限约 5.6 倍。但缩放滑块以 0.05 步进，**绝大多数取值下有效缩放是小数**，纹理必然经历重采样——"零损失"只在 `scale` 与界面缩放的乘积为整数时严格成立。实际观感由实机验收第 5 条裁决，不由这条推理裁决。

### 4.5 图层与交互

- 图层默认 **`MEDIUM`**，**做成配置项**（用户决议）。EUI 自家资源条与单位框体同层；暴雪设置窗口在 `DIALOG`、下拉菜单在 `FULLSCREEN_DIALOG`，都在其上。
- 同一图层内的前后关系由 `SetFrameLevel` 决定，取正常值即可。
- **位置：直接复用 EUI 现成的位置控件，不自建。** 用户决议——EUI 那个控件是「锚点下拉 + X/Y 两个小滑块」一行（`EllesmereUIOptions/EllesmereUI_Widgets.lua:3693-3697` 的 `DropdownWithOffsets`），成熟、与 EUI 一致，而且**天生支持锚点**。v1 只有这一个"位置"设置，不再单独设"偏移"。
- **拖动复用 EUI 的解锁模式**，并照 EUI 自家模块的位置助手写法（`EllesmereUIResourceBars.lua:2119-2160` 的 `MakePosHelpers`）：拖动写入 `unlockPos = {锚点, 相对点, x, y}`，清除位置时把偏移复位成默认值。
- **像素吸附必须照抄，不能省**：EUI 那段助手对 `CENTER` 锚点用的是 `SnapCenterForDim` 而不是普通的 `SnapForES`——源码注释写明后者会让奇数像素尺寸的框体**每次保存/退出或切专精漂 1 像素**。
- **解锁元素的契约比一句话重**（`EllesmereUI:RegisterUnlockElements` + `EllesmereUI.MakeUnlockElement`）：必填 9 个字段，且 `getSize` 的语义是"**屏幕上的**宽高"——这与 §4.4 的父框 `SetScale` 直接冲突：mover 框按设计稿尺寸画会得到大小错误的拖动框。**在票据 6 之前补一张只读调研票**逐项核对（见 §10）。
- **主开关关闭时必须让 `isHidden` 报告"未启用"**：EUI 的 mover 会读它（`EUI_UnlockMode.lua:7595-7599`），否则关掉主开关后屏幕中心会留下一个**可拖动的空框**。显隐由 `Core` 单点驱动。
- **不调用 `EnableMouse`**，HUD 永不拦截鼠标点击。

## 5. 资源读数契约

依据[死亡骑士符文读数契约](issues/04-deathknight-rune-contract.md)。

### 5.1 血量与符能

- 血量：`UnitHealth("player")` / `UnitHealthMax("player")`
- 符能：`UnitPower("player", Enum.PowerType.RunicPower)` / 对应最大值（v1 只面向死亡骑士，固定用符能，不做主资源类型分派）
- 比例**钳位到 `[0,1]`**。
- 事件：`UNIT_HEALTH`、`UNIT_MAXHEALTH`、`UNIT_POWER_UPDATE`、`UNIT_POWER_FREQUENT`、`UNIT_MAXPOWER`，均限定 `player`。
- **秘密值防御（必需，四个接口的标注已逐条核实）**：

  | 接口 | 标注 |
  | --- | --- |
  | `UnitHealth` | **`SecretReturns = true`**——可能**无条件**返回秘密值 |
  | `UnitHealthMax` | `SecretWhenUnitHealthMaxRestricted = true` |
  | `UnitPower` | `SecretWhenUnitPowerRestricted = true` |
  | `UnitPowerMax` | `SecretWhenUnitPowerMaxRestricted = true` |

  `UnitHealth` 是四者中最危险的——它不需要任何前置条件就可能返回秘密值。做法：取到不可读值时**跳过本次更新、保留上一次的值**，绝不让秘密值参与比较或算术。

  （对照：符文读数的 `GetRuneCooldown` **没有** `SecretReturns`，它的风险是"整次返回空"而非秘密值——两者的防御写法不同，不要混用同一套。）

  **这条分支必须离线测，因为实机测不到。** 用户无法在游戏里按需让 `UnitHealth` 返回秘密值——13 条人工清单**一条都覆盖不了它**。而仓库的测试环境今天就能造出来：`tests/addons/Sim2GSEProbe/test_probe.py:26` 已经示范了哨兵值写法（`function issecretvalue(value) return value == secret end`）。同理，符文空转态（§5.2）在实机只能靠"一次花掉 4 个以上符文"碰运气触发，也必须靠离线测试覆盖。

  → **把最脆的两条分支放进唯一无法验证的那一层，是初版方案最大的设计失误，已修正：两条都归离线测试。**

### 5.2 符文

```lua
startTime, duration, isRuneReady = GetRuneCooldown(runeIndex)   -- 索引 1..6
```

- `duration` 单位秒、基准 `GetTime()`；就绪时 `startTime` 为 `0`；**就绪时 `duration` 仍返回真实值**，因此不能用 `duration > 0` 判断"正在充能"。
- **三种状态**：就绪 / 充能中 / **空转**。空转的表现是**整次调用什么都不返回**（三个值全 `nil`），成因是同时最多只有 3 个符文在充能；**必须显示为整格背景色，不能显示成 1%**。
- **判定顺序必须是：先判就绪 → 再判返回是否为空 → 最后才做除法**。这是三个坑（`start=0`、返回空、`duration=0`）的唯一安全顺序。
- **数量固定 6**，不从 `UnitPowerMax` 推导。
- **索引不等于屏幕槽位**：`runeIndex` 是稳定标识符，显示位置由 5.3 的排序决定。
- 事件：`RUNE_POWER_UPDATE`（**忽略事件参数、整表重读**，其负载可能不可读）；结构性事件 `PLAYER_SPECIALIZATION_CHANGED`、`ACTIVE_TALENT_GROUP_CHANGED`、`TRAIT_CONFIG_UPDATED`、`PLAYER_TALENT_UPDATE`（后两者去抖 0.1 秒合并）、`PLAYER_ENTERING_WORLD`（延迟 0.5 秒重读）、`PLAYER_DEAD`／`PLAYER_ALIVE`、`ZONE_CHANGED_NEW_AREA`。**不注册 `RUNE_TYPE_UPDATE`**——正式服没有符文类型。
- **必须 ~10Hz 轮询**：符文回复速度受急速等影响，`duration` 是动态值且这些变化**不保证触发事件**。纯事件驱动会让进度条在增益生效期间走偏。

### 5.3 符文格排列

**动态重排**（用户实机选定）：就绪的排在前、充能中按剩余时间升序、空转垫底。代价是充能完成时格子会跳位——用户实机确认可接受。

**注意**：6 张符文格纹理各自是环上不同角度的弧段，**位置固定、不可互换**。重排改变的是"每个槽位显示哪个符文的状态"，不是换纹理。

### 5.4 颜色只能按状态编码

正式服**没有**血/冰/邪符文类型（三重独立证据见票据）。符文格的颜色只能表达状态：就绪 = 填充色、充能中 = 按比例的角度填充、空转 = 背景色。

**职业配色**取值来源为 EUI 的职业色接口；自定义配色为独立存储的 RGB。

## 6. EUI 集成契约

依据[EUI 集成契约核实](issues/03-eui-integration-contract.md)。

### 6.1 挂载

- 侧边栏读三张挂在 `EllesmereUI` 命名空间上的普通表：模块描述表、行元数据表、分组表。
- **文件夹名无 `Ellesmere*` 前缀要求**（`RegisterModule` 的白名单校验的是调用者文件路径，不是文件夹名）。
- 做法：先 `pcall` 调用官方注册函数，失败则直接写表；两者落到同一张表。
- **不设 `alwaysLoaded`**：本插件是真实插件，保留行右边的电源按钮（用户实机确认该按钮可真正禁用插件）。
- **注入必须早于用户首次打开 EUI 面板**——侧边栏行只在首次建面板时创建。面板已打开后注入是**静默失败**（无行、不报错），但此时 `ShowModule` 仍可打开页面。
- 分组：新建绿字分组 `MYUI`，行为 `CrosshairHUD`。

### 6.2 `buildPage` 的四条契约

1. **必须返回内容总高度**（数值），返回 `nil` 会被当成 600。
2. **必须能在离屏、无 header API 的状态下安全跑完**——EUI 全局搜索会预构建每一页。
3. **控件工厂只能在 `buildPage` 内取**（选项插件是按需加载的，加载期取不到）；取到 `nil` 时首行判空返回。
4. 构建期**不得注册长生命周期监听**。

### 6.3 不需要的东西（因改为独立存储而消掉）

- **不需要包装 `EllesmereUI.RefreshAllAddons`**：配置不跟随档案，档案切换时没有东西需要重新应用。
- 不需要 `Lite.NewDB`，也就避开了它清空插件自身 SavedVariables 的行为。
- 不存在"缓存 `db.profile` 会写进废弃表"这个陷阱。

### 6.4 风险清单（全部为静默失败）

| 风险 | 缓解 |
| --- | --- |
| 面板已打开后才注入 → 无侧边栏行 | 在 `PLAYER_LOGIN` 完成注入；必要时提示 `/reload` |
| `buildPage` 在控件工厂为 `nil` 时被调用 → 报错 | 页面体首行判空返回 |
| 误调官方注册函数 → 静默什么都没注册 | 写表后断言三张表确实写进去了 |
| EUI 改版导致三张表改名 | 全部访问加空值守卫；失效表现为"侧边栏没有行"，此时页面仍可打开 |

## 7. 配置项规格（19 项）

依据用户逐项决议。**每个元素独立一组设置**，填充色可选职业配色或自定义，背景色只有自定义。

### 7.1 常规（4 项）

| 键名 | 控件 | 默认值 |
| --- | --- | --- |
| `enabled` | 开关 | `true` |
| `scale` | 滑块 0.5–2.0，步进 0.05 | `1.0` |
| `position` | **EUI 标准位置控件**（锚点下拉 + X/Y 两个小滑块，一行；计入一项） | 锚点 `CENTER`、偏移 `0, 0` |

| 元素 | 键前缀 | 启用 | 填充色 | 背景色 | 透明度 |

| 符能弧 | `power` | ✓ | 职业配色 或 自定义 | 自定义 | ✓ |
| 符文格 | `runes` | ✓ | 职业配色 或 自定义 | 自定义 | ✓ |
| 准星 | `crosshair` | ✓ | 职业配色 或 自定义 | ——（准星是线，没有背景） | ✓ |

### 7.3 默认颜色（取自设计稿采样）

| 元素 | 填充色 | 背景色 |
| --- | --- | --- |

- 分四组呈现：**常规**（启用 / 缩放 / 偏移 / 图层）、**血弧**、**符能弧**、**符文格**、**准星**。

### 7.5 存储

- `## SavedVariables: MYUI_CrosshairHUDDB`，**账号级**。

## 9. 测试与验收

依据[测试与验收策略](issues/06-test-acceptance-strategy.md)。

### 9.1 分层

| 层 | 覆盖 | 手段 |
| --- | --- | --- |
| **离线自测** | `Logic.lua` 的三组纯函数 **+ 秘密值降级 + 符文空转降级** | `tests/addons/MYUI_CrosshairHUD/test_logic.py`，Python 驱动本机 Lua 5.1 |
| 静态诊断 | 源码拼写、类型、清单、Lua 5.1 语法 | `scripts/dev/check.py` 的 luals / luacheck / toc |
| 素材 | 10 个纹理 | `verify.crosshair-media` |
| **游戏内验收** | 渲染、交互、EUI 集成 | 16 条人工清单 |

**离线测试的接缝比初版方案假设的高，必须用足**（设计审查修正）：

- 仓库的测试 harness 提供**全套 WoW 接口 mock**——`tests/addons/Sim2GSEProbe/test_probe.py:20-42` 造了 `GetTimePreciseSec`／`UnitPower`／`GetRuneCooldown`／`issecretvalue`／`CreateFrame` 等，`:83-97` 投递事件与脚本回调，`:99-136` 断言插件留下的数据；并以**零参数 `loadfile`** 加载被测文件（`:81`）。所以接缝是**文件级**，不是"纯函数级"。
- 因此**秘密值降级（§5.1）与符文空转降级（§5.2）都能离线确定性地覆盖**——而这两条在实机**无法按需触发**。`test_probe.py:26` 已经示范了哨兵值写法：`function issecretvalue(value) return value == secret end`。
- **`MaskAngle` 的测试不能写成对公式的自证**（例如断言 `MaskAngle(99,102,0.5) == rad(-150)`）。应当把原型期那次数值验证用过的**独立几何判据**（点是否落在弧上 ∧ 是否在半平面内）写成测试——那才复现了原验证的价值，并把"遮罩镜像约定"与公式**钉在同一个文件里**（现在这个约定散在四处、互不引用）。
- 三层不得互相冒充：离线自测通过 ≠ 原型可行 ≠ 实机验收通过。

### 9.2 验证登记

- `MYUI`：当前沿用 `verify.crosshair-media`。**这是一条永久约束**——`check.py` 要求目录里至少有一个 `.lua`（`:45-46`），所以 `MYUI` 在拿到 Lua 代码之前**不能**登记 toc 检查。后来者不要加一条永远失败的检查。
- `MYUI_CrosshairHUD`：luals / luacheck / toc 三条源码检查 + 一条逻辑测试，全部用 `paths` 限定命中范围。
  - **toc 检查有个隐性前提**：它要求 `.toc` 里列出的每个文件都已存在（`:37`）。所以这一票必须在四个 `.lua` 都已存在之后，或者先只登记已存在的文件、后续票再追加清单条目。
  - 逻辑测试的 `inputs` 里要含本机 Lua 可执行文件（`.tools/lua-5.1.5/src/lua.exe`），照 `verify.sim2gse-probe-test` 的先例。

### 9.3 游戏内人工验收清单（16 条：用户确认的 13 条 + 设计审查补的 3 条）

1. 血弧、符能弧、6 个符文格都按真实数值正确填充，方向对（血弧从近 6 点钟那端向上生长，与符能弧镜像）
2. 花掉 1 个符文 → 该格整格变背景色，再按比例长回来
3. 一次花掉 4 个以上符文 → 多出来的显示为整格背景色（不是 1%），且不报错
4. 总开关 + 4 个子开关都生效；总开关关掉时子开关置灰不可点
5. 缩放滑块两端（0.5 与 2.0）都正常：不糊、不跑位
6. 图层：打开暴雪设置窗口、打开任意下拉菜单 → HUD 都在其下方
7. 默认在屏幕正中；进 EUI 解锁模式 → 出现拖动框、能拖、退出解锁后位置保持
8. 切专精、死亡复活、过图 → 不报错、数值恢复正常
9. EUI 侧边栏 `MYUI` 分组下出现 `CrosshairHUD` 一行，页面能打开；行右边的电源按钮能真的禁用它
10. 改几条配置后 `/reload`，设置仍然保留
11. 打开 EUI 的全局搜索并输入关键字 → 不报错
12. 禁用 EllesmereUI → 本插件也不加载（硬依赖生效）
13. 性能轻度观察：战斗中体感流畅；用 Numy Addon Profiler 看平均耗时与尖峰无异常

**设计审查新增的三条（覆盖空白，原 13 条盖不到）：**

14. **解锁拖动框的尺寸与位置正确**——父框 `SetScale` 下，EUI 的 mover 框按"屏幕上的宽高"绘制，若按设计稿尺寸上报会得到大小错误的拖动框（§4.5）
15. **改界面缩放（或 EUI 改 `UIParent:SetScale`）后，HUD 不偏移、不发糊**（§4.4 的 `UI_SCALE_CHANGED`）
16. **主开关关掉后，屏幕中心不残留可拖动的空框**（§4.5 的 `isHidden`）

**原第 8 条里的"符文空转只能碰运气触发"已不靠实机**：它改由离线测试确定性覆盖（§9.1）。

**性能不做基准测试**：解析估算约为百来次 C 调用/秒（符文轮询 10Hz × 6 次 + 符文格填充 10Hz × 6 次 + 两条主弧的事件驱动更新），对照 EUI 自家资源条跑的是 20Hz 基频、工作量远大于此。纯函数层面测不出真实开销，因为开销在 C 侧控件更新。

## 11. 已知偏差、前提假设与遗留

### 11.1 相对设计稿的偏差

**无。** 早先记录过的两处偏差都已消解：

- ~~共用背景色导致默认取单一深色~~ → 用户改为**每个元素独立背景色**，设计稿三条资源各自的深色背景可原样还原。
- ~~两侧数值文字的字号需放大~~ → 用户决定 **v1 不做数值文字**。

### 11.2 前提假设（未经验证，影响面已限定）

- **界面缩放上限为 1.0**：这是"素材密度 2 像素/设计稿单位足够覆盖滑块上限 2.0"这条推理的前提。本机固定的界面源码里**没有找到该钳制的证据**。若将来发现客户端允许更大的界面缩放，需要重估导出倍率与滑块上限。**影响面**：只在用户把界面缩放调到 1.0 以上且 HUD 缩放拉到接近 2.0 时才会出现贴图软化。
- **现代死亡骑士符文没有类型区分**：三重独立证据支持（读取接口的版本位排除正式服、客户端接口表无此项、固定版本界面源码零消费），但未实机确认。**影响面**：若有类型，符文格需要按类型分色——设计与配置都可容纳，实现改动局限在颜色来源。

### 11.3 遗留（不阻塞实施）

- 弧段之间 18° 空隙的比例在实机下的观感——原型已验证整体观感，此类微调留给实施期。
- 配置项在页面上的分组文案与呈现顺序的最终措辞。
- 两项与 v1 目标无关的可选增强：把 10 张纹理注册进 LibSharedMedia 供其他插件复用；接入 EUI 官方的皮肤接口 `RegisterSkin` 以统一视觉。
- 配置的分享与迁移：独立存储后不随 EUI 档案串走，将来若需分享得自备序列化。

### 11.4 一次性产物

### 11.5 独立设计审查的修订（2026-09-16）

进入实施前，按仓库开发流程委派了 **Architect（架构师，只读）** 角色，实际使用 `codebase-design` 技能对本方案做独立审查。**审查发现 8 处设计缺陷，其中 3 处阻断级**，已就地修订：

| 缺陷 | 性质 | 修订位置 |
| --- | --- | --- |
| `Elements` 的"按比例更新"接口**承载不了**颜色／背景／透明度／启用 | **阻断** | §3.2 改为**显示状态表**接口 |

**两项方法论层面的修正，影响面比单个缺陷更大：**

1. **离线测试接缝比初版假设的高。** 仓库的 harness 提供全套 WoW 接口 mock 并以零参数 `loadfile` 加载被测文件，接缝是**文件级**。初版把**最脆的两条分支（秘密值降级、符文空转）放进了唯一无法验证的那一层**——两者在实机都无法按需触发，13 条清单一条都盖不到。已改为离线确定性覆盖（§9.1）。
2. **"零错误"那条验证原本不可复跑**（脚本没进仓库）。`MaskAngle` 的测试不得写成对公式的自证，必须把当时的**独立几何判据**写成测试，并把"遮罩镜像约定"与公式钉在同一个文件里（§9.1）。

**连带修正**：验收清单 13 → **16 条**（新增 3 条盖住审查发现的实机空白）；配置项 20 → **19 项**（位置控件合并了原 `offsetX`／`offsetY`）；票据拆分修正（§10）。

**审查的核验**：主代理逐条核对了审查引用的关键证据——`check.py:33-46` 的三种硬失败、`test_probe.py:81` 的零参数 `loadfile`、`:26` 的秘密值哨兵——并确认只读角色**未产生任何写入**（`git status` 干净）。

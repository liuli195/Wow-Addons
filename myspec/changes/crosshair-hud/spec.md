## Destination（目标）

把用户确认的准星 HUD 需求转成可逐项消除疑问、随后交给开发流程实施的路线：先用**实机原型**钉死弧线填充的技术选型与默认尺寸，再核实 **EUI 集成契约**与**死亡骑士符文读数契约**，最后成文为方案计划与路线图。

地图完成意味着实施前的决策与验收契约已经明确，**不意味着插件已经开发，也不意味着游戏已经验收**。本轮的产出物是**方案计划**与**一个一次性原型**；正式实施另走仓库的开发流程。

## Decisions so far（已完成决策索引）

- [需求追问：准星 HUD 的范围与集成决策](issues/01-requirements-grilling.md)：交付物为方案计划加一次性弧线渲染原型；v1 只做死亡骑士、符文充能按角度填充、不做两侧数值文字；素材允许从 SVG 重导但不改图形；默认尺寸留到原型定；四元素各自独立配置填充色／背景色／透明度；硬依赖 EUI 且不做兜底；每功能一个真插件（`MYUI` 公共核心 + `MYUI_CrosshairHUD`）；配置跟随 EUI 配置档案。

## Not yet specified（尚待明确）

- 素材进入仓库素材流水线后的具体校验规则（尺寸、中性灰、格式断言），取决于素材重导规格票的结论。
- 配置项在页面上的分组文案与呈现顺序、总开关与子开关的置灰联动细节，属实施期可定的小事。
- 两个插件在仓库验证配置里的具体检查项与变更匹配路径，取决于测试与验收策略票的结论。
- 是否把 9 张纹理注册进 LibSharedMedia 供其他插件复用（可选增强，与 v1 目标无关）。
- 原型暴露的、当前无法预见的观感问题：18° 空隙在实机下的比例是否合适、12° 符文格的充能填充是否看得清、不同界面缩放下弧线是否锐利。

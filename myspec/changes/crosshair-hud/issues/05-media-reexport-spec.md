## Question（问题）

9 张纹理各自按什么裁切范围、导出倍率与文件格式重新导出，才能既配合选定的渲染技术、又保持外观与设计图一致？这些素材如何进入仓库的素材流水线？

## 调查或讨论范围

用户已授权**从 SVG 重新导出、但不改图形**（线条粗细、弧线角度、6 格间隔、圆角一律不动）。可选范围是：画布范围与裁切位置、导出倍率、文件格式。

本票由[弧线渲染实机原型](02-arc-fill-prototype.md)的结论驱动——选定的技术决定每个纹理需要怎样的裁切（是否需要以圆心为中心、是否需要额外的透明留白、是否要正方形画布），默认尺寸决定导出倍率。

需要确定的内容：

1. **每个纹理的导出规格**：裁切范围（在 256×256 设计稿坐标系中，用 `viewBox` 表述）、画布尺寸、导出倍率、文件格式。至少覆盖：准星、血弧、符能弧、6 个符文格。
2. **导出倍率与锐利度的关系**：默认尺寸下要清晰，滑块放大到上限时也不至于明显模糊。给出选择依据（结合原型中观察到的锐利度）。
3. **格式**：PNG 还是 TGA；是否要求中性灰（视觉上等价于白色蒙版）、是否要求不透明像素的 alpha 为满值。仓库既有的素材校验脚本对格式有断言，新素材应当落在同一套规则内。
4. **素材进入仓库的位置**：按用户决议，`MYUI` 是公共核心插件，素材归它持有。确定源图放 `assets/` 的哪里、构建输出到哪里、校验脚本放在 `scripts/media/` 的哪里。
5. **可复现的导出脚本草案**：从 SVG 到成品纹理的自动化步骤（本机已有的矢量渲染能力需先确认），使重导可重复、可校验。
6. **外观一致性核对方法**：如何证明重导结果与设计图一致（叠加比对？逐度采样比对？），并给出结论。

### 边界

- 不改图形本身；若发现某个纹理必须改图形才能成立，停下来交回用户，不擅自改。
- 本票不做实机验证；导出的纹理在游戏中的实际表现由原型票之后的一次实机确认覆盖。
- 素材包原版保持不动，不做任何修改。

## 关闭条件

- 产出**导出规格表**：每个纹理的裁切、画布、倍率、格式。
- 产出可复现的导出脚本草案，并说明本机矢量渲染能力的准备情况。
- 产出一致性核对结果：重导纹理与设计图的比对证据。
- 用户过目确认外观与设计图一致。
- 明确记录素材包原版与仓库重导版的来源与派生关系。

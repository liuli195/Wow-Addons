# 01: 核实历史占位并保留原清理门槛

**What to build:** 用户通过现有引用管理公开入口，按已有登记与归档恢复记录生成具体审核清单，确认实际消费者状态后分类 unknown 角色并关闭精确自动旧路径未知占位；已有真实保护保持，旧归档仍可恢复，之后继续原隔离和逐项永久删除流程。

**Blocked by:** None（无前置票据）。

**Status:** ready-for-agent

- [x] 新动作只处理明确批次的 unknown 角色及自动 legacy-path unknown 引用，预览包含当前 ID、路径、身份/SHA、角色、精确引用及计划摘要。
- [x] 批次依据已有归档/恢复记录和简短消费者核实理由生成；不能仅因压缩成功声明可删除，不要求用户逐文件手填。
- [x] 批准执行使用原根锁、事务和实际元数据空间检查，重新核验计划并记录审计；身份或引用变化拒绝，失败不部分解除。
- [x] 已明确的保护角色、pins、活动生产者/读者/锁、真实持久业务引用及全根未知来源保持，不提供全根一键解除或自动删除。
- [x] 角色核实后既有未知角色归档仍能通过准确审计兼容恢复；原包、稳定 ID 和原件字节不改变。
- [ ] 通过同一公开 CLI 的最小红绿检查和一个必要小样往返，固定基线 fast（快速）有效通过；单票结束后完成独立限定审查，CI 结果据实记录。

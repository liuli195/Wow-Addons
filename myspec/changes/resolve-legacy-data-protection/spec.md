# 核实历史对象占位保护

## Problem Statement

已批准的全仓数据治理已完成真实小样归档和恢复验证，但历史目录登记自动加入的 unknown（未知）角色及 legacy-path unknown（旧路径未知消费者）占位没有公开的核实转换入口。即使明确确认不存在原路径消费者，也无法进入既有隔离和逐项删除流程。归档成功本身不能证明无人消费。

## Solution

复用现有 reference（引用管理）公开命令增加一个有界的 resolve-legacy（核实历史占位）动作。根据已有归档成员及登记记录生成具体对象清单，操作者提供确认后的现有目标角色和简短消费者核实理由；用户审核生成清单，不逐文件手填。先预览当前身份、摘要、角色及精确占位引用和保留保护，再按同一计划摘要批准。在根锁和单事务内仅分类 unknown 角色、关闭明确列出的自动旧路径未知占位并记录审计。

已有 input/evidence/model/analysis/sqlite-source（输入/证据/模型/分析/可变数据库来源）角色不得降级。raw/native/cache（原始报告/原生报告/缓存）在现代码中并非自动保护角色，唯一原始输入应保留 input 或 evidence 归属。仍不明确的对象保持 unknown。

## User Stories

1. 作为仓库数据所有者，我希望核实后的历史生成载荷不再被占位保护永久阻塞，以便使用既有安全清理流程。
2. 作为操作者，我希望复用登记、归档和恢复记录生成有界清单，以便按组审核而不手填数十万条记录。
3. 作为数据消费者，我希望仍在使用的原路径和真实依赖继续受保护，以免压缩成功被误当成删除许可。
4. 作为数据所有者，我希望已明确的输入和证据角色不能通过该动作降级，以免唯一证据被误清理。
5. 作为操作者，我希望计划批准后文件或引用变化导致明确拒绝，以便重新核实而不是使用过时批准。
6. 作为恢复使用者，我希望核实角色后旧归档仍可恢复，以便不重写已有包、清单或稳定身份。
7. 作为数据所有者，我希望核实动作不删除文件，最终不可恢复删除仍由既有具体清单单独确认。

## Implementation Decisions

- 单一纵向切片、单一公开 Interface（接口）：现有引用命令新增受控核实动作；不提供通用角色编辑器或万能解除保护参数。
- 优先从明确归档的已有成员生成至多一千对象、至多既有一 MiB 计划上限的审核批次。复用对象 ID、根身份、当前路径/文件身份/SHA、已有角色、精确旧路径引用 owner、现有归档/恢复记录和消费者核实理由；不引入新的证据平台或签名链。
- 仅 unknown 占位角色可以转为明确审核的现有角色；仅该批精确自动 legacy-path unknown 引用可以关闭。真实持久业务引用、pins（保留标记）、读者/生产者租约、文件锁及全根 unknown_refs（未核实来源）不被删除或豁免。存在剩余保护时如实报告，既有隔离/删除继续拒绝。
- 复用原计划摘要、根写锁、元数据实际空间检查、SQLite 事务和操作审计。执行重新核对计划；失败不留下部分解除。
- 归档清单记录归档时角色，不重写历史包。旧归档恢复仅对同对象、路径、SHA、大小且存在本动作批准审计的 unknown 到明确角色转换提供窄兼容；其余身份和角色异常仍拒绝。
- 核实完成仅解除此项占位原因，不表示所有保护已满足，不自动隔离或删除。
- 独立审查收敛：旧索引没有引用来源记录，不能以名称形状推断自动生成。操作者复用精确 owner 参数确认原登记归属，工具只生成该 owner 在归档内的对象清单；其他同形引用保留。通常一个登记批次只确认一个 owner，不新增证据格式。已识别的消费者锁持续至提交并复用同批共享祖先。

## Testing Decisions

- 最高层级真实用户 Seam（测试接缝）为共用数据 CLI 的 reference 动作；从该入口预览和批准，再通过既有 protect、restore 及隔离预览观察结果，不以直接数据库编辑替代使用流程。
- 复用已有数据管理测试帮助与临时根。先写最小公开入口失败检查，再实施到同一检查通过。
- 一个必要的小数据往返覆盖：历史未知登记、归档/恢复、核实预览/批准、旧归档再次恢复及原件保持；不使用数百样本或长时间模拟。
- 少量有判别力的失败检查覆盖过时身份/引用、无真实消费者确认及不可覆盖的既有保护；纯计划验证优先内存输入。
- 固定基线快速验证，checked（实际检查清单）必须非空；Windows 必要行为由本机 Luna 执行，CI 按仓库既有完整检查。单票完成后统一独立审查，不增加本机 full（全量）门槛。

## Out of Scope

- 不解除或治理全根 unknown_refs，不自动切换旧数据库消费者，不撤销真实持久业务依赖。
- 不改变已有明确角色，不新增策略引擎、守护进程、定时任务、通用批处理框架或批次暂停机制。
- 不修改本机生产配置，不在实现/测试中操作真实对象保护，不执行真实隔离或永久删除。
- 不提前修改正式规格；经原流程完整差异确认后才应用。

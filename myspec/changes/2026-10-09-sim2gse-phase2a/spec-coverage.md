# 第01—15票的可观察行为覆盖

范围为本次已批准全部15张票。正式规格按能力组织，不按票号重复建15份。下表说明本次正式规格的需求覆盖关系；实现细节和验收操作留在原开发计划、票据及验证文档。已有规则保留，新规则由本次增量补充。需求覆盖不等于实际验收完成，两端实际调用与游戏仍未通过。

| 票号 | 用户或维护者能观察到的核心结果 | 规格覆盖 |
| --- | --- | --- |
| 01 | 引擎可重新构建；版本或内容不一致拒绝执行；同版本战斗对照一致 | 模拟评估：升级身份核验（新增）、保留游戏战斗规则（已有） |
| 02 | 整理后动作目录、报告中的战斗内容和战斗结果一致 | 模拟评估：同版本整理场景（新增）；角色输入：合法动作目录（更新） |
| 03 | 从固定版本重新构建；查询结果保持原义；旧结果保留 | 模拟评估：升级身份核验（新增）；角色输入：动作目录（更新）；导入：检查后模拟（已有） |
| 04 | 输入时机、顺序和每轮重置行为不因整理改变 | 模拟评估：同版本整理（新增）、按导出顺序评估与按输入时刻回放（已有） |
| 05 | 序列推进、空点击及连续施法不因整理改变；日志开关不影响执行；技能效果仍遵守游戏规则 | 模拟评估：同版本整理（新增）、保留战斗规则与成功后推进（已有）；导入：循环及空点击（已有） |
| 06 | 新引擎适配已核实客户端；版本可核对；不把新旧伤害差异当作必然错误 | 模拟评估：升级身份与跨版本回归（新增） |
| 07 | 升级错误可恢复完整旧版本；旧任务可读；不同版本成绩不能混用 | 模拟评估：升级恢复（新增）、恢复不混用成绩（已有）；用户流程：可靠结果重读（已有） |
| 08 | 按专精保存人工审核的固定爆发；第三序列可导入；保存失败旧定义可用 | 审核爆发：定义及历史、保存失败（新增）；用户流程：三序列导出（更新） |
| 09 | 循环与爆发作用于同一个角色，分别推进；执行或失败可区分，药水和饰品实际计入效果 | 审核爆发：同一角色、按法及不可用内容（新增）；模拟评估：真实执行与失败（已有） |
| 10 | 当前爆发内容不进入普通循环；内容改变后排除范围随之改变；旧材料及旧成绩保留 | 审核爆发：动态排除（新增）；角色输入：动作目录（更新）；训练：不同条件成绩隔离（更新） |
| 11 | 一次输入依次完成单目标和5目标，每场600秒；三序列及批量导入；部分成功和取消可恢复 | 用户流程：默认页面、三导出、页面恢复（更新/新增）；模拟评估：每场预算（更新） |
| 12 | 三份导出真实可用；进度和用时如实显示；本机与游戏验收分别标明 | 用户流程：真实进度、有效导出、验收状态（已有/更新）；模拟评估：离线状态如实标明（已有） |
| 13 | 默认训练使用新版标准角色；运行与查询默认同模式；训练及页面都能处理固定爆发中的不可用内容 | 训练：标准角色、默认模式（更新）；审核爆发：兼容行为一致（新增） |
| 14 | 本仓库两端使用同一升级入口；步骤清楚；前后检查只读证据，错版本或缺证据失败；不提高日常测试预算 | 模拟评估：仓库升级入口（新增） |
| 15 | 指定少量材料可完整训练及复测、发布入选；页面读取并重新评分；失败保留旧库，可靠成果不重算 | 训练：限定材料、成果复用（更新），独立复测、自动发布及页面使用（已有）；用户流程：同中心结果重读（已有） |

本次正式规格已应用5个能力文件、8条修改及6条新增，无删除或改名需求。额外角色输入更新用于消除旧禁药、300毫秒和饰品搜索规则与本次独立爆发模式的冲突。其他已有规格不为补齐票号而重复新增。

具体模块、接口、源码连接、补丁数量、存储键、批次数换算和脚本数量不进入本次新增核心规格。当前专精具体按法属于用户实际使用与模拟行为，作为适用场景保留。

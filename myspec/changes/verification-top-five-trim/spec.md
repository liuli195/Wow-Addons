# 慢项验证精简：保留核心真实通道，减少低收益重复

## Problem Statement

GSE上一轮最简真实冒烟已经通过：官方全仓实际39.858秒、GSE17.48秒。用户随后要求调查慢前五项，并已选择继续精简其中的装备浏览器、检查器自测和GSE准备/重复组合；主LuaLS保留，不重启Lua整体内存化。既有通过结果不是本轮新改动已经通过的证据。

## Solution

同一完整验证入口继续覆盖主要正常通道和有判别力的真实错误代表，不为没有对应断言的旁路和重复组合反复付费。可直接验证的规则通过无外部副作用检查验证；主动退出的边缘覆盖明确列出，不冒称全部等价承接。产品功能、默认行为和已有数据不因测试精简改变。

## User Stories

1. 作为装备规划器使用者，我导入配装方案后仍能取得真实计算的完整结果，修改宝石后的差值有实际计算依据。
2. 作为装备规划器使用者，我仍能保存、另存、刷新加载、比较方案，并将实际下载的导出重新导入；未被验证的旁路不被宣称已经通过。
3. 作为开发者，我仍能从真实检查器看到错误接口名和错误参数被拒绝，不把假错误输出当检查器证据。
4. 作为开发者，我能快速确认固定源码身份匹配或不匹配，以及加载清单引用缺失文件会被拒绝，不为了这些规则创建真实版本库或文件。
5. 作为GSE使用者，我仍能通过真实页面完成双场计算、导出编译、物理结果读取和复制。
6. 作为GSE维护者，我仍有原生战斗一致性、新项目接入读写及Windows进程所有权的真实证明，所有真实检查仍使用各自隔离的数据位置，不因无关准备重复安装结果中心。
7. 作为GSE使用者，退役设置仍被拒绝，页面诊断设置仍只影响指定任务；测试报告不会把减少交叉组合说成每一种组合都验证过。
8. 作为用户，我仍得到主LuaLS检查、完整普通守卫和全部登记检查的实际结果，不用关掉其它组制造提速。
9. 作为用户，我能区分旧正式基线、诊断定位结果和新正式验收，看到实际耗时和覆盖取舍。
10. 作为用户，我的正式数据和历史证据保留；本轮临时文件放约定仓内目录，成功后清理本轮可重建产物。

## Observable Requirements

- 保留上述主要真实通道及真实检查器的有判别力错误代表；普通检查不创建业务目录、不访问网络或启动原生子进程。
- 正常Windows全仓完整验证继续实际执行全部43项，全部剩余自动测试正常收集、通过，成功缓存跳过为零，无未完成和残留进程。
- 同环境非诊断正式工具总时不高于39.5877264秒、实际墙钟不高于39.858秒；GSE真实仍低于30秒。三组前后耗时如实报告，不承诺未经测量的具体节省。
- 主LuaLS及其它非目标检查保持原样。产品默认、算法、身份验证、错误处理及正式数据不变；不新增隐藏、夜间或替代重型测试入口。
- 被删除或不再执行的真实边缘风险逐项披露；内存规则通过不证明物理持久化、网络或原生组合全部通过。
- 新一轮预计单次运行超过15分钟或增量磁盘超过516MB时先停止申请，不自动继承旧任务1.7GB额度。
- 最终正式规格差异只在完整第二门禁展示并确认后应用；未获确认不得合并或发布。

## Testing Decisions

优先沿已有公开浏览器、检查器和任务入口验证保留行为；可观察规则直接消费现有生产入口和内存输入。当前正式通过作为优化前态，不虚构产品功能红灯。新增内存检查先验证，再移除重复的真实路径；完整固定候选经独立审查和官方全仓验证确认后态。

## Out of Scope

生产代码重构；关闭主LuaLS；Lua整体内存化；改并发制造比较优势；重跑6/8或新增4路矩阵；复制数据中心、工具和虚拟环境；创建新框架或夜间套件；清历史证据；门禁前改正式规格。

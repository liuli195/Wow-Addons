# 准星 HUD 血量与符能刷新恢复

Status: ready-for-agent
Gate: 门禁一已确认，实施完成，等待正式验证与独立审查
Flow Level: Full

## Problem Statement

用户感到血量变化后约0.5～1秒才显示。云端调查未证明实机唯一根因，但确认与暴雪和EllesmereUI的预测读取口径不同，以及血能旧读数恢复与最大生命值补读差异。用户要求对齐这些行为，不把静态差异或离线通过冒称实机延迟已消除。

## Solution

血量使用客户端默认开启的预测口径；资源事件继续即时读取与绘制；复用原有0.1秒定时器补读应显示且启用的生命值弧和符能弧；最大生命值及其修正事件立即读取，再合并下一帧补读。隐藏重新显示首个显示状态读新值，死亡/复活状态恢复，不依赖重载界面。

## User Stories

1. 玩家希望血量读取与暴雪、EllesmereUI的默认预测口径一致。
2. 玩家希望收到血量或符能事件后立即更新，不等定时器。
3. 玩家希望一次读取失败后保留旧画面，接口恢复后自动补读。
4. 玩家希望接口快照变更而无后续专用事件时，显示也能恢复。
5. 玩家希望隐藏后重新显示或重新启用时第一幅画面使用新读数。
6. 玩家希望最大生命值先变、当前值后变时，次帧显示最终比例。
7. 玩家希望关闭的元素不增加周期性采样成本。
8. 玩家希望现有圆弧几何、配色、其他资源刷新节奏不被改变。

## Implementation Decisions

- 保留既有 Core Module（模块）和 Elements Interface（接口）；不新增模块、公开接口、调度器或设置开关。
- 血量 usePredicted 显式 true；符能 unmodified=false 语义不变，不能当作预测开关。
- 原有0.1秒 ticker 中分别补读可见且启用的弧。判定复用当前 ShouldShow 语义，不仅检查上帧可见状态。不整套重复读取符文和其他功能。
- 整体隐藏恢复首次显示前补读；单项重新启用复用配置应用。不得绕过总开关、可见性条件或专精限制。演示状态不增加真实采样。
- UNIT_MAXHEALTH 与 UNIT_MAX_HEALTH_MODIFIERS_CHANGED 都即时读取，合并一个 After(0) 延后补读；回调先清标志，再依据当前显示条件读取，不因失败永久挂起。
- 继续使用已有失败保护和最近成功读数。秘密角度仅缓存和交给绘制，不比较、不运算、不输出。
- 不照搬原生或EUI断线填满、置灰、死亡强制赋值策略。正常死亡、复活、隐藏恢复通过新的读取链验证，不扩大无关监听重构。

## Testing Decisions

最高真实用户入口：玩家登录并启用 HUD，游戏事件、计时器和可见性改变驱动屏幕上的生命值弧/符能弧。云端最高可用 Seam（接缝）复用真实模块加载→PLAYER_LOGIN→真实事件/计时回调→Core→Elements→遮罩 SetRotation；不是仅检查内部读取表。

复用已有测试 Adapter（适配器）注入可控 API、失败和秘密值哨兵。After 必须在本票测试中使用可推进的下一帧队列，不用同步回调替代。验证预测参数、即时绘制、无后续事件恢复、失败后恢复、隐藏/关闭和恢复、最大生命值事件合并与再次重试。必要时保留独立的曲线/秘密值低层契约测试。

性能：两条稳定可见时新增周期性查询约20次/秒，单条约10次/秒；隐藏、关闭的弧新增周期查询为零。此数字不包含原有事件读取和一次性恢复读取，不宣称总调用上限。通过调用计数验证，没有新增常驻定时器；记录相关测试耗时，不冒称游戏帧率证明。

# 准星 HUD：沸点预测细弧与素材复用

**Status:** ready-for-agent
**Flow Level:** Full（完整）
**Fixed baseline:** 78205d4381bb0d178f750ab91495e3aeb9d0022e
**Development gate:** 门禁二已展示并获明确确认；正式规格已由官方MySpec应用并校验。最终代码ed937d5的Windows固定基线快验、74项HUD回归、Astra限定复审与用户游戏验收通过；PR检查、合并及同步清理按本次授权继续。

## Problem Statement

玩家希望在准星右侧能量弧外看到沸点强化消耗后的三秒预测倒计时，同时减少准星 HUD 的重复素材和透明画布开销。凝固之血与新增沸点功能的最终产品范围均为鲜血死亡骑士；其他专精应清楚显示禁用原因，不丢失个人设置。

## Solution

保留现有准星 HUD 和 EllesmereUI 配置入口，增加与左侧凝固之血对称的右侧沸点预测细弧。只在玩家施法成功与法术 50842 的发光消失相差不超过 0.30 秒时推断强化消耗，以施法时刻起算三秒。复用现有弧线、符文格、素材加工和绘制能力，准星使用四张小源图组成四臂与中心点，不新增框架。

## User Stories

1. 作为鲜血死亡骑士玩家，我希望强化消耗后在右侧看到三秒细弧，便于保持视线在屏幕中心。
2. 作为玩家，我希望仅收到触发发光时不出现三秒条，避免把可用强化误认为已消耗强化。
3. 作为玩家，我希望施法成功与发光消失两种到达顺序都能配对，避免事件先后导致漏显示。
4. 作为玩家，我希望不匹配的法术、其他单位和超过配对窗口的信号不启动倒计时，避免误报。
5. 作为玩家，我希望倒计时从玩家施法成功时刻起算，而不是从稍晚的处理时刻起算。
6. 作为玩家，我希望正在倒计时时的新触发只记为待续轮，而不重置本轮剩余时间。
7. 作为玩家，我希望本轮到期且期间有新触发时，从旧截止时刻续三秒，避免刷新延迟导致累计漂移。
8. 作为玩家，我希望没有待续触发时到期隐藏填充与背景。
9. 作为玩家，我希望关闭功能、切换专精和重载后不残留预测状态，重新启用时不猜测历史。
10. 作为玩家，我希望在受限场景中信号不可读时安全忽略，基础资源条继续正常显示。
11. 作为鲜血死亡骑士玩家，我希望凝固之血和沸点都可独立开关，不要求插件判断是否点了天赋。
12. 作为其他专精玩家，我希望这两项隐藏且设置置灰，说明仅鲜血死亡骑士可用。
13. 作为玩家，我希望切回鲜血专精恢复自己的开关与颜色，切换专精时配置页与 HUD 一起刷新。
14. 作为玩家，我希望关闭单项后仍能重新打开该单项，开关不会因自身关闭而永久禁用。
15. 作为玩家，我希望沸点默认启用、填充深红色且完全不透明、同色背景完全透明，并能分别调整两种颜色及透明度。
16. 作为玩家，我希望沸点只提供开关、填充和背景三种配置，不增加职业配色和最大层数选项。
17. 作为玩家，我希望复用左右主弧与对称符文素材后，主体轮廓、位置、充能方向和填充进度保持原样。
18. 作为玩家，我希望左右细弧共用居中主体，左侧受限凝固之血层数仍由游戏原生绑定绘制。
19. 作为玩家，我希望小图组成的准星保留四臂、中心定位点、独立外围阴影、染色与缩放。
20. 作为玩家，我希望线与线影同向旋转，中心点与点影各只绘制一次。
21. 作为玩家，我希望所有正式素材保持八像素每设计单位、完整缩小图层和平滑采样。
22. 作为玩家，我希望素材节省由实际成品重新统计，游戏观感经必要实际客户端验收后再宣称通过。

## Implementation Decisions

- 保持现有 Module（模块）分工：协调与事件状态、配置、绘制、纯计算、原生受限层数绑定。Logic（纯逻辑）仅做纯计算，不承载游戏事件或配置状态。
- 沸点是预测信号，并非读取实际回声施法结果或增益到期时刻。采用参考 A 的小型配对与续链逻辑，不复制参考插件的图标、独立窗口、配置、计时框架或十五秒条。
- 先检查信号是否为 secret value（受限值），再做普通判断；不可读或调用失败不得对受限负载运算、拼接或输出。
- 只接受玩家施法成功与 50842 发光消失的配对，窗口包含 0.30 秒边界；每次配对只消费一次。首次截止时刻为施法时刻加三秒。新触发不修改当前截止时刻，到期续轮使用旧截止时刻加三秒；新的有效手动消耗配对重新按该次施法加三秒起算，并清除旧待续标记。
- 凝固之血与沸点资格仅由鲜血专精 250 决定；这是用户产品范围，不声称服务器机制只允许该专精。资格与用户 enabled（启用）设置分离，不额外监听天赋来判断资格。
- 沸点默认设置仅有 enabled=true、填充 RGB(0.77,0.12,0.23)/透明度 1、背景同 RGB/透明度 0，不设职业色模式或最大层数滑块。
- 左右主弧及其阴影复用生命值素材；右侧仅镜像纹理。六个符文按 01/06、02/05、03/04 三对共享主体与阴影。填充遮罩不随纹理镜像，保持现有填充方向。
- 两侧细弧统一复用居中的凝固之血填充素材，均锚定圆心 (0,0)，右侧仅镜像纹理。删除运行包中旧偏移細弧素材；原生受限层数绑定路径不改变，仅替换背景素材引用和居中位置。
- 准星源图为臂、臂影、点、点影四张；四臂与四臂影使用固定 90 度纹理坐标旋转，中心点与点影各一次，共十个纹理实例。使用小循环，不引入 atlas（纹理图集）或通用旋转框架。
- 从仓库现有 PNG 导出/核对图裁出主体，用已有 Pillow（三层模糊、峰值归一化、MinFilter 挖空）配方重建外围阴影；保留相同风格，经校准与观感验收，不宣称逐像素无损。
- 预计源图尺寸为臂 256×64、臂影 512×256、点 64×64、点影 256×256；保持实际主体尺寸、间距、透明度、层级、染色与整体缩放。
- 沿用素材构建与验证入口，正式 BLP 保留完整 mipmap（缩小图层）与 TRILINEAR（三线性）采样，PNG 留作核对，不进入正式游戏部署。

## Testing Decisions

- 最高层级真实用户入口为登录后的玩家游戏事件和现有 EllesmereUI 配置页；最高公开测试接缝复用仓库已有“登录/事件/设置回调到真实绘制状态”的 Lua 沙箱，以及正式素材构建、验证入口。
- 测试跨过相同 Interface（接口），断言细弧显示、倒计时边界、配置可操作性与实际绘制结果；不为观察实现私有状态新增产品接口、测试框架或并行资源。
- 沸点覆盖：仅 SHOW 不启动、两种配对顺序、0.30 秒内外、三秒结束、续链、当前不误重置、无 proc 到期隐藏、重复/无关信号、受限值、关闭/专精切换/重载清状态。
- 资格覆盖：专精 250 与其他专精、配置页与 HUD 同步、存档保留、开关能重新开启、关闭总开关后的回调不写设置。
- 绘制覆盖：主弧及符文 full/half/empty（满/半/空），纹理镜像且遮罩未镜像，细弧居中与原生绑定不回退，线影四向同步、点影保留、颜色/透明度/缩放。
- 素材覆盖：源图与成品范围、二次生成、透明主体挖空、尺寸/密度、完整缩小层、白色可染色模板、包内仅保留仍被引用的成品；实际统计包大小与纹理内存估算。
- 全部新增测试登记统一验证；使用 TDD（测试驱动开发）红灯→绿灯循环、固定基线差异验证和独立只读审查。
- 当前云端只有 Linux；原仓库统一配置含 Windows 路径、固定 Lua5.1 与工具依赖。可运行的云端检查和远端 Windows 检查分别报告，缺依赖、失败、跳过与实际游戏验收不得混称通过，不为本功能新造跨平台运行器。
- 实际正式服 12.1.0/69814 中的副本信号可读性、强化预测准确度与阴影观感必须单独游戏验收；Lua 替身不能替代。

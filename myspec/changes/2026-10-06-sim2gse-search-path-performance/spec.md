# 搜索全流程五项性能优化

Status（状态）: ready-for-agent（实施和验收完成，待规格与交付门禁）

## Problem Statement（问题）

当前已优化数据保存的搜索整轮约395.30秒。进程退出等待、同层候选串行计算和重复检查仍有可测开销。

## Solution（方案）

采用用户确认的五项：进程退出立即返回；同层候选最多两个同时评分；两项编译检查一次启动完成；只生成一份完整运行交换报告；晋级判断和摘要复用同一次比较结果。不给调用方新增调参要求。

## User Stories（用户需求）

1. 用户希望相同计算工作量更快完成，不能将更多批次当作同等工作量提速。
2. 用户希望仍遵守默认累计600秒预算和五轮完整无改善停止规则。
3. 用户希望候选、种子、样本、评分、淘汰和晋级门槛保持原规则。
4. 用户希望程序结束后立即返回，同时取消与超时仍及时生效。
5. 用户希望最多同时两个单线程引擎，按原顺序使用结果，整层结束后筛选。
6. 用户希望取消、超时、失败和强制中断后保留完整已完成结果，恢复不重算成功批次、不重置预算。
7. 用户希望编译合并后仍核验校验码、真实导入、动作顺序、篡改拒绝和最终编码。
8. 用户希望完整报告的字段和类型保留，部分报告不能当作成功。
9. 用户希望通用查询继续通过逻辑表完成，不依赖文件路径或文件名。
10. 用户希望量化记录保留，临时测量脚本和副本在完成后清理。

## Implementation Decisions（实施决定）

- 继续使用现有进程等待、搜索评分、导出编译、报告发布和统计比较入口，避免增加调用方配置。
- 候选准备串行，同层评分内部最多两个；不把已有晋级双进程再计为新增收益，不跨层预读成绩。
- 出错或停止时停止新增派发，收尾本任务所属进程；完整成绩按原顺序消费、保存和恢复。
- 编译检查合并启动但不删除核验；最后编码必须对应通过真实编译检查的对象。
- 报告先核验再原子发布；比较区间与晋级判断共用原统计方法的同一结果。
- 固定资料缓存、跨任务复用、常驻引擎、构建参数和算法调整不纳入。

## Testing Decisions（验收决定）

- 最高真实入口：现有本地页面的创建搜索任务、查看结果、取消和恢复流程。沿用现有公开入口，不另造生产测试接口；此测试接缝在开始开发门禁一并确认。
- 逐项先用现有公开函数和真实程序测试可观察行为，再通过真实任务入口验证组合。
- 对取消、累计预算、失败、不完整报告、双进程逆序完成、成功结果保存与恢复进行回归。
- 相同历史请求、候选、种子和样本做固定工作量完整比较；逐请求核对成绩、波动统计、样本、导出和记录数量。当前参照752次请求、586次模拟、46988个样本。
- 单独报告两项主优化及组合收益；133秒是短测推算，不能写成整轮实测。固定预算搜索的候选增加另行报告。
- 执行统一本机完整验证，失败、缺依赖和未运行分别记录；游戏验收仍为未运行。

## Out of Scope（范围外）

不改变搜索算法、预算、角色数据、统计方法、游戏接口、存储格式及正式规格；本轮允许记录逐票本地提交，门禁二确认前不推送、合并或发布。

# 本机构建与完整验证合计 60 秒

**Status（状态）：** ready-for-agent

## Problem Statement

本机最近一次完整验证的 37 项检查全部通过，但单是验证已耗时 80.33 秒，超过用户要求的“构建＋完整验证合计 60 秒”。检查耗时累计 143.68 秒，当前并行上限为 2，因此即使排程理想，验证至少需要 71.84 秒。构建耗时尚无同机连续计时证据，需要先实测。

## Solution

复用 Build and Verify（构建与验证）的现有入口，在同一台机器上连续计时 `build`（构建）与 `verify --full`（完整验证）。先优化验证检查顺序与并行度，再依据实测优化构建或进一步调整排程，直到两段合计不超过 60 秒。保留全部检查、Sim2GSE 测试及其模拟次数。

## User Stories

1. 作为开发者，我希望本机日常构建和完整验证的总耗时在 60 秒内结束，以便及时得到可靠反馈。
2. 作为维护者，我希望 37 项已登记检查继续全部运行，以免用减少覆盖换取速度。
3. 作为 Sim2GSE 维护者，我希望自动发现的测试和模拟次数不变，以免性能优化改变验证语义。
4. 作为维护者，我希望性能报告记录总耗时、预算和各检查耗时，以便复核是否真的达标。
5. 作为 CI（持续集成）使用者，我希望远端保留原有完整覆盖，本机预算不成为远端功能门禁。
6. 作为维护者，我希望分别看到构建耗时、验证耗时和合计耗时，以免单段达标掩盖整体超时。

## Implementation Decisions

- 首轮将 `verify.sim2gse` 提到并行检查队列前部，同时将 `verify.maxParallel` 从 2 调至 3。按历史各项耗时静态估算，验证约需 50 秒；这不含构建，且不是实测结论。
- 若两段合计仍超时，依据逐段和逐项实测，继续评估外层并行上限 4、构建阶段的重复工作或其他已证实瓶颈；每轮仅改变有证据支持的因素。
- 保留 `verify.sim2gse` 的 pytest-xdist（Pytest 并行插件）8 工作进程与 worksteal（工作窃取）调度。
- 保留检查命令、检查清单、60 秒预算、失败与超时语义。
- 若优化构建，必须保留固定上游提交、补丁散列、源码一致性、编译器与产物身份检查；身份变化或损坏时必须重新构建或明确失败。
- 已有变更文档中“并行上限 2”的历史决定需与新的实测决定明确衔接；不静默改写历史结果。

## Testing Decisions

- 最高层公开验收入口：在同一台机器上连续执行 Build and Verify 的构建与完整验证；验证生成性能报告，同时记录两段及合计耗时。
- 同一机器连续三轮“构建＋完整验证”，每轮检查清单均为 37 项、功能状态通过、Sim2GSE 测试均被收集且无新增跳过，最慢一轮总耗时不超过 60 秒。
- 对比历史验证报告 80.33 秒及每项耗时，确认改进来自调度或构建优化而非漏跑检查。构建耗时以本轮首个同机连续计时为基线。

## Out of Scope

- 不减少测试、模拟次数或失败检查；不编写自定义并行器。
- 不以跳过必要构建或放松来源与产物校验来伪造 60 秒结果。
- 不修改 PR（拉取请求）中的引擎构建方案；该方案由上游 Build and Verify 问题单单独处理。

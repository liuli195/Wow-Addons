# 第二阶段最终收益对照与记录收尾

Triage（分拣）: ready-for-agent

## Problem Statement（问题）

现有比较工具要求420秒搜索及五节奏复测，无法读取新版已完成的搜索结果；第二阶段路线图及旧票据仍保留过时的验收与待办说明。

## Solution（方案）

比较整套产品改动：旧版保留七分钟搜索及最终复测，新版使用累计十分钟搜索且不复测。两侧总预算600秒、相同真实角色、固定按键节奏、三组配对随机条件，六次任务尽量并行。报告最终输出序列伤害、与自由选招参考的差距及达到固定伤害线的时间，由用户判断第二阶段是否结束。

## User Stories（用户需求）

1. 用户能比较取消复测和延长搜索等整套改动的实际收益，不剔除多搜索三分钟的收益。
2. 用户能看到每对最终输出序列的伤害及差值，不以搜索锁定但没有输出的候选代替最终结果。
3. 用户能看到同一固定节奏下的伤害，而不是旧版五节奏的中位数与新版单节奏混比。
4. 用户能看到自由选招参考、相对差距以及固定伤害线的首次达到时间。
5. 用户能区分搜索内评分与旧版独立复测，不能把两者说成相同证据强度。
6. 用户能核对预算、角色、引擎、随机条件、版本及冷缓存，并查看不足或失败证据。
7. 用户不需要五小时实验，也不因本次验收让新版额外复测。
8. 用户能看到与最新决定一致的路线图，未证实收益的总体票不得自动关闭。

## Implementation Decisions（实施约定）

- 只修改比较工具、相关测试及任务记录，不修改搜索算法或旧算法测试副本。
- 固定旧版为第二阶段既有基线cc94eb7253004ba1bff74e029fd6f3a8f23681d2；新版为当前已合并版本9e50f2c3191744462059c9c77b26983781de48dc的搜索源码，不计本次工具改动为算法改动。
- 保留历史比较入口和旧数据，增加明确的当前产品对照模式。旧版420秒搜索且运行原复测，新版600秒搜索、诊断总开关关闭。
- 旧版取最终实际输出序列在正常固定节奏下的成绩；新版取最终实际输出序列的搜索成绩，明确两侧样本及评分来源不同。不得在旧版发生回退时错取锁定候选成绩。
- 复用算法必需记录获取新版引擎身份、预算和评分时间，不依赖已关闭的诊断文件，不为了补统计额外模拟。
- 达线时间使用真实记录的累计时间；不能从每0.1秒读取整份历史得出的近似时间冒充精确达线时间，无法精确获取时明确近似或缺失。
- 先检查和独立审查，再运行六次真实任务；运行期间不并发构建测试。失败及残缺如实报告，不自动扩大实验、不写死收益通过百分比。

## Testing Decisions（验证约定）

- 复用现有比较命令的运行、结果提取及最终汇总公开入口。
- 先失败再修复，覆盖新版无复测、旧版回退、相同节奏取值、诊断关闭后的证据核验、两侧不同搜索预算、参考比例、残缺结果与人工判断。
- 最高真实产品入口仍为既有任务运行入口，六次真实任务使用相同角色副本和受控引擎；新目录与固定源码快照保护历史。

## Out of Scope（不做）

新增搜索策略、可执行性拦截、跨节奏稳定性评分、修改正式规格、游戏部署、自动通过判断、提前进入第三阶段。

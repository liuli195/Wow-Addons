# Sim2GSE 本地模拟配置

## Problem Statement

Sim2GSE（角色级按键序列优化器）的目标参数目前固定在代码中，万奥宝典天赋也只能跟随角色导出。用户需要通过 Git（版本管理）忽略的本地配置统一控制模拟目标和万奥宝典，同时保证基线与受控引擎条件一致、旧任务不会混用新配置。

## Solution

服务启动时读取 `.local/sim2gse/config.toml`，生成一份经过校验的实际生效配置，并将同一份配置传给任务副本处理、基线引擎、受控引擎和恢复条件。配置文件缺失时使用约定默认值；配置修改后重启服务生效。

## User Stories

1. 作为本机用户，我希望通过一个本地文件调整模拟目标，不修改受版本控制的源码。
2. 作为本机用户，我希望配置文件不存在时仍按明确默认值运行。
3. 作为结果使用者，我希望基线与受控引擎始终采用相同目标条件。
4. 作为结果使用者，我希望实际生效配置可从任务记录中核对。
5. 作为恢复任务的用户，我希望配置变化时旧任务被拒绝恢复，避免混合成绩。
6. 作为角色导入用户，我希望原始输入始终逐字节保留。
7. 作为本机用户，我希望关闭万奥宝典时只从任务副本删除完整的 `omnium_talents=` 行。
8. 作为本机用户，我希望开启万奥宝典时任务副本原样保留该行。
9. 作为服务使用者，我希望错误配置在服务启动时直接报错，而不是带着部分配置运行。

## Implementation Decisions

- 使用 Python（编程语言）标准库 `tomllib`，不新增依赖。
- 使用一个小型配置模块集中完成读取、补默认值、校验、引擎参数生成和任务副本转换；不新增配置类或后台状态。
- 配置文件缺失时采用：`Damage_Dummy`、等级 `90`、护甲系数 `4531.03`、目标数 `1`、关闭万奥宝典。
- 配置文件可省略单项，省略项继承默认值；未知字段、错误类型和越界值直接拒绝。
- 目标名只接受 SimC（模拟引擎）安全标识符；等级和目标数为正整数；护甲系数为有限正数；开关必须是布尔值。
- 服务进程只在启动时读取一次配置，并把不可变的实际生效值传给任务入口。
- 命令行入口同样在进程启动时读取同一路径；公开任务入口允许显式传入配置，未传时使用默认值。
- 引擎从实际生效配置生成 `enemy`、`level`、`armor_coefficient`、`desired_targets` 参数；基线与受控运行共用它们。
- 报告校验按实际目标数核对，不再把目标数写死为 1。
- `input.original.simc` 始终保留原始字节；`input.simc` 是实际模拟副本，只在关闭开关时删除完整的 `omnium_talents=` 行。
- 角色身份从原始输入解析；记录原始与有效输入散列，恢复时不把已经过滤的任务副本误当原始输入。
- 实际生效配置及生成的引擎参数写入任务状态并参与条件摘要；恢复入口在启动任何模拟前比较当前配置与任务记录。
- 不修改全局公共参数；配置沿现有任务、搜索和评估调用链逐层传递，避免并发任务互相污染。
- 本变更明确修改两条既有合同：角色天赋保留合同允许本地配置只控制 `omnium_talents=`；固定单目标合同改为默认单目标、目标数可配置。
- 不新增页面配置项，不引入配置热加载或迁移框架。

## Testing Decisions

- 先写失败检查，再完成最小实现；每张票执行 Red-Green-Refactor（红灯、绿灯、整理）循环。
- 配置检查覆盖：文件缺失、部分配置继承默认值、完整配置、未知字段、错误类型和越界值。
- 引擎检查覆盖：基线与受控命令含相同目标参数，报告按配置目标数核对。
- 任务检查覆盖：万奥宝典关闭、开启、原始字节保留、实际配置记录、配置变化拒绝恢复且没有启动模拟。
- 恢复检查同时覆盖：相同配置可恢复、任务副本或原始输入被篡改时拒绝恢复。
- 接口检查覆盖：服务启动时注入一次配置，并通过真实公开任务入口传递。
- 最终运行 Sim2GSE 角色入口测试、页面接口测试及仓库统一验证；重启本地服务并确认 `http://127.0.0.1:8780/` 可访问。

## Out of Scope

- 页面编辑配置、自动刷新配置或监视文件变化。
- 改变搜索算法、按键序列生成、统计门禁或游戏内验收方式。
- 支持多个配置文件、环境变量覆盖或命令行逐项覆盖。
- 修改用户提供的原始角色文件。
- 在门禁 2 获准前提交、推送、创建 PR（拉取请求）或合并。

# 正式搜索复用遗传训练链

**Status:** ready-for-agent
**Flow Level:** Full（完整）
**Development authorization:** 用户已确认完整门禁一，实施中；本状态不表示验收、合并或发布。

## Problem Statement

现有正式搜索与预训练维护不同的搜索与晋级路线。用户希望正式搜索最大限度复用现有遗传算法链，而不是在遗传算法外再叠旧局部搜索、分档评分和置信区间晋级。此前120秒共同参数实验不是本次产品默认设计，也不能代替新旧完整默认流程的实际输出对照。

## Solution

正式入口继续接受真实角色，按原逻辑一次冻结原生起点、训练代表和适用正式历史冠军，适配并去重后作为固定容量种群。复用训练链的遗传繁殖、真实粗评、反馈、完整代早停、成功凭据缓存及恢复能力；自然早停后完成正常场景复测，输出一个可导出的冠军。

新正式遗传搜索主体不设600秒或其他总时间硬截止，不新增定时配额。完整代历史前K榜连续无改善达到训练链的既有阈值后自然停止，再完成正常场景复测；总耗时可能超过600秒。手动取消、错误暂停、材料准备及单次故障超时继续保留，不能把“无总截止”解释成删掉全部局部安全限制。

开发后使用同一个角色、同一份冻结外部输入，对照旧方案和新方案各自的完整默认行为，记录自然总耗时及DPS曲线。中间参数和功能不强行统一，不新增共同独立评分来重排或替换自然输出。

## User Stories

1. As a 正式搜索用户, I want 使用原角色输入和场景入口, so that 不需转成训练模板或学习新的实验命令。
2. As a 正式搜索用户, I want 原生起点、训练代表和适用历史冠军只冻结一次, so that 运行及恢复期间新增训练成果不改变当前种群。
3. As a 正式搜索用户, I want 合法去重后的全部起点进入种群, so that 不按粗分截断或复制凑数。
4. As a 正式搜索用户, I want 复用现有遗传繁殖与完整代早停, so that 不叠加旧局部搜索、阶梯评分和CI晋级。
5. As a 正式搜索用户, I want 新流程自然结束后完成正常场景复测, so that 单冠军来自该流程本身的可靠复测结果。
6. As a 正式搜索用户, I want 总运行允许超过600秒并持续显示真实进度, so that 页面不以假倒计时或假百分比暗示截止。
7. As a 正式搜索用户, I want 随时取消并在条件一致时恢复, so that 完整成功批次、随机计划和已耗重试不丢失或重复计算。
8. As a 正式搜索用户, I want 失败或保存未完成时不发布冠军, so that 旧可靠成果和明确的未完成状态保持可信。
9. As a 正式搜索用户, I want 新冠军和旧历史按各自真实契约验真, so that 新复测不会被伪装成旧CI晋级证据。
10. As a 预训练用户, I want 原五场景复测与四条入选成果保持, so that 正式适配不改变已有训练默认行为或共享成果。
11. As a 对照结果读取者, I want 同输入的新旧流程分别保留自己的默认参数和自然结果, so that 能直接查看各自耗时和DPS走势而非另一轮统一参数实验。
12. As a 对照结果读取者, I want 评分阶段、迭代数、样本、缓存和环境身份可追溯, so that 不把不同精度的自然输出冒称同口径统计胜负。

## Implementation Decisions

- 采用一个端到端纵向切片，复用现有遗传执行器和真实评价深模块，只增加正式输入、正常复测及单冠军结果适配；不另建遗传算法、模拟后端、策略注册表或插件框架。
- 初始输入按原成果契约一次冻结：v2最多4原生＋4训练代表＋1角色正式冠军；受支持v1或无版本保留独立旧训练冠军，最多4＋4＋2。适用性、裁剪、合法性和完整点击行为去重沿用原逻辑，行为去重后N可减少，保存各来源及拒绝原因；冠军缺席明确记录，不复制凑数。未知或混合版本明确拒绝，不通过改标签制造兼容。保留旧训练冠军兼容是既有能力，不新增另一条成果链。
- 遗传算法复用固定N、锦标赛选择、独立交叉和变异、非法子代额外10次重生、原请求一次重试、全程前K榜及完整代无改善判断。正式流程沿用既有单场并发与单引擎单线程，不把预训练多组资源拓扑带入页面。
- 默认算法参数复用训练链：粗评32、前K=8、连续2完整代无改善、锦标赛3、交叉与变异概率分别0.8；正常场景复测每候选3批、每批请求128。实际有效样本按原生凭据报告。正式只复测正常场景并选一个冠军，不要求四条合格结果，不运行训练的四种扰动。
- 新正式任务以明确版本化的自然停止策略和算法/评价身份保存；无限总预算只存在于运行时，不把Infinity塞进原有限数配置校验或标准JSON。任务、页面双场、取消与恢复入口必须使用一致政策。
- 正式流程复用真实角色、当前原生能力、实际按键间隔/重置事件、模拟场景和已冻结爆发，不套用训练标准角色或硬编码实验场景。旧阶梯及CI晋级不再作为新正式冠军的前置条件。
- 正常复测覆盖冻结前K入围者，按完整成功复测的正常DPS择单冠军，同分按既有稳定行为身份排序。取消、半代、复测失败或存储失败不得伪装完成、换用未完整复测候选或发布半份冠军。
- 新正式冠军与恢复收据显式版本化，核验完整入围名单、候选、条件、引擎、种子、请求迭代、有效样本、全部正常复测凭据及导出身份。发布保持先可靠保存再按版本比较更新、幂等恢复；不伪造旧global_validation或CI晋级链。
- 旧完整任务及旧冠军按旧版本只读验真；适用旧程序可作为新起点重新评分，旧分不直接参与当前排名。不兼容的旧未完成任务明确拒绝恢复，不篡改旧身份；旧版本代码仍可用于只读历史和本次默认对照。
- 复用现有真实任务生命周期及轻量曲线导出。对照只增加既有观察开关，不改变搜索参数、评分、早停或自然结果；新旧运行使用隔离结果/缓存/发布空间，避免前一侧污染后一侧或共享冠军。

## Testing Decisions

- 最高公开接缝采用现有页面HTTP任务生命周期：创建双场任务、读取实际结果/进度、取消、恢复；覆盖真实角色→两场依次搜索→单冠军与原导出/集合的完整主路。现有公开任务、双场引擎身份及冠军恢复用例提供先例，不新增仅供测试调用的生产入口。
- 正例验证原起点只冻结一次、遗传自然早停、完整正常复测、可靠保存后可读取/导出；页面不再按elapsed/600显示有确定终点的进度，同时CLI和页面遵守相同停止政策。
- 失败及恢复代表覆盖半代取消、复测故障、暂时存储不可读、最终保存/发布故障、输入或引擎身份漂移、旧未完成契约拒绝；可靠成功批次不补跑，随机计划及已耗重试保持，发布恢复不重做评分。
- 训练回归证明原五场景、四条成果、自然早停和材料准备局部超时不变。旧局部搜索内部机制专属断言按新公开契约替换，不为迁就旧断言叠回阶梯或CI。
- 算法快速用例可以复用既有原生评分边界替身，但不代替正式验收。业务测试仍经仓库统一验证入口；环境缺失、失败、跳过分别记录，不沿用旧实验绿色结果作交付证明。
- 开发及独立审查通过后才运行真实新旧默认对照。原始角色字节、各场有效角色/引擎/爆发、外部训练代表与历史冠军来源快照保持一致，各侧完整参数另记；旧版按旧自然/限时/候选默认，新版按新自然结束默认，不强制共同120秒、不增加共同3×128端点评分、不按中间DPS调整参数或重跑挑结果。
- 曲线复用已有返回时刻和真实分数，不插值、不回填未来值，不把不同场景或评分阶段混成同一分数；分别报告准备、搜索、正常复测、保存及总调用时间。此对照是默认完整产品输出比较，不沿用此前8/16对符号检验结论。

## Out of Scope

不修改预训练五场景/四代表的产品语义；不增加定时配额或新的配置框架；不复用此前AB实验调度器或伪造旧CI收据；不改GSE语义和游戏时点；不新增外部采集、页面开关体系、性能图表平台或共同独立评分；不合并、发布、自动部署或冒称游戏验收。

# 默认搜索加测上限256与完整对比

Status（状态）: completed（实施验收完成，等待门禁二交付）

## Problem Statement（问题）

用户选择更高探索收益：将默认最后加测上限从512改为256，并完成一次完整搜索对比，量化真实省时和结果质量。已有短测未发现明确下降，但不能证明所有搜索路径质量不变。

## Solution（方案）

默认累计请求改为32、128、256，保留原筛选、挑战及独立晋级复核；以同一真实邪恶角色资料、环境、随机条件执行512与256两次完整任务。600秒为每次任务预算上限，保留正常提前停止规则，不强制跑满。

## User Stories（用户需求）

1. 用户不传搜索参数时，最后加测默认256，节省计算资源用于更多候选探索。
2. 用户明确指定512时，仍可使用512，不收窄已有配置范围。
3. 用户能看到两边实际总用时、候选与轮次数、模拟启动次数、实际有效样本、停止原因及最终结果。
4. 两边都跑满600秒时，不将同预算产出提升写成节省时间。
5. 用户能用与搜索不同的配对随机条件检查两个最终序列，避免用不同样本数的搜索成绩判断质量。
6. 用户原资料、历史结果保留；配置和版本一致时按已保存配置恢复，不跨采样条件复用成绩。版本或规则已变化时沿用现有拒绝混用行为，保留旧数据并新建任务，不增加旧版本迁移。

## Implementation Decisions（实施决策）

- 单一纵向变更，仅改默认最后加测档位，同步运行约定及公开入口检查。
- 保留显式512配置能力、评分和波动计算、每方四批100场晋级核验、最多两个单线程引擎、600秒预算及完整五轮无改善停止规则。
- 正式规格要求原默认512；实施阶段仅准备候选修订，交付门禁确认后才修改正式规格。
- 完整搜索串行运行，两边采用同一源码和引擎，仅显式512对照与新默认256不同；使用独立任务、成绩缓存和隔离结果目录，不共享搜索结果。
- 允许搜索路径自然不同，不能宣称工作量相同；同预算产出和正常停止省时分开报告。

# Sim2GSE 可编辑指南配置与自适应搜索审阅稿

Status: draft
Triage: needs-info

日期：2026-10-17。本文件与既有 01→02→03 三票是唯一四份变更方案。本轮只重整需求文档，不改产品代码、配置或测试。新版方案与测试接缝仍待审阅，尚未展示并取得本版“门禁一——开始开发”的明确批准；旧方案的实施授权不覆盖本版变更。01 有旧实现但未最终验收，02/03 未开工。

## Problem Statement（问题）

现有初始化虽然已能读取单个 JSON（结构化配置文件），仍保留八条通用策略、细粒度 APL（动作优先列表）条件和供资/消费的两层骨架。只替换配置内容，不能实现用户现在要求的“以专精指南提供默认策略和起手，再按实际结果人工调整”。

用户需要看得懂、能编辑、能经现有任务入口生成合法 GSE（高级按键序列插件）序列的配置。后续搜索应诊断当前候选的全部适用条件，由现成选择器挑一个合法具体操作，再用真实模拟结果学习；不能继续把旧八条策略或旧骨架藏在通用程序里。

## Solution（方案）

1. 仅以专精指南作为默认策略和有序起手的来源；同一邪DK配置纳入萨莱因、天启骑士两个英雄天赋各自的起手及单体/群体优先级，入库前逐条审阅结构化数据及表达。指南是默认值的依据，最终可编辑配置是运行权威。
2. 人或助手可根据结果修改起手、优先级、条件及修改细则，记录简短修改说明；无需永久与指南一致，已有底层能力内无需每次重编 SimC（SimulationCraft，战斗模拟引擎）。
3. 复用现有单 JSON 的读取、校验、保存、摘要和任务快照，通用程序按结构化数据执行，不按技能名或规则 ID（标识）硬编码业务。
4. 只替换原目录均匀起点来源，保留其余起点及 4＋4＋2 框架；用配置中的有序起手及真实角色 GCD（公共冷却时间）、输入节奏生成可导出的初始化候选，并展示逐步来源与损失。
5. 对任意当前候选，使用同次真实模拟证据诊断同一配置的全部适用条件，汇总全部合法单步选项。原多起点调度选定当前候选后，Coba 现成 LinUCB（线性置信上界选择器）每次只选择一个操作，用既有共同模拟批次的相对 DPS（每秒伤害）反馈学习。

## User Stories（用户故事）

1. 作为用户，我希望知道默认策略和起手来自指南的哪个版本与分支，以便先核对适用性。
2. 作为用户，我希望同时保存萨莱因和天启骑士各自的起手及单体/群体优先级，按角色英雄天赋和场景选择，以便两分支都能独立审阅、编辑和复用。
3. 作为用户，我希望调整起手顺序及重复步骤，以便按实际表现改进初始候选。
4. 作为用户，我希望修改优先级、条件和修改细则，以便让最终配置表达自己的选择。
5. 作为用户，我希望已有能力内只改配置就能生效，以免每次重新编译引擎。
6. 作为用户，我希望区分指南默认值、明确人工差异和未知事实，以便理解每个决定的依据。
7. 作为用户，我希望看到初始化的中文逐节点动作、随后空点击、来源和 GSE 映射，以便审阅实际输出。
8. 作为用户，我希望替换形态仍对应同一基础按钮，以免序列伪造第二个可按动作。
9. 作为用户，我希望独立爆发宏首次按下与起手对齐、以后每45秒执行，以便保留独立爆发并看清实际输入计划及对齐损失。
10. 作为用户，我希望已有其他起点、训练代表、冠军和原多起点调度继续可用，以免扩大变更。
11. 作为用户，我希望任意候选都按同一配置的全部适用条件诊断，以免只解释指南起点或人工挑中的一条规则。
12. 作为用户，我希望每个候选说明对象、位置和改量，以便看清一次具体修改。
13. 作为用户，我希望未知状态明确报告且学习依据来自真实模拟，以免静态估计或教师状态被冒充学生证据。
14. 作为用户，我希望跨角色、专精和任务复用兼容经验，以免重复学习或恢复旧任务时回滚新经验。
15. 作为用户，我希望运行固定启动快照、规则变化时拒绝恢复，以免新旧条件成绩混用。
16. 作为用户，我希望逐票看到实际产物，最后仅以新旧各 600 秒输出 DPS 比较，以免增加低收益实验。

## Implementation Decisions（实施决策，待本版门禁）

### 1. 策略来源与配置权威

- 删除八条通用目标策略及 APL 细粒度条件作为规则指导的要求，不迁移其 8＋23 清单作为新验收。APL 可保留作既有模拟基准，不再提供隐藏的优先级、前序让位或硬约束。原生资源、冷却、天赋、替换和伤害机制保留。
- 默认数据只来自已逐条核对的专精指南。同一邪DK配置保存萨莱因、天启骑士各自的起手及单体/群体优先级，优先复用既有配置适用条件，按输入角色英雄天赋事实＋场景选择；共同内容可复用，不同规则隔离。指南每英雄页面只有独立Opener（起手）标签、没有单体/群体子切换；各英雄已核实起手作为基准。用户已明确AOE（群体）起手的人工派生方法：仅将死亡缠绕对应消费位置替换为Epidemic（扩散），保留其他动作顺序和次数，适用于两英雄各自起手，不冒称指南另有四套起手原文。此派生映射保存在邪DK可编辑配置，通用程序读取，不做技能特判。分支缺失或无法匹配时明确报告，不静默套用另一分支，不按技能/天赋名在程序中硬编码分派。两分支均可人工编辑，已有能力内免编译；六个来源视图已核验，不等于具体结构化默认配置已获用户审阅、入库或已支持。人工调整是明确差异，不冒称指南原文；已批准的人工选择按下文待核项处理，不能因更换来源自动取消。
- 最终生效配置决定起手、优先级、条件、诊断和修改细则。指南更新不自动覆盖人工配置；不新增网页同步、复杂来源管理或全文复制，只保留最低必要的来源链接、版本/核对日期、适用范围和修改说明。
- 继续使用一个 JSON。若保留 general（通用）区域，只用于参数化表达与编辑能力复用，不含旧八条目标策略；专精区域保存实际默认值及人工修改。程序只读有限结构化表达、事实与已有操作，不执行任意代码，不以技能/规则 ID 分派业务回调。
- 配置至少须表达：来源与适用分支、有序起手、动作/替换按钮映射、适用条件及优先级、诊断所需事实与未知处理、允许的单步编辑及范围、人工差异。这里是待审的内容清单，不是已确认新 schema（数据结构）或要求全量实现的新增字段表；优先缩减、复用现有表达，具体默认数据和必要调整逐条确认。

### 2. 复用链路与必须替换的旧耦合

现有链路为 rule_config.load/save/validate（配置读取/保存/校验）→search.initial_programs（起点组合）→rule_initialization.generate（初始化）→既有 program/sequence（程序表示、编译及模拟）。沿用这一链路，不另建配置服务、生成框架或模拟器。

当前 bind 仍强制 funding（指定生成动作供资）及唯一目标消费按钮，generate 仍强制供资、骨架及二层填充。01 必须替换这些业务耦合及相应旧校验，不能只改 JSON 后声称已完成。原初始化中的“消费一次、合格供资额度、先预消费、CD 各一次、周期收尾、两层填充”等旧骨架要求全部退出新默认契约；只有被明确写入新人工配置的具体选择才生效，不以程序默认或隐式回退保留。

配置按启动时一次加载与校验，使用现有原子保存和期望摘要冲突检查；直接编辑坏文件时下一次加载明确拒绝，不承诺外部编辑器具有原子保存保护。保存有效配置后，下一次生成/新任务加载；运行固定完整快照，单场、双场和训练均不在热路径读当前文件。暂停恢复发现规则变化或缺少必要身份时拒绝并提示新建任务，旧结果和原快照保持可读。配置摘要及实际爆发输入计划继续进入任务快照、缓存和训练语义身份，避免首次时点不同的结果混用；不因配置编辑改变原生构建身份。

### 3. 初始化候选与可审阅输出

- 读取选定配置的有序起手，保留重复步骤及来源顺序；按真实角色有效 GCD、动作属性和输入节奏估计间隔，再复用既有表示、编译和导出。不以目录基础 GCD 冒充有效 GCD，不以尝试次数冒充成功施放。
- 基础按钮与替换形态映射来自配置及现有能力资料；替换形态不是可同时任意选择的另一个按钮，派生效果不是额外可按动作。固定原生源码已核实：Forbidden Knowledge激活时，死亡缠绕替换为Necrotic Coil，Epidemic（扩散）替换为Graveyard；已有同键反查机制可复用，不凭名称创建第二个按钮。现配置死亡缠绕/扩散的variants（替换形态列表）为空，初始化静态费用仅按native_action（原生动作名）匹配、且快照仅战前，不能代表Forbidden Knowledge中的实际扣费；01须复用补齐配置绑定和费用读取，不硬编码动作名或费用。AOE派生初始化的目标费用独立读取，不能假定相同或照搬旧账，须按目标实际机制参数重新估计/模拟；若影响初始化可排时序须重新估算并报告，不因资源不足擅自补生成动作或重排。
- 输出逐步说明：源起手步骤、实际按钮/节点、动作尝试、随后 WaitClicks（空点击数）、估计时刻、参数来源、近似/未知、保留或映射方式及语义损失；完整源步骤不能因不可表达而从报告消失。
- 起手只是可被后续搜索修改的循环候选，不保证最优，也不声称完整保持指南战斗语义；不新增一次性起手执行引擎。无法用现有循环/等待表示的部分明确报告，不能静默改成“已实现”。
- 四类基础起点仅替换目录均匀来源；其余三个来源、最多四个训练代表、训练冠军和正式冠军各一个保留，经既有合法性和行为去重后最多 4＋4＋2，不凑数。
- 现有结构/导出/爆发合法性是硬边界，不因指南或人工配置越过。缺必需事实、非法动作、结构超限或不可表达间隔明确失败或列出阻塞；未知按经审阅的配置处理，不自动填 0/false 或回退旧骨架。

### 4. 独立爆发首次对齐与人工差异

用户已确认：爆发宏仍独立，仅把第一次按下时间与初始化起手对齐。初始化根据爆发入口前的步骤、真实角色有效GCD及既有输入节奏估计首次时点t0，后续为t0＋45k秒（k为非负整数）。若t0＝5秒，输入时点即5/50/95/140秒；5秒只是示例，不是固定默认值。独立宏内容、既有窗口/按法、独立步进状态、普通循环排除受保护动作及暂停后原位续接不变。指南完整起手包含Army、Dark Transformation或Blightfall时，保留源步骤并说明其如何映射到独立爆发实际输入计划，不重新塞入普通循环，也不静默删除。无法精确对齐的顺序/表示差异与语义损失须如实报告；“首次对齐＋后续45秒间隔”不再待确认。

建议在初始化推导后冻结本任务实际输入计划，后续搜索沿用；这一具体冻结口径待本版门禁审阅。配置摘要和实际输入计划必须一并纳入任务快照、缓存和恢复核验，不能混用不同t0的结果。本版不自行引入搜索联合优化t0、每个候选重新对齐或按成功施放事件触发爆发。

已批准的“单体枯萎凋零、腐化替代爆发维护疾病、灵魂收割普通 CD 示范”作为人工差异在本版沿用。用户新确认枯萎凋零（地板Death and Decay）取消目标位置/是否停留判断，按普通CD技能处理并保留原优先位置；网页原条件“预计敌人会留在区域内”仅作为来源差异保留。该差异写入邪DK可编辑配置，不做通用技能特判；其减少腐化CD的效果由实际角色天赋及原生机制决定，不造人人必有的常数效果。单体凋零具体插入点及其余差异表达仍待逐项核对，不自动在起手新增凋零；既有批准不证明整份默认配置已经验收，也不扩为所有CD各示范一次。

### 5. 同次学生诊断与合法单步选项

- 输入可以是任意当前合法 GSE 候选，不要求来自01。使用该候选同次真实模拟状态，按同一冻结配置评估全部适用条件，不按旧八规则分类，不先人工选一条规则。
- 每项记录配置身份、适用性、场景/时间/源位置、结论、证据及缺口；区分不适用、未知、符合、违反及有证据的合理让位。未知不当作已证违规，不用教师轨迹、另一候选状态或初始化静态估计填补。
- 02 先按实际配置列出“所需事实、现有输出、缺口”。控制器已有输入/动作来源、部分 GCD、主资源、当前动作冷却等；没有全部指南状态。仅补必要的轻量同次采集/聚合，不能把源码有 getter（取值接口）说成项目已导出或诊断已实现。
- 全部适用诊断及配置范围内的全部合法具体单步选项一起输出。复用现有编辑体，每项明确对象、位置、改前改后/改量及影响范围，一候选只应用一个操作，不生成组合。
- Loop（循环）编辑说明全部重复受影响；CastSequence（施法序列）的成功推进/重置与普通动作步进不能混同；off-GCD（不占公共冷却）及空点击边界沿现有语义。所有候选经现有硬合法性、爆发保护和行为去重；改后证据重新模拟，不能复用改前动态状态。诊断改善本身不构成晋级。

### 6. Coba 单操作选择、反馈及共享经验

- 原有多起点轮转、当前路径/父候选选择、预算、批次和晋级不改。调度确定当前候选后，将它的全部诊断（含未知）及全部合法单步选项交给一个现成 LinUCB；每次 predict（选择）只选一个具体操作，不做“起点＋操作”的联合选择，不按规则拆学习器。
- 一轮可按既有候选数量多次选择，生成同父的独立单步候选；不同选择不能叠成组合。已入队的候选不因随后反馈被假称为即时重排。无合法选项沿既有路径停滞/跳过机制处理，不用随机算子、固定启发式或搜索洗牌兜底；随机初始化仍保留。
- 直接复用 Coba 的 predict/learn（选择/学习），只加必要薄适配，不自写选择算法或引入整套实验框架。跨角色/专精使用含义稳定的通用数值特征及未知有效性标记；技能/规则 ID 只做身份，不作连续数值或隐藏业务权重，相同特征的不同具体候选也不能误合并。
- 特征/反馈语义与维度版本化，兼容时跨角色、专精和任务共享经验；配置摘要变化不等于另建一份模型。含义不兼容则明确拒绝旧模型/待反馈，处理方式另审，不静默混学。
- 反馈仅用生成父与候选已有的共同 search（搜索）批次，按实际 samples（样本数）加权计算 DPS，reward＝(候选均值－父均值)/父均值。匹配场景、种子/输入计划及执行条件，不要求不同程序的完整身份相等；正升负降，不额外模拟、不加人工规则分。无共同证据或分母无效不学习；正常早筛已有可比完成批次可学习，取消/错误/未完成不造零。
- 复用现有 TaskStore（任务存储）、检查点和结果中心，保存模型、随机进度、决策快照、兼容版本及一次反馈去重。共享实例及必要短锁不持锁跑模拟；恢复旧任务不能回滚其他任务的新经验。Coba 版本锁、序列化/随机恢复、并发与崩溃一致性须实际验证，不假定已支持；不新建数据库、常驻服务或每任务副本归并。
- 普通搜索及新启动的既有训练使用同一操作选择机制；旧任务不原地换算法、不自动重训，兼容旧程序进入新任务须按当前条件重新评价。现有训练入口、停止及独立评价不因此扩展。

## Testing Decisions（测试决策，待接缝审阅）

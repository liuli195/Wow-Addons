## What to build

让一个实际学生序列经过现有模拟后产生八规则诊断、跨规则统一有限合法候选池，并将一个明确操作应用后通过现有编译和模拟评分验证。

范围：复用[总规格2节](../spec.md#2-两个可编辑规则库与通用执行机制)两库契约中的diagnose/edits/features及同一任务快照，最小同次状态读取/聚合、完整绑定条件的有限诊断、unknown与合理让位、来源位置关联、现有编辑体参数化及合法/去重/评分连接。按2026-10-16用户确认，承接第4条动态短窗口：01仅保留绑定及unknown，本票用同次学生实际Buff窗口与动作上下文诊断、提出合法调序，后续由03接入搜索；不从初始化静态快照预测随机相位。全八规则同时进入候选池，不先人为挑一条规则；一候选一具体操作，不生成多组合。

复用controller已有事件/实际结果、sequence.evaluate、mutate中的编辑体、program/codec/burst和评分缓存。数据可取的研究不算已实现学生诊断。业务谓词、证据需求、前序让位、unknown及候选关系全部由两库声明；通用程序仅求值、聚合区间和调用已有合法编辑，不能按技能/规则ID或业务类别选Python诊断回调。

## Acceptance criteria

- [ ] 诊断包含身份、适用性、时间/来源位置、结论/原因、证据/缺口和有界摘要；教师数据不补学生缺口。
- [ ] 八规则按完整条件及前序让位判断；unknown、不适用、不可用和合理等待不混同。第4条保留Vampiric Strike/Essence完整条件、动作GCD及替换身份；只有学生实际状态支持时才诊断并提出短窗口修改，缺状态继续unknown。
- [ ] 不新增诊断完整模拟、额外ready或每点击全APL扫描；同种子采集不改变执行、随机过程和伤害。
- [ ] 候选写明实际对象/位置/改量和影响范围；Loop影响全部重复、CastSequence语义、off-GCD和Wait边界正确。
- [ ] 现有硬合法性、行为去重、爆发保护及模拟接缝通过；改后不复用改前动态状态当证据。
- [ ] 取得诊断→单操作→合法程序→实际评分的可追溯例及必要负例/unknown例，成本诚实报告。
- [ ] 此票接缝完成不宣称旧搜索策略已全部替换；该全入口交付由03完成。

- [ ] 对总规格4.1的8规则逐条完成证据→结论→单操作映射；阶段未支持的事实保留unknown，不把静态近似当学生证据。
- [ ] 复用同一版本快照和digest，不在每步读配置；变更配置条件/候选界限与一致重命名后，经公开诊断入口证明数据确实生效，无新增模拟批次。
- [ ] 按总规格10.1逐条复审：①存储字段②初始化映射③原初始化顺序/次数/停止是否仍正确④实际证据、对象位置、合法候选及后续固定数值列。目标/表达/实现/验证分别记录，不能整库勾选。

## Validation and budget

复用既有公开入口、自动发现及统一验证。云端开发，确依赖本机引擎/Windows/Lua/真实数据中心安装副本的正式验证另列获准动作。现有构建超时1200秒、整套正式验证预算60秒；单项检查上限不等于整套预算，未测耗时不作承诺。具体入口、真实输入及运行总上限在该动作开始前明确，不借本草案运行。

## Boundaries and stop conditions

缺条件只能保留unknown，不为了补覆盖扫描全APL或加入副作用观察。既有结构不支持的改法明确跳过并解释；不凭诊断改善直接晋级。

发现受保护爆发变化、未知值被伪造、硬合法性越界、恢复不一致、超过获准预算或需要额外架构时停止相关动作并报告。不得把未运行验收勾选为完成。

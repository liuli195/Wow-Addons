## What to build（交付）

用户编辑一个配置文件并经既有保存校验后，新任务按“专精＋英雄天赋＋目标类型”唯一选定完整起手，读取冻结角色与源形态自身的原生有效GCD、施法段、完整引导段及费用，生成合法循环候选/GSE并看清来源、空点击、估计时刻和未知。方案通用，邪DK四配置仅首个MVP；无状态切换可一个优先列表，其他配置可有1到N个内部状态。

初始化只按配置起手，不执行八模板的准备或短期窗口逻辑。只替换原目录均匀起点，其他三个基础来源、至多四个训练代表及两类冠军保持（最多4＋4＋2，不凑数）。继续原结构、行为去重、缓存、预算和导出一致性，不恢复供资/消费两层骨架、自动CD各一次或一次性起手引擎。

## Implementation decisions（本轮明确接法）

- 复用现有配置读取、类型/单位/引用校验、期望摘要保存、原子性及完整任务冻结；加入三键唯一匹配、动作与替换形态对象，未知/多匹配报错，不默认另一个英雄或场景。模板处理留共用数据，专精只填对象和参数。
- 公共快照沿既有catalogue→原native报告→reference.static_snapshot。将公共触发从Unholy专用override移到本actor完成precombat_init之后、战前回调和战前动作之前；已有DK额外parameters/talents/unknown可保留，不是公共门禁。逐字段保留安全/未知，不因删除专精guard就遍调任意虚函数，不建采集平台。
- cast_ms明确为引导前施法段，channel_ms为其后完整引导段。占用＝max(有效GCD,cast_ms＋channel_ms)，再取现有时间表中占用结束后的允许输入，至少推进一次输入。普通步骤、已有战前占用和首次锚点估时共用计算；不把GCD和读条相加，不裁剪引导。
- 源步骤保留source_step/source_form/attribute_query，查询该形态自身属性，不借基础按钮时长或费用；实际施放形态仍按原生资格，不保证必触发。必要时序未知明确定位该动作并不支持依赖排位，费用/收益未知单独传播资源未知，不抹掉其他已知时序。
- 快照是初始化静态估计，后续Buff、资源及职业combat_begin变化仍由真实模拟决定。效果应用/首跳/消费完成与GCD/读条/完整引导/队列占用分开。
- 固定爆发按法、周期、宏、窗口、独立步进、暂停/原位续接原样复用。首MVP按已有起手估计t0后冻结，后续t0＋45k；不逐候选重对齐，不用成功事件触发。其他专精引用自身宏，不复制DK技能，不增加本轮无爆发产品功能。
- 继续三人工覆盖：普通首位Putrefy替代源Outbreak、既有单命令战前Raise Dead；单体凋零普通CD；腐化疾病维护及收割CD初始化。四实例完整源步骤、普通序列和宏顺序差异在总方案，不把疾病组件映成场景独占。

- [ ] 四MVP起手源顺序、重复、源形态、普通首位腐化、单命令战前及尾部收割保留；AOE只替换已确认两个消费位置，独立宏顺序差异如实展示。

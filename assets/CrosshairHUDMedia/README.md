# CrosshairHUD 素材（固化副本）

这里是准星 HUD 素材包在仓库内的固化副本。原包位于仓库外（`D:\Downloads\CrosshairHUD_Media_Pack`），
易失，因此把需要的东西复制进来，让构建与校验可复现。

## 来源与范围

原始素材包由用户提供（2026-09-16）。本目录只收进来三样：

| 内容 | 说明 |
| --- | --- |
| `Source/*.svg` | 11 个矢量源，含 `hud_master.svg`（256×256 总图，9 条弧线路径都在上面） |
| `Textures/*.png` | 9 张成品位图，2 像素/设计稿单位导出 |
| `manifest.json` | 显示尺寸与相对圆心的偏移；坐标系与导出倍率的权威来源 |
| `hud_reference.png` | 设计参考图，仅用于对位与配色采样，不参与构建 |

**没有收进来**的：素材包自带的插件外壳（`CrosshairHUD_Media/` 的 `.toc` 与 `Media.lua`）与
`MyMedia_registration_snippet.lua`。这些是"把素材当作独立媒体插件发布"用的包装，与本项目的
使用方式无关——本项目的素材由公共核心插件 `MYUI` 持有。

## 加工边界（用户授权范围）

**允许**：画布范围、裁切位置、导出倍率、文件格式。

**不允许**：线条粗细、弧线起止角度、分段间隔、圆角——设计稿的图形本身一个字不改。

## 实际做法：原样使用，不重新导出

9 张成品**原样复制**，不缩放、不重采样。依据是它们在 0.5–2.0 的缩放范围内**永远不会被放大**：

- 素材本身是 2 像素/设计稿单位
- 界面缩放滑块上限 2.0，即最多 2 界面单位/设计稿单位
- 魔兽的界面缩放上限使 1 界面单位不超过 1 物理像素

于是最坏情况恰好是 1:1，不存在放大导致的模糊。重新导出只会增加体积而不改善观感。

> **前提**：以上推理依赖"界面缩放的上限是 1.0"这一条。本机固定的界面源码里没有找到该钳制的
> 证据，属于**待验证假设**；若将来发现客户端允许更大的界面缩放，需要重新评估导出倍率。

**关于重新导出的可行性**：本机目前**没有 SVG 光栅化工具**（venv 内无相关库，PATH 上没有
Inkscape / rsvg-convert；`convert` 是 Windows 自带的磁盘转换工具，不是 ImageMagick）。所以
"从 SVG 重导"这条路现在实际走不通，需要先装工具。鉴于当前结论是不需要重导，暂不安装。

## 唯一新增的素材

半平面遮罩 `mask_half.png` 由构建脚本生成，不是素材包的一部分。它是"旋转半平面遮罩"这项渲染
技术唯一的额外素材，左半不透明、右半透明、中线 2 像素过渡（抗锯齿来源）。

**它与实现里的角度换算公式是一对**：遮罩镜像翻转会让所有填充方向整体反向。校验脚本会断言
遮罩方向，正是因为这一条光看代码发现不了。

## 流水线

- 构建：`scripts/media/build_crosshair_media.py` → 输出到 `addons/MYUI/Media/CrosshairHUD/`
- 校验：`scripts/media/verify_crosshair_media.py`（尺寸、中性度、蒙版纯度、遮罩方向）

> **只刷新准星素材时，直接运行 `build_crosshair_media.py`，不要用裸的 `build_assets.py`。**
>
> 统一入口 `build_assets.py` 会连带重建 EUI_FacetedMedia 的 TGA 素材，而**那两个成品相对构建脚本已经过期**
> （重跑会产生不同字节，构建本身是确定性的，说明脚本或源图在成品提交之后变过）。裸跑会在无关文件上留下差异。
> `verify.assets` 对新旧两版都通过，所以校验拦不住这个差异。
>
> 仓库统一构建检查用的是 `build_assets.py --output-root .local/build/assets`（只写 `.local/`，不碰仓库文件），
> 那条路径不受影响。

两者的详细规格与决策依据见 `myspec/changes/crosshair-hud/issues/05-media-reexport-spec.md`。

# 本仓库模拟引擎升级

技能真身和两个脚本均在本目录。Codex从`.agents/skills/`发现；Claude Code从`.claude/skills/sim2gse-upgrade`指向同一目录。仅用于包含`projects/sim2gse/`的本仓库，项目运行能力仍由仓库提供。

## 五步流程

1. **确认现状和开发门禁。** 加载宿主当前dev-flow（开发流程），记录同一工作树、功能分支、固定基线、目标客户端版本和明确共享数据项目。用当前项目Python（编程语言）运行随包`precheck.py`，保存输出与退出码。先准备可审阅的升级票据，再取得门禁一确认。缺受检构建、标准角色或已审核专精定义时，先补齐对应前置；不能把缺项写作通过。
2. **升级一次并构建。** 按票据更新固定上游与本项目源码锁，复用仓库构建入口。先处理少量连接补丁及编译错误，再检查三个构建产物；正常产品使用基准及受控两个模式，原版产物只作验证。保留旧记录和明确恢复位置。
3. **验证公共行为。** 使用宿主当前build-and-verify（构建与验证）技能，按固定基线执行本机快速验证。复用已有轻量比较检查；跨上游版本不要求伤害、动作次数、搜索路径相等。日常检查不加入真实训练、不提高预算。每票按已批准的双轴独立审查规则处理发现。
4. **专项验收一次。** 从公开训练命令选择批准的少量真实材料，保留正式收敛规则，完成标准角色的单目标、五目标训练及独立复测、入选发布，再从页面真实入口读取并重新评分入选起点。把真实记录键、训练条件、页面任务路径及评分批次组写到普通证据索引；索引只负责定位。运行随包`postcheck.py`。Codex与Claude Code复用同一证据，不重复训练。实际游戏验收单独记录。
5. **交付和关闭。** 汇总构建、验证、双轴审查及专项证据；按开发流程展示门禁二，再取得规格应用与交付授权。复用已有拉取请求流程。缺项或失败保留准确恢复步骤，不宣告升级完成。

## 两个只读命令

从当前技能目录解析`scripts/`；以下`<python>`是项目现有Python程序，`<repo>`为执行仓库，`<data-project>`为已经接入的共享中心所属项目。

```text
<python> <skill>/scripts/precheck.py --project <repo> --data-project <data-project>
<python> <skill>/scripts/postcheck.py --project <repo> --data-project <data-project> --evidence <index.json>
```

前检查只读当前构建、标准角色及专精定义；后核验按指定键和字段读取，任务检查点用只读数据库连接。两个脚本不运行模拟、训练、安装、发布或历史扫描。成功退出0；缺项、旧身份和不一致退出2，并说明原因。正确拒绝旧证据只能证明核验工具工作，不能证明新版升级成功。

证据索引包含`scenes`（场景列表），分别指定`targets`（目标数）1、5。每场字段：`training_condition`（训练条件）、`processed`（三个真实材料编号，两类成功及一类拒绝）、`selected`（本次真实入选材料编号）、`run_id`（页面子任务编号）、`page_task`（页面子任务目录）、`batches`（页面搜索评分批次）。每个批次用`group`（实际存储组）与`key`（实际批次键）定位。索引不保存“已通过”断言。记录字段缺失时修复真实链，禁止添加允许旧版本通过的开关。

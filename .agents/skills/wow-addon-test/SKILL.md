# 魔兽插件逻辑比较

把插件的**真实生产代码**接到工具内置的输入与参考期望上，逐检查点比较，报告真实差异与覆盖缺口。

## 怎么跑

本文件所在目录即技能根；下面的命令都相对它。**先用你所在环境提供的技能目录定位方式
把 `<技能目录>` 换成实际路径**，再执行。

```text
python <技能目录>/scripts/wowtest.py doctor --json      # 环境与数据完整性
python <技能目录>/scripts/wowtest.py catalog --json     # 可用专精与用例规模
python <技能目录>/scripts/wowtest.py run --config <项目>/.wow-test/wowtest.json \
       --output <项目>/.wow-test/report.json --json
```

Lua 后端由环境变量 `WOWTEST_LUA` 指定（宿主仓库若固定了后端，会通过这个变量传进来）；
未设置时 `doctor` 会按「`lupa.lua51` → 本机 Lua 共享库 → 本机 Lua 程序」的顺序自动探测并报出
选了哪一个。技能自身不安装任何东西。

## 流程

1. **先看环境**：`doctor` 报出数据完整性、可用 Lua 后端与范围；`catalog` 报出专精与用例规模。
   **不要声称工具支持目录之外的能力。**
2. **读真实源码**：读插件的加载清单、实际源文件与版本控制状态，定位真实的数据读取、初始化、
   事件、计时、缓存与输出入口。**不得凭聊天历史猜接口，也不得让用户代贴已可读的文件。**
3. **接入**：在项目下建立接入配置与适配器；**绝不覆盖已有的接入**。
   适配器只做输入接线、真实生命周期启动与实际输出归一化；**生产算法必须来自配置列出的真实文件**。
4. **运行**：`run` 出报告（含同名 Markdown）。读**第一个具体失败**与差异字段，
   区分"替身不足／适配错误／产品语义差异／生产代码缺陷"。
5. **验证测试本身有效**：在临时副本里对真实生产代码**注入一个相关缺陷**，确认测试会失败，
   随后恢复并核对差异。**没做这一步，就标记"适配有效性待验证"。**
6. **报告**：实际加载的文件与摘要、所选专精与组件、用例与检查点数、通过/差异/执行错误、
   未覆盖内容、是否做过真实错误变体验证。

## 不可违反的边界

- 参考期望**不能**提供给适配器；不得自行读取基线来算输出。
- 适配器**不得**复制一份"正确的资源计算器"；已有模型就读模型，没有就截取真实输出函数的参数。
- 必须走**真实注册的事件／逐帧／计时路径**；禁止为通过测试而每步直接调用内部刷新函数。
- 未实现的接口**必须显式失败**；可以添加**有依据的局部替身**，不可安装万能空对象或让未知调用成功。
- 不得修改参考基线来消除失败；不得通过缩小范围、删除断言、默认返回零来让测试变绿。
- 只执行受信任的本地源码；**不要把用户源码或任何凭据发到外部**。

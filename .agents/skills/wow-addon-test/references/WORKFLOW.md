# AI 接入执行清单

先读实际代码，然后给用户 5 行以内的接入说明：入口、所选范围、必要小改动、已知缺口、运行命令。完成后必须真实执行。

## 工具启动

运行本技能 `scripts/wowtest.py doctor --json`。目录中存在 `.venv` 时优先使用该环境的 Python。缺 Lua 时，用户已授权安装则执行工具根目录 `bootstrap.py`；需要网络仅发生在依赖安装，不上传代码。

## 定位生产逻辑

读取 `.toc`（插件清单）与实际模块；查看当前版本控制差异，保留用户更改。找到各组件数据读取、选择专精/形态的分支、事件注册、时间回调、可见性与缓存。可以只加载这些真实模块及必要依赖，不强制全插件初始化。

## 接入边界

选用已有状态模型或输出函数的参数。记录器只是接住实际计算结果，不能代算。如果没有任何逻辑边界，做小范围依赖注入；不能为了测试另外写一个“简化版 MYUI”。

必须告诉用户哪些生产文件被执行、哪些仍未执行。工具只能检查 files 白名单确实加载，不能自动证明适配器没有绕开核心逻辑；必须读代码审查并做错误变体验证。

## 失败处理

先查报告 stage（阶段），再看用例步骤、输入、字段。缺失 API/模板属于宿主/适配能力问题，不先改生产业务。数字不一致时检查原始单位、显示单位、专精索引/ID、当前值/最大值、可用零/空值。

`none` 是本工具基本范围的选择约定。项目已有漩涡武器/灵魂等附加计数时，列入缺口，不能把它删除来对齐 none。必要时先只选择 health/primary 并明确报告 resource 未覆盖；新增独立契约必须单独审核与版本化。

## 验证有效性

选择一个真实风险路径，在临时副本中制造缺陷；确认测试显示预期的具体字段差异，而不是环境错误。恢复缺陷后重跑并对比 git diff（版本差异）。未经授权不提交、不推送、不删除文件。

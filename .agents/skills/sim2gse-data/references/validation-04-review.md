# 票04：云端首轮两项P2修复

固定起点 `f9ad2cb4ed81731f2cfe90e685b51613e41a4fcf`；全局验证基线仍 `f554538993161cc045d19c4ed47d261f709f741b`。Standards（规范）轴通过；Spec（规格）轴要求修复大合法清单元数据峰值漏计及resolve只选首个恢复位置。本票继续，不进入05、不修改生产配置或真实历史数据；无本机审查子代理。

## 公开CLI先失败

- 多位置测试：同一登记ID恢复到a、b，再仅删除临时合成原件和a，b仍完整；resolve报a缺失（1.723秒），复现规格问题。
- 大清单：220个同层native.json、共享约2300字符嵌套路径，合法自动生成清单；低容量restore报容量不足前仍写入操作元数据，根逻辑字节从5023589增至5048348，断言失败（96.385秒）。只扫描该隔离Temp根，不读取历史树。

## 修复与回归

元数据预算与payload分开：实际编码plan及产品字段/路径上界、封口行和阶段/隔离日志；各事务按主库/WAL复制和实际SQLite页面/索引深度估算峰值，计划预算字段固定点收敛。整个增长在首次DDL/登记jobs之前准入。阶段提交后的实际字节已在根盘点里，余量只计未来阶段和重试，避免全部元数据预留再与已落盘数据重复叠加。产品清单编码另核对预留上界；不以payload常数掩盖近1MiB计划。

初版测试使用根字节严格相等，曾将SQLite正常释放32768字节SHM（共享内存文件）误判；最终断言为根逻辑字节不增加、主库SHA相同、未知操作ID、无新工作区。低容量合法自动清单及约801KiB带可选元数据的合法清单均须在写入前拒绝；足额大清单逐一模拟reserved/writing/verified/published/sealed（预留/写入/验证/发布/封口）提交后终止，再重试恢复220项并核对原字节。测试临时根容量值只为演练，不写默认或生产配置。大清单使全技能回归变长，统一测试超时600秒，不属于生产维护频率参数。

resolve（位置解析）最多取1001行以发现超过1000的有界限制，先验证祖先和路径边界，仅跳过FileNotFoundError（确认缺失）。选择存在的副本后核对原摘要和登记身份；可疑副本、权限错误、非目录祖先或链接直接失败，不能跳过异常选择另一个。回归同时覆盖原件篡改、首个副本篡改、首个副本缺失而第二个有效、有效副本随后篡改和全部缺失。

首轮修复归档专项21项通过（171.589秒）；之后补足801KiB清单、大清单五阶段和更保守索引拆分页上界，由最终固定提交统一验证确认。此前小清单三类操作五阶段、WAL、空间、路径、锁及事实回归继续保留；准确最终测试和推送提交见交付信息。真实断电、多卷、几十GiB吞吐和全仓全量验证未运行。保持票05/06范围及待上线参数不变。
